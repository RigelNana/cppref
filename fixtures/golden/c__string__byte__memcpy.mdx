<SourceHtml html={"<div class=\"t-li1\"><span class=\"t-li\">1)</span> Copies <code>count</code> characters from the object pointed to by <code>src</code> to the object pointed to by <code>dest</code>. Both objects are interpreted as arrays of <span class=\"t-c\"><span class=\"mw-geshi c source-c\"><span class=\"kw4\">unsigned</span> <span class=\"kw4\">char</span></span></span>.</div>"} />

{/* source:c-string-byte-memcpy:0002 */}
<SourceHtml html={"<div class=\"t-li1\"><span class=\"t-li\"></span> The behavior is undefined if access occurs beyond the end of the <code>dest</code> array. If the objects overlap<span class=\"t-rev-inl t-since-c99\"><span> (which is a violation of the <a href=\"../../language/restrict.html\" title=\"c/language/restrict\"><tt>restrict</tt></a> contract)</span><span><span class=\"t-mark-rev t-since-c99\">(since C99)</span></span></span>, the behavior is undefined. The behavior is undefined if either <code>dest</code> or <code>src</code> is an invalid or null pointer.</div>"} />

{/* source:c-string-byte-memcpy:0003 */}
<SourceHtml html={"<div class=\"t-li1\"><span class=\"t-li\">2)</span> Same as <span class=\"t-v\">(1)</span>, except that the following errors are detected at runtime and cause the entire destination range <span class=\"t-c\"><span class=\"mw-geshi c source-c\"><span class=\"br0\">[</span>dest, dest<span class=\"sy2\">+</span>destsz<span class=\"br0\">)</span></span></span> to be zeroed out (if both <code>dest</code> and <code>destsz</code> are valid), as well as call the currently installed <a href=\"../../error/set_constraint_handler_s.html\" title=\"c/error/set constraint handler s\">constraint handler</a> function:\n<dl><dd><ul><li> <code>dest</code> or <code>src</code> is a null pointer\n</li><li> <code>destsz</code> or <code>count</code> is greater than <span class=\"t-lc\">RSIZE_MAX</span>\n</li><li> <code>count</code> is greater than <code>destsz</code> (buffer overflow would occur)\n</li><li> the source and the destination objects overlap</li></ul></dd></dl></div>"} />

{/* source:c-string-byte-memcpy:0004 */}

<h3 id="Notes">Notes</h3>

{/* source:c-string-byte-memcpy:0008 */}
<SourceHtml html={"<p><code>memcpy</code> may be used to set the <a href=\"../../language/object.html#Effective_type\" title=\"c/language/object\">effective type</a> of an object obtained by an allocation function.\n</p>"} />

{/* source:c-string-byte-memcpy:0009 */}
<SourceHtml html={"<p><code>memcpy</code> is the fastest library routine for memory-to-memory copy. It is usually more efficient than <span class=\"t-lc\"><a href=\"strcpy.html\" title=\"c/string/byte/strcpy\">strcpy</a></span>, which must scan the data it copies or <span class=\"t-lc\"><a href=\"memmove.html\" title=\"c/string/byte/memmove\">memmove</a></span>, which must take precautions to handle overlapping inputs.\n</p>"} />

{/* source:c-string-byte-memcpy:0010 */}
Several C compilers transform suitable memory-copying loops to memcpy calls.

{/* source:c-string-byte-memcpy:0011 */}
<SourceHtml html={"<p>Where <a href=\"../../language/object.html#Strict_aliasing\" title=\"c/language/object\">strict aliasing</a> prohibits examining the same memory as values of two different types, <code>memcpy</code> may be used to convert the values.\n</p>"} />
