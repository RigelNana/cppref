{/* source:cpp-standard-library-decay-copy:0001 */}
Returns `std::forward<T>(value)` (implicitly converted to the decayed type), a decayed prvalue copy of `value`.

### Parameters

{/* source:cpp-standard-library-decay-copy:0002 */}
<ParameterList>
  <Parameter name="value">the value to be copied</Parameter>
</ParameterList>

### Return value

{/* source:cpp-standard-library-decay-copy:0003 */}
A decayed copy of `value` as a prvalue.

### Notes

{/* source:cpp-standard-library-decay-copy:0004 */}
`decay-copy` was introduced by the resolution of [LWG issue 929](https://cplusplus.github.io/LWG/issue929). It is initially used in the [concurrency support library](/docs/cpp/library/atomic) to ensure that arguments are decayed when passing-by-value, and is later used in the [ranges library](/docs/cpp/library/ranges).

{/* source:cpp-standard-library-decay-copy:0005 */}
The language feature [`auto`](/docs/cpp/language/expressions/explicit_cast)`(x)` introduced in C++23 also allows decayed copies to be created as prvalues. The only difference is that `decay-copy` always [materializes](/docs/cpp/language/expressions/implicit_cast#Temporary_materialization) `value` and produces a copy, while `auto(expr)` is a no-op if `expr` is a prvalue.

{/* source:cpp-standard-library-decay-copy:0006 */}
All usages of `decay-copy` in the standard library (see below) except [`views::all`](/docs/cpp/library/ranges/all_view), [`ranges::take_view`](/docs/cpp/library/ranges/take_view) and [`ranges::drop_view`](/docs/cpp/library/ranges/drop_view) are replaced with `auto(x)` since C++23.
