{/* source:cpp-string-basic-string-operator:0001 */}
Returns a string containing characters from `lhs` followed by the characters from `rhs`. Equivalent to:

{/* source:cpp-string-basic-string-operator:0002 */}
1. 1,2) `std::basic_string<CharT, Traits, Allocator> r = lhs; r.append(rhs); return r;`

{/* source:cpp-string-basic-string-operator:0003 */}
2. 3) `std::basic_string<CharT, Traits, Allocator> r = lhs; r.push_back(rhs); return r;`

{/* source:cpp-string-basic-string-operator:0004 */}
3. 4) `std::basic_string<CharT, Traits, Allocator> r = lhs; r.append(rhs); return r;`

{/* source:cpp-string-basic-string-operator:0005 */}
4. 5) `std::basic_string<CharT, Traits, Allocator> r = rhs; r.insert(0, lhs); return r;`

{/* source:cpp-string-basic-string-operator:0006 */}
5. 6) `std::basic_string<CharT, Traits, Allocator> r = rhs; r.insert(r.begin(), lhs); return r;`

{/* source:cpp-string-basic-string-operator:0007 */}
6. 7) `std::basic_string<CharT, Traits, Allocator> r = rhs; r.insert(0, lhs); return r;`

{/* source:cpp-string-basic-string-operator:0008 */}
7. 8) `lhs.append(rhs); return std::move(lhs);` except that both `lhs` and `rhs` are left in valid but unspecified states. If `lhs` and `rhs` have equal allocators, the implementation can move from either.

{/* source:cpp-string-basic-string-operator:0009 */}
8. 9,10) `lhs.append(rhs); return std::move(lhs);`

{/* source:cpp-string-basic-string-operator:0010 */}
9. 11) `lhs.push_back(rhs); return std::move(lhs);`

{/* source:cpp-string-basic-string-operator:0011 */}
10. 12) `lhs.append(rhs); return std::move(lhs);`

{/* source:cpp-string-basic-string-operator:0012 */}
11. 13,14) `rhs.insert(0, lhs); return std::move(rhs);`

{/* source:cpp-string-basic-string-operator:0013 */}
12. 15) `rhs.insert(rhs.begin(), lhs); return std::move(rhs);`

{/* source:cpp-string-basic-string-operator:0014 */}
13. 16) `rhs.insert(0, lhs); return std::move(rhs);`

{/* source:cpp-string-basic-string-operator:0015 */}
<Revision since="C++11">
The allocator used for the result is:

- 1-4) `std::allocator_traits<Alloc>::select_on_container_copy_construction(lhs.get_allocator())`
- 5-7) `std::allocator_traits<Alloc>::select_on_container_copy_construction(rhs.get_allocator())`
- 8-12) `lhs.get_allocator()`
- 13-16) `rhs.get_allocator()`

In other words:

- If one operand is a `basic_string` rvalue, its allocator is used.
- Otherwise, `select_on_container_copy_construction` is used on the allocator of the lvalue `basic_string` operand.

In each case, the left operand is preferred when both are `basic_string`s of the same value category.

For ([8-16](/docs/cpp/library/string/basic_string/operator_plus#Version_8)), all rvalue `basic_string` operands are left in valid but unspecified states.
</Revision>

### Notes

`operator+` should be used with great caution when stateful allocators are involved <InlineRevision since="C++17">(such as when [`std::pmr::string`](/docs/cpp/library/string/basic_string) is used)</InlineRevision>. Prior to [P1165R1](https://wg21.link/P1165R1), the allocator used for the result was determined by historical accident and can vary from overload to overload for no apparent reason. Moreover, for ([1-5](/docs/cpp/library/string/basic_string/operator_plus#Version_1)), the allocator propagation behavior varies across major standard library implementations and differs from the behavior depicted in the standard.

Because the allocator used by the result of `operator+` is sensitive to value category, `operator+` is not associative with respect to allocator propagation:

```cpp
using my_string = std::basic_string<char, std::char_traits<char>, my_allocator<char>>;
my_string cat();
const my_string& dog();
 
my_string meow = /* ... */, woof = /* ... */;
meow + cat() + /* ... */; // uses select_on_container_copy_construction on meow's allocator
woof + dog() + /* ... */; // uses allocator of dog()'s return value instead
 
meow + woof + meow; // uses select_on_container_copy_construction on meow's allocator
meow + (woof + meow); // uses SOCCC on woof's allocator instead
```

For a chain of `operator+` invocations, the allocator used for the ultimate result may be controlled by prepending an rvalue `basic_string` with the desired allocator:

```cpp
// use my_favorite_allocator for the final result
my_string(my_favorite_allocator) + meow + woof + cat() + dog();
```

For better and portable control over allocators, member functions like [`append`](/docs/cpp/library/string/basic_string/append), [`insert`](/docs/cpp/library/string/basic_string/insert), and [`operator+=`](/docs/cpp/library/string/basic_string/operator_plus_assign) should be used on a result string constructed with the desired allocator.
</Revision>

### Example

```cpp
#include <iostream>
#include <string>
#include <string_view>
 
int main()
{
    std::string s1 = "Hello";
    std::string s2 = "world";
    const char* end = "!\n";
    std::cout << s1 + ' ' + s2 + end;
 
    std::string_view water{" Water"};
    #if __cpp_lib_string_view >= 202403
    std::cout << s1 + water + s2 << end; // overload (4), then (1)
    #else
    std::cout << s1 + std::string(water) + s2 << end; // OK, but less efficient
    #endif
}
```

Output:

```text
Hello world!
Hello Waterworld!
```
