{/* source:cpp-memory-weak-ptr-atomic2:0001 */}
The partial template specialization of [`std::atomic`](/docs/cpp/library/atomic/atomic) for `std::weak_ptr<T>` allows users to manipulate weak_ptr objects atomically.

{/* source:cpp-memory-weak-ptr-atomic2:0002 */}
If multiple threads of execution access the same [`std::weak_ptr`](/docs/cpp/library/memory/weak_ptr) object without synchronization and any of those accesses uses a non-const member function of `weak_ptr` then a data race will occur unless all such access is performed through an instance of `std::atomic<std::weak_ptr>`.

{/* source:cpp-memory-weak-ptr-atomic2:0003 */}
Associated `use_count` increments are guaranteed to be part of the atomic operation. Associated `use_count` decrements are sequenced after the atomic operation, but are not required to be part of it, except for the `use_count` change when overriding `expected` in a failed CAS. Any associated deletion and deallocation are sequenced after the atomic update step and are not part of the atomic operation.

{/* source:cpp-memory-weak-ptr-atomic2:0004 */}
Note that the control block used by [`std::weak_ptr`](/docs/cpp/library/memory/weak_ptr) and [`std::shared_ptr`](/docs/cpp/library/memory/shared_ptr) is thread-safe: different non-atomic [`std::weak_ptr`](/docs/cpp/library/memory/weak_ptr) objects can be accessed using mutable operations, such as `operator=` or `reset`, simultaneously by multiple threads, even when these instances are copies or otherwise share the same control block internally.

{/* source:cpp-memory-weak-ptr-atomic2:0005 */}
The type `T` may be an incomplete type.

## `atomic<weak_ptr<T>>::store`

<DeclarationDoc>
  <Declaration language="cpp" code={`void store(std::weak_ptr<T> desired,
           std::memory_order order = std::memory_order_seq_cst) noexcept;`} />
</DeclarationDoc>

Atomically replaces the value of `*this` with the value of `desired` as if by `p.swap(desired)` where `p` is the underlying `std::weak_ptr<T>`. Memory is ordered according to `order`. The behavior is undefined if `order` is [`std::memory_order_consume`](/docs/cpp/library/atomic/memory_order), [`std::memory_order_acquire`](/docs/cpp/library/atomic/memory_order), or [`std::memory_order_acq_rel`](/docs/cpp/library/atomic/memory_order).

## `atomic<weak_ptr<T>>::exchange`

<DeclarationDoc>
  <Declaration language="cpp" code={`std::weak_ptr<T> exchange(std::weak_ptr<T> desired,
                          std::memory_order order = std::memory_order_seq_cst) noexcept;`} />
</DeclarationDoc>

Atomically replaces the underlying `std::weak_ptr<T>` with `desired` as if by `p.swap(desired)` where `p` is the underlying `std::weak_ptr<T>`, and returns a copy of the value that `p` had immediately before the swap. Memory is ordered according to `order`. This is an atomic read-modify-write operation.

## `atomic<weak_ptr<T>>::compare_exchange_weak, compare_exchange_strong`

<DeclarationDoc>
  <Declaration id="1" language="cpp" code={`bool compare_exchange_strong(std::weak_ptr<T>& expected, std::weak_ptr<T> desired,
                             std::memory_order success, std::memory_order failure) noexcept;`} />
  <Declaration id="2" language="cpp" code={`bool compare_exchange_weak(std::weak_ptr<T>& expected, std::weak_ptr<T> desired,
                           std::memory_order success, std::memory_order failure) noexcept;`} />
  <Declaration id="3" language="cpp" code={`bool compare_exchange_strong(std::weak_ptr<T>& expected, std::weak_ptr<T> desired,
                             std::memory_order order = std::memory_order_seq_cst) noexcept;`} />
  <Declaration id="4" language="cpp" code={`bool compare_exchange_weak(std::weak_ptr<T>& expected, std::weak_ptr<T> desired,
                           std::memory_order order = std::memory_order_seq_cst) noexcept;`} />

  <DeclarationDescription>

    1. 1) If the underlying `std::weak_ptr<T>` stores the same pointer value as `expected` and shares ownership with it, or if both underlying and `expected` are empty, assigns from `desired` to the underlying `std::weak_ptr<T>`, returns `true`, and orders memory according to `success`, otherwise assigns from the underlying `std::weak_ptr<T>` to `expected`, returns `false`, and orders memory according to `failure`. The behavior is undefined if `failure` is [`std::memory_order_release`](/docs/cpp/library/atomic/memory_order) or [`std::memory_order_acq_rel`](/docs/cpp/library/atomic/memory_order). On success, the operation is an atomic read-modify-write operation on `*this` and `expected` is not accessed after the atomic update. On failure, the operation is an atomic load operation on `*this` and `expected` is updated with the existing value read from the atomic object. This update to `expected`'s use_count is part of this atomic operation, although the write itself (and any subsequent deallocation/destruction) is not required to be.
    2. 2) Same as (1), but may also fail spuriously.
    3. 3) Equivalent to: `return compare_exchange_strong(expected, desired, order, fail_order);`, where `fail_order` is the same as `order` except that [`std::memory_order_acq_rel`](/docs/cpp/library/atomic/memory_order) is replaced by [`std::memory_order_acquire`](/docs/cpp/library/atomic/memory_order) and [`std::memory_order_release`](/docs/cpp/library/atomic/memory_order) is replaced by [`std::memory_order_relaxed`](/docs/cpp/library/atomic/memory_order).
    4. 4) Equivalent to: `return compare_exchange_weak(expected, desired, order, fail_order);`, where `fail_order` is the same as `order` except that [`std::memory_order_acq_rel`](/docs/cpp/library/atomic/memory_order) is replaced by [`std::memory_order_acquire`](/docs/cpp/library/atomic/memory_order) and [`std::memory_order_release`](/docs/cpp/library/atomic/memory_order) is replaced by [`std::memory_order_relaxed`](/docs/cpp/library/atomic/memory_order).

  </DeclarationDescription>
</DeclarationDoc>

## `atomic<weak_ptr<T>>::wait`

<DeclarationDoc>
  <Declaration language="cpp" code={`void wait(std::weak_ptr<T> old
          std::memory_order order = std::memory_order_seq_cst) const noexcept;`} />
</DeclarationDoc>

Performs an atomic waiting operation.

Compares `load(order)` with `old` and if they are equivalent then blocks until `*this` is notified by `notify_one()` or `notify_all()`. This is repeated until `load(order)` changes. This function is guaranteed to return only if value has changed, even if underlying implementation unblocks spuriously.

Memory is ordered according to `order`. The behavior is undefined if `order` is [`std::memory_order_release`](/docs/cpp/library/atomic/memory_order) or [`std::memory_order_acq_rel`](/docs/cpp/library/atomic/memory_order).

Notes: two [`std::weak_ptrs`](/docs/cpp/library/memory/weak_ptr) are equivalent if they store the same pointer and either share ownership or are both empty.

## `atomic<weak_ptr<T>>::notify_one`

<DeclarationDoc>
  <Declaration language="cpp" code={`void notify_one() noexcept;`} />
</DeclarationDoc>

Performs an atomic notifying operation.

If there is a thread blocked in atomic waiting operations (i.e. `wait()`) on `*this`, then unblocks at least one such thread; otherwise does nothing.

{/* source:cpp-memory-weak-ptr-atomic2:0018 */}
## `atomic<weak_ptr<T>>::notify_all`

<DeclarationDoc>
  <Declaration language="cpp" code={`void notify_all() noexcept;`} />
</DeclarationDoc>

Performs an atomic notifying operation.

Unblocks all threads blocked in atomic waiting operations (i.e. `wait()`) on `*this`, if there are any; otherwise does nothing.
