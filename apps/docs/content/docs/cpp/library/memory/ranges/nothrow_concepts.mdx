{/* source:cpp-memory-ranges-nothrow-concepts:0001 */}
These exposition-only concepts specify that no exceptions are thrown from operations required by algorithms on iterators, sentinels, and ranges.

{/* source:cpp-memory-ranges-nothrow-concepts:0002 */}
1. 1) The no-throw-input-iterator concept requires that dereferencing the iterator yields an lvalue, like [contiguous_iterator](/docs/cpp/library/iterator/contiguous_iterator) and [LegacyForwardIterator](/docs/cpp/library/named_req/ForwardIterator).

### Semantic requirements

{/* source:cpp-memory-ranges-nothrow-concepts:0003 */}
Like all standard concepts, every concept listed here is modeled only if all concepts it subsumes are modeled.

{/* source:cpp-memory-ranges-nothrow-concepts:0004 */}
1. 1) A type `I` models no-throw-input-iterator only if no exceptions are thrown from increment, copy construction, move construction, copy assignment, move assignment, or indirection through valid iterators.

{/* source:cpp-memory-ranges-nothrow-concepts:0005 */}
2. 3) Types `S` and `I` model no-throw-sentinel-for only if no exceptions are thrown from copy construction, move construction, copy assignment, move assignment, or comparisons between valid values of type `I` and `S`.

{/* source:cpp-memory-ranges-nothrow-concepts:0006 */}
3. 4) A type `R` models no-throw-input-range only if no exceptions are thrown from calls to `ranges::begin` and `ranges::end` on an object of type `R`.

### Notes

{/* source:cpp-memory-ranges-nothrow-concepts:0007 */}
These concepts allow some operations on iterators and sentinels to throw exceptions, e.g. operations on invalid values.
