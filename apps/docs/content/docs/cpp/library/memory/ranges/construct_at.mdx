Call signature

  <Declaration language="cpp" since="C++20" code={`template< class T, class... Args >
constexpr T* construct_at( T* location, Args&&... args );`} />
</DeclarationDoc>

{/* source:cpp-memory-ranges-construct-at:0001 */}
Creates a `T` object initialized with the arguments in `args` at given address `location`.

{/* source:cpp-memory-ranges-construct-at:0002 */}
Equivalent to `if constexpr (std::is_array_v<T>) return ::new (`[`voidify`](/docs/cpp/library/memory/voidify)`(*location)) T[1](); else return ::new (`[`voidify`](/docs/cpp/library/memory/voidify)`(*location)) T(std::forward<Args>(args)...);`<InlineRevision until="C++26">, except that construct_at may be used in evaluation of [`constant expressions`](/docs/cpp/language/expressions/constant_expression)</InlineRevision>.

{/* source:cpp-memory-ranges-construct-at:0003 */}
When `construct_at` is called in the evaluation of some constant expression `expr`, `location` must point to either a storage obtained by `std::allocator<T>::allocate` or an object whose lifetime began within the evaluation of `expr`.

{/* source:cpp-memory-ranges-construct-at:0004 */}
This overload participates in overload resolution only if all following conditions are satisfied:

{/* source:cpp-memory-ranges-construct-at:0005 */}
- `std::is_unbounded_array_v<T>` is `false`.
- `::new(std::declval<void*>()) T(std::declval<Args>()...)` is well-formed when treated as an [`unevaluated operand`](/docs/cpp/language/expressions#Potentially-evaluated_expressions).

{/* source:cpp-memory-ranges-construct-at:0006 */}
If `std::is_array_v<T>` is `true` and `sizeof...(Args)` is nonzero, the program is ill-formed.

{/* source:cpp-memory-ranges-construct-at:0007 */}
The function-like entities described on this page are [*algorithm function objects*](/docs/cpp/library/algorithm/ranges#Algorithm_function_objects) (informally known as *niebloids*), that is:

{/* source:cpp-memory-ranges-construct-at:0008 */}
- Explicit template argument lists cannot be specified when calling any of them.
- None of them are visible to [`argument-dependent lookup`](/docs/cpp/language/functions/adl).
- When any of them are found by [`normal unqualified lookup`](/docs/cpp/language/basic_concepts/unqualified_lookup) as the name to the left of the function-call operator, [`argument-dependent lookup`](/docs/cpp/language/functions/adl) is inhibited.

### Return value

{/* source:cpp-memory-ranges-construct-at:0010 */}
`location`

### Notes

{/* source:cpp-memory-ranges-construct-at:0011 */}
`std::ranges::construct_at` behaves exactly same as [`std::construct_at`](/docs/cpp/library/memory/construct_at), except that it is invisible to argument-dependent lookup.

### Example

{/* source:cpp-memory-ranges-construct-at:0012 */}
```cpp
#include <iostream>
#include <memory>
 
struct S
{
    int x;
    float y;
    double z;
 
    S(int x, float y, double z) : x{x}, y{y}, z{z} { std::cout << "S::S();\n"; }
 
    ~S() { std::cout << "S::~S();\n"; }
 
    void print() const
    {
        std::cout << "S { x=" << x << "; y=" << y << "; z=" << z << "; };\n";
    }
};
 
int main()
{
    alignas(S) unsigned char buf[sizeof(S)];
 
    S* ptr = std::ranges::construct_at(reinterpret_cast<S*>(buf), 42, 2.71828f, 3.1415);
    ptr->print();
 
    std::ranges::destroy_at(ptr);
}
```

Output:

```text
S::S();
S { x=42; y=2.71828; z=3.1415; };
S::~S();
```
