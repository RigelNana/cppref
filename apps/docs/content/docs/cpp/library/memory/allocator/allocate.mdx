{/* source:cpp-memory-allocator-allocate:0001 */}
Allocates `n * sizeof(T)` bytes of uninitialized storage by calling `::operator new(std::size_t)` <InlineRevision since="C++17">or `::operator new(std::size_t, std::align_val_t)`</InlineRevision>, but it is unspecified when and how this function is called. The pointer `hint` may be used to provide locality of reference: the allocator, if supported by the implementation, will attempt to allocate the new memory block as close as possible to `hint`.

{/* source:cpp-memory-allocator-allocate:0002 */}
Then, this function creates an array of type `T[n]` in the storage and starts its lifetime, but does not start lifetime of any of its elements.

{/* source:cpp-memory-allocator-allocate:0003 */}
Use of this function is ill-formed if `T` is an [incomplete type](/docs/cpp/language/basic_concepts/type-id#Incomplete_type).

{/* source:cpp-memory-allocator-allocate:0004 */}
<Revision since="C++20">
In order to use this function in a constant expression, the allocated storage must be deallocated within the evaluation of the same expression.
</Revision>

### Parameters

{/* source:cpp-memory-allocator-allocate:0005 */}
<ParameterList>
  <Parameter name="n">the number of objects to allocate storage for</Parameter>
  <Parameter name="hint">pointer to a nearby memory location</Parameter>
</ParameterList>

### Return value

{/* source:cpp-memory-allocator-allocate:0006 */}
Pointer to the first element of an array of `n` objects of type `T` whose elements have not been constructed yet.

### Exceptions

{/* source:cpp-memory-allocator-allocate:0007 */}
<Revision since="C++11">
Throws [`std::bad_array_new_length`](/docs/cpp/library/memory/new/bad_array_new_length) if `std::numeric_limits<std::size_t>::max() / sizeof(T) < n`.
</Revision>

{/* source:cpp-memory-allocator-allocate:0008 */}
Throws [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc) if allocation fails.

### Notes

{/* source:cpp-memory-allocator-allocate:0009 */}
The "unspecified when and how" wording makes it possible to [combine or optimize away heap allocations](/docs/cpp/language/expressions/new#Allocation) made by the standard library containers, even though such optimizations are disallowed for direct calls to `::operator new`. For example, this is implemented by libc++ ([1](https://github.com/llvm-mirror/libcxx/blob/master@%7B2017-02-09%7D/include/memory#L1766-L1772) and [2](https://github.com/llvm-mirror/libcxx/blob/master@%7B2017-02-09%7D/include/new#L211-L217)).

{/* source:cpp-memory-allocator-allocate:0010 */}
After calling `allocate()` and before construction of elements, pointer arithmetic of `T*` is well-defined within the allocated array, but the behavior is undefined if elements are accessed.
