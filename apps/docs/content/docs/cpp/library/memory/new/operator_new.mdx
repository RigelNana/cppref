{/* source:cpp-memory-new-operator-new:0001 */}
Attempts to allocate requested number of bytes, and the allocation request can fail (even if the requested number of bytes is zero). These allocation functions are called by [`new` expressions](/docs/cpp/language/expressions/new) to allocate memory in which new object would then be initialized. They may also be called using regular function call syntax.

{/* source:cpp-memory-new-operator-new:0002 */}
1. 1) Called by `new` to allocate storage required for a single object.

{/* source:cpp-memory-new-operator-new:0003 */}
2. The standard library implementation allocates `count` bytes from free store.

{/* source:cpp-memory-new-operator-new:0004 */}
3. In case of failure, the standard library implementation calls the function pointer returned by [`std::get_new_handler`](/docs/cpp/library/memory/new/get_new_handler) and repeats allocation attempts until new handler does not return or becomes a null pointer, at which time it throws [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc).

{/* source:cpp-memory-new-operator-new:0005 */}
4. This function is required to return a pointer suitably aligned to point to an object of the requested size.

{/* source:cpp-memory-new-operator-new:0006 */}
5. 2) Called by `new[]` to allocate all storage required for an array (including possible `new` expression overhead).

{/* source:cpp-memory-new-operator-new:0007 */}
6. The standard library implementation calls version (1).

{/* source:cpp-memory-new-operator-new:0008 */}
7. 3) Called by `new` to allocate storage required for a single object whose alignment requirement exceeds `__STDCPP_DEFAULT_NEW_ALIGNMENT__`.

{/* source:cpp-memory-new-operator-new:0009 */}
8. 4) Called by `new[]` to allocate all storage required for an array of objects whose alignment requirement exceeds `__STDCPP_DEFAULT_NEW_ALIGNMENT__`.

{/* source:cpp-memory-new-operator-new:0010 */}
9. 5) Called by the non-throwing `new`.

{/* source:cpp-memory-new-operator-new:0011 */}
10. The standard library implementation calls the version (1) and returns a null pointer on failure instead of propagating the exception.

{/* source:cpp-memory-new-operator-new:0012 */}
11. 6) Called by the non-throwing `new[]`.

{/* source:cpp-memory-new-operator-new:0013 */}
12. The standard library implementation calls the version (2) and returns a null pointer on failure instead of propagating the exception.

{/* source:cpp-memory-new-operator-new:0014 */}
13. 7) Called by the non-throwing `new` when the object's alignment requirement exceeds `__STDCPP_DEFAULT_NEW_ALIGNMENT__`.

{/* source:cpp-memory-new-operator-new:0015 */}
14. The standard library implementation calls the version (3) and returns a null pointer on failure instead of propagating the exception.

{/* source:cpp-memory-new-operator-new:0016 */}
15. 8) Called by the non-throwing `new[]` when the alignment requirement of array elements exceeds `__STDCPP_DEFAULT_NEW_ALIGNMENT__`.

{/* source:cpp-memory-new-operator-new:0017 */}
16. The standard library implementation calls the version (4) and returns a null pointer on failure instead of propagating the exception.

{/* source:cpp-memory-new-operator-new:0018 */}
17. 9) Called by the standard [placement new](/docs/cpp/language/expressions/new#Placement_new).

{/* source:cpp-memory-new-operator-new:0019 */}
18. The standard library implementation performs no action and returns `ptr` unmodified.

{/* source:cpp-memory-new-operator-new:0020 */}

{/* source:cpp-memory-new-operator-new:0021 */}

{/* source:cpp-memory-new-operator-new:0022 */}

### Return value

{/* source:cpp-memory-new-operator-new:0049 */}
1. 1-4) If the allocation succeeds, a non-null pointer `p0` which points to suitably aligned memory of size at least `size` and is different from any previously returned value `p1`, unless that value `p1` was subsequently passed to a replaceable [deallocation function](/docs/cpp/library/memory/new/operator_delete); if the allocation fails, does not return (an exception is thrown, see below).

{/* source:cpp-memory-new-operator-new:0050 */}
2. 5-8) Same as (1-4), but returns a null pointer if the allocation fails.

{/* source:cpp-memory-new-operator-new:0051 */}
3. 9,10) `ptr`

{/* source:cpp-memory-new-operator-new:0052 */}
4. 11-22) Same as (1-4) if the function does not return on allocation failure, otherwise same as (5-8).

### Exceptions

{/* source:cpp-memory-new-operator-new:0053 */}
1. 1-4) Throws an exception of a type that would match a handler of type [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc) on failure to allocate memory.

{/* source:cpp-memory-new-operator-new:0054 */}
2. 11-22) Same as (1-4) if the function does not return on allocation failure, otherwise same as (5-8).

### Global replacements

{/* source:cpp-memory-new-operator-new:0055 */}
The versions ([1-4](/docs/cpp/library/memory/new/operator_new#Version_1)) are implicitly declared in each translation unit even if the [`<new>`](/docs/cpp/library/headers/new) header is not included. Versions ([1-8](/docs/cpp/library/memory/new/operator_new#Version_1)) are replaceable: a user-provided non-member function with the same signature defined anywhere in the program, in any source file, replaces the default version. Its declaration does not need to be visible.

{/* source:cpp-memory-new-operator-new:0056 */}
The program is ill-formed, no diagnostic required if more than one replacement is provided in the program for any of the replaceable allocation function, or if a replacement is declared with the [`inline`](/docs/cpp/language/declarations/inline) specifier. The program is ill-formed if a replacement is defined in namespace other than global namespace, or if it is defined as a static non-member function at global scope.

{/* source:cpp-memory-new-operator-new:0057 */}
The standard library implementations of the nothrow versions ([5-8](/docs/cpp/library/memory/new/operator_new#Version_5)) directly calls the corresponding throwing versions ([1-4](/docs/cpp/library/memory/new/operator_new#Version_1)). The standard library implementation of the throwing array versions ([2,4](/docs/cpp/library/memory/new/operator_new#Version_2)) directly calls the corresponding single-object version ([1,3](/docs/cpp/library/memory/new/operator_new#Version_1)). Thus, replacing the throwing single object allocation functions is sufficient to handle all allocations.

{/* source:cpp-memory-new-operator-new:0058 */}
<Revision since="C++26">
On [freestanding implementations](/docs/cpp/library/freestanding), it is implementation-defined whether the default versions of ([1-8](/docs/cpp/library/memory/new/operator_new#Version_1)) satisfy the behaviors required above. Freestanding implementations are recommended that if any of these default versions meet the requirements of a hosted implementation, they all should.
</Revision>

{/* source:cpp-memory-new-operator-new:0059 */}
Global operators `new`/`delete` replacement:

```cpp
#include <cstdio>
#include <cstdlib>
#include <new>
 
// no inline, required by [replacement.functions]/3
void* operator new(std::size_t sz)
{
    std::printf("1) new(size_t), size = %zu\n", sz);
    if (sz == 0)
        ++sz; // avoid std::malloc(0) which may return nullptr on success
 
    if (void *ptr = std::malloc(sz))
        return ptr;
 
    throw std::bad_alloc{}; // required by [new.delete.single]/3
}
 
// no inline, required by [replacement.functions]/3
void* operator new[](std::size_t sz)
{
    std::printf("2) new[](size_t), size = %zu\n", sz);
    if (sz == 0)
        ++sz; // avoid std::malloc(0) which may return nullptr on success
 
    if (void *ptr = std::malloc(sz))
        return ptr;
 
    throw std::bad_alloc{}; // required by [new.delete.single]/3
}
 
void operator delete(void* ptr) noexcept
{
    std::puts("3) delete(void*)");
    std::free(ptr);
}
 
void operator delete(void* ptr, std::size_t size) noexcept
{
    std::printf("4) delete(void*, size_t), size = %zu\n", size);
    std::free(ptr);
}
 
void operator delete[](void* ptr) noexcept
{
    std::puts("5) delete[](void* ptr)");
    std::free(ptr);
}
 
void operator delete[](void* ptr, std::size_t size) noexcept
{
    std::printf("6) delete[](void*, size_t), size = %zu\n", size);
    std::free(ptr);
}
 
int main()
{
    int* p1 = new int;
    delete p1;
 
    int* p2 = new int[10]; // guaranteed to call the replacement in C++11
    delete[] p2;
}
```

{/* source:cpp-memory-new-operator-new:0060 */}
Overloads of `operator new` and `operator new[]` with additional user-defined parameters ("placement forms", versions ([11-14](/docs/cpp/library/memory/new/operator_new#Version_11))) may be declared at global scope as usual, and are called by the matching [placement forms](/docs/cpp/language/expressions/new#Placement_new) of new expressions.

{/* source:cpp-memory-new-operator-new:0061 */}
The standard library's non-allocating placement forms of `operator new` ([9,10](/docs/cpp/library/memory/new/operator_new#Version_9)) cannot be replaced and can only be customized if the placement new expression did not use the `::new` syntax, by providing a class-specific placement new ([19,20](/docs/cpp/library/memory/new/operator_new#Version_19)) with matching signature: `void* T::operator new(std::size_t, void*)` or `void* T::operator new[](std::size_t, void*)`.

{/* source:cpp-memory-new-operator-new:0062 */}
<Revision since="C++14">
The placement form `void* operator new(std::size_t, std::size_t)` is not allowed because the matching signature of the deallocation function, `void operator delete(void*, std::size_t)`, is a usual (not placement) deallocation function.
</Revision>

### Class-specific overloads

{/* source:cpp-memory-new-operator-new:0063 */}
Both single-object and array allocation functions may be defined as public static member functions of a class (versions ([15-18](/docs/cpp/library/memory/new/operator_new#Version_15))). If defined, these allocation functions are called by `new` expressions to allocate memory for single objects and arrays of this class, unless the `new` expression used the form `::new` which bypasses class-scope lookup. The keyword [`static`](/docs/cpp/language/keywords/static) is optional for these functions: whether used or not, the allocation function is a static member function.

{/* source:cpp-memory-new-operator-new:0064 */}
The `new` expression looks for appropriate allocation function's name firstly in the class scope, and after that in the global scope. Note, that as per [name lookup rules](/docs/cpp/language/basic_concepts/lookup), any allocation functions declared in class scope hides all global allocation functions for the `new` expressions that attempt to allocate objects of this class.

{/* source:cpp-memory-new-operator-new:0065 */}
<Revision since="C++17">
When allocating objects and arrays of objects whose alignment exceeds `__STDCPP_DEFAULT_NEW_ALIGNMENT__`, overload resolution is performed twice: first, for alignment-aware function signatures, then for alignment-unaware function signatures. This means that if a class with extended alignment has an alignment-unaware class-specific allocation function, it is the function that will be called, not the global alignment-aware allocation function. This is intentional: the class member is expected to know best how to handle that class.
</Revision>

{/* source:cpp-memory-new-operator-new:0066 */}
<Revision since="C++20">
When allocating objects and arrays of objects whose alignment does not exceed `__STDCPP_DEFAULT_NEW_ALIGNMENT__`, overload resolution is performed twice: first, for alignment-unaware function signatures, then for alignment-aware function signatures.
</Revision>

{/* source:cpp-memory-new-operator-new:0067 */}
```cpp

#include <iostream>
 
// class-specific allocation functions
struct X
{
    static void* operator new(std::size_t count)
    {
        std::cout << "custom new for size " << count << '\n';
        return ::operator new(count);
    }
 
    static void* operator new[](std::size_t count)
    {
        std::cout << "custom new[] for size " << count << '\n';
        return ::operator new[](count);
    }
};
 
int main()
{
    X* p1 = new X;
    delete p1;
    X* p2 = new X[10];

}

When the placement new expression with the matching signature looks for the corresponding allocation function to call, it begins at class scope before examining the global scope, and if the class-specific placement new is provided, it is called.

{/* source:cpp-memory-new-operator-new:0069 */}

</Revision>

{/* source:cpp-memory-new-operator-new:0072 */}
If class-level `operator new` is a template function, it must have the return type of `void*`, the first argument [`std::size_t`](/docs/cpp/library/utility/types/size_t), and it must have two or more parameters. In other words, only placement forms can be templates.

### Notes

{/* source:cpp-memory-new-operator-new:0073 */}
Even though the non-allocating placement new ([9,10](/docs/cpp/library/memory/new/operator_new#Version_9)) cannot be replaced, a function with the same signature may be defined at class scope as described above. In addition, global overloads that look like placement new but take a non-void pointer type as the second argument are allowed, so the code that wants to ensure that the true placement new is called (e.g. [`std::allocator::construct`](/docs/cpp/library/memory/allocator/construct)), must use `::new` and also cast the pointer to `void*`.

{/* source:cpp-memory-new-operator-new:0074 */}
If the behavior of a deallocation function does not satisfy the default constraints, the behavior is undefined.

{/* source:cpp-memory-new-operator-new:0075 */}
<Revision since="C++11">
The following functions are required to be thread-safe:

- The library versions of `operator new` and [`operator delete`](/docs/cpp/library/memory/new/operator_delete)
- User replacement versions of global `operator new` and [`operator delete`](/docs/cpp/library/memory/new/operator_delete)
- [`std::calloc`](/docs/cpp/library/memory/c/calloc), [`std::malloc`](/docs/cpp/library/memory/c/malloc), [`std::realloc`](/docs/cpp/library/memory/c/realloc)<InlineRevision since="C++17">, [`std::aligned_alloc`](/docs/cpp/library/memory/c/aligned_alloc)</InlineRevision>, [`std::free`](/docs/cpp/library/memory/c/free)

Calls to these functions that allocate or deallocate a particular unit of storage occur in a single total order, and each such deallocation call [happens-before](/docs/cpp/library/atomic/memory_order) the next allocation (if any) in this order.
</Revision>

{/* source:cpp-memory-new-operator-new:0076 */}
It is unspecified whether library versions of `operator new` make any calls to [`std::malloc`](/docs/cpp/library/memory/c/malloc) <InlineRevision since="C++17">or [`std::aligned_alloc`](/docs/cpp/library/memory/c/aligned_alloc)</InlineRevision>.

{/* source:cpp-memory-new-operator-new:0077 */}
For loading a large file, file mapping via OS-specific functions, e.g., [`mmap`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/mmap.html) on POSIX or CreateFileMapping([A](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createfilemappinga)/[W](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-createfilemappingw)) along with [`MapViewOfFile`](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-mapviewoffile) on Windows, is preferable to allocating a buffer for file reading.

### Defect reports

{/* source:cpp-memory-new-operator-new:0080 */}
The following behavior-changing defect reports were applied retroactively to previously published C++ standards.

{/* source:cpp-memory-new-operator-new:0081 */}
<DefectReportList>
  <DefectReport kind="cwg" id={521} standard="C++98">
    <PublishedBehavior>any class derived from [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc) could be thrown,<br />even if the [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc) base is ambiguous or inaccessible</PublishedBehavior>
    <CorrectedBehavior>the exception thrown should match<br />a handler of type [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc)</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="lwg" id={9} standard="C++98">
    <PublishedBehavior>multiple calls for allocating zero<br />bytes could yield the same pointer</PublishedBehavior>
    <CorrectedBehavior>only allowed if all such previously<br />yielded pointers have been<br />passed to deallocation functions</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="lwg" id={206} standard="C++98">
    <PublishedBehavior>replacing the replaceable allocation functions did<br />not affect the default behaviors of the corresponding<br />replaceable non-throwing allocation functions</PublishedBehavior>
    <CorrectedBehavior>the default behaviors<br />change accordingly</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="lwg" id={404} standard="C++98">
    <PublishedBehavior>replacements of the replaceable allocation<br />functions could be declared `inline`</PublishedBehavior>
    <CorrectedBehavior>prohibited, no diagnostic required</CorrectedBehavior>
  </DefectReport>
</DefectReportList>
