{/* source:cpp-memory-uses-allocator:0001 */}
If `T` has a nested type `allocator_type` which is convertible from `Alloc`, the member constant `value` is `true`. Otherwise `value` is `false`.

### Uses-allocator construction

{/* source:cpp-memory-uses-allocator:0004 */}
There are three conventions of passing an allocator `alloc` to a constructor of some type `T`:

{/* source:cpp-memory-uses-allocator:0005 */}
- If `T` does not use a compatible allocator (`std::uses_allocator_v<T, Alloc>` is `false`), then `alloc` is ignored.
- Otherwise, `std::uses_allocator_v<T, Alloc>` is `true`, and
  {/* source:cpp-memory-uses-allocator:0006 */}
  - if `T` uses the *leading-allocator convention* (is invocable as `T(std::allocator_arg, alloc, args...)`), then uses-allocator construction uses this form.
  - if `T` uses the *trailing-allocator convention* (is invocable as `T(args..., alloc)`), then uses-allocator construction uses this form.
  - Otherwise, the program is ill-formed (this means `std::uses_allocator_v<T, Alloc>` is `true`, but the type does not follow either of the two allowed conventions).

{/* source:cpp-memory-uses-allocator:0007 */}
- As a special case, [`std::pair`](/docs/cpp/library/utility/pair) is treated as a uses-allocator type even though `std::uses_allocator` is `false` for pairs (unlike e.g. [`std::tuple`](/docs/cpp/library/utility/tuple)): see pair-specific overloads of <InlineRevision until="C++20">[`std::pmr::polymorphic_allocator::construct`](/docs/cpp/library/memory/polymorphic_allocator/construct) and [`std::scoped_allocator_adaptor::construct`](/docs/cpp/library/memory/scoped_allocator_adaptor/construct)</InlineRevision><InlineRevision since="C++20">[`std::uses_allocator_construction_args`](/docs/cpp/library/memory/uses_allocator_construction_args)</InlineRevision>.

{/* source:cpp-memory-uses-allocator:0008 */}
<Revision since="C++20">
The utility functions [`std::make_obj_using_allocator`](/docs/cpp/library/memory/make_obj_using_allocator), and [`std::uninitialized_construct_using_allocator`](/docs/cpp/library/memory/uninitialized_construct_using_allocator) may be used to explicitly create an object following the above protocol, and [`std::uses_allocator_construction_args`](/docs/cpp/library/memory/uses_allocator_construction_args) can be used to prepare the argument list that matches the flavor of uses-allocator construction expected by the type.
</Revision>

### Specializations

{/* source:cpp-memory-uses-allocator:0009 */}
Given a [program-defined type](/docs/cpp/language/basic_concepts/type-id#Program-defined_type) `T` that does not have a nested `allocator_type`, a program can specialize `std::uses_allocator` to derive from [`std::true_type`](/docs/cpp/library/meta/integral_constant) for `T` if any of the following requirements is satisfied:

{/* source:cpp-memory-uses-allocator:0010 */}
- `T` has a constructor which takes [`std::allocator_arg_t`](/docs/cpp/library/memory/allocator_arg_t) as the first argument, and `Alloc` as the second argument.
- `T` has a constructor which takes `Alloc` as the last argument.

{/* source:cpp-memory-uses-allocator:0011 */}
In the above, `Alloc` is a type that satisfies [*Allocator*](/docs/cpp/library/named_req/Allocator)<InlineRevision since="Library Fundamentals TS"> or is a pointer type convertible to `std::experimental::pmr::memory_resource*`</InlineRevision>.

### Notes

{/* source:cpp-memory-uses-allocator:0014 */}
This type trait is used by [`std::tuple`](/docs/cpp/library/utility/tuple), [`std::scoped_allocator_adaptor`](/docs/cpp/library/memory/scoped_allocator_adaptor), and [`std::pmr::polymorphic_allocator`](/docs/cpp/library/memory/polymorphic_allocator). It may also be used by custom allocators or wrapper types to determine whether the object or member being constructed is itself capable of using an allocator (e.g. is a container), in which case an allocator should be passed to its constructor.
