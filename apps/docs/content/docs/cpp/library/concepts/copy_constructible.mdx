<DeclarationDoc>
Defined in header [`<concepts>`](/docs/cpp/library/headers/concepts)

  <Declaration language="cpp" since="C++20" code={`template< class T >
concept copy_constructible =
    std::move_constructible<T> &&
    std::constructible_from<T, T&> && std::convertible_to<T&, T> &&
    std::constructible_from<T, const T&> && std::convertible_to<const T&, T> &&

    std::constructible_from<T, const T> && std::convertible_to<const T, T>;`} />
</DeclarationDoc>

{/* source:cpp-concepts-copy-constructible:0001 */}
The concept `copy_constructible` is satisfied if `T` is an lvalue reference type, or if it is a [`move_constructible`](/docs/cpp/library/concepts/move_constructible) object type where an object of that type can constructed from a (possibly const) lvalue or const rvalue of that type in both direct- and copy-initialization contexts with the usual semantics (a copy is constructed with the source unchanged).

### Semantic requirements

{/* source:cpp-concepts-copy-constructible:0002 */}
If `T` is an object type, then `copy_constructible<T>` is modeled only if given

{/* source:cpp-concepts-copy-constructible:0003 */}
- `v`, an lvalue of type (possibly const) `T` or an rvalue of type `const T`,

{/* source:cpp-concepts-copy-constructible:0004 */}
the following are true:

{/* source:cpp-concepts-copy-constructible:0005 */}
- After the definition `T u = v;`, `u` is equal to `v` and `v` is not modified;
- `T(v)` is equal to `v` and does not modify `v`.
