{/* source:cpp-container-flat-multimap:0001 */}
The flat multimap is a [`container adaptor`](/docs/cpp/library/container#Container_adaptors) that gives the functionality of an associative container that contains key-value pairs, while permitting multiple entries with the same key value. Keys are sorted by using the comparison function `Compare`.

{/* source:cpp-container-flat-multimap:0002 */}
The class template `flat_multimap` acts as a wrapper to the two underlying containers, passed as objects of type `KeyContainer` and `MappedContainer` respectively. The first container is sorted, and for each key its corresponding value is in the second container at the same index (offset). The number of elements in both containers is the same.

{/* source:cpp-container-flat-multimap:0003 */}
Everywhere the standard library uses the [`Compare`](/docs/cpp/library/named_req/Compare) requirements, uniqueness is determined by using the equivalence relation. Informally, two objects `a` and `b` are considered equivalent if neither compares less than the other: `!comp(a, b) && !comp(b, a)`.

{/* source:cpp-container-flat-multimap:0004 */}
`std::flat_multimap` meets the requirements of [`Container`](/docs/cpp/library/named_req/Container), [`ReversibleContainer`](/docs/cpp/library/named_req/ReversibleContainer), [`optional container requirements`](/docs/cpp/library/named_req/Container#Optional_container_requirements), and all requirements of [`AssociativeContainer`](/docs/cpp/library/named_req/AssociativeContainer) (including logarithmic search complexity), except that:

{/* source:cpp-container-flat-multimap:0005 */}
- requirements related to nodes are not applicable,
- iterator invalidation requirements differ,
- the complexity of insertion and erasure operations is linear.

{/* source:cpp-container-flat-multimap:0006 */}
A flat multimap supports most of [`AssociativeContainer`](/docs/cpp/library/named_req/AssociativeContainer)'s operations that use equal keys.

### Template parameters

{/* source:cpp-container-flat-multimap:0008 */}
<ParameterList>
  <Parameter name="Key">The type of the keys. The program is ill-formed if `Key` is not the same type as `KeyContainer::value_type`.</Parameter>
  <Parameter name="T">The type of mapped values. The program is ill-formed if `T` is not the same type as `MappedContainer::value_type`.</Parameter>
  <Parameter name="Compare">A [`Compare`](/docs/cpp/library/named_req/Compare) type providing a strict weak ordering.</Parameter>
  <Parameter name="KeyContainer MappedContainer">The types of the underlying [`SequenceContainer`](/docs/cpp/library/named_req/SequenceContainer) to store keys and mapped values correspondingly. The iterators of such containers should satisfy [`LegacyRandomAccessIterator`](/docs/cpp/library/named_req/RandomAccessIterator) or model [`random_access_iterator`](/docs/cpp/library/iterator/random_access_iterator). Invocations of their member functions `size` and `max_size` should not exit via an exception.<br />The standard containers [`std::vector`](/docs/cpp/library/container/vector) and [`std::deque`](/docs/cpp/library/container/deque) satisfy these requirements.</Parameter>
</ParameterList>

### Notes

{/* source:cpp-container-flat-multimap:0016 */}
The member types `iterator` and `const_iterator` may be aliases to the same type. This means defining a pair of function overloads using the two types as parameter types may violate the [`One Definition Rule`](/docs/cpp/language/basic_concepts/definition#One_Definition_Rule). Since `iterator` is convertible to `const_iterator`, a single function with a `const_iterator` as parameter type will work instead.
