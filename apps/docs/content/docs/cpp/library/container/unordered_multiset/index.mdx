{/* source:cpp-container-unordered-multiset:0001 */}
`std::unordered_multiset` is an associative container that contains set of possibly non-unique objects of type `Key`. Search, insertion, and removal have average constant-time complexity.

{/* source:cpp-container-unordered-multiset:0002 */}
Internally, the elements are not sorted in any particular order, but organized into buckets. Which bucket an element is placed into depends entirely on the hash of its value. This allows fast access to individual elements, since once hash is computed, it refers to the exact bucket the element is placed into.

{/* source:cpp-container-unordered-multiset:0003 */}
The iteration order of this container is not required to be stable (so, for example, [`std::equal`](/docs/cpp/library/algorithm/equal) cannot be used to compare two `std::unordered_multisets`), except that every group of elements whose keys compare *equivalent* (compare equal with [`key_eq()`](/docs/cpp/library/container/unordered_multiset/key_eq) as the comparator) forms a contiguous subrange in the iteration order, also accessible with [`equal_range()`](/docs/cpp/library/container/unordered_multiset/equal_range).

{/* source:cpp-container-unordered-multiset:0004 */}
`std::unordered_multiset` meets the requirements of [`Container`](/docs/cpp/library/named_req/Container), [`AllocatorAwareContainer`](/docs/cpp/library/named_req/AllocatorAwareContainer), [`UnorderedAssociativeContainer`](/docs/cpp/library/named_req/UnorderedAssociativeContainer).

### Notes

{/* source:cpp-container-unordered-multiset:0010 */}
The member types `iterator` and `const_iterator` may be aliases to the same type. This means defining a pair of function overloads using the two types as parameter types may violate the [`One Definition Rule`](/docs/cpp/language/basic_concepts/definition#One_Definition_Rule). Since `iterator` is convertible to `const_iterator`, a single function with a `const_iterator` as parameter type will work instead.
