{/* source:cpp-container-unordered-map-operator-at:0001 */}
Returns a reference to the value that is mapped to a key equivalent to `key` or `x` respectively, performing an insertion if such key does not already exist.

{/* source:cpp-container-unordered-map-operator-at:0002 */}
- 1) Inserts a [`value_type`](/docs/cpp/library/container/unordered_map#Member_types) object constructed in-place from `std::piecewise_construct, std::forward_as_tuple(key), std::tuple<>()` if the key does not exist.

{/* source:cpp-container-unordered-map-operator-at:0003 */}
- <InlineRevision since="C++17">Equivalent to `return this->try_emplace(key).first->second;`.</InlineRevision> When the default allocator is used, this results in the key being copy constructed from `key` and the mapped value being [value-initialized](/docs/cpp/language/initialization/value_initialization). - `value_type` must be [EmplaceConstructible](/docs/cpp/library/named_req/EmplaceConstructible) from `std::piecewise_construct, std::forward_as_tuple(key), std::tuple<>()`. When the default allocator is used, this means that [`key_type`](/docs/cpp/library/container/unordered_map#Member_types) must be [CopyConstructible](/docs/cpp/library/named_req/CopyConstructible) and `mapped_type` must be [DefaultConstructible](/docs/cpp/library/named_req/DefaultConstructible).

{/* source:cpp-container-unordered-map-operator-at:0004 */}
- 2) Inserts a [`value_type`](/docs/cpp/library/container/unordered_map#Member_types) object constructed in-place from `std::piecewise_construct, std::forward_as_tuple(std::move(key)), std::tuple<>()` if the key does not exist.

{/* source:cpp-container-unordered-map-operator-at:0005 */}
- <InlineRevision since="C++17">Equivalent to `return this->try_emplace(std::move(key)).first->second;`.</InlineRevision> When the default allocator is used, this results in the key being move constructed from `key` and the mapped value being [value-initialized](/docs/cpp/language/initialization/value_initialization). - `value_type` must be [EmplaceConstructible](/docs/cpp/library/named_req/EmplaceConstructible) from `std::piecewise_construct, std::forward_as_tuple(std::move(key)), std::tuple<>()`. When the default allocator is used, this means that [`key_type`](/docs/cpp/library/container/unordered_map#Member_types) must be [MoveConstructible](/docs/cpp/library/named_req/MoveConstructible) and `mapped_type` must be [DefaultConstructible](/docs/cpp/library/named_req/DefaultConstructible).

{/* source:cpp-container-unordered-map-operator-at:0006 */}
- 3) Inserts a [`value_type`](/docs/cpp/library/container/unordered_map#Member_types) object constructed in-place if there is no key that transparently compares *equivalent* to the value `x`.

{/* source:cpp-container-unordered-map-operator-at:0007 */}
- Equivalent to `return this->try_emplace(std::forward<K>(x)).first->second;`. This overload participates in overload resolution only if `Hash::is_transparent` and `KeyEqual::is_transparent` are valid and each denotes a type. This assumes that such `Hash` is callable with both `K` and `Key` type, and that the `KeyEqual` is transparent, which, together, allows calling this function without constructing an instance of `Key`.

{/* source:cpp-container-unordered-map-operator-at:0008 */}
If after the operation the new number of elements is greater than old [`max_load_factor()`](/docs/cpp/library/container/unordered_map/max_load_factor) * [`bucket_count()`](/docs/cpp/library/container/unordered_map/bucket_count) a rehashing takes place.
If rehashing occurs (due to the insertion), all iterators are invalidated. Otherwise (no rehashing), iterators are not invalidated.

### Parameters

{/* source:cpp-container-unordered-map-operator-at:0009 */}
<ParameterList>
  <Parameter name="key">the key of the element to find</Parameter>
  <Parameter name="x">a value of any type that can be transparently compared with a key</Parameter>
</ParameterList>

### Return value

{/* source:cpp-container-unordered-map-operator-at:0010 */}
- 1,2) A reference to the mapped value of the new element if no element with key `key` existed. Otherwise, a reference to the mapped value of the existing element whose key is equivalent to `key`.

{/* source:cpp-container-unordered-map-operator-at:0011 */}
- 3) A reference to the mapped value of the new element if no element with key that compares equivalent to the value `x` existed. Otherwise, a reference to the mapped value of the existing element whose key compares equivalent to `x`.

### Exceptions

{/* source:cpp-container-unordered-map-operator-at:0012 */}
If an exception is thrown by any operation, the insertion has no effect.

### Complexity

{/* source:cpp-container-unordered-map-operator-at:0013 */}
Average case: constant, worst case: linear in size.

### Notes

{/* source:cpp-container-unordered-map-operator-at:0014 */}
In the published C++11 and C++14 standards, this function was specified to require `mapped_type` to be [DefaultInsertable](/docs/cpp/library/named_req/DefaultInsertable) and [`key_type`](/docs/cpp/library/container/unordered_map#Member_types) to be [CopyInsertable](/docs/cpp/library/named_req/CopyInsertable) or [MoveInsertable](/docs/cpp/library/named_req/MoveInsertable) into `*this`. This specification was defective and was fixed by [LWG issue 2469](https://cplusplus.github.io/LWG/issue2469), and the description above incorporates the resolution of that issue.

{/* source:cpp-container-unordered-map-operator-at:0015 */}
However, one implementation (libc++) is known to construct the [`key_type`](/docs/cpp/library/container/unordered_map#Member_types) and `mapped_type` objects via two separate allocator `construct()` calls, as arguably required by the standards as published, rather than emplacing a [`value_type`](/docs/cpp/library/container/unordered_map#Member_types) object.

{/* source:cpp-container-unordered-map-operator-at:0016 */}
`operator[]` is non-const because it inserts the key if it doesn't exist. If this behavior is undesirable or if the container is `const`, [`at`](/docs/cpp/library/container/unordered_map/at) may be used.

{/* source:cpp-container-unordered-map-operator-at:0017 */}
<Revision since="C++17">
[`insert_or_assign`](/docs/cpp/library/container/unordered_map/insert_or_assign) returns more information than `operator[]` and does not require default-constructibility of the mapped type.
</Revision>

### Example

{/* source:cpp-container-unordered-map-operator-at:0019 */}
```cpp
#include <iostream>
#include <string>
#include <unordered_map>

void println(auto const comment, auto const& map)
{
    std::cout << comment << '{';
    for (const auto& pair : map)
        std::cout << '{' << pair.first << ": " << pair.second << '}';
    std::cout << "}\n";
}

int main()
{
    std::unordered_map<char, int> letter_counts{{'a', 27}, {'b', 3}, {'c', 1}};

    println("letter_counts initially contains: ", letter_counts);

    letter_counts['b'] = 42; // updates an existing value
    letter_counts['x'] = 9;  // inserts a new value

    println("after modifications it contains: ", letter_counts);

    // count the number of occurrences of each word
    // (the first call to operator[] initialized the counter with zero)
    std::unordered_map<std::string, int>  word_map;
    for (const auto& w : {"this", "sentence", "is", "not", "a", "sentence",
                          "this", "sentence", "is", "a", "hoax"})
        ++word_map[w];
    word_map["that"]; // just inserts the pair {"that", 0}

    for (const auto& [word, count] : word_map)
        std::cout << count << " occurrence(s) of word '" << word << "'\n";
}
```

Possible output:

```text
letter_counts initially contains: {{a: 27}{b: 3}{c: 1}}
after modifications it contains: {{a: 27}{b: 42}{c: 1}{x: 9}}
2 occurrence(s) of word 'a'
1 occurrence(s) of word 'hoax'
2 occurrence(s) of word 'is'
1 occurrence(s) of word 'not'
3 occurrence(s) of word 'sentence'
0 occurrence(s) of word 'that'
2 occurrence(s) of word 'this'
```
