{/* source:cpp-container-unordered-set:0001 */}
`std::unordered_set` is an associative container that contains a set of unique objects of type `Key`. Search, insertion, and removal have average constant-time complexity.

{/* source:cpp-container-unordered-set:0002 */}
Internally, the elements are not sorted in any particular order, but organized into buckets. Which bucket an element is placed into depends entirely on the hash of its value. This allows fast access to individual elements, since once a hash is computed, it refers to the exact bucket the element is placed into.

{/* source:cpp-container-unordered-set:0003 */}
Container elements may not be modified (even by non const iterators) since modification could change an element's hash and corrupt the container.

{/* source:cpp-container-unordered-set:0004 */}
`std::unordered_set` meets the requirements of [`Container`](/docs/cpp/library/named_req/Container), [`AllocatorAwareContainer`](/docs/cpp/library/named_req/AllocatorAwareContainer), [`UnorderedAssociativeContainer`](/docs/cpp/library/named_req/UnorderedAssociativeContainer).

### Iterator invalidation

{/* source:cpp-container-unordered-set:0005 */}
| Operations | Invalidated |
| --- | --- |
| All read only operations, [`swap`](/docs/cpp/library/container/unordered_set/swap), [`std::swap`](/docs/cpp/library/algorithm/swap) | Never |
| [`clear`](/docs/cpp/library/container/unordered_set/clear), [`rehash`](/docs/cpp/library/container/unordered_set/rehash), [`reserve`](/docs/cpp/library/container/unordered_set/reserve), [`operator=`](/docs/cpp/container/unordered-set/operator%3D) | Always |
| [`insert`](/docs/cpp/library/container/unordered_set/insert), [`emplace`](/docs/cpp/library/container/unordered_set/emplace), [`emplace_hint`](/docs/cpp/library/container/unordered_set/emplace_hint) | Only if causes rehash |
| [`erase`](/docs/cpp/library/container/unordered_set/erase) | Only to the element erased |

#### Notes

{/* source:cpp-container-unordered-set:0006 */}
- The swap functions do not invalidate any of the iterators inside the container, but they do invalidate the iterator marking the end of the swap region.

{/* source:cpp-container-unordered-set:0007 */}
- References and pointers to data stored in the container are only invalidated by erasing that element, even when the corresponding iterator is invalidated.

{/* source:cpp-container-unordered-set:0008 */}
- After container move assignment, unless elementwise move assignment is forced by incompatible allocators, references, pointers, and iterators (other than the past-the-end iterator) to moved-from container remain valid, but refer to elements that are now in `*this`.

### Notes

{/* source:cpp-container-unordered-set:0014 */}
The member types `iterator` and `const_iterator` may be aliases to the same type. This means defining a pair of function overloads using the two types as parameter types may violate the [`One Definition Rule`](/docs/cpp/language/basic_concepts/definition#One_Definition_Rule). Since `iterator` is convertible to `const_iterator`, a single function with a `const_iterator` as parameter type will work instead.

### Example

{/* source:cpp-container-unordered-set:0016 */}
```cpp
#include <iostream>
#include <unordered_set>
 
void print(const auto& set)
{
    for (const auto& elem : set)
        std::cout << elem << ' ';
    std::cout << '\n';
}
 
int main()
{
    std::unordered_set<int> mySet{2, 7, 1, 8, 2, 8}; // creates a set of ints
    print(mySet);
 
    mySet.insert(5); // puts an element 5 in the set
    print(mySet);
 
    if (auto iter = mySet.find(5); iter != mySet.end())
        mySet.erase(iter); // removes an element pointed to by iter
    print(mySet);
 
    mySet.erase(7); // removes an element 7
    print(mySet);
}```

Possible output:

```text
8 1 7 2
5 8 1 7 2
8 1 7 2
8 1 2```
