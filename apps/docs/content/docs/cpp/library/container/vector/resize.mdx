    1. <InlineRevision since="C++20" /> Resizes the container to contain `count` elements, does nothing if `count == size()`.

    2. <InlineRevision since="C++20" />
  </DeclarationDescription>
</DeclarationDoc>

{/* source:cpp-container-vector-resize:0002 */}
If the current size is greater than `count`, the container is reduced to its first `count` elements.

{/* source:cpp-container-vector-resize:0003 */}
If the current size is less than `count`, then:

{/* source:cpp-container-vector-resize:0004 */}
- 1) Additional [default-inserted](/docs/cpp/library/named_req/DefaultInsertable) elements are appended.

{/* source:cpp-container-vector-resize:0005 */}
- 2) Additional copies of `value` are appended.

### Parameters

{/* source:cpp-container-vector-resize:0006 */}
<ParameterList>
  <Parameter name="count">new size of the container</Parameter>
  <Parameter name="value">the value to initialize the new elements with</Parameter>
</ParameterList>

Type requirements

- `T` must meet the requirements of [`MoveInsertable`](/docs/cpp/library/named_req/MoveInsertable) and [`DefaultInsertable`](/docs/cpp/library/named_req/DefaultInsertable) in order to use overload (1).
- `T` must meet the requirements of [`CopyInsertable`](/docs/cpp/library/named_req/CopyInsertable) in order to use overload (2).

### Complexity

{/* source:cpp-container-vector-resize:0007 */}
Linear in the difference between the current size and `count`. Additional complexity possible due to reallocation if capacity is less than `count`.

### Exceptions

{/* source:cpp-container-vector-resize:0008 */}
If an exception is thrown for any reason, these functions have no effect ([strong exception safety guarantee](/docs/cpp/language/exceptions#Exception_safety)). Although not explicitly specified, [`std::length_error`](/docs/cpp/library/error/length_error) is thrown if the capacity required by the new `vector` would exceed [`max_size()`](/docs/cpp/library/container/vector/max_size).

{/* source:cpp-container-vector-resize:0009 */}
<Revision since="C++11">
In overload ([1](/docs/cpp/library/container/vector/resize#Version_1)), if `T`'s move constructor is not `noexcept` and `T` is not [`CopyInsertable`](/docs/cpp/library/named_req/CopyInsertable) into `*this`, vector will use the throwing move constructor. If it throws, the guarantee is waived and the effects are unspecified.
</Revision>

### Notes

{/* source:cpp-container-vector-resize:0010 */}
If value-initialization in overload ([1](/docs/cpp/library/container/vector/resize#Version_1)) is undesirable, for example, if the elements are of non-class type and zeroing out is not needed, it can be avoided by providing a [custom `Allocator::construct`](https://stackoverflow.com/a/21028912/273767).

Vector capacity is never reduced when resizing to smaller size because that would invalidate all iterators, rather than only the ones that would be invalidated by the equivalent sequence of [`pop_back()`](/docs/cpp/library/container/vector/pop_back) calls.

### Example

{/* source:cpp-container-vector-resize:0011 */}
```cpp
#include <vector>
#include <iostream>

void print(auto rem, const std::vector<int>& c)
{
    for (std::cout << rem; const int el : c)
        std::cout << el << ' ';
    std::cout << '\n';
}

int main()
{
    std::vector<int> c = {1, 2, 3};
    print("The vector holds: ", c);

    c.resize(5);
    print("After resize up to 5: ", c);

    c.resize(2);
    print("After resize down to 2: ", c);

    c.resize(6, 4);
    print("After resize up to 6 (initializer = 4): ", c);
}
```

Output:

```text
The vector holds: 1 2 3
After resize up to 5: 1 2 3 0 0
After resize down to 2: 1 2
After resize up to 6 (initializer = 4): 1 2 4 4 4 4
```

{/* source:cpp-container-vector-resize:0014 */}
1. ↑ [`erase()`](/docs/cpp/library/container/vector/erase) can remove elements in the middle of a `vector`, so the value type is required to be [`MoveAssignable`](/docs/cpp/library/named_req/MoveAssignable) so that the elements following the removed section can be moved forward to fill the gap. However, `resize()` can only remove elements at the end of the `vector`, making the [`MoveAssignable`](/docs/cpp/library/named_req/MoveAssignable) unnecessary.

2. ↑ Removing elements by using [`pop_back()`](/docs/cpp/library/container/vector/pop_back) implies that the elements are required to be removed from back to front.
