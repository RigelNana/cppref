{/* source:cpp-ranges-view-interface-front:0001 */}
The default implementation of `front()` member function returns the first element in the view of the derived type. Whether the element is returned by value or by reference depends on the `operator*` of the iterator type.

{/* source:cpp-ranges-view-interface-front:0002 */}
1. 1) Let `derived` be `static_cast<D&>(*this)`. Equivalent to `return *ranges::begin(derived);`. The behavior is undefined if [`empty()`](/docs/cpp/library/ranges/view_interface/empty) is `true` (i.e. the beginning iterator compares equal to the sentinel), even if the iterator obtained in the same way is dereferenceable.

{/* source:cpp-ranges-view-interface-front:0003 */}
2. 2) Same as (1), except that `derived` is `static_cast<const D&>(*this)`.

### Parameters

{/* source:cpp-ranges-view-interface-front:0004 */}
(none)

### Return value

{/* source:cpp-ranges-view-interface-front:0005 */}
The first element in the view.

### Notes

{/* source:cpp-ranges-view-interface-front:0006 */}
In C++20, no type derived from [`std::ranges::view_interface`](/docs/cpp/library/ranges/view_interface) in the standard library provides their own `front()` member function. Almost all of these types use the default implementation.

{/* source:cpp-ranges-view-interface-front:0007 */}
A notable exception is [`std::ranges::basic_istream_view`](/docs/cpp/library/ranges/basic_istream_view). For it never satisfies [`forward_range`](/docs/cpp/library/ranges/forward_range), the view cannot use the inherited `front()`.

{/* source:cpp-ranges-view-interface-front:0008 */}
The inherited `front()` member function is available for [`std::ranges::empty_view`](/docs/cpp/library/ranges/empty_view), but a call to it always results in undefined behavior.
