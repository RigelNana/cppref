{/* source:cpp-ranges-view-interface-operator-at:0001 */}
The default implementation of `operator[]` member function obtains the element at the specified offset relative to the beginning iterator, reusing the `operator[]` of the iterator type.

{/* source:cpp-ranges-view-interface-operator-at:0002 */}
1. 1) Let `derived` be `static_cast<D&>(*this)`. Equivalent to `return ranges::begin(derived)[n];`.

{/* source:cpp-ranges-view-interface-operator-at:0003 */}
2. 2) Same as (1), except that `derived` is `static_cast<const D&>(*this)`.

  <Parameter name="n">position of the element to return</Parameter>
</ParameterList>

### Return value

{/* source:cpp-ranges-view-interface-operator-at:0005 */}
The element at offset `n` relative to the beginning iterator.

### Notes

{/* source:cpp-ranges-view-interface-operator-at:0006 */}
In C++20, no type derived from [`std::ranges::view_interface`](/docs/cpp/library/ranges/view_interface) in the standard library provides their own `operator[]` member function.

{/* source:cpp-ranges-view-interface-operator-at:0007 */}
However, following derived types cannot use the default implementations, as they never satisfy [`random_access_range`](/docs/cpp/library/ranges/random_access_range):

{/* source:cpp-ranges-view-interface-operator-at:0008 */}
- [`std::ranges::basic_istream_view`](/docs/cpp/library/ranges/basic_istream_view)
- [`std::ranges::filter_view`](/docs/cpp/library/ranges/filter_view)
- [`std::ranges::join_view`](/docs/cpp/library/ranges/join_view)
- `std::ranges::lazy_split_view`
- [`std::ranges::split_view`](/docs/cpp/library/ranges/split_view)

{/* source:cpp-ranges-view-interface-operator-at:0009 */}
The inherited `operator[]` member function is available for [`std::ranges::empty_view`](/docs/cpp/library/ranges/empty_view), but a call to it always results in undefined behavior.
