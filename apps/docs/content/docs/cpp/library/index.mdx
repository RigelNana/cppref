{/* source:cpp-standard-library:0000 */}
The C++ standard library provides a wide range of facilities that are usable in standard C++.

### Category

{/* source:cpp-standard-library:0001 */}
The [language support library](/docs/cpp/library/utility#Language_support) provides components that are required by certain parts of the C++ language, such as memory allocation ([new](/docs/cpp/language/expressions/new)/[delete](/docs/cpp/language/expressions/delete)) and [exception processing](/docs/cpp/language/exceptions).

{/* source:cpp-standard-library:0002 */}
<Revision since="C++20">

The [concepts library](/docs/cpp/library/concepts) describes library components that C++ programs may use to perform compile-time validation of [template arguments](/docs/cpp/language/templates/template_parameters) and perform function dispatch based on properties of types.

</Revision>

{/* source:cpp-standard-library:0003 */}
The [diagnostics library](/docs/cpp/library/error) provides a consistent framework for reporting errors in a C++ program, including [predefined exception classes](/docs/cpp/library/error#Exception_categories).

{/* source:cpp-standard-library:0004 */}
The [memory management library](/docs/cpp/library/memory) provides components for memory management, including [smart pointers](/docs/cpp/library/memory#Smart_pointers)<InlineRevision since="C++11"> and [scoped allocator](/docs/cpp/library/memory/scoped_allocator_adaptor)</InlineRevision>.

{/* source:cpp-standard-library:0005 */}
<Revision since="C++11">

The [metaprogramming library](/docs/cpp/library/meta) describes facilities for use in [templates](/docs/cpp/language/templates) and during constant evaluation, including [type traits](/docs/cpp/library/meta#Type_traits)<InlineRevision since="C++14">, [integer sequence](/docs/cpp/library/meta/integer_sequence),</InlineRevision> and [rational arithmetic](/docs/cpp/library/meta/ratio).

</Revision>

{/* source:cpp-standard-library:0006 */}
The [general utilities library](/docs/cpp/library/utility#General-purpose_utilities) includes components used by other library elements, such as a [predefined storage allocator](/docs/cpp/library/memory#Allocators) for dynamic storage management, and components used as infrastructure in C++ programs, such as<InlineRevision since="C++11"> [tuples](/docs/cpp/library/utility/tuple) and</InlineRevision> [function wrappers](/docs/cpp/library/utility/functional).

{/* source:cpp-standard-library:0007 */}
The [containers](/docs/cpp/library/container), [iterators](/docs/cpp/library/iterator)<InlineRevision since="C++20">, [ranges](/docs/cpp/library/ranges)</InlineRevision>, and [algorithms](/docs/cpp/library/algorithm) libraries provide a C++ program with access to a subset of the most widely used algorithms and data structures.

{/* source:cpp-standard-library:0008 */}
The [strings library](/docs/cpp/library/string) provides support for manipulating text represented as homogeneous sequences of following types: `char`<InlineRevision since="C++20">, `char8_t`</InlineRevision><InlineRevision since="C++11">, `char16_t`, `char32_t`</InlineRevision>, `wchar_t`, and any other character-like types.

{/* source:cpp-standard-library:0009 */}
The [text processing library](/docs/cpp/library/text) provides <InlineRevision since="C++11">[regular expression](/docs/cpp/library/text/regex) matching and searching</InlineRevision><InlineRevision since="C++20">, utilities for [text formatting](/docs/cpp/library/text/format)</InlineRevision><InlineRevision since="C++26"> and [identifying text encodings](/docs/cpp/library/text/text_encoding)</InlineRevision>, and [localization facilities](/docs/cpp/library/text/locale).

{/* source:cpp-standard-library:0010 */}
The [numerics library](/docs/cpp/library/numeric) provides [numeric algorithms](/docs/cpp/library/numeric#Numeric_algorithms) and [complex number](/docs/cpp/library/numeric/complex) components that extend support for numeric processing. The [valarray](/docs/cpp/library/numeric/valarray) component provides support for n-at-a-time processing, potentially implemented as parallel operations on platforms that support such processing.<InlineRevision since="C++11"> The [random number component](/docs/cpp/library/numeric/random) provides facilities for generating pseudo-random numbers.</InlineRevision>

{/* source:cpp-standard-library:0011 */}
The [time library](/docs/cpp/library/chrono) provides generally useful time utilities.

{/* source:cpp-standard-library:0012 */}
The [input/output library](/docs/cpp/library/io) provides the [iostream components](/docs/cpp/library/io#Stream-based_I.2FO) that are the primary mechanism for C++ program input and output. They can be used with other elements of the library, particularly strings, locales, and iterators.

{/* source:cpp-standard-library:0013 */}
<Revision since="C++11">

The [thread support library](/docs/cpp/library/atomic) provides components to create and manage threads, including [atomic operations](/docs/cpp/library/atomic/atomic), [mutual exclusion](/docs/cpp/library/thread/mutex), and inter-thread communication.

</Revision>

{/* source:cpp-standard-library:0014 */}
<Revision since="C++26">

The [execution support](/docs/cpp/library/experimental/execution) library provides a framework for managing asynchronous execution on generic execution resources.

</Revision>

### Library contents

{/* source:cpp-standard-library:0015 */}
The C++ standard library provides definitions for the [entities](/docs/cpp/language/basic_concepts) and [macros](/docs/cpp/language/preprocessor/replace) described in the synopses of the [C++ standard library headers](/docs/cpp/library/headers), unless otherwise specified.

{/* source:cpp-standard-library:0016 */}
All library entities except [`operator new`](/docs/cpp/library/memory/new/operator_new) and [`operator delete`](/docs/cpp/library/memory/new/operator_delete) are defined within the namespace `std` or [namespaces](/docs/cpp/language/declarations/namespace) nested within namespace `std` (except the entities for the C standard library facilities, see below).<InlineRevision since="C++11"> It is unspecified whether names declared in a specific namespace are declared directly in that namespace or in an [inline namespace](/docs/cpp/language/declarations/namespace#Inline_namespaces) inside that namespace.</InlineRevision>

### C standard library

{/* source:cpp-standard-library:0022 */}
The C++ standard library also makes available the facilities of the C standard library, suitably adjusted to ensure static type safety. The descriptions of many library functions rely on the C standard library for the semantics of those functions.

{/* source:cpp-standard-library:0023 */}
In some cases, the signatures specified in standard C++ may be different from the signatures in the C standard library, and additional overloads may be declared, but the behavior and the preconditions <InlineRevision since="C++17">(including those implied by C's [`restrict`](/docs/c/language/declarations/restrict))</InlineRevision> are the same unless otherwise stated.

{/* source:cpp-standard-library:0024 */}

It is possible that C++ source files need to include one of these headers in order to be valid ISO C. Source files that are not intended to also be valid ISO C should not use any of the C headers. {/* source:cpp-standard-library:0026 */}
Except otherwise noted, the contents of each header `cxxx` is the same as that of the corresponding header `xxx.h` as specified in the [C standard library](/docs/c/library/header). In the C++ standard library, however, the declarations (except for names which are defined as macros in C) are within namespace scope of the namespace `std`. It is unspecified whether these names (including any overloads added) are first declared within the global namespace scope and are then injected into namespace `std` by explicit [using-declarations](/docs/cpp/language/declarations/namespace#Using-declarations).

{/* source:cpp-standard-library:0027 */}
Names which are defined as macros in C ([`assert`](/docs/cpp/library/error/assert), [`offsetof`](/docs/cpp/library/utility/types/offsetof), [`setjmp`](/docs/cpp/library/utility/program/setjmp), [`va_arg`](/docs/cpp/library/utility/variadic/va_arg), [`va_end`](/docs/cpp/library/utility/variadic/va_end) and [`va_start`](/docs/cpp/library/utility/variadic/va_start)) must be defined as macros in the C++ standard library, even if C grants license for implementation as functions.

{/* source:cpp-standard-library:0028 */}
Names that are defined as functions in C must be defined as functions in the C++ standard library. This disallows the practice, allowed in C, of providing a masking macro in addition to the function prototype. The only way to achieve equivalent inline behavior in C++ is to provide a definition as an extern [inline function](/docs/cpp/language/declarations/inline).

{/* source:cpp-standard-library:0029 */}
Identifiers that are keywords or operators in C++ cannot be defined as macros in C++ standard library headers. In particular, including the standard header [`<iso646.h>`](/docs/cpp/library/headers/ciso646) has no effect.

### Using the library

#### Including headers

{/* source:cpp-standard-library:0032 */}
The entities in the C++ standard library are defined in headers, whose contents are made available to a translation unit when it contains the appropriate [`#include`](/docs/cpp/language/preprocessor/include) preprocessing directive.

{/* source:cpp-standard-library:0033 */}
A translation unit may include library headers in any order. Each may be included more than once, with no effect different from being included exactly once, except that the effect of including either [`<cassert>`](/docs/cpp/library/headers/cassert) or [`<assert.h>`](/docs/cpp/library/headers/cassert) depends each time on the lexically current definition of `NDEBUG`.

{/* source:cpp-standard-library:0034 */}
A translation unit can only include a header outside of any declaration or definition, and lexically before the first reference in that translation unit to any of the entities declared in that header. No diagnostic is required.

{/* source:cpp-standard-library:0035 */}
<Revision since="C++20">

In [module units](/docs/cpp/language/basic_concepts/modules), headers can only be included in [global module fragments](/docs/cpp/language/basic_concepts/modules#Global_module_fragment).

</Revision>

{/* source:cpp-standard-library:0036 */}
<Revision since="C++20">

#### Importing headers

The [C++ library headers](/docs/cpp/library/standard_library#Headers), or, for a freestanding implementation, the subset of such headers that are provided by the implementation, are collectively known as the *importable C++ library headers*.

The contents of importable C++ library headers are made available to a translation unit when it contains the appropriate [import declaration](/docs/cpp/language/basic_concepts/modules#Importing_modules_and_headers).

</Revision>

<Revision since="C++23">

#### Importing modules

The C++ standard library provides the following *C++ library modules*:

- The [named module](/docs/cpp/language/basic_concepts/modules#Module_declarations) `std` exports declarations in namespace `std` that are provided by the importable C++ library headers (e.g. [`std::rotr`](/docs/cpp/library/utility/bit/rotr) from [`<bit>`](/docs/cpp/library/headers/bit)) and the [C++ headers for C library facilities](/docs/cpp/library/standard_library#Headers) (e.g. [`std::puts`](/docs/cpp/library/io/c/puts) from [`<cstdio>`](/docs/cpp/library/headers/cstdio)). It additionally exports declarations in the global namespace for the storage [allocation](/docs/cpp/library/memory/new/operator_new) and [deallocation](/docs/cpp/library/memory/new/operator_delete) functions that are provided by [`<new>`](/docs/cpp/library/headers/new) (e.g. [`::operator new`](/docs/cpp/library/memory/new/operator_new)).
- The named module `std.compat` exports the same declarations as the named module `std`, and additionally exports declarations in the global namespace corresponding to the declarations in namespace `std` that are provided by the C++ headers for C library facilities (e.g. [`::fclose`](/docs/cpp/library/io/c/fclose)).

For each declaration in the standard library,

- the module it [attaches to](/docs/cpp/language/basic_concepts/modules#Module_ownership) is unspecified, and
- it denotes the same [entity](/docs/cpp/language/basic_concepts) regardless of whether it was made reachable through including a header, importing a header unit, or importing a C++ library module.

[Feature-test](/docs/cpp/library/utility/feature_test) macro Value Std Feature   [`__cpp_lib_modules`](/docs/cpp/library/feature_test#cpp_lib_modules) [`202207L`](/docs/cpp/library/compiler_support/23#cpp_lib_modules_202207L) (C++23) Standard library modules `std` and `std.compat`

</Revision>

#### Linkage

{/* source:cpp-standard-library:0037 */}
Entities in the C++ standard library have [storage duration#external linkage](/docs/cpp/language/declarations/storage_duration#external_linkage). Unless otherwise specified, objects and functions have the default `extern "C++"` [linkage](/docs/cpp/language/declarations/language_linkage).

{/* source:cpp-standard-library:0038 */}
Whether a name from the C standard library declared with external linkage has `extern "C"` or `extern "C++"` linkage is implementation-defined. The C++ standard recommends using `extern "C++"` in this case.

{/* source:cpp-standard-library:0039 */}
Objects and functions defined in the library and required by a C++ program are included in the program prior to program startup.

### Requirements on standard library implementations

#### Guarantees

{/* source:cpp-standard-library:0040 */}
A C++ header must provide [declarations](/docs/cpp/language/declarations) and [definitions](/docs/cpp/language/basic_concepts/definition) that appear in

{/* source:cpp-standard-library:0041 */}
- the synopsis of that header, or
- the synopsis of another header which is appeared to be included in the synopsis of that header.

{/* source:cpp-standard-library:0042 */}
For types and macros defined in multiple headers (such as [`NULL`](/docs/cpp/library/utility/types/NULL)), including any number of these headers in any order never violates the [one definition rule](/docs/cpp/language/basic_concepts/definition#One_Definition_Rule).

{/* source:cpp-standard-library:0043 */}
Unless otherwise specified, all [object-like macros](/docs/cpp/language/preprocessor/replace#Object-like_macros) defined by the C standard library that expand to integral [constant expressions](/docs/cpp/language/expressions/constant_expression) can be used in [`#if`](/docs/cpp/language/preprocessor/conditional) preprocessing directives.

{/* source:cpp-standard-library:0044 */}
Calling a standard library non-member function signature always results in actually calling that function. Therefore a conforming standard library implementation cannot define additional non-member functions that may be called by a valid C++ program.

{/* source:cpp-standard-library:0045 */}
Non-member function signatures are never declared with additional [default arguments](/docs/cpp/language/functions/default_arguments).

{/* source:cpp-standard-library:0046 */}
Unless otherwise specified, calls made by functions in the standard library to non-operator, non-member functions do not use functions from another [namespace](/docs/cpp/language/declarations/namespace) which are found through [argument-dependent name lookup](/docs/cpp/language/functions/adl).

{/* source:cpp-standard-library:0047 */}
For each [friend declaration](/docs/cpp/language/classes/friend) of a function (template) within a class (template) definition, no other declaration is provided for that function (template).

{/* source:cpp-standard-library:0048 */}
<Revision since="C++11">

Standard library function signatures can only be declared as `constexpr` if they are required to be [constexpr](/docs/cpp/language/declarations/constexpr) (libstdc++ cmath [is notably non-conforming](https://gcc.gnu.org/bugzilla/show_bug.cgi?id=102916) here). If a header provides any non-defining declarations of constexpr functions or constructors, the corresponding definitions should also be provided within that header.

Unless otherwise specified, each standard library function should meet each of the following requirements to prevent [data races](/docs/cpp/language/basic_concepts/memory_model#Threads_and_data_races):

- A C++ standard library function cannot (directly or indirectly) access objects accessible by threads other than the current thread unless the objects are accessed (directly or indirectly) via the function’s arguments, including `this`.
- A C++ standard library function cannot (directly or indirectly) modify objects accessible by threads other than the current thread unless the objects are accessed (directly or indirectly) via the function’s non-const arguments, including `this`.
  - For example, an object with static storage duration cannot be used for internal purposes without synchronization because doing so can cause a data race even in programs that do not explicitly share objects between threads.
- A C++ standard library function cannot access objects indirectly accessible via its arguments or via elements of its [container](/docs/cpp/library/container) arguments except by invoking functions required by its specification on those container elements.
- An operation on [iterators](/docs/cpp/library/iterator) obtained by calling a standard library container or string member function can access, but not modify, the underlying container.
  - In particular, container operations that invalidate iterators conflict with operations on iterators associated with that container.
- A C++ standard library function can only perform all operations solely within the current thread if those operations have effects that are [visible](/docs/cpp/language/basic_concepts/memory_model#Memory_order) to users.
  - Operations without visible side effects can be parallelized.

</Revision>

{/* source:cpp-standard-library:0049 */}
For each class defined in the C++ standard library required to be [derived](/docs/cpp/language/classes/derived_class) from another class defined in the C++ standard library,

{/* source:cpp-standard-library:0050 */}
- the base class must be [virtual](/docs/cpp/language/classes/derived_class#Virtual_base_classes) if it is specified as `virtual`,
- the base class cannot be virtual if it is not specified as `virtual`, and
- unless otherwise specified, types with distinct names shall be distinct types.

{/* source:cpp-standard-library:0051 */}
<Revision since="C++11">

Unless otherwise specified, all types specified in the C++ standard library are non-[final](/docs/cpp/language/classes/final) types.

</Revision>

{/* source:cpp-standard-library:0052 */}
If a function defined in the C++ standard library is specified to throw an [exception](/docs/cpp/language/exceptions) (in a particular situation) of a given type, the exception thrown can only have that type or a type derived from that type so that an exception handler for the base type can catch it.

{/* source:cpp-standard-library:0053 */}
Functions from the C standard library can only throw exceptions when such a function calls a program-supplied function that throws an exception ([`qsort()`](/docs/cpp/library/algorithm/qsort) and [`bsearch()`](/docs/cpp/library/algorithm/bsearch) meet this condition).

{/* source:cpp-standard-library:0054 */}
Destructor operations defined in the C++ standard library never throw exceptions. Every destructor in the C++ standard library behaves as if it had a [non-throwing exception specification](/docs/cpp/language/exceptions/noexcept_spec).

{/* source:cpp-standard-library:0055 */}
<Revision since="C++11">

If a function in the C++ standard library report errors via a [`std::error_code`](/docs/cpp/library/error/error_code) object, that object's [`category()`](/docs/cpp/library/error/error_code/category) member must return [`std::system_category()`](/docs/cpp/library/error/system_category) for errors originating from the operating system, or a reference to an implementation-defined [`std::error_category`](/docs/cpp/library/error/error_category) object for errors originating elsewhere. The possible values of [`value()`](/docs/cpp/library/error/error_code/value) for each of these error categories should be defined.

Objects of types defined in the C++ standard library may be [moved from](/docs/cpp/language/classes/move_constructor). Move operations can either be explicitly specified or implicitly generated. Unless otherwise specified, such moved-from objects will be placed in a valid but unspecified state.

An object of a type defined in the C++ standard library may be [move-assigned](/docs/cpp/language/classes/move_operator) to itself. Unless otherwise specified, such an assignment places the object in a valid but unspecified state.

</Revision>

#### Implementation freedom

{/* source:cpp-standard-library:0056 */}
It is unspecified whether any member or non-member functions in the C++ standard library are defined as [inline](/docs/cpp/language/declarations/inline).

{/* source:cpp-standard-library:0057 */}
For a non-[virtual](/docs/cpp/language/classes/virtual) C++ standard library member function, a different set of member function signatures can be declared, provided that any call to that member function that would select an overload from the given set of declarations behaves as if that overload was selected. This allows, for instance:

{/* source:cpp-standard-library:0058 */}
- adding parameters with default arguments,
- replacing a member function with default arguments with two or more member functions with equivalent behavior, or
- adding additional signatures for a member function name.

{/* source:cpp-standard-library:0059 */}
Unless otherwise specified, it is implementation-defined which functions in the C++ standard library may be recursively reentered.

{/* source:cpp-standard-library:0060 */}
<Revision since="C++11">

C++ standard library implementations can share their own internal objects between threads if the objects are not visible to users and are protected against data races.

</Revision>

{/* source:cpp-standard-library:0061 */}
It is unspecified whether any function signature or class in the C++ standard library is a friend of another class in the C++ standard library.

{/* source:cpp-standard-library:0062 */}
The names and global function signatures described [here](/docs/cpp/library/standard_library#Library_contents) are reserved to the implementation.

{/* source:cpp-standard-library:0063 */}
Any class in the C++ standard library can be derived from a class with a name reserved to the implementation. If a class defined in the C++ standard library is required to be derived from other classes in the C++ standard library, that class can be derived directly from the required base or indirectly through a hierarchy of base classes with names reserved to the implementation.

{/* source:cpp-standard-library:0064 */}
If a function defined in the C++ standard library is not specified to throw an exception but does not have a non-throwing exception specification, the exception thrown is implementation-defined, but its type should be [`std::exception`](/docs/cpp/library/error/exception) or any type derived from [`std::exception`](/docs/cpp/library/error/exception).

{/* source:cpp-standard-library:0065 */}
The exception specification for a non-virtual function can be strengthened by adding a non-throwing exception specification.
