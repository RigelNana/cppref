{/* source:cpp-algorithm-stable-sort:0001 */}
Sorts the elements in the range `[first, last)` in non-descending order. The order of equivalent elements is guaranteed to be preserved.

{/* source:cpp-algorithm-stable-sort:0002 */}
1. 1) Elements are [sorted](/docs/cpp/library/algorithm#Requirements) with respect to <InlineRevision until="C++20">`operator<`</InlineRevision><InlineRevision since="C++20">`std::less{}`</InlineRevision>.

{/* source:cpp-algorithm-stable-sort:0003 */}
2. 3) Elements are sorted with respect to `comp`.

{/* source:cpp-algorithm-stable-sort:0004 */}
3. 2,4) Same as (1,3), but executed according to `policy`.

{/* source:cpp-algorithm-stable-sort:0005 */}
4. These overloads participate in overload resolution only if all following conditions are satisfied:

<Revision until="C++20">

`std::is_execution_policy_v<std::decay_t<ExecutionPolicy>>` is `true`.

</Revision>

<Revision since="C++20">

`std::is_execution_policy_v<std::remove_cvref_t<ExecutionPolicy>>` is `true`.

</Revision>

{/* source:cpp-algorithm-stable-sort:0006 */}
If any of the following conditions is satisfied, the behavior is undefined:

{/* source:cpp-algorithm-stable-sort:0007 */}
<Revision until="C++11">

- The type of `*first` is not [*Swappable*](/docs/cpp/library/named_req/Swappable).

</Revision>

<Revision since="C++11">

- `RandomIt` is not [*ValueSwappable*](/docs/cpp/library/named_req/ValueSwappable).
- The type of `*first` is not [*MoveConstructible*](/docs/cpp/library/named_req/MoveConstructible).
- The type of `*first` is not [*MoveAssignable*](/docs/cpp/library/named_req/MoveAssignable).

</Revision>

### Parameters

{/* source:cpp-algorithm-stable-sort:0008 */}
<ParameterList>
  <Parameter name="first, last">the range of elements to sort</Parameter>
  <Parameter name="policy">the [execution policy](/docs/cpp/library/algorithm/execution_policy_tag_t) to use</Parameter>
  <Parameter name="comp">

comparison function object (i.e. an object that satisfies the requirements of [*Compare*](/docs/cpp/library/named_req/Compare)) which returns `true` if the first argument is *less* than (i.e. is ordered before) the second.

The signature of the comparison function should be equivalent to the following:

`bool cmp(const Type1& a, const Type2& b);`

While the signature does not need to have `const&`, the function must not modify the objects passed to it and must be able to accept all values of type (possibly const) `Type1` and `Type2` regardless of [value category](/docs/cpp/language/expressions/value_category) (thus, `Type1&` is not allowed<InlineRevision since="C++11">, nor is `Type1` unless for `Type1` a move is equivalent to a copy</InlineRevision>). The types `Type1` and `Type2` must be such that an object of type `RandomIt` can be dereferenced and then implicitly converted to both of them.

Type requirements:

- `RandomIt` must meet the requirements of [*LegacyRandomAccessIterator*](/docs/cpp/library/named_req/RandomAccessIterator).
- `Compare` must meet the requirements of [*Compare*](/docs/cpp/library/named_req/Compare).

</Parameter>
</ParameterList>

### Complexity

{/* source:cpp-algorithm-stable-sort:0009 */}
Given `N` as `last - first`:

{/* source:cpp-algorithm-stable-sort:0010 */}
1. 1,2) O(N·log(N)) comparisons using <InlineRevision until="C++20">`operator<`</InlineRevision><InlineRevision since="C++20">`std::less{}`</InlineRevision> if enough extra memory is available, otherwise O(N·log2 (N)) comparisons.

{/* source:cpp-algorithm-stable-sort:0011 */}
2. 3,4) O(N·log(N)) applications of the comparator `comp` if enough extra memory is available, otherwise O(N·log2 (N)) applications.

### Exceptions

{/* source:cpp-algorithm-stable-sort:0012 */}
The overloads with a template parameter named `ExecutionPolicy` report errors as follows:

{/* source:cpp-algorithm-stable-sort:0013 */}
- If execution of a function invoked as part of the algorithm throws an exception and `ExecutionPolicy` is one of the [standard policies](/docs/cpp/library/algorithm/execution_policy_tag_t), [`std::terminate`](/docs/cpp/library/error/terminate) is called. For any other `ExecutionPolicy`, the behavior is implementation-defined.
- If the algorithm fails to allocate memory, [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc) is thrown.

### Notes

{/* source:cpp-algorithm-stable-sort:0015 */}
This function attempts to allocate a temporary buffer equal in size to the sequence to be sorted. If the allocation fails, the less efficient algorithm is chosen.

### Example

{/* source:cpp-algorithm-stable-sort:0017 */}
```cpp
#include <algorithm>
#include <array>
#include <iostream>
#include <string>
#include <vector>
 
struct Employee
{
    int age;
    std::string name; // Does not participate in comparisons
};
 
bool operator<(const Employee& lhs, const Employee& rhs)
{
    return lhs.age < rhs.age;
}
 
#if __cpp_lib_constexpr_algorithms >= 202306L
consteval auto get_sorted()
{
    auto v = std::array{3, 1, 4, 1, 5, 9};
    std::stable_sort(v.begin(), v.end());
    return v;
}
static_assert(std::ranges::is_sorted(get_sorted()));
#endif
 
int main()
{
    std::vector<Employee> v{{108, "Zaphod"}, {32, "Arthur"}, {108, "Ford"}};
 
    std::stable_sort(v.begin(), v.end());
 
    for (const Employee& e : v)
        std::cout << e.age << ", " << e.name << '\n';
}
```

Output:

```text
32, Arthur
108, Zaphod
108, Ford
```
