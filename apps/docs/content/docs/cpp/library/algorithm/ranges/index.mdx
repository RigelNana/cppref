{/* source:cpp-algorithm-ranges:0000 */}
C++20 provides [constrained](/docs/cpp/language/templates/constraints) versions of most algorithms in the namespace `std::ranges`. In these algorithms, a range can be specified as either an [iterator](/docs/cpp/library/iterator/input_or_output_iterator)-[sentinel](/docs/cpp/library/iterator/sentinel_for) pair or as a single [range](/docs/cpp/library/ranges/range) argument, and projections and pointer-to-member callables are supported. Additionally, the [return types](/docs/cpp/library/algorithm/ranges#Return_types) of most algorithms have been changed to return all potentially useful information computed during the execution of the algorithm.

### Algorithm function objects

{/* source:cpp-algorithm-ranges:0001 */}
An algorithm function object (AFO), informally known as *niebloid*, is a [customization point object](/docs/cpp/library/standard_library/cpo) (CPO) that is specified as one or more overloaded function templates. The name of these function templates designates the corresponding algorithm function object.

{/* source:cpp-algorithm-ranges:0002 */}
For an algorithm function object `o`, let `S` be the corresponding set of function templates. Then for any sequence of arguments `args...`, `o(args...)` is [expression-equivalent](/docs/cpp/language/expressions#Expression-equivalence) to `s(args...)`, where the result of name lookup for `s` is the overload set `S`.

{/* source:cpp-algorithm-ranges:0003 */}
The constrained algorithms in the namespace `std::ranges` are defined as algorithm function objects. As a result:

{/* source:cpp-algorithm-ranges:0004 */}
- Explicit template argument lists cannot be specified when calling any of them.
- None of them are visible to [argument-dependent lookup](/docs/cpp/language/functions/adl).
- When any of them are found by [normal unqualified lookup](/docs/cpp/language/basic_concepts/unqualified_lookup) as the name to the left of the function-call operator, [argument-dependent lookup](/docs/cpp/language/functions/adl) is inhibited.
