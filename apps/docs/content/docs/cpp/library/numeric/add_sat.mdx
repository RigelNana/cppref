{/* source:cpp-numeric-add-sat:0001 */}
Computes the [saturating](https://en.wikipedia.org/wiki/Saturation_arithmetic) addition `x + y`. This operation (unlike built-in [arithmetic operations on integers](/docs/cpp/language/expressions/operator_arithmetic#Overflows)) behaves as-if it is a mathematical operation with an infinite range. Let `q` denote the result of such operation. Returns:

{/* source:cpp-numeric-add-sat:0002 */}
- `q`, if `q` is representable as a value of type `T`. Otherwise, the largest or smallest value of type `T`, whichever is closer to the `q`.

{/* source:cpp-numeric-add-sat:0003 */}
This overload participates in overload resolution only if `T` is an [integer type](/docs/cpp/language/basic_concepts/types#Integer_types), that is: `signed char`, `short`, `int`, `long`, `long long`, an extended signed integer type, or an unsigned version of such types. In particular, `T` must not be (possibly cv-qualified) `bool`, `char`, `wchar_t`, `char8_t`, `char16_t`, and `char32_t`, as these types are not intended for arithmetic.

### Return value

{/* source:cpp-numeric-add-sat:0005 */}
Saturated `x + y`.

### Notes

{/* source:cpp-numeric-add-sat:0006 */}
Unlike the built-in arithmetic operators on integers, the [integral promotion](/docs/cpp/language/expressions/implicit_cast#Integral_promotion) does not apply to the `x` and `y` arguments.

{/* source:cpp-numeric-add-sat:0007 */}
If two arguments of different type are passed, the call fails to compile, i.e. the behavior relative to [template argument deduction](/docs/cpp/language/templates/template_argument_deduction) is the same as for [`std::min`](/docs/cpp/library/algorithm/min) or [`std::max`](/docs/cpp/library/algorithm/max).

{/* source:cpp-numeric-add-sat:0008 */}
Most modern hardware architectures have efficient support for saturation arithmetic on SIMD vectors, including SSE2 for x86 and NEON for ARM.

### Example

{/* source:cpp-numeric-add-sat:0011 */}
Can be previewed on [Compiler Explorer](https://godbolt.org/z/G6o9ajz6d).

```cpp
#include <climits>
#include <limits>
#include <numeric>
 
static_assert(CHAR_BIT == 8);
static_assert(UCHAR_MAX == 255);
 
int main()
{
    constexpr int a = std::add_sat(3, 4); // no saturation occurs, T = int
    static_assert(a == 7);
 
    constexpr unsigned char b = std::add_sat<unsigned char>(UCHAR_MAX, 4); // saturated
    static_assert(b == UCHAR_MAX);
 
    constexpr unsigned char c = std::add_sat(UCHAR_MAX, 4); // not saturated, T = int
        // add_sat(int, int) returns int tmp == 259,
        // then assignment truncates 259 % 256 == 3
    static_assert(c == 3);
 
//  unsigned char d = std::add_sat(252, c); // Error: inconsistent deductions for T
 
    constexpr unsigned char e = std::add_sat<unsigned char>(251, a); // saturated
    static_assert(e == UCHAR_MAX);
        // 251 is of type T = unsigned char, `a` is converted to unsigned char value;
        // might yield an int -> unsigned char conversion warning for `a`
 
    constexpr signed char f = std::add_sat<signed char>(-123, -3); // not saturated
    static_assert(f == -126);
 
    constexpr signed char g = std::add_sat<signed char>(-123, -13); // saturated
    static_assert(g == std::numeric_limits<signed char>::min()); // g == -128
}
```
