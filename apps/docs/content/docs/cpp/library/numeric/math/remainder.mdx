A) Additional overloads are provided for all integer types, which are treated as `double`.

{/* source:cpp-numeric-math-remainder:0004 */}
The IEEE floating-point remainder of the division operation `x / y` calculated by this function is exactly the value `x - quo * y`, where the value `quo` is the integral value nearest the exact value `x / y`. When `|quo - x / y| = ½`, the value `quo` is chosen to be even.

{/* source:cpp-numeric-math-remainder:0005 */}
In contrast to [std::fmod](/docs/cpp/library/numeric/math/fmod), the returned value is not guaranteed to have the same sign as `x`.

{/* source:cpp-numeric-math-remainder:0006 */}
If the returned value is zero, it will have the same sign as `x`.

### Return value

{/* source:cpp-numeric-math-remainder:0008 */}
If successful, returns the IEEE floating-point remainder of the division `x / y` as defined above.

{/* source:cpp-numeric-math-remainder:0009 */}
If a domain error occurs, an implementation-defined value is returned (NaN where supported).

{/* source:cpp-numeric-math-remainder:0010 */}
If a range error occurs due to underflow, the correct result is returned.

{/* source:cpp-numeric-math-remainder:0011 */}
If `y` is zero, but the domain error does not occur, zero is returned.

### Error handling

{/* source:cpp-numeric-math-remainder:0012 */}
Errors are reported as specified in [math_errhandling](/docs/cpp/library/numeric/math/math_errhandling).

{/* source:cpp-numeric-math-remainder:0013 */}
Domain error may occur if `y` is zero.

{/* source:cpp-numeric-math-remainder:0014 */}
If the implementation supports IEEE floating-point arithmetic (IEC 60559),

{/* source:cpp-numeric-math-remainder:0015 */}
- The current [rounding mode](/docs/cpp/library/numeric/fenv/FE_round) has no effect.
- [FE_INEXACT](/docs/cpp/library/numeric/fenv/FE_exceptions) is never raised, the result is always exact.
- If `x` is ±∞ and `y` is not NaN, NaN is returned and [FE_INVALID](/docs/cpp/library/numeric/fenv/FE_exceptions) is raised.
- If `y` is ±0 and `x` is not NaN, NaN is returned and [FE_INVALID](/docs/cpp/library/numeric/fenv/FE_exceptions) is raised.
- If either argument is NaN, NaN is returned.

### Notes

{/* source:cpp-numeric-math-remainder:0016 */}
[POSIX requires](https://pubs.opengroup.org/onlinepubs/9699919799/functions/remainder.html) that a domain error occurs if `x` is infinite or `y` is zero.

{/* source:cpp-numeric-math-remainder:0017 */}
[std::fmod](/docs/cpp/library/numeric/math/fmod), but not `std::remainder` is useful for doing silent wrapping of floating-point types to unsigned integer types: `(0.0 <= (y = std::fmod(std::rint(x), 65536.0)) ? y : 65536.0 + y)` is in the range `[-0.0, 65535.0]`, which corresponds to `unsigned short`, but `std::remainder(std::rint(x), 65536.0)` is in the range `[-32767.0, +32768.0]`, which is outside of the range of `signed short`.

{/* source:cpp-numeric-math-remainder:0018 */}
The additional overloads are not required to be provided exactly as (A). They only need to be sufficient to ensure that for their first argument `num1` and second argument `num2`:

{/* source:cpp-numeric-math-remainder:0019 */}
<Revision until="C++23">
If `num1` or `num2` has type `long double`, then `std::remainder(num1, num2)` has the same effect as `std::remainder(static_cast<long double>(num1), static_cast<long double>(num2))`. Otherwise, if `num1` and/or `num2` has type `double` or an integer type, then `std::remainder(num1, num2)` has the same effect as `std::remainder(static_cast<double>(num1), static_cast<double>(num2))`. Otherwise, if `num1` or `num2` has type `float`, then `std::remainder(num1, num2)` has the same effect as `std::remainder(static_cast<float>(num1), static_cast<float>(num2))`.
</Revision>
<Revision since="C++23">
If `num1` and `num2` have arithmetic types, then `std::remainder(num1, num2)` has the same effect as `std::remainder(static_cast</*common-floating-point-type*/>(num1), static_cast</*common-floating-point-type*/>(num2))`, where `/*common-floating-point-type*/` is the floating-point type with the greatest [floating-point conversion rank](/docs/cpp/language/expressions/usual_arithmetic_conversions#Floating-point_conversion_rank) and greatest [floating-point conversion subrank](/docs/cpp/language/expressions/usual_arithmetic_conversions#Floating-point_conversion_subrank) between the types of `num1` and `num2`, arguments of integer type are considered to have the same floating-point conversion rank as `double`.
If no such floating-point type with the greatest rank and subrank exists, then [overload resolution](/docs/cpp/language/functions/overload_resolution) does not result in a usable candidate from the overloads provided.
</Revision>

### Example

{/* source:cpp-numeric-math-remainder:0020 */}
```cpp
#include <cfenv>
#include <cmath>
#include <iostream>
// #pragma STDC FENV_ACCESS ON
 
int main()
{
    std::cout << "remainder(+5.1, +3.0) = " << std::remainder(5.1, 3) << '\n'
              << "remainder(-5.1, +3.0) = " << std::remainder(-5.1, 3) << '\n'
              << "remainder(+5.1, -3.0) = " << std::remainder(5.1, -3) << '\n'
              << "remainder(-5.1, -3.0) = " << std::remainder(-5.1, -3) << '\n';
 
    // special values
    std::cout << "remainder(-0.0, 1.0) = " << std::remainder(-0.0, 1) << '\n'
              << "remainder(5.1, Inf) = " << std::remainder(5.1, INFINITY) << '\n';
 
    // error handling
    std::feclearexcept(FE_ALL_EXCEPT);
    std::cout << "remainder(+5.1, 0) = " << std::remainder(5.1, 0) << '\n';
    if (fetestexcept(FE_INVALID))
        std::cout << "    FE_INVALID raised\n";
}
```

Possible output:

```text
remainder(+5.1, +3.0) = -0.9
remainder(-5.1, +3.0) = 0.9
remainder(+5.1, -3.0) = -0.9
remainder(-5.1, -3.0) = 0.9
remainder(-0.0, 1.0) = -0
remainder(5.1, Inf) = 5.1
remainder(+5.1, 0) = -nan
    FE_INVALID raised
```
