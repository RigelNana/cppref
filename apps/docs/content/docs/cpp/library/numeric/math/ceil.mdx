### Return value

{/* source:cpp-numeric-math-ceil:0005 */}
If no errors occur, the smallest integer value not less than `num`, that is `⌈num⌉`, is returned.

{/* source:cpp-numeric-math-ceil:0006 */}
Return value · `num`

### Error handling

{/* source:cpp-numeric-math-ceil:0007 */}
Errors are reported as specified in [math_errhandling](/docs/cpp/library/numeric/math/math_errhandling).

{/* source:cpp-numeric-math-ceil:0008 */}
If the implementation supports IEEE floating-point arithmetic (IEC 60559),

{/* source:cpp-numeric-math-ceil:0009 */}
- The current [rounding mode](/docs/cpp/library/numeric/fenv/FE_round) has no effect.
- If `num` is ±∞, it is returned unmodified.
- If `num` is ±0, it is returned, unmodified.
- If `num` is NaN, NaN is returned.

### Notes

{/* source:cpp-numeric-math-ceil:0010 */}
[FE_INEXACT](/docs/cpp/library/numeric/fenv/FE_exceptions) may be (but is not required to be) raised when rounding a non-integer finite value.

{/* source:cpp-numeric-math-ceil:0011 */}
The largest representable floating-point values are exact integers in all standard floating-point formats, so this function never overflows on its own; however the result may overflow any integer type (including [std::intmax_t](/docs/cpp/library/utility/types/integer)), when stored in an integer variable. It is for this reason that the return type is floating-point not integral.

{/* source:cpp-numeric-math-ceil:0012 */}
This function (for `double` argument) behaves as if (except for the freedom to not raise [FE_INEXACT](/docs/cpp/library/numeric/fenv/FE_exceptions)) implemented by the following code:

{/* source:cpp-numeric-math-ceil:0013 */}
```cpp
#include <cfenv>
#include <cmath>
#pragma STDC FENV_ACCESS ON
 
double ceil(double x)
{
    int save_round = std::fegetround();
    std::fesetround(FE_UPWARD);
    double result = std::rint(x); // or std::nearbyint
    std::fesetround(save_round);
    return result;
}
```

{/* source:cpp-numeric-math-ceil:0014 */}
The additional overloads are not required to be provided exactly as (A). They only need to be sufficient to ensure that for their argument `num` of integer type, `std::ceil(num)` has the same effect as `std::ceil(static_cast<double>(num))`.

### Example

{/* source:cpp-numeric-math-ceil:0015 */}
```cpp
#include <cmath>
#include <iostream>
 
int main()
{
    std::cout << std::fixed
              << "ceil(+2.4) = " << std::ceil(+2.4) << '\n'
              << "ceil(-2.4) = " << std::ceil(-2.4) << '\n'
              << "ceil(-0.0) = " << std::ceil(-0.0) << '\n'
              << "ceil(-Inf) = " << std::ceil(-INFINITY) << '\n';
}
```

Output:

```text
ceil(+2.4) = 3.000000
ceil(-2.4) = -2.000000
ceil(-0.0) = -0.000000
ceil(-Inf) = -inf
```
