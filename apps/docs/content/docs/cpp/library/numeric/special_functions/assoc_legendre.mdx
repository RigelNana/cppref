        1-3) Computes the [Associated Legendre polynomials](https://en.wikipedia.org/wiki/Associated_Legendre_polynomials) of the degree `n`, order `m`, and argument `x`. <InlineRevision since="C++23">The library provides overloads of `std::assoc_legendre` for all cv-unqualified floating-point types as the type of the parameter `x`.</InlineRevision>

| dm |
| --- |
| dxm |

{/* source:cpp-numeric-special-functions-assoc-legendre:0005 */}
Note that the [Condon-Shortley phase term](https://mathworld.wolfram.com/Condon-ShortleyPhase.html) (-1)m is omitted from this definition.

### Error handling

{/* source:cpp-numeric-special-functions-assoc-legendre:0006 */}
Errors may be reported as specified in [math_errhandling](/docs/cpp/library/numeric/math/math_errhandling)

{/* source:cpp-numeric-special-functions-assoc-legendre:0007 */}
- If the argument is NaN, NaN is returned and domain error is not reported
- If |x| \> 1, a domain error may occur
- If n is greater or equal to 128, the behavior is implementation-defined

### Notes

{/* source:cpp-numeric-special-functions-assoc-legendre:0008 */}
Implementations that do not support C++17, but support [ISO 29124:2010](/docs/cpp/library/experimental/special_math), provide this function if `__STDCPP_MATH_SPEC_FUNCS__` is defined by the implementation to a value at least `201003L` and if the user defines `__STDCPP_WANT_MATH_SPEC_FUNCS__` before including any standard library headers.

{/* source:cpp-numeric-special-functions-assoc-legendre:0009 */}
Implementations that do not support ISO 29124:2010 but support TR 19768:2007 (TR1), provide this function in the header `tr1/cmath` and namespace `std::tr1`.

{/* source:cpp-numeric-special-functions-assoc-legendre:0010 */}
An implementation of this function is also [available in boost.math](https://www.boost.org/doc/libs/release/libs/math/doc/html/math_toolkit/sf_poly/legendre.html) as boost::math::legendre_p, except that the boost.math definition includes the Condon-Shortley phase term.

{/* source:cpp-numeric-special-functions-assoc-legendre:0011 */}
The first few associated Legendre polynomials are:

{/* source:cpp-numeric-special-functions-assoc-legendre:0012 */}
| Function | Polynomial |
| --- | --- |
| `assoc_legendre(0, 0, x)` | 1 |
| `assoc_legendre(1, 0, x)` | x |
| `assoc_legendre(1, 1, x)` | (1 - x2 )1/2 |
| `assoc_legendre(2, 0, x)` | 1 2(3x2 - 1) |
| `assoc_legendre(2, 1, x)` | 3x(1 - x2 )1/2 |
| `assoc_legendre(2, 2, x)` | 3(1 - x2 ) |

{/* source:cpp-numeric-special-functions-assoc-legendre:0013 */}
The additional overloads are not required to be provided exactly as (A). They only need to be sufficient to ensure that for their argument `num` of integer type, `std::assoc_legendre(int_num1, int_num2, num)` has the same effect as `std::assoc_legendre(int_num1, int_num2, static_cast<double>(num))`.

### Example

{/* source:cpp-numeric-special-functions-assoc-legendre:0014 */}
```cpp
#include <cmath>
#include <iostream>
 
double P20(double x)
{
    return 0.5 * (3 * x * x - 1);
}
 
double P21(double x)
{
    return 3.0 * x * std::sqrt(1 - x * x);
}
 
double P22(double x)
{
    return 3 * (1 - x * x);
}
 
int main()
{
    // spot-checks
    std::cout << std::assoc_legendre(2, 0, 0.5) << '=' << P20(0.5) << '\n'
              << std::assoc_legendre(2, 1, 0.5) << '=' << P21(0.5) << '\n'
              << std::assoc_legendre(2, 2, 0.5) << '=' << P22(0.5) << '\n';
}
```

Output:

```text
-0.125=-0.125
1.29904=1.29904
2.25=2.25
```
