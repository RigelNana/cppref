### Notes

{/* source:cpp-numeric-special-functions-ellint-3:0007 */}
Implementations that do not support C++17, but support [ISO 29124:2010](/docs/cpp/library/experimental/special_math), provide this function if `__STDCPP_MATH_SPEC_FUNCS__` is defined by the implementation to a value at least `201003L` and if the user defines `__STDCPP_WANT_MATH_SPEC_FUNCS__` before including any standard library headers.

{/* source:cpp-numeric-special-functions-ellint-3:0008 */}
Implementations that do not support ISO 29124:2010 but support TR 19768:2007 (TR1), provide this function in the header `tr1/cmath` and namespace `std::tr1`.

{/* source:cpp-numeric-special-functions-ellint-3:0009 */}
An implementation of this function is also available in [boost.math](https://www.boost.org/doc/libs/release/libs/math/doc/html/math_toolkit/ellint/ellint_3.html).

{/* source:cpp-numeric-special-functions-ellint-3:0010 */}
The additional overloads are not required to be provided exactly as (A). They only need to be sufficient to ensure that for their first argument `num1`, second argument `num2` and third argument `num3`:

{/* source:cpp-numeric-special-functions-ellint-3:0011 */}
<Revision until="C++23">
- If `num1`, `num2` or `num3` has type `long double`, then `std::ellint_3(num1, num2, num3)` has the same effect as `std::ellint_3(static_cast<long double>(num1),` `              static_cast<long double>(num2),` `              static_cast<long double>(num3))`.
- Otherwise, if `num1`, `num2` and/or `num3` has type `double` or an integer type, then `std::ellint_3(num1, num2, num3)` has the same effect as `std::ellint_3(static_cast<double>(num1),` `              static_cast<double>(num2),` `              static_cast<double>(num3))`.
- Otherwise, if `num1`, `num2` or `num3` has type `float`, then `std::ellint_3(num1, num2, num3)` has the same effect as `std::ellint_3(static_cast<float>(num1),` `              static_cast<float>(num2),` `              static_cast<float>(num3))`.
</Revision>
<Revision since="C++23">
If `num1`, `num2` and `num3` have arithmetic types, then `std::ellint_3(num1, num2, num3)` has the same effect as `std::ellint_3(static_cast</* common-floating-point-type */>(num1),` `              static_cast</* common-floating-point-type */>(num2),` `              static_cast</* common-floating-point-type */>(num3))`, where `/* common-floating-point-type */` is the floating-point type with the greatest [floating-point conversion rank](/docs/cpp/language/expressions/usual_arithmetic_conversions#Floating-point_conversion_rank) and greatest [floating-point conversion subrank](/docs/cpp/language/expressions/usual_arithmetic_conversions#Floating-point_conversion_subrank) among the types of `num1`, `num2` and `num3`, arguments of integer type are considered to have the same floating-point conversion rank as `double`.
If no such floating-point type with the greatest rank and subrank exists, then [overload resolution](/docs/cpp/language/functions/overload_resolution) does not result in a usable candidate from the overloads provided.
</Revision>

### Example

{/* source:cpp-numeric-special-functions-ellint-3:0012 */}
```cpp
#include <cmath>
#include <iostream>
#include <numbers>
 
int main()
{
    const double hpi = std::numbers::pi / 2;
 
    std::cout << "Π(0,0,π/2) = " << std::ellint_3(0, 0, hpi) << '\n'
              << "π/2 = " << hpi << '\n';
}
```

Output:

```text
Π(0,0,π/2) = 1.5708
π/2 = 1.5708
```
