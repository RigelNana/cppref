  <DeclarationDescription>
    {/* source:cpp-numeric-complex-complex:0001 */}
    Constructs the `std::complex` object. <InlineRevision until="C++23">The standard explicit specializations (`std::complex<float>`, `std::complex<double>` and `std::complex<long double>`) have different constructor declarations from the main template.</InlineRevision>

    {/* source:cpp-numeric-complex-complex:0002 */}
    1. Constructs the complex number from real part `re` and imaginary part `im`.

    {/* source:cpp-numeric-complex-complex:0003 */}
    2. Copy constructor. Constructs the object with the copy of the contents of `other`. <InlineRevision until="C++20">The copy constructors are implicitly declared in the standard explicit specializations.</InlineRevision>

    {/* source:cpp-numeric-complex-complex:0004 */}
    <Revision until="C++23">
    3. [Converting constructor](/docs/cpp/language/classes/converting_constructor). Constructs the object from a complex number of a different type. The main template provides a converting constructor template, while each standard explicit specialization provides two non-template constructors for the two other standard explicit specializations. The non-template constructors are converting constructors (i.e. non-explicit) if and only if the conversions of the real and imaginary parts are not narrowing.
    </Revision>
    <Revision since="C++23">
    For the main template, the expression inside `explicit` evaluates to `false` if and only if the [floating-point conversion rank](/docs/cpp/language/expressions/usual_arithmetic_conversions#Floating-point_conversion_rank) of `T` is greater than or equal to the floating-point conversion rank of `X`.
    </Revision>
  </DeclarationDescription>
</DeclarationDoc>

## Notes

{/* source:cpp-numeric-complex-complex:0006 */}
Since C++23, the copy constructor is required to be [trivial](/docs/cpp/language/classes/copy_constructor#Trivial_copy_constructor) in order to satisfy the [TriviallyCopyable](/docs/cpp/library/named_req/TriviallyCopyable) requirement, but implementations generally make it trivial in all modes.
