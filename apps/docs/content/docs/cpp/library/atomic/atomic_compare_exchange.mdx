{/* source:cpp-atomic-atomic-compare-exchange:0001 */}
Atomically compares the <InlineRevision until="C++20">[`object representation`](/docs/cpp/language/basic_concepts/objects)</InlineRevision><InlineRevision since="C++20">[`value representation`](/docs/cpp/language/basic_concepts/objects)</InlineRevision> of the object pointed to by `obj` with that of the object pointed to by `expected`, and if those are bitwise-equal, replaces the former with `desired` (performs read-modify-write operation). Otherwise, loads the actual value pointed to by `obj` into `*expected` (performs load operation).

{/* source:cpp-atomic-atomic-compare-exchange:0002 */}
| Overloads | Memory model for read-modify-write operation | load operation |
| --- | --- | --- |
| (1-4) | `std::memory_order_seq_cst` | `std::memory_order_seq_cst` |
| (5-8) | `success` | `failure` |

{/* source:cpp-atomic-atomic-compare-exchange:0003 */}
These functions are defined in terms of [member functions](/docs/cpp/library/atomic/atomic/compare_exchange) of [`std::atomic`](/docs/cpp/library/atomic/atomic):

{/* source:cpp-atomic-atomic-compare-exchange:0004 */}
1,2) `obj->compare_exchange_weak(*expected, desired)`

{/* source:cpp-atomic-atomic-compare-exchange:0005 */}
3,4) `obj->compare_exchange_strong(*expected, desired)`

{/* source:cpp-atomic-atomic-compare-exchange:0006 */}
5,6) `obj->compare_exchange_weak(*expected, desired, success, failure)`

{/* source:cpp-atomic-atomic-compare-exchange:0007 */}
7,8) `obj->compare_exchange_strong(*expected, desired, success, failure)`

{/* source:cpp-atomic-atomic-compare-exchange:0008 */}
If `failure`<InlineRevision until="C++17"> is stronger than `success` or</InlineRevision> is one of `std::memory_order_release` and `std::memory_order_acq_rel`, the behavior is undefined.

### Parameters

{/* source:cpp-atomic-atomic-compare-exchange:0009 */}
<ParameterList>
  <Parameter name="obj">pointer to the atomic object to test and modify</Parameter>
  <Parameter name="expected">pointer to the value expected to be found in the atomic object</Parameter>
  <Parameter name="desired">the value to store in the atomic object if it is as expected</Parameter>
  <Parameter name="success">the memory synchronization ordering for the read-modify-write operation if the comparison succeeds</Parameter>
  <Parameter name="failure">the memory synchronization ordering for the load operation if the comparison fails</Parameter>
</ParameterList>

### Return value

{/* source:cpp-atomic-atomic-compare-exchange:0010 */}
The result of the comparison: `true` if `*obj` was equal to `*expected`, `false` otherwise.

### Notes

{/* source:cpp-atomic-atomic-compare-exchange:0011 */}
`std::atomic_compare_exchange_weak` and `std::atomic_compare_exchange_weak_explicit` (the weak versions) are allowed to fail spuriously, that is, act as if `*obj != *expected` even if they are equal. When a compare-and-exchange is in a loop, they will yield better performance on some platforms.

{/* source:cpp-atomic-atomic-compare-exchange:0012 */}
When a weak compare-and-exchange would require a loop and a strong one would not, the strong one is preferable unless the object representation of `T` may include <InlineRevision until="C++20">padding bits,</InlineRevision> trap bits, or offers multiple object representations for the same value (e.g. floating-point NaN). In those cases, weak compare-and-exchange typically works because it quickly converges on some stable object representation.

{/* source:cpp-atomic-atomic-compare-exchange:0013 */}
For a union with bits that participate in the value representations of some members but not the others, compare-and-exchange might always fail because such padding bits have indeterminate values when they do not participate in the value representation of the active member.

{/* source:cpp-atomic-atomic-compare-exchange:0014 */}
<Revision since="C++20">
Padding bits that never participate in an object's value representation are ignored.
</Revision>

### Example

{/* source:cpp-atomic-atomic-compare-exchange:0015 */}
Compare and exchange operations are often used as basic building blocks of lockfree data structures.

```cpp
#include <atomic>

template<class T>
struct node
{
    T data;
    node* next;
    node(const T& data) : data(data), next(nullptr) {}
};

template<class T>
class stack
{
    std::atomic<node<T>*> head;
public:
    void push(const T& data)
    {
        node<T>* new_node = new node<T>(data);

        // put the current value of head into new_node->next
        new_node->next = head.load(std::memory_order_relaxed);

        // now make new_node the new head, but if the head
        // is no longer what's stored in new_node->next
        // (some other thread must have inserted a node just now)
        // then put that new head into new_node->next and try again
        while (!std::atomic_compare_exchange_weak_explicit(
                   &head, &new_node->next, new_node,
                   std::memory_order_release, std::memory_order_relaxed))
            ; // the body of the loop is empty
// note: the above loop is not thread-safe in at least
// GCC prior to 4.8.3 (bug 60272), clang prior to 2014-05-05 (bug 18899)
// MSVC prior to 2014-03-17 (bug 819819). See member function version for workaround
    }
};

int main()
{
    stack<int> s;
    s.push(1);
    s.push(2);
    s.push(3);
}
```
