{/* source:cpp-atomic-atomic-ref:0001 */}
The `std::atomic_ref` class template applies atomic operations to the object it references.

{/* source:cpp-atomic-atomic-ref:0002 */}
For the lifetime of the `std::atomic_ref` object, the object it references is considered an atomic object. If one thread writes to an atomic object while another thread reads from it, the behavior is well-defined (see [memory model](/docs/cpp/language/basic_concepts/memory_model) for details on data races). In addition, accesses to atomic objects may establish inter-thread synchronization and order non-atomic memory accesses as specified by [`std::memory_order`](/docs/cpp/library/atomic/memory_order).

{/* source:cpp-atomic-atomic-ref:0003 */}
The lifetime of an object must exceed the lifetime of all `std::atomic_refs` that references the object. While any `std::atomic_ref` instance referencing an object exists, the object must be exclusively accessed through these `std::atomic_ref` instances. No subobject of an object referenced by an `std::atomic_ref` object may be concurrently referenced by any other `std::atomic_ref` object.

{/* source:cpp-atomic-atomic-ref:0004 */}
Atomic operations applied to an object through an `std::atomic_ref` are atomic with respect to atomic operations applied through any other `std::atomic_ref` referencing the same object.

{/* source:cpp-atomic-atomic-ref:0005 */}
Like [references](/docs/cpp/language/declarations/reference) in the core language, constness is shallow for `std::atomic_ref` - it is possible to modify the referenced value through a `const std::atomic_ref` object.

{/* source:cpp-atomic-atomic-ref:0006 */}
If any of the following conditions are satisfied, the program is ill-formed:

{/* source:cpp-atomic-atomic-ref:0007 */}
- `std::is_trivially_copyable_v<T>` is `false`.
- [`is_always_lock_free`](/docs/cpp/library/atomic/atomic_ref/is_always_lock_free) is `false` and `std::is_volatile_v<T>` is `true`.

{/* source:cpp-atomic-atomic-ref:0008 */}
`std::atomic_ref` is [`CopyConstructible`](/docs/cpp/library/named_req/CopyConstructible).

### Specializations

{/* source:cpp-atomic-atomic-ref:0012 */}
The standard specifies that `std::atomic_ref` has following specializations:

{/* source:cpp-atomic-atomic-ref:0013 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" since="C++20" code={`template<>
struct atomic_ref</*integral-type*/>;`} />
  <Declaration id="2" language="cpp" since="C++20" code={`template<>
struct atomic_ref</*floating-point-type*/>;`} />
  <Declaration id="3" language="cpp" since="C++20" code={`template< class /*pointer-type*/ >
    requires /* see below */

struct atomic_ref</*pointer-type*/>;`} />

  <DeclarationDescription>
    {/* source:cpp-atomic-atomic-ref:0014 */}
    1) `/*integral-type*/` denotes a possibly cv-qualified integral type other than `cv bool`.

    {/* source:cpp-atomic-atomic-ref:0015 */}
    2) `/*floating-point-type*/` denotes a possibly cv-qualified floating-point type.

    {/* source:cpp-atomic-atomic-ref:0016 */}
    3) The partial specialization is provided for `/*pointer-type*/` types that are possibly cv-qualified pointer-to-object types.
  </DeclarationDescription>
</DeclarationDoc>

### Notes

{/* source:cpp-atomic-atomic-ref:0017 */}
Implementations may merge the specified specializations. E.g. MSVC STL merges all of them into the primary template.

{/* source:cpp-atomic-atomic-ref:0018 */}
When `T` is *cv* `void` or a function type, `std::atomic_ref<T*>` (i.e. `std::atomic_ref<void*>`, `std::atomic_ref<int(*)()>` etc.) does not have `difference_type` or any operation requiring pointer arithmetic<InlineRevision since="C++26"> or relational comparison</InlineRevision>.
