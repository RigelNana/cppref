  <DeclarationDescription>
    {/* source:cpp-atomic-atomic-flag-wait:0001 */}
    Performs atomic waiting operations.

    {/* source:cpp-atomic-atomic-flag-wait:0002 */}
    Compares `object->test(std::memory_order_seq_cst)` or `object->test(order)` with `old`, and if they are equal then blocks until `*object` is notified by [`std::atomic_flag::notify_one()`](/docs/cpp/library/atomic/atomic_flag/notify_one) or [`std::atomic_flag::notify_all()`](/docs/cpp/library/atomic/atomic_flag/notify_all) (or the thread is unblocked spuriously). This is repeated until the values compare unequal.

    {/* source:cpp-atomic-atomic-flag-wait:0003 */}
    1,2) The memory synchronization order is `std::memory_order_seq_cst`.

    {/* source:cpp-atomic-atomic-flag-wait:0004 */}
    3,4) The memory synchronization order is `order`.

    {/* source:cpp-atomic-atomic-flag-wait:0005 */}
    If `order` is one of `std::memory_order_release` and `std::memory_order_acq_rel`, the behavior is undefined.

    {/* source:cpp-atomic-atomic-flag-wait:0006 */}
    These functions are guaranteed to return only if value has changed, even if underlying implementation unblocks spuriously.
  </DeclarationDescription>
</DeclarationDoc>

### Parameters

{/* source:cpp-atomic-atomic-flag-wait:0007 */}
<ParameterList>
  <Parameter name="object">pointer to the atomic flag to check and wait on</Parameter>
  <Parameter name="old">the value to check the atomic flag no longer contains</Parameter>
  <Parameter name="order">the memory synchronization ordering</Parameter>
</ParameterList>

### Return value

{/* source:cpp-atomic-atomic-flag-wait:0008 */}
(none)

### Notes

{/* source:cpp-atomic-atomic-flag-wait:0009 */}
This form of change-detection is often more efficient than simple polling or pure spinlocks.

{/* source:cpp-atomic-atomic-flag-wait:0010 */}
Due to the [ABA problem](https://en.wikipedia.org/wiki/ABA_problem), transient changes from `old` to another value and back to `old` might be missed, and not unblock.
