{/* source:cpp-atomic-atomic-operator-arith2:0001 */}
Atomically replaces the current value with the result of computation involving the previous value and `arg`. The operation is read-modify-write operation.

{/* source:cpp-atomic-atomic-operator-arith2:0002 */}
- `operator+=` performs atomic addition. Equivalent to `return fetch_add(arg) + arg;`.
- `operator-=` performs atomic subtraction. Equivalent to `return fetch_sub(arg) - arg;`.

{/* source:cpp-atomic-atomic-operator-arith2:0003 */}
1-4) For signed integral types, arithmetic is defined to use two's complement representation. There are no undefined results.

<Revision since="C++20">
For floating-point types, the [floating-point environment](/docs/cpp/library/numeric/fenv) in effect may be different from the calling thread's floating-point environment. The operation need not be conform to the corresponding [`std::numeric_limits`](/docs/cpp/library/utility/types/numeric_limits) traits but is encouraged to do so. If the result is not a representable value for its type, the result is unspecified but the operation otherwise has no undefined behavior.
</Revision>

{/* source:cpp-atomic-atomic-operator-arith2:0004 */}
5-8) The result may be an undefined address, but the operations otherwise have no undefined behavior.

{/* source:cpp-atomic-atomic-operator-arith2:0005 */}
If `T` is not a complete object type, the program is ill-formed.

{/* source:cpp-atomic-atomic-operator-arith2:0006 */}
<Revision since="C++20">
It is deprecated if `std::atomic<T>::is_always_lock_free` is `false` and any volatile overload participates in overload resolution.
</Revision>

### Return value

{/* source:cpp-atomic-atomic-operator-arith2:0008 */}
The resulting value (that is, the result of applying the corresponding binary operator to the value immediately preceding the effects of the corresponding member function in the [modification order](/docs/cpp/library/atomic/memory_order#Modification_order) of `*this`).

### Notes

{/* source:cpp-atomic-atomic-operator-arith2:0009 */}
Unlike most compound assignment operators, the compound assignment operators for atomic types do not return a reference to their left-hand arguments. They return a copy of the stored value instead.
