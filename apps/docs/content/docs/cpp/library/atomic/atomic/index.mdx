{/* source:cpp-atomic-atomic:0001 */}
Each instantiation and full specialization of the `std::atomic` template defines an atomic type. If one thread writes to an atomic object while another thread reads from it, the behavior is well-defined (see [memory model](/docs/cpp/language/basic_concepts/memory_model) for details on data races).

{/* source:cpp-atomic-atomic:0002 */}
In addition, accesses to atomic objects may establish inter-thread synchronization and order non-atomic memory accesses as specified by [`std::memory_order`](/docs/cpp/library/atomic/memory_order).

{/* source:cpp-atomic-atomic:0003 */}
`std::atomic` is neither copyable nor movable.

{/* source:cpp-atomic-atomic:0004 */}
<Revision since="C++23">
The compatibility macro `_Atomic` is provided in [`<stdatomic.h>`](/docs/cpp/library/headers/stdatomic.h) such that `_Atomic(T)` is identical to `std::atomic<T>` while both are well-formed.

It is unspecified whether any declaration in namespace `std` is available when [`<stdatomic.h>`](/docs/cpp/library/headers/stdatomic.h) is included.
</Revision>

### Specializations

#### Primary template

{/* source:cpp-atomic-atomic:0005 */}
The primary `std::atomic` template may be instantiated with any [`TriviallyCopyable`](/docs/cpp/library/named_req/TriviallyCopyable) type `T` satisfying both [`CopyConstructible`](/docs/cpp/library/named_req/CopyConstructible) and [`CopyAssignable`](/docs/cpp/library/named_req/CopyAssignable). The program is ill-formed if any of following values is `false`:

{/* source:cpp-atomic-atomic:0006 */}
- `std::is_trivially_copyable<T>::value`
- `std::is_copy_constructible<T>::value`
- `std::is_move_constructible<T>::value`
- `std::is_copy_assignable<T>::value`
- `std::is_move_assignable<T>::value`
- `std::is_same<T, typename std::remove_cv<T>::type>::value`

{/* source:cpp-atomic-atomic:0007 */}
```cpp
struct Counters { int a; int b; }; // user-defined trivially-copyable type
std::atomic<Counters> cnt;         // specialization for the user-defined type
```

{/* source:cpp-atomic-atomic:0008 */}
`std::atomic<bool>` uses the primary template. It is guaranteed to be a [standard layout struct](/docs/cpp/language/classes#Standard-layout_class) and has a [trivial destructor](/docs/cpp/language/classes/destructor#Trivial_destructor).

#### Partial specializations

{/* source:cpp-atomic-atomic:0009 */}
The standard library provides partial specializations of the `std::atomic` template for the following types with additional properties that the primary template does not have:

{/* source:cpp-atomic-atomic:0010 */}
2) Partial specializations `std::atomic<U*>` for all pointer types. These specializations have standard layout<InlineRevision until="C++20">, trivial default constructors,</InlineRevision> and trivial destructors. Besides the operations provided for all atomic types, these specializations additionally support atomic arithmetic operations appropriate to pointer types, such as [`fetch_add`](/docs/cpp/library/atomic/atomic/fetch_add), [`fetch_sub`](/docs/cpp/library/atomic/atomic/fetch_sub).

{/* source:cpp-atomic-atomic:0011 */}
<Revision since="C++20">
3,4) Partial specializations `std::atomic<std::shared_ptr<U>>` and `std::atomic<std::weak_ptr<U>>` are provided for [`std::shared_ptr`](/docs/cpp/library/memory/shared_ptr) and [`std::weak_ptr`](/docs/cpp/library/memory/weak_ptr). See [`std::atomic<std::shared_ptr>`](/docs/cpp/library/memory/shared_ptr/atomic2) and [`std::atomic<std::weak_ptr>`](/docs/cpp/library/memory/weak_ptr/atomic2) for details.
</Revision>

#### Specializations for integral types

{/* source:cpp-atomic-atomic:0012 */}
When instantiated with one of the following integral types, `std::atomic` provides additional atomic operations appropriate to integral types such as [`fetch_add`](/docs/cpp/library/atomic/atomic/fetch_add), [`fetch_sub`](/docs/cpp/library/atomic/atomic/fetch_sub), [`fetch_and`](/docs/cpp/library/atomic/atomic/fetch_and), [`fetch_or`](/docs/cpp/library/atomic/atomic/fetch_or), [`fetch_xor`](/docs/cpp/library/atomic/atomic/fetch_xor):

{/* source:cpp-atomic-atomic:0013 */}
- The character types `char`<InlineRevision since="C++20">, `char8_t`</InlineRevision>, `char16_t`, `char32_t`, and `wchar_t`;
- The standard signed integer types: `signed char`, `short`, `int`, `long`, and `long long`;
- The standard unsigned integer types: `unsigned char`, `unsigned short`, `unsigned int`, `unsigned long`, and `unsigned long long`;
- Any additional integral types needed by the typedefs in the header [`<cstdint>`](/docs/cpp/library/headers/cstdint).

{/* source:cpp-atomic-atomic:0014 */}
Additionally, the resulting `std::atomic<Integral>` specialization has standard layout<InlineRevision until="C++20">, a trivial default constructor,</InlineRevision> and a trivial destructor. Signed integer arithmetic is defined to use two's complement; there are no undefined results.

{/* source:cpp-atomic-atomic:0015 */}
<Revision since="C++20">
#### Specializations for floating-point types

When instantiated with one of the cv-unqualified floating-point types (`float`, `double`, `long double`<InlineRevision since="C++23"> and cv-unqualified [extended floating-point types](/docs/cpp/language/basic_concepts/types#Extended_floating-point_types)</InlineRevision>), `std::atomic` provides additional atomic operations appropriate to floating-point types such as [`fetch_add`](/docs/cpp/library/atomic/atomic/fetch_add), [`fetch_sub`](/docs/cpp/library/atomic/atomic/fetch_sub).

Additionally, the resulting `std::atomic<Floating>` specialization has standard layout and a trivial destructor.

No operations result in undefined behavior even if the result is not representable in the floating-point type. The [floating-point environment](/docs/cpp/library/numeric/fenv) in effect may be different from the calling thread's floating-point environment.
</Revision>

### Notes

{/* source:cpp-atomic-atomic:0023 */}
There are non-member function template equivalents for all member functions of `std::atomic`. Those non-member functions may be additionally overloaded for types that are not specializations of `std::atomic`, but are able to guarantee atomicity. The only such type in the standard library is `std::shared_ptr<U>`.

{/* source:cpp-atomic-atomic:0024 */}
`_Atomic` is a [keyword](/docs/c/language/keyword/_Atomic) and used to provide [atomic types](/docs/c/language/declarations/atomic) in C.

{/* source:cpp-atomic-atomic:0025 */}
Implementations are recommended to ensure that the representation of `_Atomic(T)` in C is same as that of `std::atomic<T>` in C++ for every possible type `T`. The mechanisms used to ensure atomicity and memory ordering should be compatible.

{/* source:cpp-atomic-atomic:0026 */}
On GCC and Clang, some of the functionality described here requires linking against `-latomic`.

### Example

{/* source:cpp-atomic-atomic:0028 */}
```cpp
#include <atomic>
#include <iostream>
#include <thread>
#include <vector>

std::atomic_int acnt;
int cnt;

void f()
{
    for (auto n{10000}; n; --n)
    {
        ++acnt;
        ++cnt;
        // Note: for this example, relaxed memory order is sufficient,
        // e.g. acnt.fetch_add(1, std::memory_order_relaxed);
    }
}

int main()
{
    {
        std::vector<std::jthread> pool;
        for (int n = 0; n < 10; ++n)
            pool.emplace_back(f);
    }

    std::cout << "The atomic counter is " << acnt << '\n'
              << "The non-atomic counter is " << cnt << '\n';
}
```

Possible output:

```text
The atomic counter is 100000
The non-atomic counter is 69696
```
