{/* source:cpp-atomic-atomic-is-lock-free:0001 */}
Checks whether the atomic operations on all objects of this type are lock-free.

### Parameters

{/* source:cpp-atomic-atomic-is-lock-free:0002 */}
(none)

### Return value

{/* source:cpp-atomic-atomic-is-lock-free:0003 */}
`true` if the atomic operations on the objects of this type are lock-free, `false` otherwise.

### Notes

{/* source:cpp-atomic-atomic-is-lock-free:0004 */}
All atomic types except for [`std::atomic_flag`](/docs/cpp/library/atomic/atomic_flag) may be implemented using mutexes or other locking operations, rather than using the lock-free atomic CPU instructions. Atomic types are also allowed to be sometimes lock-free, e.g. if only aligned memory accesses are naturally atomic on a given architecture, misaligned objects of the same type have to use locks.

{/* source:cpp-atomic-atomic-is-lock-free:0005 */}
The C++ standard recommends (but does not require) that lock-free atomic operations are also address-free, that is, suitable for communication between processes using shared memory.

### Example

{/* source:cpp-atomic-atomic-is-lock-free:0006 */}
```cpp
#include <atomic>
#include <iostream>
#include <utility>
 
struct A { int a[100]; };
struct B { int x, y; };
 
int main()
{
    std::cout << std::boolalpha
              << "std::atomic<A> is lock free? "
              << std::atomic<A>{}.is_lock_free() << '\n'
              << "std::atomic<B> is lock free? "
              << std::atomic<B>{}.is_lock_free() << '\n';
}
```

Possible output:

```text
std::atomic<A> is lock free? false
std::atomic<B> is lock free? true
```
