{/* source:cpp-atomic-atomic-flag-wait:0001 */}
Performs atomic waiting operations. Behaves as if it repeatedly performs the following steps:

{/* source:cpp-atomic-atomic-flag-wait:0002 */}
- Compare `this->test(order)` with that of `old`.
  - If those are equal, then blocks until `*this` is notified by `notify_one()` or `notify_all()`, or the thread is unblocked spuriously.
  - Otherwise, returns.

{/* source:cpp-atomic-atomic-flag-wait:0003 */}
These functions are guaranteed to return only if value has changed, even if underlying implementation unblocks spuriously.

{/* source:cpp-atomic-atomic-flag-wait:0004 */}
If `order` is not `std::memory_order_relaxed`, `std::memory_order_consume`, `std::memory_order_acquire` or `std::memory_order_seq_cst`, the behavior is undefined.

### Parameters

{/* source:cpp-atomic-atomic-flag-wait:0005 */}
<ParameterList>
  <Parameter name="old">the value to check the `atomic_flag`'s object no longer contains</Parameter>
  <Parameter name="order">memory order constraints to enforce</Parameter>
</ParameterList>

### Notes

{/* source:cpp-atomic-atomic-flag-wait:0006 */}
This form of change-detection is often more efficient than simple polling or pure spinlocks.

{/* source:cpp-atomic-atomic-flag-wait:0007 */}
Due to the [ABA problem](https://en.wikipedia.org/wiki/ABA_problem), transient changes from `old` to another value and back to `old` might be missed, and not unblock.
