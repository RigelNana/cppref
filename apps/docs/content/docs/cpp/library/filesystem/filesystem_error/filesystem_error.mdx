    Constructs a new `filesystem_error` object.

    {/* source:cpp-filesystem-filesystem-error-filesystem-error:0002 */}
    1-3. The error code is set to `ec` and optionally, the paths that were involved in the operation that resulted in the error, are set to `p1` and `p2`. [`what()`](/docs/cpp/library/filesystem/filesystem_error/what) after construction returns a string that contains `what_arg` (assuming that it does not contain an embedded null character ). If either or both path arguments are not provided, a null path is used instead.

    {/* source:cpp-filesystem-filesystem-error-filesystem-error:0003 */}
    4. Copy constructor. Initialize the contents with those of `other`. If `*this` and `other` both have dynamic type `std::filesystem_error::filesystem_error` then `std::strcmp(what(), other.what()) == 0`.

### Notes

{/* source:cpp-filesystem-filesystem-error-filesystem-error:0005 */}
Because copying `std::filesystem::filesystem_error` is not permitted to throw exceptions, the explanatory string is typically stored internally in a separately-allocated reference-counted storage. This is also why there is no constructor taking `std::string&&`: it would have to copy the content anyway.

{/* source:cpp-filesystem-filesystem-error-filesystem-error:0006 */}
Typical implementations also store path objects referenced by [`path1()`](/docs/cpp/library/filesystem/filesystem_error/path) and [`path2()`](/docs/cpp/library/filesystem/filesystem_error/path) in the reference-counted storage.
