{/* source:cpp-thread-shared-future-wait-until:0001 */}
`wait_until` waits for a result to become available. It blocks until specified `timeout_time` has been reached or the result becomes available, whichever comes first. The return value indicates why `wait_until` returned.

{/* source:cpp-thread-shared-future-wait-until:0002 */}
If the future is the result of a call to [`async`](/docs/cpp/library/thread/async) that used lazy evaluation, this function returns immediately without waiting.

{/* source:cpp-thread-shared-future-wait-until:0003 */}
The behavior is undefined if [`valid()`](/docs/cpp/library/thread/shared_future/valid) is `false` before the call to this function, or `Clock` does not meet the [`Clock`](/docs/cpp/library/named_req/Clock) requirements. <InlineRevision since="C++20">The programs is ill-formed if [`std::chrono::is_clock_v<Clock>`](/docs/cpp/library/chrono/is_clock) is `false`.</InlineRevision>

### Exceptions

{/* source:cpp-thread-shared-future-wait-until:0006 */}
Any exception thrown by `clock`, `time_point`, or `duration` during the execution (clocks, time points, and durations provided by the standard library never throw).

### Notes

{/* source:cpp-thread-shared-future-wait-until:0007 */}
The implementations are encouraged to detect the case when `valid() == false` before the call and throw a [`std::future_error`](/docs/cpp/library/thread/future_error) with an error condition of [`future_errc::no_state`](/docs/cpp/library/thread/future_errc).

{/* source:cpp-thread-shared-future-wait-until:0008 */}
The standard recommends that the clock tied to `timeout_time` be used to measure time; that clock is not required to be a monotonic clock. There are no guarantees regarding the behavior of this function if the clock is adjusted discontinuously, but the existing implementations convert `timeout_time` from `Clock` to [`std::chrono::system_clock`](/docs/cpp/library/chrono/system_clock) and delegate to POSIX [`pthread_cond_timedwait`](https://pubs.opengroup.org/onlinepubs/9699919799/functions/pthread_cond_timedwait.html) so that the wait honors adjustments to the system clock, but not to the user-provided `Clock`. In any case, the function also may wait for longer than until after `timeout_time` has been reached due to scheduling or resource contention delays.
