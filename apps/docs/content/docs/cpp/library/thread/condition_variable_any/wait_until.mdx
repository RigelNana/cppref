  <DeclarationDescription>
    {/* source:cpp-thread-condition-variable-any-wait-until:0001 */}
    `wait_until` causes the current thread to block until the condition variable is notified, the given duration has been elapsed, or a spurious wakeup occurs. `pred` can be optionally provided to detect spurious wakeup.

    {/* source:cpp-thread-condition-variable-any-wait-until:0002 */}
    1. 1) Atomically calls `lock.unlock()` and blocks on `*this`.

    {/* source:cpp-thread-condition-variable-any-wait-until:0003 */}
    2. The thread will be unblocked when [`notify_all()`](/docs/cpp/library/thread/condition_variable_any/notify_all) or [`notify_one()`](/docs/cpp/library/thread/condition_variable_any/notify_one) is executed, or `abs_time` is reached. It may also be unblocked spuriously.

    {/* source:cpp-thread-condition-variable-any-wait-until:0004 */}
    3. When unblocked, calls `lock.lock()` (possibly blocking on the lock), then returns.

    {/* source:cpp-thread-condition-variable-any-wait-until:0005 */}
    4. 2,3) Waiting for a specific condition to become `true`, can be used to ignore spurious awakenings.

    {/* source:cpp-thread-condition-variable-any-wait-until:0006 */}
    5. 2) Equivalent to

    ```cpp
    while (!pred())
        if (wait_until(lock, abs_time) == std::cv_status::timeout)
            return pred();
    return true;
    ```

    {/* source:cpp-thread-condition-variable-any-wait-until:0007 */}
    6. 3) Registers `*this` for the duration of this call, to be notified if a stop request is made on `stoken`'s associated stop-state; it is then equivalent to

    ```cpp
    while (!stoken.stop_requested())
    {
        if (pred())
            return true;
        if (wait_until(lock, abs_time) == std::cv_status::timeout)
            return pred();
    }
    return pred();
    ```
  </DeclarationDescription>
</DeclarationDoc>

{/* source:cpp-thread-condition-variable-any-wait-until:0008 */}
Right after `wait_until` returns, `lock` is locked by the calling thread. If this postcondition cannot be satisfied[^1], calls [`std::terminate`](/docs/cpp/library/error/terminate).

{/* source:cpp-thread-condition-variable-any-wait-until:0009 */}
[^1]: ↑ This can happen if the re-locking of the mutex throws an exception.

### Parameters

{/* source:cpp-thread-condition-variable-any-wait-until:0010 */}
<ParameterList>
  <Parameter name="lock">an lock which must be locked by the calling thread</Parameter>
  <Parameter name="stoken">a stop token to register interruption for</Parameter>
  <Parameter name="abs_time">the time point where waiting expires</Parameter>
  <Parameter name="pred">the predicate to check whether the waiting can be completed</Parameter>
</ParameterList>

Type requirements
- `Lock` must meet the requirements of [*BasicLockable*](/docs/cpp/library/named_req/BasicLockable).
- `Predicate` must meet the requirements of [*FunctionObject*](/docs/cpp/library/named_req/FunctionObject).
- `pred()` must be a valid expression, and its type and value category must meet the [*BooleanTestable*](/docs/cpp/library/named_req/BooleanTestable) requirements.

### Return value

{/* source:cpp-thread-condition-variable-any-wait-until:0011 */}
1. 1) `std::cv_status::timeout` if `abs_time` has been reached, otherwise `std::cv_status::no_timeout`.

{/* source:cpp-thread-condition-variable-any-wait-until:0012 */}
2. 2,3) The latest result of `pred()` before returning to the caller.

### Exceptions

{/* source:cpp-thread-condition-variable-any-wait-until:0013 */}
1. 1) Timeout-related exceptions.

{/* source:cpp-thread-condition-variable-any-wait-until:0014 */}
2. 2,3) Timeout-related exceptions, and any exception thrown by `pred`.

### Notes

{/* source:cpp-thread-condition-variable-any-wait-until:0015 */}
The standard recommends that the clock tied to `abs_time` be used to measure time; that clock is not required to be a monotonic clock. There are no guarantees regarding the behavior of this function if the clock is adjusted discontinuously, but the existing implementations convert `abs_time` from `Clock` to [`std::chrono::system_clock`](/docs/cpp/library/chrono/system_clock) and delegate to POSIX [pthread_cond_timedwait](https://pubs.opengroup.org/onlinepubs/9699919799/functions/pthread_cond_timedwait.html) so that the wait honors adjustments to the system clock, but not to the user-provided `Clock`. In any case, the function also may wait for longer than until after `abs_time` has been reached due to scheduling or resource contention delays.

{/* source:cpp-thread-condition-variable-any-wait-until:0016 */}
Even if the clock in use is [`std::chrono::steady_clock`](/docs/cpp/library/chrono/steady_clock) or another monotonic clock, a system clock adjustment may induce a spurious wakeup.

{/* source:cpp-thread-condition-variable-any-wait-until:0017 */}
The effects of `notify_one()`/`notify_all()` and each of the three atomic parts of `wait()`/`wait_for()`/`wait_until()` (unlock+wait, wakeup, and lock) take place in a single total order that can be viewed as [modification order](/docs/cpp/library/atomic/memory_order#Modification_order) of an atomic variable: the order is specific to this individual condition variable. This makes it impossible for `notify_one()` to, for example, be delayed and unblock a thread that started waiting just after the call to `notify_one()` was made.

### Example

{/* source:cpp-thread-condition-variable-any-wait-until:0018 */}
```cpp
#include <chrono>
#include <condition_variable>
#include <iostream>
#include <thread>
 
std::condition_variable_any cv;
std::mutex cv_m; // This mutex is used for three purposes:
                 // 1) to synchronize accesses to i
                 // 2) to synchronize accesses to std::cerr
                 // 3) for the condition variable cv
int i = 0;
 
void waits()
{
    std::unique_lock<std::mutex> lk(cv_m);
    std::cerr << "Waiting... \n";
    cv.wait(lk, []{ return i == 1; });
    std::cerr << "...finished waiting. i == 1\n";
}
 
void signals()
{
    std::this_thread::sleep_for(std::chrono::seconds(1));
    {
        std::lock_guard<std::mutex> lk(cv_m);
        std::cerr << "Notifying...\n";
    }
    cv.notify_all();
 
    std::this_thread::sleep_for(std::chrono::seconds(1));
 
    {
        std::lock_guard<std::mutex> lk(cv_m);
        i = 1;
        std::cerr << "Notifying again...\n";
    }
    cv.notify_all();
}
 
int main()
{
    std::thread t1(waits), t2(waits), t3(waits), t4(signals);
    t1.join(); 
    t2.join(); 
    t3.join();
    t4.join();
}
```

Possible output:

```text
Waiting...
Waiting...
Waiting...
Notifying...
Notifying again...
...finished waiting. i == 1
...finished waiting. i == 1
...finished waiting. i == 1
```
