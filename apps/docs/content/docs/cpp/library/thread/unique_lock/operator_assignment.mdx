{/* source:cpp-thread-unique-lock-operator:0001 */}
Move assignment operator. Replaces the contents with those of `other` using move semantics.

{/* source:cpp-thread-unique-lock-operator:0002 */}
If prior to the call `*this` has an associated mutex and has acquired ownership of it, the mutex is unlocked.

### Parameters

{/* source:cpp-thread-unique-lock-operator:0003 */}
<ParameterList>
  <Parameter name="other">another `unique_lock` to replace the state with</Parameter>
</ParameterList>

### Return value

{/* source:cpp-thread-unique-lock-operator:0004 */}
`*this`

### Exceptions

{/* source:cpp-thread-unique-lock-operator:0005 */}
Throws nothing.

### Notes

{/* source:cpp-thread-unique-lock-operator:0006 */}
With a recursive mutex it is possible for both `*this` and `other` to own the same mutex before the assignment. In this case, `*this` will own the mutex after the assignment and `other` will not.

### Defect reports

{/* source:cpp-thread-unique-lock-operator:0007 */}

{/* source:cpp-thread-unique-lock-operator:0009 */}
1. ↑ For example, `*this` is constructed with [`std::adopt_lock`](/docs/cpp/library/thread/lock_tag_t), but the calling thread does not have the ownership of the associated mutex. In this case, `*this` cannot properly release the ownership of the associated mutex, and it may result in an exception to be thrown.
