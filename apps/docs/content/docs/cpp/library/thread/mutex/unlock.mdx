{/* source:cpp-thread-mutex-unlock:0001 */}
Unlocks the mutex.

{/* source:cpp-thread-mutex-unlock:0002 */}
The mutex must be locked by the current thread of execution, otherwise, the behavior is undefined.

{/* source:cpp-thread-mutex-unlock:0003 */}
This operation *synchronizes-with* (as defined in [`std::memory_order`](/docs/cpp/library/atomic/memory_order)) any subsequent lock operation that obtains ownership of the same mutex.

### Parameters

{/* source:cpp-thread-mutex-unlock:0004 */}
(none)

### Return value

{/* source:cpp-thread-mutex-unlock:0005 */}
(none)

### Exceptions

{/* source:cpp-thread-mutex-unlock:0006 */}
Throws nothing.

### Notes

{/* source:cpp-thread-mutex-unlock:0007 */}
`unlock()` is usually not called directly: [`std::unique_lock`](/docs/cpp/library/thread/unique_lock) and [`std::lock_guard`](/docs/cpp/library/thread/lock_guard) are used to manage exclusive locking.

### Example

{/* source:cpp-thread-mutex-unlock:0008 */}
This example shows how `lock` and `unlock` can be used to protect shared data.

```cpp
#include <chrono>
#include <iostream>
#include <mutex>
#include <thread>
 
int g_num = 0; // protected by g_num_mutex
std::mutex g_num_mutex;
 
void slow_increment(int id) 
{
    for (int i = 0; i < 3; ++i)
    {
        g_num_mutex.lock();
        int g_num_running = ++g_num;
        g_num_mutex.unlock();
        std::cout << id << " => " << g_num_running << '\n';
 
        std::this_thread::sleep_for(std::chrono::seconds(1));
    }
}
 
int main()
{
    std::thread t1(slow_increment, 0);
    std::thread t2(slow_increment, 1);
    t1.join();
    t2.join();
}
```

Possible output:

```text
0 => 1
1 => 2
0 => 3
1 => 4
0 => 5
1 => 6
```
