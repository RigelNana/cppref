  <DeclarationDescription>
    {/* source:cpp-thread-async:0001 */}
    The function template `std::async` runs the function `f` asynchronously (potentially in a separate thread which might be a part of a thread pool) and returns a [`std::future`](/docs/cpp/library/thread/future) that will eventually hold the result of that function call.

    {/* source:cpp-thread-async:0002 */}
    1. Behaves as if (2) is called with `policy` being `std::launch::async | std::launch::deferred`.

    {/* source:cpp-thread-async:0003 */}
    2. Calls a function `f` with arguments `args` according to a specific launch policy `policy` (see [below](/docs/cpp/library/thread/async#Launch_policies)).
  </DeclarationDescription>
</DeclarationDoc>

{/* source:cpp-thread-async:0004 */}
The return type of `std::async` is `std::future<V>`, where `V` is:

{/* source:cpp-thread-async:0005 */}
<Revision until="C++17">
`typename std::result_of<typename std::decay<F>::type(`
`                typename std::decay<Args>::type...)>::type`.
</Revision>
<Revision since="C++17">
`std::invoke_result_t<std::decay_t<F>, std::decay_t<Args>...>`.
</Revision>

{/* source:cpp-thread-async:0006 */}
<Revision until="C++20">
If any of the following conditions is satisfied, the program is ill-formed:

- `F` is not [`MoveConstructible`](/docs/cpp/library/named_req/MoveConstructible).
- Any type in `Args` is not [`MoveConstructible`](/docs/cpp/library/named_req/MoveConstructible).
- [`INVOKE`](/docs/cpp/library/utility/functional)([`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<F>(f)`), [`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<Args>(args)`...) is not a valid expression.
</Revision>
<Revision since="C++20">
If any of the following is `false`, the program is ill-formed:

- `std::is_constructible_v<std::decay_t<F>, F>`
- (`std::is_constructible_v<std::decay_t<Args>, Args> && ...`)
- `std::is_invocable_v<std::decay_t<F>, std::decay_t<Args>...>`
</Revision>

{/* source:cpp-thread-async:0007 */}
The call to `std::async` [synchronizes with](/docs/cpp/library/atomic/memory_order) the call to `f`, and the completion of `f` is [sequenced before](/docs/cpp/language/expressions/eval_order) making the shared state ready.

### Parameters

{/* source:cpp-thread-async:0008 */}
<ParameterList>
  <Parameter name="f">[`Callable`](/docs/cpp/library/named_req/Callable) object to call</Parameter>
  <Parameter name="args">parameters to pass to `f`</Parameter>
  <Parameter name="policy">bitmask value, where individual bits control the allowed methods of execution</Parameter>
</ParameterList>

### Return value

{/* source:cpp-thread-async:0009 */}
[`std::future`](/docs/cpp/library/thread/future) referring to the shared state created by this call to `std::async`.

### Launch policies

#### Async invocation

{/* source:cpp-thread-async:0010 */}
If the async flag is set, i.e. `(policy & std::launch::async) != 0`, then `std::async` calls

{/* source:cpp-thread-async:0011 */}
<Revision until="C++23">
[`INVOKE`](/docs/cpp/library/utility/functional)([`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<F>(f)`), [`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<Args>(args)`...)
</Revision>
<Revision since="C++23">
`std::invoke(auto(std::forward<F>(f)),`
`                auto(std::forward<Args>(args))...)`
</Revision>

{/* source:cpp-thread-async:0012 */}
as if in a new thread of execution represented by a [`std::thread`](/docs/cpp/library/thread/thread) object.

{/* source:cpp-thread-async:0013 */}
<Revision until="C++23">
The calls of [`decay-copy`](/docs/cpp/library/standard_library/decay-copy) are evaluated in the current thread.
</Revision>
<Revision since="C++23">
The values produced by `auto` are [materialized](/docs/cpp/language/expressions/implicit_cast#Temporary_materialization) in the current thread.
</Revision>

{/* source:cpp-thread-async:0014 */}
If the function `f` returns a value or throws an exception, it is stored in the shared state accessible through the `std::future` that `std::async` returns to the caller.

#### Deferred invocation

{/* source:cpp-thread-async:0015 */}
If the deferred flag is set (i.e. `(policy & std::launch::deferred) != 0`), then `std::async` stores

{/* source:cpp-thread-async:0016 */}
<Revision until="C++23">
[`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<F>(f)`) and [`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<Args>(args)`...) in the shared state.
</Revision>
<Revision since="C++23">
`auto(std::forward<F>(f))` and `auto(std::forward<Args>(args))...` in the shared state.
</Revision>

{/* source:cpp-thread-async:0017 */}
Lazy evaluation is performed:

{/* source:cpp-thread-async:0018 */}
- The first call to a non-timed wait function on the `std::future` that `std::async` returned to the caller will evaluate [`INVOKE`](/docs/cpp/library/utility/functional)(`std::move(g), std::move(xyz)`) in the thread that called the waiting function (which does not have to be the thread that originally called `std::async`), where

{/* source:cpp-thread-async:0019 */}
<Revision until="C++23">
`g` is the stored value of [`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<F>(f)`) and `xyz` is the stored copy of [`decay-copy`](/docs/cpp/library/standard_library/decay-copy)(`std::forward<Args>(args)`...).
</Revision>
<Revision since="C++23">
`g` is the stored value of `auto(std::forward<F>(f))` and `xyz` is the stored copy of `auto(std::forward<Args>(args))...`.
</Revision>

{/* source:cpp-thread-async:0020 */}
- The result or exception is placed in the shared state associated with the returned `std::future` and only then it is made ready. All further accesses to the same `std::future` will return the result immediately.

#### Other policies

{/* source:cpp-thread-async:0021 */}
If neither [`std::launch::async`](/docs/cpp/library/thread/launch) nor [`std::launch::deferred`](/docs/cpp/library/thread/launch), nor any implementation-defined policy flag is set in `policy`, the behavior is undefined.

### Policy selection

{/* source:cpp-thread-async:0022 */}
If more than one flag is set, it is implementation-defined which policy is selected. For the default (both the [`std::launch::async`](/docs/cpp/library/thread/launch) and [`std::launch::deferred`](/docs/cpp/library/thread/launch) flags are set in `policy`), standard recommends (but does not require) utilizing available concurrency, and deferring any additional tasks.

{/* source:cpp-thread-async:0023 */}
If the [`std::launch::async`](/docs/cpp/library/thread/launch) policy is chosen,

{/* source:cpp-thread-async:0024 */}
- a call to a waiting function on an asynchronous return object that shares the shared state created by this `std::async` call blocks until the associated thread has completed, as if joined, or else time out; and the associated thread completion synchronizes-with the successful return from the first function that is waiting on the shared state, or with the return of the last function that releases the shared state, whichever comes first.

### Exceptions

{/* source:cpp-thread-async:0025 */}
Throws

{/* source:cpp-thread-async:0026 */}
- [`std::bad_alloc`](/docs/cpp/library/memory/new/bad_alloc), if the memory for the internal data structures cannot be allocated, or [`std::system_error`](/docs/cpp/library/error/system_error) with error condition [`std::errc::resource_unavailable_try_again`](/docs/cpp/library/error/errc), if `policy == std::launch::async` and the implementation is unable to start a new thread. If `policy` is `std::launch::async | std::launch::deferred` or has additional bits set, it will fall back to deferred invocation or the implementation-defined policies in this case.

### Notes

{/* source:cpp-thread-async:0027 */}
The implementation may extend the behavior of the first overload of `std::async` by enabling additional (implementation-defined) bits in the default launch policy.

{/* source:cpp-thread-async:0028 */}
Examples of implementation-defined launch policies are the sync policy (execute immediately, within the `std::async` call) and the task policy (similar to `std::async`, but thread-locals are not cleared)

{/* source:cpp-thread-async:0029 */}
If the `std::future` obtained from `std::async` is not moved from or bound to a reference, the destructor of the `std::future` will block at the end of the full expression until the asynchronous operation completes, essentially making code such as the following synchronous:

{/* source:cpp-thread-async:0030 */}
```cpp
std::async(std::launch::async, []{ f(); }); // temporary's dtor waits for f()
std::async(std::launch::async, []{ g(); }); // does not start until f() completes
```

{/* source:cpp-thread-async:0031 */}
Note that the destructors of `std::futures` obtained by means other than a call to `std::async` never block.

### Example

{/* source:cpp-thread-async:0032 */}
```cpp
#include <algorithm>
#include <future>
#include <iostream>
#include <mutex>
#include <numeric>
#include <string>
#include <vector>
 
std::mutex m;
 
struct X
{
    void foo(int i, const std::string& str)
    {
        std::lock_guard<std::mutex> lk(m);
        std::cout << str << ' ' << i << '\n';
    }
 
    void bar(const std::string& str)
    {
        std::lock_guard<std::mutex> lk(m);
        std::cout << str << '\n';
    }
 
    int operator()(int i)
    {
        std::lock_guard<std::mutex> lk(m);
        std::cout << i << '\n';
        return i + 10;
    }
};
 
template<typename RandomIt>
int parallel_sum(RandomIt beg, RandomIt end)
{
    auto len = end - beg;
    if (len < 1000)
        return std::accumulate(beg, end, 0);
 
    RandomIt mid = beg + len / 2;
    auto handle = std::async(std::launch::async,
                             parallel_sum<RandomIt>, mid, end);
    int sum = parallel_sum(beg, mid);
    return sum + handle.get();
}
 
int main()
{
    std::vector<int> v(10000, 1);
    std::cout << "The sum is " << parallel_sum(v.begin(), v.end()) << '\n';
 
    X x;
    // Calls (&x)->foo(42, "Hello") with default policy:
    // may print "Hello 42" concurrently or defer execution
    auto a1 = std::async(&X::foo, &x, 42, "Hello");
    // Calls x.bar("world!") with deferred policy
    // prints "world!" when a2.get() or a2.wait() is called
    auto a2 = std::async(std::launch::deferred, &X::bar, x, "world!");
    // Calls X()(43); with async policy
    // prints "43" concurrently
    auto a3 = std::async(std::launch::async, X(), 43);
    a2.wait();                     // prints "world!"
    std::cout << a3.get() << '\n'; // prints "53"
} // if a1 is not done at this point, destructor of a1 prints "Hello 42" here
```

Possible output:

```text
The sum is 10000
43
world!
53
Hello 42
```
