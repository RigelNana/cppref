## std::ranges::less::operator()

<DeclarationDoc>
  <Declaration language="cpp" code={`template< class T, class U >
constexpr bool operator()( T&& t, U&& u ) const;`} />
</DeclarationDoc>

Given the expression `std::forward<T>(t) < std::forward<U>(u)` as `expr`:

- If `expr` results in a call to [built-in](/docs/cpp/language/expressions/operator_comparison#Built-in_pointer_relational_comparison) `operator<` comparing pointers, given the [composite pointer type](/docs/cpp/language/declarations/pointer#Composite_pointer_type) of `t` and `u` as `P`:

  - If the converted `t` precedes the converted `u` (both are of type `P`) in the [implementation-defined strict total order over pointers](/docs/cpp/language/expressions/operator_comparison#Pointer_total_order), returns `true`, otherwise returns `false`.
  - If the conversion sequence from `T` to `P` or the conversion sequence from `U` to `P` is not [equality-preserving](/docs/cpp/library/concepts#Equality_preservation), the behavior is undefined.

- Otherwise:

  - Returns the result of `expr`.
  - If `std::totally_ordered_with<T, U>` is not modeled, the behavior is undefined.

This overload participates in overload resolution only if `std::totally_ordered_with<T, U>` is satisfied.

If there exists an expression `expr1` of type `T` and an expression `expr2` of `U`, such that the comparison results of `expr1` and `expr2` violate [strict total ordering](https://en.wikipedia.org/wiki/Total_order#Strict_and_non-strict_total_orders) (rules are defined below), the behavior is undefined.

The comparison results of `expr1` and `expr2` follow strict total ordering only if **exactly one** of the following expressions is `true`:

- `std::ranges::less{}(expr1, expr2)`
- `std::ranges::less{}(expr2, expr1)`
- `std::ranges::equal_to{}(expr1, expr2)`

### Notes

{/* source:cpp-utility-functional-ranges-less:0005 */}
Unlike [`std::less`](/docs/cpp/library/utility/functional/less), `std::ranges::less` requires all six comparison operators `<`, `<=`, `>`, `>=`, `==` and `!=` to be valid (via the [`totally_ordered_with`](/docs/cpp/library/concepts/totally_ordered) constraint).
