{/* source:cpp-utility-compare-compare-strong-order-fallback:0001 */}
Performs three-way comparison on [subexpressions](/docs/cpp/language/expressions#Full-expressions) `t` and `u` and produces a result of type [`std::strong_ordering`](/docs/cpp/library/utility/compare/strong_ordering), even if the operator `<=>` is unavailable.

{/* source:cpp-utility-compare-compare-strong-order-fallback:0002 */}
If `std::decay_t<T>` and `std::decay_t<U>` are the same type, `std::compare_strong_order_fallback(t, u)` is [expression-equivalent](/docs/cpp/language/expressions#Expression-equivalence) to:

{/* source:cpp-utility-compare-compare-strong-order-fallback:0003 */}
- `std::strong_order(t, u)`, if it is a well-formed expression;
- otherwise, `t == u ? std::strong_ordering::equal :`<br />
  `t < u  ? std::strong_ordering::less :`<br />
  `         std::strong_ordering::greater`

{/* source:cpp-utility-compare-compare-strong-order-fallback:0004 */}
if the expressions `t == u` and `t < u` are both well-formed and each of `decltype(t == u)` and `decltype(t < u)` models [*boolean-testable*](/docs/cpp/library/concepts/boolean-testable), except that `t` and `u` are evaluated only once.

{/* source:cpp-utility-compare-compare-strong-order-fallback:0005 */}
In all other cases, `std::compare_strong_order_fallback(t, u)` is ill-formed, which can result in [substitution failure](/docs/cpp/language/templates/sfinae) when it appears in the immediate context of a template instantiation.

### Customization point objects

{/* source:cpp-utility-compare-compare-strong-order-fallback:0006 */}
The name `std::compare_strong_order_fallback` denotes a *customization point object*, which is a const [function object](/docs/cpp/library/named_req/FunctionObject) of a [literal](/docs/cpp/library/named_req/LiteralType) [`semiregular`](/docs/cpp/library/concepts/semiregular) class type. For exposition purposes, the cv-unqualified version of its type is denoted as `__compare_strong_order_fallback_fn`.

{/* source:cpp-utility-compare-compare-strong-order-fallback:0007 */}
All instances of `__compare_strong_order_fallback_fn` are equal. The effects of invoking different instances of type `__compare_strong_order_fallback_fn` on the same arguments are equivalent, regardless of whether the expression denoting the instance is an lvalue or rvalue, and is const-qualified or not (however, a volatile-qualified instance is not required to be invocable). Thus, `std::compare_strong_order_fallback` can be copied freely and its copies can be used interchangeably.

{/* source:cpp-utility-compare-compare-strong-order-fallback:0008 */}
Given a set of types `Args...`, if `std::declval<Args>()...` meet the requirements for arguments to `std::compare_strong_order_fallback` above, `__compare_strong_order_fallback_fn` models

{/* source:cpp-utility-compare-compare-strong-order-fallback:0009 */}
- `std::invocable<__compare_strong_order_fallback_fn, Args...>`,
- `std::invocable<const __compare_strong_order_fallback_fn, Args...>`,
- `std::invocable<__compare_strong_order_fallback_fn&, Args...>`, and
- `std::invocable<const __compare_strong_order_fallback_fn&, Args...>`.

{/* source:cpp-utility-compare-compare-strong-order-fallback:0010 */}
Otherwise, no function call operator of `__compare_strong_order_fallback_fn` participates in overload resolution.
