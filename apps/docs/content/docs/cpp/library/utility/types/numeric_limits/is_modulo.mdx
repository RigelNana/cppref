{/* source:cpp-types-numeric-limits-is-modulo:0001 */}
The value of `std::numeric_limits<T>::is_modulo` is `true` for all arithmetic types `T` that handle overflows with modulo arithmetic, that is, if the result of addition, subtraction, multiplication, or division of this type would fall outside the range `[` [`min()`](/docs/cpp/library/utility/types/numeric_limits/min) `, ` [`max()`](/docs/cpp/library/utility/types/numeric_limits/max) `]`, the value returned by such operation differs from the expected value by a multiple of `max() - min() + 1`.

{/* source:cpp-types-numeric-limits-is-modulo:0002 */}
`is_modulo` is `false` for signed integer types, unless the implementation defines signed integer overflow to wrap.

### Notes

{/* source:cpp-types-numeric-limits-is-modulo:0004 */}
The standard said "On most machines, this is `true` for signed integers." before the resolution of [LWG issue 2422](https://cplusplus.github.io/LWG/issue2422). See [GCC PR 22200](http://gcc.gnu.org/bugzilla/show_bug.cgi?id=22200) for a related discussion.

### Example

{/* source:cpp-types-numeric-limits-is-modulo:0005 */}
Demonstrates the behavior of modulo types:

```cpp
#include <iostream>
#include <type_traits>
#include <limits>
 
template<class T>
typename std::enable_if<std::numeric_limits<T>::is_modulo>::type
    check_overflow()
{
    std::cout << "max value is " << std::numeric_limits<T>::max() << '\n'
              << "min value is " << std::numeric_limits<T>::min() << '\n'
              << "max value + 1 is " << std::numeric_limits<T>::max()+1 << '\n';
}
 
int main()
{
    check_overflow<int>();
    std::cout << '\n';
    check_overflow<unsigned long>();
//  check_overflow<float>(); // compile-time error, not a modulo type
}
```

Possible output:



```text
max value is 2147483647
min value is -2147483648
max value + 1 is -2147483648
 
max value is 18446744073709551615
min value is 0
max value + 1 is 0
```

### Defect reports

{/* source:cpp-types-numeric-limits-is-modulo:0006 */}
The following behavior-changing defect reports were applied retroactively to previously published C++ standards.

{/* source:cpp-types-numeric-limits-is-modulo:0007 */}
<DefectReportList>
  <DefectReport kind="lwg" id={612} standard="C++98">
    <PublishedBehavior>the definition of "handle overflows <br /> with modulo arithmetic" was poor[[1]](/docs/cpp/library/utility/types/numeric_limits/is_modulo#cite_note-1)</PublishedBehavior>
    <CorrectedBehavior>provided a <br /> better definition</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="lwg" id={2422} standard="C++98">
    <PublishedBehavior>`is_modulo` was required to be `true` for <br /> signed integer types on most machines</PublishedBehavior>
    <CorrectedBehavior>required to be `false` for signed integer types <br /> unless signed integer overflow is defined to wrap</CorrectedBehavior>
  </DefectReport>
</DefectReportList>

{/* source:cpp-types-numeric-limits-is-modulo:0008 */}
[↑](/docs/cpp/library/utility/types/numeric_limits/is_modulocite_ref-1) The definition is "adding two positive numbers can have a result that wraps around to a third number that is less". It has the following problems: It does not define the wrapped value. It does not state whether result is repeatable. It does not require that doing addition, subtraction and other operations on all values have defined behavior.
