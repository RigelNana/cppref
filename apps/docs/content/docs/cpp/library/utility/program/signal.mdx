{/* source:cpp-utility-program-signal:0001 */}
Changes handling of the signal `sig`. Depending on `handler`, the signal can be ignored, set to default, or handled by a user-defined function.

{/* source:cpp-utility-program-signal:0002 */}
When signal handler is set to a function and a signal occurs, it is implementation defined whether `std::signal(sig, SIG_DFL)` will be executed immediately before the start of signal handler. Also, the implementation can prevent some implementation-defined set of signals from occurring while the signal handler runs.

{/* source:cpp-utility-program-signal:0003 */}
For some of the signals, the implementation may call `std::signal(sig, SIG_IGN)` at the startup of the program. For the rest, the implementation must call `std::signal(sig, SIG_DFL)`.

{/* source:cpp-utility-program-signal:0004 */}
(Note: POSIX introduced [sigaction](https://pubs.opengroup.org/onlinepubs/9699919799/functions/sigaction.html) to standardize these implementation-defined behaviors)

### Parameters

{/* source:cpp-utility-program-signal:0005 */}
<ParameterList>
  <Parameter name="sig">
    the signal to set the signal handler to. It can be an implementation-defined value or one of the following values:

    <DescriptionList>
      <DescriptionItem>
        <DescriptionTerm>[`SIGABRT SIGFPE SIGILL SIGINT SIGSEGV SIGTERM`](/docs/cpp/library/utility/program/SIG_types)</DescriptionTerm>
        <DescriptionBody>defines signal types (macro constant)</DescriptionBody>
      </DescriptionItem>
    </DescriptionList>
  </Parameter>
  <Parameter name="handler">
    the signal handler. This must be one of the following:

    - [`SIG_DFL`](/docs/cpp/library/utility/program/SIG_strategies) macro. The signal handler is set to default signal handler.
    - [`SIG_IGN`](/docs/cpp/library/utility/program/SIG_strategies) macro. The signal is ignored.
    - A pointer to a function. The signature of the function must be equivalent to the following:

      ```cpp
      extern "C" void fun(int sig);
      ```
  </Parameter>
</ParameterList>

### Return value

{/* source:cpp-utility-program-signal:0006 */}
Previous signal handler on success or [`SIG_ERR`](/docs/cpp/library/utility/program/SIG_ERR) on failure (setting a signal handler can be disabled on some implementations).

### Signal handler

{/* source:cpp-utility-program-signal:0007 */}
The following limitations are imposed on the user-defined function that is installed as a signal handler.

{/* source:cpp-utility-program-signal:0008 */}
<Revision until="C++17">
If the signal handler is called NOT as a result of [`std::abort`](/docs/cpp/library/utility/program/abort) or [`std::raise`](/docs/cpp/library/utility/program/raise) (asynchronous signal), the behavior is undefined if

- the signal handler calls any function within the standard library, except

  - [`std::abort`](/docs/cpp/library/utility/program/abort)
  - [`std::_Exit`](/docs/cpp/library/utility/program/_Exit)
  - [`std::quick_exit`](/docs/cpp/library/utility/program/quick_exit)
  - `std::signal` with the first argument being the number of the signal currently handled (async handler can re-register itself, but not other signals).
- the signal handler refers to any object with static storage duration that is not <InlineRevision since="C++11">[`std::atomic`](/docs/cpp/library/atomic/atomic) or </InlineRevision>`volatile` [`std::sig_atomic_t`](/docs/cpp/library/utility/program/sig_atomic_t).
</Revision>
<Revision since="C++17">
A *plain lock-free atomic operation* is an invocation of a function `f` from [`<atomic>`](/docs/cpp/library/headers/atomic)<InlineRevision since="C++23"> or [`<stdatomic.h>`](/docs/cpp/library/headers/stdatomic.h)</InlineRevision>, such that:

- `f` is the function [`std::atomic_is_lock_free`](/docs/cpp/library/atomic/atomic_is_lock_free),
- `f` is the member function `is_lock_free` (e.g. [`std::atomic::is_lock_free()`](/docs/cpp/library/atomic/atomic/is_lock_free)),
- `f` is a non-static member function of [`std::atomic_flag`](/docs/cpp/library/atomic/atomic_flag),
- `f` is a non-member function, and the first parameter of `f` has type *cv* `std::atomic_flag*`,
- `f` is a non-static member function invoked on an object `obj`, such that `obj.is_lock_free()` yields `true`, or
- `f` is a non-member function, and for every pointer-to-atomic argument `arg` passed to `f`, `std::atomic_is_lock_free(arg)` yields `true`.

The behavior is undefined if any signal handler performs any of the following:

- call to any library function, except for plain lock-free atomic operations and the following *signal-safe* functions (note, in particular, dynamic allocation is not signal-safe):

  - `std::signal` with the first argument being the number of the signal currently handled (signal handler can re-register itself, but not other signals).
  - member functions of [`std::numeric_limits`](/docs/cpp/library/utility/types/numeric_limits)
  - [`std::_Exit`](/docs/cpp/library/utility/program/_Exit)
  - [`std::abort`](/docs/cpp/library/utility/program/abort)
  - [`std::quick_exit`](/docs/cpp/library/utility/program/quick_exit)
  - The member functions of [`std::initializer_list`](/docs/cpp/library/utility/initializer_list) and the `std::initializer_list` overloads of [`std::begin`](/docs/cpp/library/iterator/begin) and [`std::end`](/docs/cpp/library/iterator/end)
  - [`std::forward`](/docs/cpp/library/utility/forward), `std::move`, [`std::move_if_noexcept`](/docs/cpp/library/utility/move_if_noexcept)
  - All functions from [`<type_traits>`](/docs/cpp/library/headers/type_traits)
  - [`std::memcpy`](/docs/cpp/library/text/byte/memcpy) and [`std::memmove`](/docs/cpp/library/text/byte/memmove)
- access to an object with thread storage duration
- a [`dynamic_cast`](/docs/cpp/language/expressions/dynamic_cast) expression
- a [`throw`](/docs/cpp/language/exceptions/throw) expression
- entry to a [`try`](/docs/cpp/language/exceptions/try) block
- initialization of a static variable that performs [dynamic non-local initialization](/docs/cpp/language/initialization#Non-local_variables) (including delayed until first ODR-use)
- waits for completion of initialization of any variable with static storage duration due to another thread concurrently initializing it
</Revision>

{/* source:cpp-utility-program-signal:0009 */}
If the user defined function returns when handling [`SIGFPE`](/docs/cpp/library/utility/program/SIG_types), [`SIGILL`](/docs/cpp/library/utility/program/SIG_types), [`SIGSEGV`](/docs/cpp/library/utility/program/SIG_types) or any other implementation-defined signal specifying a computational exception, the behavior is undefined.

{/* source:cpp-utility-program-signal:0010 */}
If the signal handler is called as a result of [`std::abort`](/docs/cpp/library/utility/program/abort) or [`std::raise`](/docs/cpp/library/utility/program/raise) (synchronous signal), the behavior is undefined if the signal handler calls [`std::raise`](/docs/cpp/library/utility/program/raise).

{/* source:cpp-utility-program-signal:0011 */}
<Revision until="C++14">
On entry to the signal handler, the state of the [floating-point environment](/docs/cpp/library/numeric/fenv) and the values of all objects is unspecified, except for

- objects of type `volatile` [`std::sig_atomic_t`](/docs/cpp/library/utility/program/sig_atomic_t)

<Revision since="C++11">
- objects of lock-free [`std::atomic`](/docs/cpp/library/atomic/atomic) types
- side effects made visible through [`std::atomic_signal_fence`](/docs/cpp/library/atomic/atomic_signal_fence)

</Revision>

On return from a signal handler, the value of any object modified by the signal handler that is not `volatile` [`std::sig_atomic_t`](/docs/cpp/library/utility/program/sig_atomic_t) or lock-free [`std::atomic`](/docs/cpp/library/atomic/atomic) is indeterminate.
</Revision>
<Revision since="C++14">
A call to the function `signal()` [synchronizes-with](/docs/cpp/library/atomic/memory_order) any resulting invocation of the signal handler.

If a signal handler is executed as a result of a call to [`std::raise`](/docs/cpp/library/utility/program/raise) (synchronously), then the execution of the handler is *sequenced-after* the invocation of `std::raise` and *sequenced-before* the return from it and runs on the same thread as `std::raise`. Execution of the handlers for other signals is *unsequenced* with respect to the rest of the program and runs on an unspecified thread.

Two accesses to the same object of type `volatile` [`std::sig_atomic_t`](/docs/cpp/library/utility/program/sig_atomic_t) do not result in a data race if both occur in the same thread, even if one or more occurs in a signal handler. For each signal handler invocation, evaluations performed by the thread invoking a signal handler can be divided into two groups A and B, such that no evaluations in B *happen-before* evaluations in A, and the evaluations of such `volatile` [`std::sig_atomic_t`](/docs/cpp/library/utility/program/sig_atomic_t) objects take values as though all evaluations in A [happened-before](/docs/cpp/library/atomic/memory_order) the execution of the signal handler and the execution of the signal handler *happened-before* all evaluations in B.
</Revision>

### Notes

{/* source:cpp-utility-program-signal:0012 */}
POSIX requires that `signal` is thread-safe, and [specifies a list of async-signal-safe library functions](https://pubs.opengroup.org/onlinepubs/9699919799/functions/V2_chap02.html#tag_15_04) that may be called from any signal handler.

{/* source:cpp-utility-program-signal:0013 */}
Signal handlers are expected to have [C linkage](/docs/cpp/language/declarations/language_linkage) and, in general, only use the features from the common subset of C and C++. However, common implementations allow a function with C++ linkage to be used as a signal handler.

### Example

{/* source:cpp-utility-program-signal:0014 */}
```cpp
#include <csignal>
#include <iostream>
 
namespace
{
    volatile std::sig_atomic_t gSignalStatus;
}
 
void signal_handler(int signal)
{
    gSignalStatus = signal;
}
 
int main()
{
    // Install a signal handler
    std::signal(SIGINT, signal_handler);
 
    std::cout << "SignalValue: " << gSignalStatus << '\n';
    std::cout << "Sending signal: " << SIGINT << '\n';
    std::raise(SIGINT);
    std::cout << "SignalValue: " << gSignalStatus << '\n';
}
```

Possible output:

```text
SignalValue: 0
Sending signal: 2
SignalValue: 2
```
