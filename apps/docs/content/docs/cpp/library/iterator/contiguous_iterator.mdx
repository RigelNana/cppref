{/* source:cpp-iterator-contiguous-iterator:0001 */}
The `contiguous_iterator` concept refines [`random_access_iterator`](/docs/cpp/library/iterator/random_access_iterator) by providing a guarantee the denoted elements are stored contiguously in the memory.

### Iterator concept determination

{/* source:cpp-iterator-contiguous-iterator:0002 */}
Definition of this concept is specified via an exposition-only alias template `/*ITER_CONCEPT*/`.

{/* source:cpp-iterator-contiguous-iterator:0003 */}
In order to determine `/*ITER_CONCEPT*/<I>`, let `ITER_TRAITS<I>` denote `I` if the specialization `std::iterator_traits<I>` is generated from the primary template, or `std::iterator_traits<I>` otherwise:

{/* source:cpp-iterator-contiguous-iterator:0004 */}
- If `ITER_TRAITS<I>::iterator_concept` is valid and names a type, `/*ITER_CONCEPT*/<I>` denotes the type.
- Otherwise, if `ITER_TRAITS<I>::iterator_category` is valid and names a type, `/*ITER_CONCEPT*/<I>` denotes the type.
- Otherwise, if `std::iterator_traits<I>` is generated from the primary template, `/*ITER_CONCEPT*/<I>` denotes [`std::random_access_iterator_tag`](/docs/cpp/library/iterator/iterator_tags).
- Otherwise, `/*ITER_CONCEPT*/<I>` does not denote a type and results in a substitution failure.

### Semantic requirements

{/* source:cpp-iterator-contiguous-iterator:0005 */}
Let `a` and `b` be dereferenceable iterators and `c` be a non-dereferenceable iterator of type `I` such that `b` is reachable from `a` and `c` is reachable from `b`. The type `I` models `contiguous_iterator` only if all the concepts it subsumes are modeled and:

{/* source:cpp-iterator-contiguous-iterator:0006 */}
- `std::to_address(a) == std::addressof(*a)`,
- `std::to_address(b) == std::to_address(a) + std::iter_difference_t<I>(b - a)`, and
- `std::to_address(c) == std::to_address(a) + std::iter_difference_t<I>(c - a)`.

### Equality preservation

{/* source:cpp-iterator-contiguous-iterator:0007 */}
Expressions declared in [requires expressions](/docs/cpp/language/templates/requires) of the standard library concepts are required to be [equality-preserving](/docs/cpp/library/concepts#Equality_preservation) (except where stated otherwise).

### Implicit expression variations

{/* source:cpp-iterator-contiguous-iterator:0008 */}
A [requires expression](/docs/cpp/language/templates/requires) that uses an expression that is non-modifying for some constant lvalue operand also requires [implicit expression variations](/docs/cpp/library/concepts#Implicit_expression_variations).

### Notes

{/* source:cpp-iterator-contiguous-iterator:0009 */}
`contiguous_iterator` is modeled by every pointer type to complete object type.

{/* source:cpp-iterator-contiguous-iterator:0010 */}
Iterator types in the standard library that are required to satisfy the [*LegacyContiguousIterator*](/docs/cpp/library/named_req/ContiguousIterator) requirements in C++17 are also required to model `contiguous_iterator` in C++20.
