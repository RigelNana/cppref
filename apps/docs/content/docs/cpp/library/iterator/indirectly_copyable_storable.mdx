{/* source:cpp-iterator-indirectly-copyable-storable:0001 */}
The `indirectly_copyable_storable` concept specifies the relationship between an [`indirectly_readable`](/docs/cpp/library/iterator/indirectly_readable) type and an [`indirectly_writable`](/docs/cpp/library/iterator/indirectly_writable) type. In addition to [`indirectly_copyable`](/docs/cpp/library/iterator/indirectly_copyable), this concept specifies that the copy from the `indirectly_readable` type can be performed via an intermediate object.

### Semantic requirements

{/* source:cpp-iterator-indirectly-copyable-storable:0002 */}
`In` and `Out` model `std::indirectly_copyable_storable<In, Out>` only if given a dereferenceable value `i` of type `In`:

{/* source:cpp-iterator-indirectly-copyable-storable:0003 */}
- After the definition `std::iter_value_t<In> obj(*i);`, `obj` is equal to the value previously denoted by `*i`, and if `std::iter_reference_t<In>` is an rvalue reference type, `*i` is placed in a valid but unspecified state after the initialization of `obj`.

### Equality preservation

{/* source:cpp-iterator-indirectly-copyable-storable:0004 */}
Expressions declared in [requires expressions](/docs/cpp/language/templates/requires) of the standard library concepts are required to be [equality-preserving](/docs/cpp/library/concepts#Equality_preservation) (except where stated otherwise).
