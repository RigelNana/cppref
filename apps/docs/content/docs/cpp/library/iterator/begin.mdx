{/* source:cpp-iterator-begin:0001 */}
Returns an iterator to the beginning of the given range.

{/* source:cpp-iterator-begin:0002 */}
1,2) Returns `c.begin()`, which is typically an iterator to the beginning of the sequence represented by `c`.

{/* source:cpp-iterator-begin:0003 */}
1) If `C` is a standard [`Container`](/docs/cpp/library/named_req/Container), returns a `C::iterator` object.

{/* source:cpp-iterator-begin:0004 */}
2) If `C` is a standard `Container`, returns a `C::const_iterator` object.

{/* source:cpp-iterator-begin:0005 */}
3) Returns a pointer to the beginning of `array`.

{/* source:cpp-iterator-begin:0006 */}
4) Returns `std::begin(c)`, with `c` always treated as const-qualified.

{/* source:cpp-iterator-begin:0007 */}
If `C` is a standard `Container`, returns a `C::const_iterator` object.

{/* source:cpp-iterator-begin:0015 */}
Similar to the use of `swap` (described in [`Swappable`](/docs/cpp/library/named_req/Swappable)), typical use of the `begin` function in generic context is an equivalent of using `using std::begin; begin(arg);`, which allows both the [ADL](/docs/cpp/language/functions/adl)-selected overloads for user-defined types and the standard library function templates to appear in the same overload set.

{/* source:cpp-iterator-begin:0016 */}
```cpp
template<typename Container, typename Function>
void for_each(Container&& cont, Function f)
{
    using std::begin;
    auto it = begin(cont);
    using std::end;
    auto end_it = end(cont);
    while (it != end_it)
    {
        f(*it);
        ++it;
    }
}
```

{/* source:cpp-iterator-begin:0017 */}
<Revision since="C++20">
Overloads of `begin` found by [argument-dependent lookup](/docs/cpp/language/functions/adl) can be used to customize the behavior of [`std::ranges::begin`](/docs/cpp/library/ranges/begin), [`std::ranges::cbegin`](/docs/cpp/library/ranges/cbegin), and other customization pointer objects depending on [`std::ranges::begin`](/docs/cpp/library/ranges/begin).
</Revision>

### Notes

{/* source:cpp-iterator-begin:0018 */}
The non-array overloads exactly reflect the behavior of `C::begin`. Their effects may be surprising if the member function does not have a reasonable implementation.

{/* source:cpp-iterator-begin:0019 */}
`std::cbegin` is introduced for unification of member and non-member range accesses. See also [LWG issue 2128](https://cplusplus.github.io/LWG/issue2128).

{/* source:cpp-iterator-begin:0020 */}
If `C` is a shallow-const view, `std::cbegin` may return a mutable iterator. Such behavior is unexpected for some users. See also [P2276](https://wg21.link/P2276) and [P2278](https://wg21.link/P2278).

### Example

{/* source:cpp-iterator-begin:0021 */}
```cpp
#include <iostream>
#include <iterator>
#include <vector>
 
int main() 
{
    std::vector<int> v = {3, 1, 4};
    auto vi = std::begin(v);
    std::cout << std::showpos << *vi << '\n'; 
 
    int a[] = {-5, 10, 15};
    auto ai = std::begin(a);
    std::cout << *ai << '\n';
}
```

Output:

```text
+3
-5
```
