  </DeclarationDescription>

### Parameters

{/* source:cpp-iterator-next:0002 */}
<ParameterList>
  <Parameter name="it">an iterator</Parameter>
  <Parameter name="n">number of elements to advance</Parameter>
</ParameterList>

Type requirements

- `InputIt` must meet the requirements of [*LegacyInputIterator*](/docs/cpp/library/named_req/InputIterator).

### Return value

{/* source:cpp-iterator-next:0003 */}
An iterator of type `InputIt` that holds the `n`th successor (or `-n`th predecessor if `n` is negative) of iterator `it`.

### Complexity

{/* source:cpp-iterator-next:0004 */}
Linear.

{/* source:cpp-iterator-next:0005 */}
However, if `InputIt` additionally meets the requirements of [*LegacyRandomAccessIterator*](/docs/cpp/library/named_req/RandomAccessIterator), complexity is constant.

### Possible implementation

{/* source:cpp-iterator-next:0006 */}
```cpp
template<class InputIt>
constexpr // since C++17
InputIt next(InputIt it, typename std::iterator_traits<InputIt>::difference_type n = 1)
{
    std::advance(it, n);
    return it;
}
```

### Notes

{/* source:cpp-iterator-next:0007 */}
Although the expression `++c.begin()` often compiles, it is not guaranteed to do so: `c.begin()` is an rvalue expression, and there is no [*LegacyInputIterator*](/docs/cpp/library/named_req/InputIterator) requirement that specifies that increment of an rvalue is guaranteed to work. In particular, when iterators are implemented as pointers or its `operator++` is lvalue-ref-qualified, `++c.begin()` does not compile, while `std::next(c.begin())` does.

### Example

{/* source:cpp-iterator-next:0008 */}
```cpp
#include <iostream>
#include <iterator>
#include <vector>
 
int main()
{
    std::vector<int> v{4, 5, 6};
 
    auto it = v.begin();
    auto nx = std::next(it, 2);
    std::cout << *it << ' ' << *nx << '\n';
 
    it = v.end();
    nx = std::next(it, -2);
    std::cout << ' ' << *nx << '\n';
}
```

Output:

```text
4 6
 5
```
