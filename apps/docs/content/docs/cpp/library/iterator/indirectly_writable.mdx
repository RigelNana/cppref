{/* source:cpp-iterator-indirectly-writable:0001 */}
The concept `indirectly_writable<Out, T>` specifies the requirements for writing a value whose type and value category are encoded by `T` into an iterator `Out`'s referenced object.

### Semantic requirements

{/* source:cpp-iterator-indirectly-writable:0002 */}
Let `e` be an expression such that `decltype((e))` is `T`, and `o` be a dereferenceable object of type `Out`, then `indirectly_writable<Out, T>` is modeled only if:

{/* source:cpp-iterator-indirectly-writable:0003 */}
- If `std::indirectly_readable<Out>` is modeled and `std::iter_value_t<Out>` is the same type as `std::decay_t<T>`, then `*o` after any above assignment is equal to the value of `e` before the assignment.

{/* source:cpp-iterator-indirectly-writable:0004 */}
`o` is not required to be dereferenceable after evaluating any of the assignment expressions above. If `e` is an xvalue, the resulting state of the object it denotes is valid but unspecified.

### Equality preservation

{/* source:cpp-iterator-indirectly-writable:0005 */}
Expressions declared in [requires expressions](/docs/cpp/language/templates/requires) of the standard library concepts are required to be [equality-preserving](/docs/cpp/library/concepts#Equality_preservation) (except where stated otherwise).

### Notes

{/* source:cpp-iterator-indirectly-writable:0006 */}
The only valid use of `operator*` is on the left side of an assignment expression. Assignment through the same value of an indirectly writable type may happen only once.

{/* source:cpp-iterator-indirectly-writable:0007 */}
The required expressions with `const_cast` prevent [`indirectly_readable`](/docs/cpp/library/iterator/indirectly_readable) objects with prvalue reference types from satisfying the syntactic requirements of `indirectly_writable` by accident, while permitting proxy references to continue to work as long as their constness is shallow. See [Ranges TS issue 381](https://github.com/ericniebler/stl2/issues/381).
