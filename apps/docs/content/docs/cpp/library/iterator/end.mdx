{/* source:cpp-iterator-end:0001 */}
Returns an iterator to the end (i.e. the element after the last element) of the given range.

{/* source:cpp-iterator-end:0002 */}
1,2) Returns `c.end()`, which is typically an iterator one past the end of the sequence represented by `c`.

{/* source:cpp-iterator-end:0003 */}
1) If `C` is a standard [`Container`](/docs/cpp/library/named_req/Container), returns a `C::iterator` object.

{/* source:cpp-iterator-end:0004 */}
2) If `C` is a standard `Container`, returns a `C::const_iterator` object.

{/* source:cpp-iterator-end:0005 */}
3) Returns a pointer to the end of `array`.

{/* source:cpp-iterator-end:0006 */}
4) Returns `std::end(c)`, with `c` always treated as const-qualified.

{/* source:cpp-iterator-end:0007 */}
If `C` is a standard `Container`, returns a `C::const_iterator` object.

4) `c.end()`

{/* source:cpp-iterator-end:0015 */}
Similar to the use of `swap` (described in [`Swappable`](/docs/cpp/library/named_req/Swappable)), typical use of the `end` function in generic context is an equivalent of using `using std::end; end(arg);`, which lets both the [ADL](/docs/cpp/language/functions/adl)-selected overloads for user-defined types and the standard library function templates to appear in the same overload set.

{/* source:cpp-iterator-end:0016 */}
```cpp
template<typename Container, typename Function>
void for_each(Container&& cont, Function f)
{
    using std::begin;
    auto it = begin(cont);
    using std::end;
    auto end_it = end(cont);
 
    for (; it != end_it; ++it)
        f(*it);
}
```

{/* source:cpp-iterator-end:0017 */}
<Revision since="C++20">
Overloads of `end` found by [argument-dependent lookup](/docs/cpp/language/functions/adl) can be used to customize the behavior of [`std::ranges::end`](/docs/cpp/library/ranges/end), [`std::ranges::cend`](/docs/cpp/library/ranges/cend), and other customization pointer objects depending on [`std::ranges::end`](/docs/cpp/library/ranges/end).
</Revision>

### Notes

{/* source:cpp-iterator-end:0018 */}
The non-array overloads exactly reflect the behavior of `C::end()`. Their effects may be surprising if the member function does not have a reasonable implementation.

{/* source:cpp-iterator-end:0019 */}
`std::cend` is introduced for unification of member and non-member range accesses. See also [LWG issue 2128](https://cplusplus.github.io/LWG/issue2128).

{/* source:cpp-iterator-end:0020 */}
If `C` is a shallow-const view, `std::cend` may return a mutable iterator. Such behavior is unexpected for some users. See also [P2276](https://wg21.link/P2276) and [P2278](https://wg21.link/P2278).

### Example

{/* source:cpp-iterator-end:0021 */}
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
 
int main()
{
    std::vector<int> v = {3, 1, 4};
    if (std::find(std::begin(v), std::end(v), 5) != std::end(v))
        std::cout << "Found a 5 in vector v!\n";
 
    int w[] = {5, 10, 15};
    if (std::find(std::begin(w), std::end(w), 5) != std::end(w))
        std::cout << "Found a 5 in array w!\n";
}
```

Output:

```text
Found a 5 in array w!
```
