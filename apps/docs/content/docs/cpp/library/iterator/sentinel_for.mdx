{/* source:cpp-iterator-sentinel-for:0001 */}
The `sentinel_for` concept specifies the relationship between an [`input_or_output_iterator`](/docs/cpp/library/iterator/input_or_output_iterator) type and a [`semiregular`](/docs/cpp/library/concepts/semiregular) type whose values denote a range. The exposition-only concept *`__WeaklyEqualityComparableWith`* is described in [`equality_comparable`](/docs/cpp/library/concepts/equality_comparable).

### Semantic requirements

{/* source:cpp-iterator-sentinel-for:0002 */}
Let `s` and `i` be values of type `S` and `I`, respectively, such that `[i, s)` denotes a [range](/docs/cpp/library/iterator#Ranges). `sentinel_for<S, I>` is modeled only if:

{/* source:cpp-iterator-sentinel-for:0003 */}
- `i == s` is well-defined.
- If `bool(i != s)` then `i` is dereferenceable and `[++i, s)` denotes a range.
- `std::assignable_from<I&, S>` is either modeled or not satisfied.

{/* source:cpp-iterator-sentinel-for:0004 */}
The domain of `==` can change over time. Given an iterator `i` and sentinel `s` such that `[i, s)` denotes a range and `i != s`, `[i, s)` is not required to continue to denote a range after incrementing any iterator equal to `i` (and so `i == s` is no longer required to be well-defined after such an increment).

### Notes

{/* source:cpp-iterator-sentinel-for:0005 */}
A sentinel type and its corresponding iterator type are not required to model [`equality_comparable_with`](/docs/cpp/library/concepts/equality_comparable), because the sentinel type may not be comparable with itself, and they are not required to have a common reference type.

{/* source:cpp-iterator-sentinel-for:0006 */}
It has been permitted to use a sentinel type different from the iterator type in the [range-based for loop](/docs/cpp/language/statements/range-for) since C++17.
