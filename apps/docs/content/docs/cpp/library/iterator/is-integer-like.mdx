### Integer-class type

{/* source:cpp-iterator-is-integer-like:0003 */}
A type `T` is an *integer-class type* if it is in a set of implementation-defined types that behave as [integer types](/docs/cpp/language/basic_concepts/types#Integral_types) do, as defined [below](/docs/cpp/library/iterator/is-integer-like#Required_behaviors). An integer-class type is not necessarily a [class type](/docs/cpp/language/classes).

{/* source:cpp-iterator-is-integer-like:0004 */}
An integer-class type can represent 2N consecutive integers, where `N`, a positive integer, is called the *width* of the integer-class type.

{/* source:cpp-iterator-is-integer-like:0005 */}
An integer-class type is either signed or unsigned:

{/* source:cpp-iterator-is-integer-like:0006 */}
- A *signed integer class type* can represent all integers in [-2N-1, 2N-1-1], where `N` is greater than the width of every signed integral type.
- An *unsigned integer class type* can represent all integers in [0, 2N-1], where `N` is greater than the width of every unsigned integral type.

{/* source:cpp-iterator-is-integer-like:0007 */}
All integer-class types model [`regular`](/docs/cpp/library/concepts/regular) and [`three_way_comparable`](/docs/cpp/library/utility/compare/three_way_comparable)`<std::strong_ordering>`.

{/* source:cpp-iterator-is-integer-like:0008 */}
A [value-initialized](/docs/cpp/language/initialization/value_initialization) object of integer-class type has value `â0â`.

{/* source:cpp-iterator-is-integer-like:0009 */}
An expression `E` of integer-class type `T` is [contextually convertible](/docs/cpp/language/expressions/implicit_cast#Contextual_conversions) to `bool` as if by `bool(E != T(0))`.

### Integer-like type

{/* source:cpp-iterator-is-integer-like:0010 */}
A type other than (possibly cv-qualified) `bool` is integer-like if it models [`integral`](/docs/cpp/library/concepts/integral) or if it is an integer-class type.

{/* source:cpp-iterator-is-integer-like:0011 */}
- An integer-like type is signed-integer-like if it models [`signed_integral`](/docs/cpp/library/concepts/signed_integral) or if it is a signed-integer-class type.
- An integer-like type is unsigned-integer-like if it models [`unsigned_integral`](/docs/cpp/library/concepts/unsigned_integral) or if it is an unsigned-integer-class type.

### Required behaviors

{/* source:cpp-iterator-is-integer-like:0012 */}
Expressions of integer-class type are explicitly convertible to any integer-like type, and implicitly convertible to any integer-class type of equal or greater width and the same signedness. Expressions of integral type are both implicitly and explicitly convertible to any integer-class type. Conversions between integral and integer-class types and between two integer-class types do not exit via an exception. The result of such a conversion is the unique value of the destination type that is congruent to the source modulo 2N, where `N` is the width of the destination type.

{/* source:cpp-iterator-is-integer-like:0013 */}
Let `Int<T>` denote the following type:

{/* source:cpp-iterator-is-integer-like:0014 */}
- If `T` is an integer-class type, `Int<T>` is a unique hypothetical [extended integer type](/docs/cpp/language/basic_concepts/types#Extended_integer_types) of the same signedness with the same width as `T`.
- If `T` is an integral type, let `Int<T>` is the same type as `T`.

| `++a` | | | [expression-equivalent](/docs/cpp/language/expressions#Expression-equivalence) to `a += 1` |
| `--a` | | | expression-equivalent to `a -= 1` |
| `&a` | | | expression-equivalent to `std::addressof(a)` |
| `!a` | `!x` is well-formed | same as `!x` | |
| `+a` | `+x` is well-formed | same as `+x`, but has type `IC` | same as `+x` |
| `-a` | `-x` is well-formed | same as `-x`, but has type `IC` | same as `-x` |
| `~a` | `~x` is well-formed | same as `~x`, but has type `IC` | same as `~x` |
