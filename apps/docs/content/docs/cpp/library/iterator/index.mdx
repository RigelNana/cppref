{/* source:cpp-iterator:0000 */}
Iterators are a generalization of [`pointers`](/docs/cpp/language/declarations/pointer) that allow a C++ program to work with different data structures (for example, [`containers`](/docs/cpp/library/container)<InlineRevision since="C++20"> and [`ranges`](/docs/cpp/library/ranges)</InlineRevision>) in a uniform manner. The iterator library provides definitions for iterators, as well as iterator traits, adaptors, and utility functions.

{/* source:cpp-iterator:0001 */}
Since iterators are an abstraction of pointers, their semantics are a generalization of most of the semantics of pointers in C++. This ensures that every [`function template`](/docs/cpp/language/templates/function_template) that takes iterators works as well with regular pointers.

### Iterator categories

{/* source:cpp-iterator:0002 */}
There are <InlineRevision until="C++17">five</InlineRevision><InlineRevision since="C++17">six</InlineRevision> kinds of iterators: [*LegacyInputIterator*](/docs/cpp/library/named_req/InputIterator), [*LegacyOutputIterator*](/docs/cpp/library/named_req/OutputIterator), [*LegacyForwardIterator*](/docs/cpp/library/named_req/ForwardIterator), [*LegacyBidirectionalIterator*](/docs/cpp/library/named_req/BidirectionalIterator), [*LegacyRandomAccessIterator*](/docs/cpp/library/named_req/RandomAccessIterator)<InlineRevision since="C++17">, and [*LegacyContiguousIterator*](/docs/cpp/library/named_req/ContiguousIterator)</InlineRevision>. (See also [*LegacyIterator*](/docs/cpp/library/named_req/Iterator) for the most basic kind of iterator.)

{/* source:cpp-iterator:0003 */}
Instead of being defined by specific types, each category of iterator is defined by the operations that can be performed on it. This definition means that any type that supports the necessary operations can be used as an iterator -- for example, a pointer supports all of the operations required by [*LegacyRandomAccessIterator*](/docs/cpp/library/named_req/RandomAccessIterator), so a pointer can be used anywhere a [*LegacyRandomAccessIterator*](/docs/cpp/library/named_req/RandomAccessIterator) is expected.

{/* source:cpp-iterator:0004 */}
All of the iterator categories (except [*LegacyOutputIterator*](/docs/cpp/library/named_req/OutputIterator)) can be organized into a hierarchy, where more powerful iterator categories (e.g. [*LegacyRandomAccessIterator*](/docs/cpp/library/named_req/RandomAccessIterator)) support the operations of less powerful categories (e.g. [*LegacyInputIterator*](/docs/cpp/library/named_req/InputIterator)). If an iterator falls into one of these categories and also satisfies the requirements of [*LegacyOutputIterator*](/docs/cpp/library/named_req/OutputIterator), then it is called a mutable iterator and supports both input and output. Non-mutable iterators are called constant iterators.

{/* source:cpp-iterator:0005 */}
<Revision since="C++20">
Iterators are called *constexpr iterators* if all operations provided to meet iterator category requirements are [`constexpr functions`](/docs/cpp/language/declarations/constexpr#constexpr_function).
</Revision>

### Definitions

#### Types and writability

{/* source:cpp-iterator:0009 */}
An input iterator `i` supports the expression `*i`, resulting in a value of some [object type](/docs/cpp/language/basic_concepts/type-id) `T`, called the value type of the iterator.

{/* source:cpp-iterator:0010 */}
An output iterator `i` has a non-empty set of types that are <InlineRevision until="C++20">*writable*</InlineRevision><InlineRevision since="C++20">[`indirectly_writable`](/docs/cpp/library/iterator/indirectly_writable)</InlineRevision> to the iterator; for each such type `T`, the expression `*i = o` is valid where `o` is a value of type `T`.

{/* source:cpp-iterator:0011 */}
For every iterator type `X` <InlineRevision until="C++20">for which equality is defined</InlineRevision>, there is a corresponding signed <InlineRevision until="C++20">[`integer`](/docs/cpp/language/basic_concepts/types#Signed_and_unsigned_integer_types)</InlineRevision><InlineRevision since="C++20">[`integer-like`](/docs/cpp/library/iterator/is-integer-like)</InlineRevision> type called the *difference type* of the iterator.

#### Dereferenceability and validity

{/* source:cpp-iterator:0012 */}
Just as a regular pointer to an [array](/docs/cpp/language/declarations/array) guarantees that there is a pointer value pointing past the last element of the array, so for any iterator type there is an iterator value that points past the last element of a corresponding sequence. Such a value is called a past-the-end value.

{/* source:cpp-iterator:0013 */}
Values of an iterator `i` for which the expression `*i` is defined are called dereferenceable. The [standard library](/docs/cpp/library/standard_library) never assumes that past-the-end values are dereferenceable.

{/* source:cpp-iterator:0014 */}
Iterators can also have singular values that are not associated with any sequence. Results of most expressions are undefined for singular values; the only exceptions are

{/* source:cpp-iterator:0015 */}
- the assignment of a non-singular value to an iterator that holds a singular value,
- destroying an iterator that holds a singular value, and,
- for iterators that meet the [*DefaultConstructible*](/docs/cpp/library/named_req/DefaultConstructible) requirements, using a [value-initialized](/docs/cpp/language/initialization/value_initialization) iterator as the source of a copy <InlineRevision since="C++11">or move</InlineRevision> operation.

{/* source:cpp-iterator:0016 */}
In these cases the singular value is overwritten the same way as any other value. Dereferenceable values are always non-singular.

{/* source:cpp-iterator:0017 */}
An invalid iterator is an iterator that may be singular.

#### Ranges

{/* source:cpp-iterator:0018 */}
Most of the standard library's algorithmic templates that operate on data structures have interfaces that use ranges.

{/* source:cpp-iterator:0019 */}
<Revision until="C++20">
An iterator `j` is called *reachable* from an iterator `i` if and only if there is a finite sequence of applications of the expression `++i` that makes `i == j`. If `j` is reachable from `i`, they refer to elements of the same sequence.

A *range* is a pair of iterators that designate the beginning and end of the computation. A range `[i, i)` is an empty range; in general, a range `[i, j)` refers to the elements in the data structure starting with the element pointed to by `i` and up to but not including the element pointed to by `j`.

Range `[i, j)` is *valid* if and only if `j` is reachable from `i`.
</Revision>
<Revision since="C++20">

    A *range* can be denoted by either

    - `[i, s)`, with an iterator `i` and a *sentinel* `s` that designate the beginning and end of the computation (`i` and `s` can have different types), or
    - `i + [0, n)`, with an iterator `i` and a count `n` that designate the beginning and the number of elements to which the computation is to be applied.

    ##### Iterator-sentinel range

    An iterator and a sentinel denoting a range are comparable. `[i, s)` is empty if `i == s`; otherwise, `[i, s)` refers to the elements in the data structure starting with the element pointed to by `i` and up to but not including the element, if any, pointed to by the first iterator `j` such that `j == s`.

    A sentinel `s` is called *reachable* from an iterator `i` if and only if there is a finite sequence of applications of the expression `++i` that makes `i == s`.

    If `s` is reachable from `i`, `[i, s)` denotes a *valid* range.

    ##### Counted range

    A *counted range* `i + [0, n)` is empty if `n == 0`; otherwise, `i + [0, n)` refers to the n elements in the data structure starting with the element pointed to by `i` and up to but not including the element, if any, pointed to by the result of `n` applications of `++i`.

    A counted range `i + [0, n)` is *valid* if and only if

    - `n == 0`; or
    - all of the following conditions are satisfied:
      - `n` is positive,
      - `i` is dereferenceable, and
      - `++i + [0, --n)` is valid.

</Revision>

{/* source:cpp-iterator:0020 */}
The result of the application of functions in the standard library to invalid ranges is undefined.
