## std::ios_base::failure::failure

<DeclarationDoc>
  <Declaration id="1" language="cpp" until="C++11" code={`explicit failure( const std::string& message );`} />
  <Declaration id="1" language="cpp" since="C++11" code={`explicit failure( const std::string& message,
          const std::error_code& ec = std::io_errc::stream );`} />
  <Declaration id="2" language="cpp" since="C++11" code={`explicit failure( const char* message,
          const std::error_code& ec = std::io_errc::stream );`} />
  <Declaration id="3" language="cpp" until="C++11" code={`failure( const failure& other );`} />
  <Declaration id="3" language="cpp" since="C++11" code={`failure( const failure& other ) noexcept;`} />

1,2. Constructs the exception object using `message` as explanation string which can later be retrieved using [`what()`](/docs/cpp/library/error/exception/what). <InlineRevision since="C++11">`ec` is used to identify the specific reason for the failure.</InlineRevision>

3. Copy constructor. Initialize the contents with those of `other`. <InlineRevision since="C++11">If `*this` and `other` both have dynamic type `std::ios_base::failure` then `std::strcmp(what(), other.what()) == 0`.</InlineRevision>

### Parameters

<ParameterList>
  <Parameter name="message">explanatory string</Parameter>
  <Parameter name="ec">error code to identify the specific reason for the failure</Parameter>
  <Parameter name="other">another `failure` to copy</Parameter>
</ParameterList>

### Notes

Because copying `std::ios_base::failure` is not permitted to throw exceptions, this message is typically stored internally as a separately-allocated reference-counted string. This is also why there is no constructor taking `std::string&&`: it would have to copy the content anyway.

## std::ios_base::failure::what

<DeclarationDoc>
  <Declaration language="cpp" until="C++11" code={`virtual const char* what() const throw();`} />
  <Declaration language="cpp" since="C++11" code={`virtual const char* what() const noexcept;`} />
</DeclarationDoc>

Returns the explanatory string.

### Return value

Pointer to an implementation-defined null-terminated string with explanatory information. The string is suitable for conversion and display as a [`std::wstring`](/docs/cpp/library/string/basic_string). The pointer is guaranteed to be valid at least until the exception object from which it is obtained is destroyed, or until a non-const member function (e.g. copy assignment operator) on the exception object is called.

<Revision since="C++26">
The returned string is encoded with the ordinary literal encoding during constant evaluation.
</Revision>

### Notes

Implementations are allowed but not required to override `what()`.

### Notes

{/* source:cpp-io-ios-base-failure:0011 */}
Before the resolution of [LWG issue 331](https://cplusplus.github.io/LWG/issue331), `std::ios_base::failure` declared a destructor without `throw()`, where [`std::exception::~exception()`](/docs/cpp/library/error/exception/~exception) was declared with `throw()`[[1]](/docs/cpp/library/io/ios_base/failure#cite_note-1). This means the `std::ios_base::failure::~failure()` had a weaker exception specification. The resolution is to remove that declaration so that the non-throwing exception specification is kept.

{/* source:cpp-io-ios-base-failure:0012 */}
[LWG issue 363](https://cplusplus.github.io/LWG/issue363) targets the same defect and its resolution is to add `throw()` to the declaration of `std::ios_base::failure::~failure()`. That resolution was not applied due to the conflict between the two resolutions.

{/* source:cpp-io-ios-base-failure:0013 */}
1. ↑ The non-throwing exception specification is now applied [globally across the standard library](/docs/cpp/library/standard_library#Guarantees), so the destructors of standard library classes are not declared with `throw()` or `noexcept`.

### Example

{/* source:cpp-io-ios-base-failure:0014 */}
```cpp
#include <fstream>
#include <iostream>
 
int main()
{
    std::ifstream f("doesn't exist");
    try
    {
        f.exceptions(f.failbit);
    }
    catch (const std::ios_base::failure& e)
    {
        std::cout << "Caught an ios_base::failure.\n"
                  << "Explanatory string: " << e.what() << '\n'
                  << "Error code: " << e.code() << '\n';
    }
}
```

Possible output:

```text
Caught an ios_base::failure.
Explanatory string: ios_base::clear: unspecified iostream_category error
Error code: iostream:1
```
