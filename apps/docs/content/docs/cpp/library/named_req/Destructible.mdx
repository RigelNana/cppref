{/* source:cpp-named-req-destructible:0000 */}
Specifies that an instance of the type can be destructed.

### Requirements

{/* source:cpp-named-req-destructible:0001 */}
The type `T` satisfies *Destructible* if

{/* source:cpp-named-req-destructible:0002 */}
Given

{/* source:cpp-named-req-destructible:0003 */}
- `u`, an expression of type `T`.

{/* source:cpp-named-req-destructible:0004 */}
The following expressions must be valid and have their specified effects.

{/* source:cpp-named-req-destructible:0005 */}
| Expression | Post-conditions |
| --- | --- |
| `u.~T()` | All resources owned by `u` are reclaimed, no exceptions are thrown. |

### Notes

{/* source:cpp-named-req-destructible:0006 */}
Destructors are called implicitly at the end of [object lifetime](/docs/cpp/language/basic_concepts/lifetime) such as when leaving [scope](/docs/cpp/language/basic_concepts/scope) or by the [delete-expression](/docs/cpp/language/expressions/delete). Explicit destructor call as shown in the type requirement table is rare.

{/* source:cpp-named-req-destructible:0007 */}
Thanks to [pseudo destructor call](/docs/cpp/language/expressions/operator_member_access#Built-in_member_access_operators), all scalar types meet the requirement of *Destructible*, while array types and reference types do not. Note that [`std::is_destructible`](/docs/cpp/library/meta/is_destructible) allows arrays and reference types.
