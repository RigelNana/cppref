{/* source:cpp-named-req-moveinsertable:0000 */}
Specifies that an object of the type can be constructed into uninitialized storage from an rvalue of that type by a given allocator.

## Requirements

{/* source:cpp-named-req-moveinsertable:0001 */}
Given the following types, values and expressions:

{/* source:cpp-named-req-moveinsertable:0002 */}
<DescriptionList>
  <DescriptionItem>
    <DescriptionTerm>`T`</DescriptionTerm>
    <DescriptionBody>an object type</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>`A`</DescriptionTerm>
    <DescriptionBody>an allocator type</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>`X`</DescriptionTerm>
    <DescriptionBody>a container type satisfying all following conditions:<br />`X::value_type` is the same as `T`.<br />`X::allocator_type` is the same as `std::allocator_traits<A>::rebind_alloc<T>`.</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>`m`</DescriptionTerm>
    <DescriptionBody>an lvalue of type `A`</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>`p`</DescriptionTerm>
    <DescriptionBody>a pointer of type `T*`</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>`rv`</DescriptionTerm>
    <DescriptionBody>an expression denoting an rvalue of type `T`</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>`expr`</DescriptionTerm>
    <DescriptionBody>`std::allocator_traits<A>::construct(m, p, rv)`</DescriptionBody>
  </DescriptionItem>
</DescriptionList>

{/* source:cpp-named-req-moveinsertable:0003 */}
T is MoveInsertable into X if all following conditions are satisfied:

{/* source:cpp-named-req-moveinsertable:0004 */}
- `expr` is well-formed.
- Right after the evaluation of `expr`, the value of `*p` is equivalent to the value of `rv` before the evaluation.

## Notes

{/* source:cpp-named-req-moveinsertable:0005 */}
If `A` is `std::allocator<T>`, then this will call placement `new`, as by <InlineRevision until="C++20">`::new((void*)p) T(rv)`</InlineRevision> <InlineRevision since="C++20">`std::construct_at(p, rv)`</InlineRevision>. This effectively requires T to be move constructible.

{/* source:cpp-named-req-moveinsertable:0006 */}
If `std::allocator<T>` or a similar allocator is used, a class does not have to implement a [move constructor](/docs/cpp/language/classes/move_constructor) to satisfy this type requirement: a [copy constructor](/docs/cpp/language/classes/copy_constructor) that takes a `const T&` argument can bind rvalue expressions. If a MoveInsertable class implements a move constructor, it may also implement [move semantics](/docs/cpp/library/utility/move) to take advantage of the fact that the value of rv after construction is unspecified.

{/* source:cpp-named-req-moveinsertable:0007 */}
Although it is required that customized construct is used when constructing elements of [`std::basic_string`](/docs/cpp/library/string/basic_string) until C++23, all implementations only used the default mechanism. The requirement is corrected by [P1072R10](https://wg21.link/P1072R10) to match existing practice.
