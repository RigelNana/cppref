{/* source:cpp-named-req-triviallycopyable:0000 */}
Note: the standard doesn't define a named requirement with this name. This is a type category defined by the core language. It is included here as a named requirement only for consistency.

### Requirements

{/* source:cpp-named-req-triviallycopyable:0001 */}
The following types are collectively called *trivially copyable types*:

{/* source:cpp-named-req-triviallycopyable:0002 */}
- [`scalar types`](/docs/cpp/library/named_req/ScalarType)
- [`trivially copyable class types`](/docs/cpp/language/classes#Trivially_copyable_class)
- arrays of such types
- cv-qualified versions of these types

### Notes

{/* source:cpp-named-req-triviallycopyable:0003 */}
In general, for any trivially copyable type `T` and an object `obj1` of `T`, the underlying bytes of `obj1` can be copied into an array of `char`, or `unsigned char` <InlineRevision since="C++17">, or [`std::byte`](/docs/cpp/library/utility/types/byte)</InlineRevision> or into `obj2`, a distinct object of `T`. Neither `obj1` nor `obj2` may be a potentially-overlapping subobject.

{/* source:cpp-named-req-triviallycopyable:0004 */}
If the underlying bytes of `obj1` are copied into such an array, and then the resulting content is copied back into `obj1`, `obj1` will hold its original value. If the underlying bytes of `obj1` are copied into `obj2`, `obj2` will hold `obj1`'s value.

{/* source:cpp-named-req-triviallycopyable:0005 */}
Underlying bytes can be copied by [`std::memcpy`](/docs/cpp/library/text/byte/memcpy) or [`std::memmove`](/docs/cpp/library/text/byte/memmove), as long as no living volatile object is accessed.
