{/* source:cpp-named-req-copyconstructible:0000 */}
Specifies that an instance of the type can be copy-constructed from an [lvalue expression](/docs/cpp/language/expressions/value_category).

### Requirements

{/* source:cpp-named-req-copyconstructible:0001 */}
The type `T` satisfies *CopyConstructible* if

{/* source:cpp-named-req-copyconstructible:0002 */}
- The type `T` satisfies [*MoveConstructible*](/docs/cpp/library/named_req/MoveConstructible), and

{/* source:cpp-named-req-copyconstructible:0003 */}
Given

{/* source:cpp-named-req-copyconstructible:0004 */}
- `v`, an [lvalue](/docs/cpp/language/expressions/value_category#lvalue) expression of type `T` or `const T` or an [rvalue](/docs/cpp/language/expressions/value_category#rvalue) expression of type `const T`,
- `u`, an arbitrary identifier.

{/* source:cpp-named-req-copyconstructible:0005 */}
The following expressions must be valid and have their specified effects:

{/* source:cpp-named-req-copyconstructible:0006 */}
| Expression | Post-conditions |
| --- | --- |
| `T u = v;` | The value of `u` is equivalent to the value of `v`.<br />The value of `v` is unchanged. |
| `T(v)` | The value of `T(v)` is equivalent to the value of `v`.<br />The value of `v` is unchanged. |

{/* source:cpp-named-req-copyconstructible:0007 */}
<Revision until="C++11">
The expression `v.~T()` also must be valid, and, for lvalue `v`, the expression `&v` must have the type `T*` or `const T*` and must evaluate to the address of `v`.
</Revision>

### Notes

{/* source:cpp-named-req-copyconstructible:0008 */}
Until C++11, classes that overloaded `operator&` were not *CopyConstructible* and thus were not usable in the [standard library containers](/docs/cpp/library/container). This is a design decision in C++98 (instead of a defect, see [LWG issue 390](https://cplusplus.github.io/LWG/issue390)).

{/* source:cpp-named-req-copyconstructible:0009 */}
Since C++11, the standard library uses [`std::addressof`](/docs/cpp/library/memory/addressof) whenever the address of an object is needed.

{/* source:cpp-named-req-copyconstructible:0010 */}
Extended content

Being a *CopyConstructible* class implies [`std::is_copy_constructible`](/docs/cpp/library/meta/is_copy_constructible) but not vice versa since [`std::is_copy_constructible`](/docs/cpp/library/meta/is_copy_constructible) will only check for the ability to call the constructor with the correct arguments, and, e.g., not a [*MoveConstructible*](/docs/cpp/library/named_req/MoveConstructible) requirement.

```cpp
#include <type_traits>
#include <utility>

struct S
{
    S() = default;
    S(S&&) = delete;
    S(const S&) = default;
};
static_assert(std::is_copy_constructible_v<S>);

int main()
{
    S s1;

    // Class `S` doesn't satisfy MoveConstructible requirement,
    // hence doesn't satisfy CopyConstructible requirement
    [[maybe_unused]] S s2{std::move(s1)}; // ill-formed, use of deleted function
}
```
