### Specializations

{/* source:cpp-locale-time-get:0004 */}
The standard library is guaranteed to provide the following specializations (they are [required to be implemented by any locale object](/docs/cpp/library/text/locale/locale)):

{/* source:cpp-locale-time-get:0005 */}
Defined in header [`<locale>`](/docs/cpp/library/headers/locale)
<DescriptionList>
  <DescriptionItem>
    <DescriptionTerm>`std::time_get<char>`</DescriptionTerm>
    <DescriptionBody>parses narrow string representations of date and time</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>`std::time_get<wchar_t>`</DescriptionTerm>
    <DescriptionBody>parses wide string representations of date and time</DescriptionBody>
  </DescriptionItem>
</DescriptionList>

{/* source:cpp-locale-time-get:0006 */}
In addition, the standard library is also guaranteed to provide every specialization that satisfies the following type requirements:

{/* source:cpp-locale-time-get:0007 */}
- `CharT` is one of `char` and `wchar_t`, and
- `InputIt` must meet the requirements of [`LegacyInputIterator`](/docs/cpp/library/named_req/InputIterator).

### Example

{/* source:cpp-locale-time-get:0013 */}
Note: choose clang to observe the output. libstdc++ does not correctly implement the %b specifier: [bug 78714](https://gcc.gnu.org/bugzilla/show_bug.cgi?id=78714).
```cpp
#include <iomanip>
#include <iostream>
#include <locale>
#include <sstream>
 
int main()
{
    std::tm t = {};
    std::istringstream ss("2011-Februar-18 23:12:34");
    ss.imbue(std::locale("de_DE.utf-8"));
 
    ss >> std::get_time(&t, "%Y-%b-%d %H:%M:%S");
    if (ss.fail())
        std::cout << "Parse failed\n";
    else
        std::cout << std::put_time(&t, "%c") << '\n';
}
```
Possible output:
```text
Sun Feb 18 23:12:34 2011
```
