  <DeclarationDescription>
    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0001 */}
    Constructs an empty basic_stacktrace, or copy/move from `other`.

    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0002 */}
    1) Default constructor. Constructs an empty basic_stacktrace with a default-constructed allocator.

    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0003 */}
    2) Constructs an empty basic_stacktrace using `alloc` as the allocator.

    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0004 */}
    3) Copy constructor. Constructs a basic_stacktrace with the copy of the contents of `other`, the allocator is obtained as if by calling `std::allocator_traits<allocator_type>::select_on_container_copy_construction(other.get_allocator())`.

    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0005 */}
    4) Move constructor. Constructs a basic_stacktrace with the contents of `other` using move semantics. Allocator is move-constructed from that of `other`. After construction, `other` is left in a valid but unspecified state.

    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0006 */}
    5) Same as the copy constructor, except that `alloc` is used as the allocator.

    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0007 */}
    6) Behaves same as the move constructor if `alloc == other.get_allocator()`. Otherwise, allocates memory with `alloc` and performs element-wise move. `alloc` is used as the allocator.

    {/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0008 */}
    (3,5,6) may throw an exception or construct an empty basic_stacktrace on allocation failure.
  </DeclarationDescription>
</DeclarationDoc>

### Exceptions

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0010 */}
1) [`noexcept`](/docs/cpp/language/exceptions/noexcept_spec) specification: `noexcept(std::is_nothrow_default_constructible_v<allocator_type>)`

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0011 */}
3,5,6) May propagate the exception thrown on allocation failure.

### Complexity

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0012 */}
1,2) Constant.

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0013 */}
3) Linear in size of `other`.

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0014 */}
4) Constant.

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0015 */}
5) Linear in size of `other`.

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0016 */}
6) Linear in size of `other` if `alloc != other.get_allocator()`, otherwise constant.

### Notes

{/* source:cpp-utility-basic-stacktrace-basic-stacktrace:0017 */}
After container move construction (overload (4)), references, pointers, and iterators (other than the end iterator) to `other` remain valid, but refer to elements that are now in `*this`. The current standard makes this guarantee via the blanket statement in [[container.reqmts]/67](https://eel.is/c++draft/container.reqmts#67), and a more direct guarantee is under consideration via [LWG issue 2321](https://cplusplus.github.io/LWG/issue2321).
