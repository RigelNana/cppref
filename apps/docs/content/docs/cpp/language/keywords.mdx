Note that: [`and`](/docs/cpp/language/keywords/and), [`bitor`](/docs/cpp/language/keywords/bitor), [`or`](/docs/cpp/language/keywords/or), [`xor`](/docs/cpp/language/keywords/xor), [`compl`](/docs/cpp/language/keywords/compl), [`bitand`](/docs/cpp/language/keywords/bitand), [`and_eq`](/docs/cpp/language/keywords/and_eq), [`or_eq`](/docs/cpp/language/keywords/or_eq), [`xor_eq`](/docs/cpp/language/keywords/xor_eq), [`not`](/docs/cpp/language/keywords/not) and [`not_eq`](/docs/cpp/language/keywords/not_eq) (along with digraphs: `<%`, `%>`, `<:`, `:>`, `%:`, `%:%:`<InlineRevision until="C++17"> and trigraphs: `??<`, `??>`, `??(`, `??)`, `??=`, `??/`, `??'`, `??!`, `??-`</InlineRevision>) provide an [alternative way to represent standard tokens](/docs/cpp/language/expressions/operator_alternative).<InlineRevision since="C++11"> These keywords are also considered reserved in attributes (excluding attribute argument lists), but some implementations handle them the same as the others.</InlineRevision>

In addition to keywords, there are *identifiers with special meaning*, which may be used as names of objects or functions, but have special meaning in certain contexts.

{/* source:cpp-keywords:0006 */}
Also, all [identifiers](/docs/cpp/language/basic_concepts/name) that contain a double underscore `__` in any position and each identifier that begins with an underscore followed by an uppercase letter is always reserved, and all identifiers that begin with an underscore are reserved for use as names in the global namespace. See [identifiers](/docs/cpp/language/basic_concepts/name) for more details.

{/* source:cpp-keywords:0007 */}
The namespace `std` is used to place names of the standard C++ library. See [Extending namespace std](/docs/cpp/language/extending_std) for the rules about adding names to it.

{/* source:cpp-keywords:0008 */}
<Revision since="C++11">
The name `posix` is reserved for a future top-level namespace. The behavior is undefined if a program declares or defines anything in that namespace.
</Revision>
