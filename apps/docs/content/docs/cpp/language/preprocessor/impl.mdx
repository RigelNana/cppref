{/* source:cpp-preprocessor-impl:0000 */}
Implementation defined behavior is controlled by `#pragma` directive.

## Syntax

{/* source:cpp-preprocessor-impl:0001 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code={`#pragma pragma-params`} />
  <Declaration id="2" language="cpp" since="C++11" grammar code={`_Pragma( string-literal )`} />
</DeclarationDoc>

{/* source:cpp-preprocessor-impl:0002 */}
1. Behaves in implementation-defined manner.

{/* source:cpp-preprocessor-impl:0003 */}
2. Removes the `L` prefix (if any), the outer quotes, and leading/trailing whitespace from `string-literal`, replaces each `\"` with `"` and each `\\` with `\`, then tokenizes the result (as in [translation phase 3](/docs/cpp/language/basic_concepts/translation_phases#Phase_3)), and then uses the result as if the input to `#pragma` in (1).

## Explanation

{/* source:cpp-preprocessor-impl:0004 */}
Pragma directive controls implementation-specific behavior of the compiler, such as disabling compiler warnings or changing alignment requirements. Any pragma that is not recognized is ignored.

## Non-standard pragmas

{/* source:cpp-preprocessor-impl:0005 */}
The ISO C++ language standard does not require the compilers to support any pragmas. However, several non-standard pragmas are supported by multiple implementations:

### #pragma STDC

{/* source:cpp-preprocessor-impl:0006 */}
ISO C language standard requires that C compilers support the following three pragmas, and some C++ compiler vendors support them, to varying degrees, in their C++ frontends:

{/* source:cpp-preprocessor-impl:0007 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code={`#pragma STDC FENV_ACCESS arg`} />
  <Declaration id="2" language="cpp" grammar code={`#pragma STDC FP_CONTRACT arg`} />
  <Declaration id="3" language="cpp" grammar code={`#pragma STDC CX_LIMITED_RANGE arg`} />
</DeclarationDoc>

{/* source:cpp-preprocessor-impl:0008 */}
where `arg` is either `ON`, `OFF`, or `DEFAULT`.

{/* source:cpp-preprocessor-impl:0009 */}
1. If set to `ON`, informs the compiler that the program will access or modify [floating-point environment](/docs/cpp/library/numeric/fenv), which means that optimizations that could subvert flag tests and mode changes (e.g., global common subexpression elimination, code motion, and constant folding) are prohibited. The default value is implementation-defined, usually `OFF`.

{/* source:cpp-preprocessor-impl:0010 */}
2. Allows *contracting* of floating-point expressions, that is optimizations that omit rounding errors and floating-point exceptions that would be observed if the expression was evaluated exactly as written. For example, allows the implementation of `(x * y) + z` with a single fused multiply-add CPU instruction. The default value is implementation-defined, usually `ON`.

{/* source:cpp-preprocessor-impl:0011 */}
3. Informs the compiler that multiplication, division, and absolute value of complex numbers may use simplified mathematical formulas (x+iy)×(u+iv) = (xu-yv)+i(yu+xv), (x+iy)/(u+iv) = [(xu+yv)+i(yu-xv)]/(u2+v2), and |x+iy| = √(x2+y2), despite the possibility of intermediate overflow. In other words, the programmer guarantees that the range of the values that will be passed to those function is limited. The default value is OFF.

{/* source:cpp-preprocessor-impl:0012 */}
The behavior of the program is undefined if any of the three pragmas above appear in any context other than outside all external declarations or preceding all explicit declarations and statements inside a compound statement.

{/* source:cpp-preprocessor-impl:0013 */}
Note: compilers that do not support these pragmas may provide equivalent compile-time options, such as gcc's `-fcx-limited-range` and `-ffp-contract`.

### #pragma once

{/* source:cpp-preprocessor-impl:0014 */}
`#pragma once` is a non-standard pragma that is supported by the [vast majority of modern compilers](https://en.wikipedia.org/wiki/Pragma_once#Portability). If it appears in a header file, it indicates that it is only to be parsed once, even if it is (directly or indirectly) included multiple times in the same source file.

{/* source:cpp-preprocessor-impl:0015 */}
Standard approach to preventing multiple inclusion of the same header is by using [include guards](https://en.wikipedia.org/wiki/Include_guard):

{/* source:cpp-preprocessor-impl:0016 */}
```cpp
#ifndef LIBRARY_FILENAME_H
#define LIBRARY_FILENAME_H
// contents of the header
#endif /* LIBRARY_FILENAME_H */
```

{/* source:cpp-preprocessor-impl:0017 */}
So that all but the first inclusion of the header in any translation unit are excluded from compilation. All modern compilers record the fact that a header file uses an include guard and do not re-parse the file if it is encountered again, as long as the guard is still defined (see e.g. [gcc](https://gcc.gnu.org/onlinedocs/cpp/Once-Only-Headers.html)).

{/* source:cpp-preprocessor-impl:0018 */}
With `#pragma once`, the same header appears as

{/* source:cpp-preprocessor-impl:0019 */}
```cpp
#pragma once
// contents of the header
```

{/* source:cpp-preprocessor-impl:0020 */}
Unlike header guards, this pragma makes it impossible to erroneously use the same macro name in more than one file. On the other hand, since with `#pragma once` files are excluded based on their filesystem-level identity, this can't protect against including a header twice if it exists in more than one location in a project.

### #pragma pack

{/* source:cpp-preprocessor-impl:0021 */}
This family of pragmas control the maximum alignment for subsequently defined class and union members.

{/* source:cpp-preprocessor-impl:0022 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code={`#pragma pack(arg)`} />
  <Declaration id="2" language="cpp" grammar code={`#pragma pack()`} />
  <Declaration id="3" language="cpp" grammar code={`#pragma pack(push)`} />
  <Declaration id="4" language="cpp" grammar code={`#pragma pack(push, arg)`} />
  <Declaration id="5" language="cpp" grammar code={`#pragma pack(pop)`} />
</DeclarationDoc>

{/* source:cpp-preprocessor-impl:0023 */}
where `arg` is a small power of two and specifies the new alignment in bytes.

{/* source:cpp-preprocessor-impl:0024 */}
1. Sets the current alignment to value `arg`.

{/* source:cpp-preprocessor-impl:0025 */}
2. Sets the current alignment to the default value (specified by a command-line option).

{/* source:cpp-preprocessor-impl:0026 */}
3. Pushes the value of the current alignment on an internal stack.

{/* source:cpp-preprocessor-impl:0027 */}
4. Pushes the value of the current alignment on the internal stack and then sets the current alignment to value `arg`.

{/* source:cpp-preprocessor-impl:0028 */}
5. Pops the top entry from the internal stack and then sets (restores) the current alignment to that value.

{/* source:cpp-preprocessor-impl:0029 */}
`#pragma pack` may decrease the alignment of a class, however, it cannot make a class overaligned.

{/* source:cpp-preprocessor-impl:0030 */}
See also specific details for [GCC](https://gcc.gnu.org/onlinedocs/gcc/Structure-Layout-Pragmas.html) and [MSVC](https://docs.microsoft.com/en-us/cpp/preprocessor/pack).
