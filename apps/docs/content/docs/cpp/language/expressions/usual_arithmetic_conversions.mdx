{/* source:cpp-language-usual-arithmetic-conversions:0000 */}
Many binary operators that expect operands of [arithmetic](/docs/cpp/language/basic_concepts/type-id) or [enumeration](/docs/cpp/language/declarations/enum) type cause conversions and yield result types in a similar way. The purpose is to yield a common type, which is also the type of the result. This pattern is called the *usual arithmetic conversions*.

## Definition

{/* source:cpp-language-usual-arithmetic-conversions:0001 */}
Usual arithmetic conversions are defined as follows:

### Stage 1

{/* source:cpp-language-usual-arithmetic-conversions:0002 */}
Applies [lvalue-to-rvalue conversion](/docs/cpp/language/expressions/implicit_cast#Lvalue-to-rvalue_conversion) to both operands, the resulting prvalues are used in place of the original operands for the remaining process.

### Stage 2

{/* source:cpp-language-usual-arithmetic-conversions:0003 */}
<Revision since="C++11">
- If either operand is of [scoped enumeration type](/docs/cpp/language/declarations/enum#Scoped_enumerations), no conversions are performed; if the other operand does not have the same type, the expression is ill-formed.
- Otherwise, proceed to the next stage.
</Revision>

### Stage 3

{/* source:cpp-language-usual-arithmetic-conversions:0004 */}
<Revision since="C++26">
- If either operand is of [enumeration type](/docs/cpp/language/declarations/enum), and the other operand is of a different enumeration type or a floating-point type, the expression is ill-formed.
- Otherwise, proceed to the next stage.
</Revision>

### Stage 4

{/* source:cpp-language-usual-arithmetic-conversions:0005 */}
- If either operand is of [floating-point type](/docs/cpp/language/basic_concepts/types#Floating-point_types), the following rules are applied:

{/* source:cpp-language-usual-arithmetic-conversions:0006 */}
  - If both operands have the same type, no further conversion will be performed.
  - Otherwise, if one of the operands is of a non-floating-point type, that operand is converted to the type of the other operand.
  - Otherwise, if the [floating-point conversion ranks](/docs/cpp/language/expressions/usual_arithmetic_conversions#Floating-point_conversion_rank) of the types of the operands are <InlineRevision since="C++23">ordered but</InlineRevision> not equal, then the operand of the type with the lesser floating-point conversion rank is converted to the type of the other operand.

{/* source:cpp-language-usual-arithmetic-conversions:0007 */}
<Revision since="C++23">
  - Otherwise, if the floating-point conversion ranks of the types of the operands are equal, then the operand with the lesser [floating-point conversion subrank](/docs/cpp/language/expressions/usual_arithmetic_conversions#Floating-point_conversion_subrank) is converted to the type of the other operand.
  - Otherwise, the expression is ill-formed.
</Revision>

{/* source:cpp-language-usual-arithmetic-conversions:0008 */}
- Otherwise, both operands are of integer types, proceed to the next stage.

### Stage 5

{/* source:cpp-language-usual-arithmetic-conversions:0009 */}
Both operands are converted to a common type `C`. Given the types `T1` and `T2` as the promoted type ([under the rules of integral promotions](/docs/cpp/language/expressions/implicit_cast#Integral_promotion)) of the operands, the following rules are applied to determine `C`:

{/* source:cpp-language-usual-arithmetic-conversions:0010 */}
- If `T1` and `T2` are the same type, `C` is that type.
- Otherwise, if `T1` and `T2` are both signed integer types or both unsigned integer types, `C` is the type of greater [integer conversion rank](/docs/cpp/language/expressions/usual_arithmetic_conversions#Integer_conversion_rank).
- Otherwise, one type between `T1` and `T2` is an signed integer type `S`, the other type is an unsigned integer type `U`. Apply the following rules:

{/* source:cpp-language-usual-arithmetic-conversions:0011 */}
  - If the integer conversion rank of `U` is greater than or equal to the integer conversion rank of `S`, `C` is `U`.
  - Otherwise, if `S` can represent all of the values of `U`, `C` is `S`.
  - Otherwise, `C` is the unsigned integer type corresponding to `S`.

{/* source:cpp-language-usual-arithmetic-conversions:0012 */}
<Revision since="C++20" until="C++26">
If one operand is of enumeration type and the other operand is of a different enumeration type or a floating-point type, this behavior is deprecated.
</Revision>

## Integer conversion rank

{/* source:cpp-language-usual-arithmetic-conversions:0013 */}
Every [integer type](/docs/cpp/language/basic_concepts/types#Integer_types) has an *integer conversion rank* defined as follows:

{/* source:cpp-language-usual-arithmetic-conversions:0014 */}
- No two signed integer types other than `char` and `signed char` (if `char` is signed) have the same rank, even if they have the same representation.
- The rank of a signed integer type is greater than the rank of any signed integer type with a smaller width.
- The ranks of the following integer types decrease in order:

{/* source:cpp-language-usual-arithmetic-conversions:0015 */}
<Revision since="C++11">
  - `long long`
</Revision>

{/* source:cpp-language-usual-arithmetic-conversions:0016 */}
  - `long`
  - `int`
  - `short`
  - `signed char`

{/* source:cpp-language-usual-arithmetic-conversions:0017 */}
- The rank of any unsigned integer type equals the rank of the corresponding signed integer type.

{/* source:cpp-language-usual-arithmetic-conversions:0018 */}
<Revision since="C++11">
- The rank of any standard integer type is greater than the rank of any extended integer type with the same width.
</Revision>

{/* source:cpp-language-usual-arithmetic-conversions:0019 */}
- The rank of `bool` is less than the rank of all standard integer types.
- The ranks of encoding character types (`char` <InlineRevision since="C++20">, `char8_t`</InlineRevision><InlineRevision since="C++11">, `char16_t`, `char32_t`,</InlineRevision> and `wchar_t`) equal the ranks of their [underlying types](/docs/cpp/language/basic_concepts/types#Character_types), which means:

{/* source:cpp-language-usual-arithmetic-conversions:0020 */}
  - The rank of `char` equals the rank of `signed char` and `unsigned char`.

{/* source:cpp-language-usual-arithmetic-conversions:0021 */}
<Revision since="C++20">
  - The rank of `char8_t` equals the rank of `unsigned char`.
</Revision>

<Revision since="C++11">
  - The rank of `char16_t` equals the rank of [`std::uint_least16_t`](/docs/cpp/library/utility/types/integer).
  - The rank of `char32_t` equals the rank of [`std::uint_least32_t`](/docs/cpp/library/utility/types/integer).
</Revision>

{/* source:cpp-language-usual-arithmetic-conversions:0022 */}
  - The rank of `wchar_t` equals the rank of its implementation-defined underlying type.

{/* source:cpp-language-usual-arithmetic-conversions:0023 */}
<Revision since="C++11">
- The rank of any extended signed integer type relative to another extended signed integer type with the same width is implementation-defined, but still subject to the other rules for determining the integer conversion rank.
</Revision>

{/* source:cpp-language-usual-arithmetic-conversions:0024 */}
- For all integer types `T1`, `T2`, and `T3`, if `T1` has greater rank than `T2` and `T2` has greater rank than `T3`, then `T1` has greater rank than `T3`.

{/* source:cpp-language-usual-arithmetic-conversions:0025 */}
The integer conversion rank is also used in the definition of [integral promotion](/docs/cpp/language/expressions/implicit_cast#Integral_promotion).

## Floating-point conversion rank and subrank

### Floating-point conversion rank

{/* source:cpp-language-usual-arithmetic-conversions:0026 */}
Every [floating-point type](/docs/cpp/language/basic_concepts/types#Floating-point_types) has a *floating-point conversion rank* defined as follows:

{/* source:cpp-language-usual-arithmetic-conversions:0027 */}
- The ranks of the standard floating-point types decrease in order:
  - `long double`
  - `double`
  - `float`

{/* source:cpp-language-usual-arithmetic-conversions:0028 */}
<Revision since="C++23">
- The rank of a floating-point type `T` is greater than the rank of any floating-point type whose set of values is a proper subset of the set of values of `T`.
- Two extended floating-point types with the same set of values have equal ranks.
- An extended floating-point type with the same set of values as exactly one cv-unqualified standard floating-point type has a rank equal to the rank of that standard floating-point type.
- An extended floating-point type with the same set of values as more than one cv-unqualified standard floating-point type has a rank equal to the rank of `double`.
</Revision>

{/* source:cpp-language-usual-arithmetic-conversions:0029 */}
<Revision since="C++23">
#### Floating-point conversion subrank

Floating-point types that have equal floating-point conversion ranks are ordered by *floating-point conversion subrank*. The subrank forms a total order among types with equal ranks.

The types `std::float16_t`, `std::float32_t`, `std::float64_t`, and `std::float128_t` ([fixed width floating-point types](/docs/cpp/library/utility/types/floating-point)) have a greater conversion subrank than any standard floating-point type with equal conversion rank. Otherwise, the conversion subrank order is implementation-defined.
</Revision>

### Usage

{/* source:cpp-language-usual-arithmetic-conversions:0030 */}
The floating-point conversion rank and subrank are also used to

{/* source:cpp-language-usual-arithmetic-conversions:0031 */}
- determine whether a conversion between different floating-point types [can be implicit](/docs/cpp/language/expressions/implicit_cast#Floating-point_conversions) or is a [narrowing conversion](/docs/cpp/language/initialization/list_initialization#Narrowing_conversions),
- [distinguish the conversion sequences](/docs/cpp/language/functions/overload_resolution#Ranking_of_implicit_conversion_sequences) in overload resolution,

{/* source:cpp-language-usual-arithmetic-conversions:0032 */}
<Revision since="C++23">
- determine the actual type extracted by [`std::num_get::get()`](/docs/cpp/library/text/locale/num_get/get) for the extraction of an extended floating-point type using [`std::basic_istream::operator>>`](/docs/cpp/library/io/basic_istream/operator_gtgt),
- determinte the actual type inserted by [`std::num_put::put()`](/docs/cpp/library/text/locale/num_put/put) for the insertion of an extended floating-point type using [`std::basic_ostream::operator<<`](/docs/cpp/library/io/basic_ostream/operator_ltlt),
</Revision>

{/* source:cpp-language-usual-arithmetic-conversions:0033 */}
- determine whether [`std::complex`](/docs/cpp/library/numeric/complex)'s [converting constructor](/docs/cpp/library/numeric/complex/complex) is explicit, or
- determine the common floating-point type if the arguments of different floating-point types are passed to [common](/docs/cpp/library/numeric/math) or [special](/docs/cpp/library/numeric/special_functions) math functions.

## Defect reports

{/* source:cpp-language-usual-arithmetic-conversions:0034 */}
The following behavior-changing defect reports were applied retroactively to previously published C++ standards.

{/* source:cpp-language-usual-arithmetic-conversions:0035 */}
<DefectReportList>
  <DefectReport kind="cwg" id={1642} standard="C++98">
    <PublishedBehavior>usual arithmetic conversions might involve lvalues</PublishedBehavior>
    <CorrectedBehavior>applies lvalue-to-rvalue conversions first</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="cwg" id={2528} standard="C++20">
    <PublishedBehavior>the three-way comparison between `unsigned char` and `unsigned int` is ill-formed because of the intermediate integral promotion[^1]</PublishedBehavior>
    <CorrectedBehavior>determines the common type based on the promoted types, without actually promoting the operands[^2]</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="cwg" id={2892} standard="C++98">
    <PublishedBehavior>when both operands are of the same floating-point type, the meaning of “no further conversion is needed” was unclear</PublishedBehavior>
    <CorrectedBehavior>changed to “no further conversion will be performed”</CorrectedBehavior>
  </DefectReport>
</DefectReportList>

{/* source:cpp-language-usual-arithmetic-conversions:0036 */}
[^1]: Before the resolution, `unsigned char` is promoted to `int` at the beginning of stage 5, then it is converted to `unsigned int`. However, the latter conversion is narrowing, which makes the three-way comparison ill-formed.

[^2]: After the resolution, the common type is still `unsigned int`. The difference is that `unsigned char` is directly converted to `unsigned int` without the intermediate integral promotion. The conversion is not narrowing and hence the three-way comparison is well-formed.
