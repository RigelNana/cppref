{/* source:cpp-language-escape:0000 */}
Escape sequences are used to represent certain special characters within [string literals](/docs/cpp/language/expressions/string_literal) and [character literals](/docs/cpp/language/expressions/character_literal).

{/* source:cpp-language-escape:0001 */}
The following escape sequences are available:

{/* source:cpp-language-escape:0002 */}
| Escape sequence | Description | Representation |
| --- | --- | --- |
| **Simple escape sequences** | | |
| `\'` | single quote | byte `0x27` in ASCII encoding |
| `\"` | double quote | byte `0x22` in ASCII encoding |
| `\?` | question mark | byte `0x3f` in ASCII encoding |
| `\\` | backslash | byte `0x5c` in ASCII encoding |
| `\a` | audible bell | byte `0x07` in ASCII encoding |
| `\b` | backspace | byte `0x08` in ASCII encoding |
| `\f` | form feed - new page | byte `0x0c` in ASCII encoding |
| `\n` | line feed - new line | byte `0x0a` in ASCII encoding |
| `\r` | carriage return | byte `0x0d` in ASCII encoding |
| `\t` | horizontal tab | byte `0x09` in ASCII encoding |
| `\v` | vertical tab | byte `0x0b` in ASCII encoding |
| **Numeric escape sequences** | | |
| `\nnn` | arbitrary octal value | code unit `nnn` (1~3 octal digits) |
| `\o{n...}` <InlineRevision since="C++23" /> | | code unit `n...` (arbitrary number of octal digits) |
| `\xn...` | arbitrary hexadecimal value | code unit `n...` (arbitrary number of hexadecimal digits) |
| `\x{n...}` <InlineRevision since="C++23" /> | | |
| **Conditional escape sequences**[^1] | | |
| `\c` | Implementation-defined | Implementation-defined |
| **Universal character names** | | |
| `\unnnn` | arbitrary [Unicode](https://en.wikipedia.org/wiki/Unicode) value; may result in several code units | code point `U+nnnn` (4 hexadecimal digits) |
| `\u{n...}` <InlineRevision since="C++23" /> | | code point `U+n...` (arbitrary number of hexadecimal digits) |
| `\Unnnnnnnn` | | code point `U+nnnnnnnn` (8 hexadecimal digits) |
| `\N{NAME}` <InlineRevision since="C++23" /> | arbitrary Unicode character | character named by `NAME` (see [below](/docs/cpp/language/expressions/escape#Named_universal_character_escapes)) |

{/* source:cpp-language-escape:0003 */}
[^1]: Conditional escape sequences are conditionally-supported. The character `c` in each conditional escape sequence is a member of <InlineRevision until="C++23">[basic source character set](/docs/cpp/language/basic_concepts/charset#Basic_source_character_set)</InlineRevision><InlineRevision since="C++23">[basic character set](/docs/cpp/language/basic_concepts/charset#Basic_character_set)</InlineRevision> that is not the character following the `\` in any other escape sequence.

## Range of universal character names

{/* source:cpp-language-escape:0004 */}
<Revision until="C++11">
If a universal character name corresponds to a code point that is not 0x24 (`$`), 0x40 (`@`), nor 0x60 (`` ` ``) and less than 0xA0, the program is ill-formed. In other words, members of [basic source character set](/docs/cpp/language/basic_concepts/charset#Basic_source_character_set) and control characters (in ranges 0x0-0x1F and 0x7F-0x9F) cannot be expressed in universal character names.
</Revision>

<Revision since="C++11" until="C++20">
If a universal character name corresponding to a code point of a member of [basic source character set](/docs/cpp/language/basic_concepts/charset#Basic_source_character_set) or control characters appear outside a [character](/docs/cpp/language/expressions/character_literal) or [string literal](/docs/cpp/language/expressions/string_literal), the program is ill-formed.

If a universal character name corresponds surrogate code point (the range 0xD800-0xDFFF, inclusive), the program is ill-formed.

If a universal character name used in a UTF-16/32 string literal does not correspond to a code point in [ISO/IEC 10646](https://www.iso.org/standard/76835.html) (the range 0x0-0x10FFFF, inclusive), the program is ill-formed.
</Revision>

<Revision since="C++20" until="C++23">
If a universal character name corresponding to a code point of a member of [basic source character set](/docs/cpp/language/basic_concepts/charset#Basic_source_character_set) or control characters appear outside a [character](/docs/cpp/language/expressions/character_literal) or [string literal](/docs/cpp/language/expressions/string_literal), the program is ill-formed.

If a universal character name does not correspond to a code point in [ISO/IEC 10646](https://www.iso.org/standard/76835.html) (the range 0x0-0x10FFFF, inclusive) or corresponds to a surrogate code point (the range 0xD800-0xDFFF, inclusive), the program is ill-formed.
</Revision>

<Revision since="C++23">
If a universal character name corresponding to a scalar value of a character in the [basic character set](/docs/cpp/language/basic_concepts/charset#Basic_character_set) or a control character appear outside a [character](/docs/cpp/language/expressions/character_literal) or [string literal](/docs/cpp/language/expressions/string_literal), the program is ill-formed.

If a universal character name does not correspond to a scalar value of a character in the [translation character set](/docs/cpp/language/basic_concepts/charset#Translation_character_set), the program is ill-formed.
</Revision>

{/* source:cpp-language-escape:0005 */}
<Revision since="C++23">
### Named universal character escapes

<DeclarationDoc>
  <Declaration language="cpp" grammar code={`\\N{n-char-sequence}`} />
</DeclarationDoc>

<ParameterList>
  <Parameter name="n-char-sequence">one or more `n-chars`</Parameter>
  <Parameter name="n-char">a character from the [translation character set](/docs/cpp/language/basic_concepts/charset#Translation_character_set), except the right curly bracket `}` or new-line character</Parameter>
</ParameterList>

A universal character name of the syntax above is a *named universal character*. It designates the corresponding character in the [Unicode Standard](https://www.unicode.org/versions/latest/) ([chapter 4.8 Name](https://www.unicode.org/versions/latest/ch04.pdf)) if the `n-char-sequence` is equal to its character name or to one of its character name aliases of type “control”, “correction”, or “alternate”; otherwise, the program is ill-formed.

These aliases are listed in the [Unicode Character Database](https://www.unicode.org/reports/tr44/)’s [NameAliases.txt](https://www.unicode.org/Public/UCD/latest/ucd/NameAliases.txt). None of these names or aliases have leading or trailing spaces.

A valid `n-char-sequence` must contain only uppercase Latin letters A through Z, digits, space, and hyphen-minus. Other characters never occur in a Unicode character name, and thus their appearance in a `n-char-sequence` always renders the program ill-formed.
</Revision>

## Notes

{/* source:cpp-language-escape:0006 */}
`\0` is the most commonly used octal escape sequence, because it represents the terminating null character in [null-terminated strings](/docs/cpp/library/string#Null-terminated_strings).

{/* source:cpp-language-escape:0007 */}
The new-line character `\n` has special meaning when used in [text mode I/O](/docs/cpp/library/io/c): it is converted to the OS-specific newline representation, usually a byte or byte sequence. Some systems mark their lines with length fields instead.

{/* source:cpp-language-escape:0008 */}
Octal escape sequences have a limit of three octal digits, but terminate at the first character that is not a valid octal digit if encountered sooner.

{/* source:cpp-language-escape:0009 */}
Hexadecimal escape sequences have no length limit and terminate at the first character that is not a valid hexadecimal digit. If the value represented by a single hexadecimal escape sequence does not fit the range of values represented by the character type used in this string literal (`char`, <InlineRevision since="C++20">`char8_t`, </InlineRevision><InlineRevision since="C++11">`char16_t`, `char32_t`, </InlineRevision>or `wchar_t`), the result is unspecified.

{/* source:cpp-language-escape:0010 */}
<Revision since="C++11">
A universal character name in a narrow string literal or a 16-bit string literal may map to more than one code unit, e.g. `\U0001f34c` is 4 `char` code units in UTF-8 (`\xF0\x9F\x8D\x8C`) and 2 `char16_t` code units in UTF-16 (`\xD83C\xDF4C`).
</Revision>

{/* source:cpp-language-escape:0011 */}
The question mark escape sequence `\?` is used to prevent [trigraphs](/docs/cpp/language/expressions/operator_alternative) from being interpreted inside string literals: a string such as `"??/"` is compiled as `"\"`, but if the second question mark is escaped, as in `"?\?/"`, it becomes `"??/"`. <InlineRevision since="C++17">As trigraphs have been removed from C++, the question mark escape sequence is no longer necessary. It is preserved for compatibility with C++14 (and former revisions) and C.</InlineRevision>

## Example

{/* source:cpp-language-escape:0013 */}
```cpp
#include <iostream>

int main()
{
    std::cout << "This\nis\na\ntest\n\n";
    std::cout << "She said, \"Sells she seashells on the seashore?\"\n";
}
```

Output:

```text
This
is
a
test

She said, "Sells she seashells on the seashore?"
```
