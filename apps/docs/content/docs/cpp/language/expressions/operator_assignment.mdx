## Definitions

{/* source:cpp-language-operator-assignment:0002 */}
Copy assignment replaces the contents of the object `a` with a copy of the contents of `b` (`b` is not modified). For class types, this is performed in a special member function, described in [copy assignment operator](/docs/cpp/language/classes/as_operator).

{/* source:cpp-language-operator-assignment:0003 */}
<Revision since="C++11">
*Move assignment* replaces the contents of the object `a` with the contents of `b`, avoiding copying if possible (`b` may be modified). For class types, this is performed in a special member function, described in [move assignment operator](/docs/cpp/language/classes/move_operator).
</Revision>

{/* source:cpp-language-operator-assignment:0004 */}
For non-class types, copy and move assignment are indistinguishable and are referred to as direct assignment.

{/* source:cpp-language-operator-assignment:0005 */}
Compound assignment replace the contents of the object `a` with the result of a binary operation between the previous value of `a` and the value of `b`.

## Assignment operator syntax

{/* source:cpp-language-operator-assignment:0006 */}
The assignment expressions have the form

{/* source:cpp-language-operator-assignment:0007 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="target-expr = new-value" />
  <Declaration id="2" language="cpp" grammar code="target-expr op new-value" />
</DeclarationDoc>

{/* source:cpp-language-operator-assignment:0008 */}
<ParameterList>
  <Parameter name="target-expr">the expression[1] to be assigned to</Parameter>
  <Parameter name="op">one of `*=`, `/=` `%=`, `+=` `-=`, `<<=`, `>>=`, `&=`, `^=`, `|=`</Parameter>
  <Parameter name="new-value">the <InlineRevision until="C++11">expression[2]</InlineRevision><InlineRevision since="C++11">[initializer clause](/docs/cpp/language/initialization#Initializer)</InlineRevision> to assign to the target</Parameter>
</ParameterList>

{/* source:cpp-language-operator-assignment:0009 */}
1. ↑ *target-expr* must have higher [precedence](/docs/cpp/language/expressions/operator_precedence) than an assignment expression.
2. ↑ *new-value* cannot be a comma expression, because its [precedence](/docs/cpp/language/expressions/operator_precedence) is lower.

{/* source:cpp-language-operator-assignment:0010 */}
1. Simple assignment expression.

{/* source:cpp-language-operator-assignment:0011 */}
2. Compound assignment expression.

{/* source:cpp-language-operator-assignment:0012 */}
<Revision since="C++11">
If *new-value* is not an expression, the assignment expression will never match an overloaded compound assignment operator.
</Revision>

## Built-in simple assignment operator

{/* source:cpp-language-operator-assignment:0013 */}
For the built-in simple assignment, *target-expr* must be a modifiable lvalue.

{/* source:cpp-language-operator-assignment:0014 */}
The object referred to by *target-expr* is modified by replacing its value with the result of *new-value*. If the object referred is of an integer type `T`, and the result of *new-value* is of the corresponding signed/unsigned integer type, the value of the object is replaced with the value of type `T` with the same value representation of the result of *new-value*.

{/* source:cpp-language-operator-assignment:0015 */}
The result of a built-in simple assignment is an lvalue of the type of *target-expr*, referring to *target-expr*. If *target-expr* is a [bit-field](/docs/cpp/language/classes/bit_field), the result is also a bit-field.

### Assignment from an expression

{/* source:cpp-language-operator-assignment:0016 */}
If *new-value* is an expression, it is [implicitly converted](/docs/cpp/language/expressions/implicit_cast) to the cv-unqualified type of *target-expr*. When *target-expr* is a bit-field that cannot represent the value of the expression, the resulting value of the bit-field is implementation-defined.

{/* source:cpp-language-operator-assignment:0017 */}
If *target-expr* and *new-value* identify overlapping objects, the behavior is undefined (unless the overlap is exact and the type is the same).

{/* source:cpp-language-operator-assignment:0018 */}
<Revision since="C++20">
If the type of *target-expr* is volatile-qualified, the assignment is deprecated, unless the (possibly parenthesized) assignment expression is a [discarded-value expression](/docs/cpp/language/expressions#Discarded-value_expressions) or an [unevaluated operand](/docs/cpp/language/expressions#Potentially-evaluated_expressions).
</Revision>

{/* source:cpp-language-operator-assignment:0019 */}
<Revision since="C++11">
**Assignment from a non-expression initializer clause**

*new-value* is only allowed not to be an expression in following situations:

- *target-expr* is of a [scalar type](/docs/cpp/library/named_req/ScalarType) `T`, and *new-value* is empty or has only one element. In this case, given an invented variable `t` declared and initialized as `T t =` *new-value*, the meaning of `x =` *new-value* is `x = t`.
- *target-expr* is of class type. In this case, *new-value* is passed as the argument to the assignment operator function selected by [overload resolution](/docs/cpp/language/functions/overload_resolution).

```cpp
#include <complex>

std::complex<double> z;
z = {1, 2};  // meaning z.operator=({1, 2})
z += {1, 2}; // meaning z.operator+=({1, 2})

int a, b;
a = b = {1}; // meaning a = b = 1;
a = {1} = b; // syntax error
```
</Revision>

{/* source:cpp-language-operator-assignment:0020 */}
In [overload resolution against user-defined operators](/docs/cpp/language/functions/overload_resolution#Call_to_an_overloaded_operator), for every type `T`, the following function signatures participate in overload resolution:

{/* source:cpp-language-operator-assignment:0021 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" code={`T*& operator=(T*&, T*);`} />
  <Declaration id="2" language="cpp" code={`T*volatile & operator=(T*volatile &, T*);`} />
</DeclarationDoc>

{/* source:cpp-language-operator-assignment:0022 */}
For every enumeration or pointer to member type `T`, optionally volatile-qualified, the following function signature participates in overload resolution:

{/* source:cpp-language-operator-assignment:0023 */}
<DeclarationDoc>
  <Declaration language="cpp" code={`T& operator=(T&, T);`} />
</DeclarationDoc>

{/* source:cpp-language-operator-assignment:0024 */}
For every pair `A1` and `A2`, where `A1` is an arithmetic type (optionally volatile-qualified) and `A2` is a promoted arithmetic type, the following function signature participates in overload resolution:

{/* source:cpp-language-operator-assignment:0025 */}
<DeclarationDoc>
  <Declaration language="cpp" code={`A1& operator=(A1&, A2);`} />
</DeclarationDoc>

## Built-in compound assignment operator

{/* source:cpp-language-operator-assignment:0026 */}
The behavior of every built-in compound-assignment expression *target-expr* `op` `=` *new-value* is exactly the same as the behavior of the expression *target-expr* `=` *target-expr* `op` *new-value*, except that *target-expr* is evaluated only once.

{/* source:cpp-language-operator-assignment:0027 */}
The requirements on *target-expr* and *new-value* of built-in simple assignment operators also apply. Furthermore:

{/* source:cpp-language-operator-assignment:0028 */}
- For `+=` and `-=`, the type of *target-expr* must be an [arithmetic type](/docs/cpp/language/basic_concepts/type-id) or a pointer to a (possibly cv-qualified) completely-defined [object type](/docs/cpp/language/basic_concepts/type-id). For all other compound assignment operators, the type of *target-expr* must be an arithmetic type.

{/* source:cpp-language-operator-assignment:0029 */}
In [overload resolution against user-defined operators](/docs/cpp/language/functions/overload_resolution#Call_to_an_overloaded_operator), for every pair `A1` and `A2`, where `A1` is an arithmetic type (optionally volatile-qualified) and `A2` is a promoted arithmetic type, the following function signatures participate in overload resolution:

{/* source:cpp-language-operator-assignment:0030 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" code={`A1& operator*=(A1&, A2);`} />
  <Declaration id="2" language="cpp" code={`A1& operator/=(A1&, A2);`} />
  <Declaration id="3" language="cpp" code={`A1& operator+=(A1&, A2);`} />
  <Declaration id="4" language="cpp" code={`A1& operator-=(A1&, A2);`} />
</DeclarationDoc>

{/* source:cpp-language-operator-assignment:0031 */}
For every pair `I1` and `I2`, where `I1` is an integral type (optionally volatile-qualified) and `I2` is a promoted integral type, the following function signatures participate in overload resolution:

{/* source:cpp-language-operator-assignment:0032 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" code={`I1& operator%=(I1&, I2);`} />
  <Declaration id="2" language="cpp" code={`I1& operator<<=(I1&, I2);`} />
  <Declaration id="3" language="cpp" code={`I1& operator>>=(I1&, I2);`} />
  <Declaration id="4" language="cpp" code={`I1& operator&=(I1&, I2);`} />
  <Declaration id="5" language="cpp" code={`I1& operator^=(I1&, I2);`} />
  <Declaration id="6" language="cpp" code={`I1& operator|=(I1&, I2);`} />
</DeclarationDoc>

{/* source:cpp-language-operator-assignment:0033 */}
For every optionally cv-qualified object type `T`, the following function signatures participate in overload resolution:

{/* source:cpp-language-operator-assignment:0034 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" code={`T*& operator+=(T*&, std::ptrdiff_t);`} />
  <Declaration id="2" language="cpp" code={`T*& operator-=(T*&, std::ptrdiff_t);`} />
  <Declaration id="3" language="cpp" code={`T*volatile & operator+=(T*volatile &, std::ptrdiff_t);`} />
  <Declaration id="4" language="cpp" code={`T*volatile & operator-=(T*volatile &, std::ptrdiff_t);`} />
</DeclarationDoc>

## Example

{/* source:cpp-language-operator-assignment:0035 */}
```cpp
#include <iostream>

int main()
{
    int n = 0;        // not an assignment

    n = 1;            // direct assignment
    std::cout << n << ' ';

    n = {};           // zero-initialization, then assignment
    std::cout << n << ' ';

    n = 'a';          // integral promotion, then assignment
    std::cout << n << ' ';

    n = {'b'};        // explicit cast, then assignment
    std::cout << n << ' ';

    n = 1.0;          // floating-point conversion, then assignment
    std::cout << n << ' ';

//  n = {1.0};        // compiler error (narrowing conversion)

    int& r = n;       // not an assignment
    r = 2;            // assignment through reference
    std::cout << n << ' ';

    int* p;
    p = &n;           // direct assignment
    p = nullptr;      // null-pointer conversion, then assignment
    std::cout << p << ' ';

    struct { int a; std::string s; } obj;
    obj = {1, "abc"}; // assignment from a braced-init-list
    std::cout << obj.a << ':' << obj.s << '\n';
}
```

Possible output:

```text
1 0 97 98 1 2 (nil) 1:abc
```

The following behavior-changing defect reports were applied retroactively to previously published C++ standards.

{/* source:cpp-language-operator-assignment:0037 */}
<DefectReportList>
  <DefectReport kind="cwg" id={1527} standard="C++11"><PublishedBehavior>for assignments to class type objects, the right operand could be an initializer list only when the assignment is defined by a user-defined assignment operator</PublishedBehavior><CorrectedBehavior>removed user-defined assignment constraint</CorrectedBehavior></DefectReport>
  <DefectReport kind="cwg" id={1538} standard="C++11"><PublishedBehavior>`E1 = {E2}` was equivalent to `E1 = T(E2)` (`T` is the type of `E1`), this introduced a C-style cast</PublishedBehavior><CorrectedBehavior>it is equivalent to `E1 = T{E2}`</CorrectedBehavior></DefectReport>
  <DefectReport kind="cwg" id={2654} standard="C++20"><PublishedBehavior>compound assignment operators for volatile-qualified types were inconsistently deprecated</PublishedBehavior><CorrectedBehavior>none of them is deprecated</CorrectedBehavior></DefectReport>
  <DefectReport kind="cwg" id={2768} standard="C++11"><PublishedBehavior>an assignment from a non-expression initializer clause to a scalar value would perform direct-list-initialization</PublishedBehavior><CorrectedBehavior>performs copy-list-initialization instead</CorrectedBehavior></DefectReport>
  <DefectReport kind="cwg" id={2901} standard="C++98"><PublishedBehavior>the value assigned to an `unsigned int` object through an `int` lvalue is unclear</PublishedBehavior><CorrectedBehavior>made clear</CorrectedBehavior></DefectReport>
  <DefectReport kind="paper" id="P2327R1" standard="C++20"><PublishedBehavior>bitwise compound assignment operators for volatile types were deprecated while being useful for some platforms</PublishedBehavior><CorrectedBehavior>they are not deprecated</CorrectedBehavior></DefectReport>
