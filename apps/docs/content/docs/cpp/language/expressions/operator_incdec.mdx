{/* source:cpp-language-operator-incdec:0000 */}
Increment/decrement operators increment or decrement the value of the object.

{/* source:cpp-language-operator-incdec:0001 */}
| Operator name | Syntax | [Over​load​able](/docs/cpp/language/expressions/operators) | Prototype examples (for `class T`) | |
| --- | --- | --- | --- | --- |
| | | | Inside class definition | Outside class definition |
| pre-increment | `++a` | Yes | `T& T::operator++();` | `T& operator++(T& a);` |
| pre-decrement | `--a` | Yes | `T& T::operator--();` | `T& operator--(T& a);` |
| post-increment | `a++` | Yes | `T T::operator++(int);` | `T operator++(T& a, int);` |
| post-decrement | `a--` | Yes | `T T::operator--(int);` | `T operator--(T& a, int);` |

**Notes**

- Prefix versions of the built-in operators return *references* and postfix versions return *values*, and typical [user-defined overloads](/docs/cpp/language/expressions/operators) follow the pattern so that the user-defined operators can be used in the same manner as the built-ins. However, in a user-defined operator overload, any type can be used as return type (including `void`).
- The `int` parameter is a dummy parameter used to differentiate between prefix and postfix versions of the operators. When the user-defined postfix operator is called, the value passed in that parameter is always zero, although it may be changed by calling the operator using function call notation (e.g., `a.operator++(2)` or `operator++(a, 2)`).

## Prefix operators

{/* source:cpp-language-operator-incdec:0002 */}
The prefix increment and decrement expressions have the form

  <Declaration language="cpp" grammar code={`-- expression`} />
</DeclarationDoc>

{/* source:cpp-language-operator-incdec:0004 */}
1. prefix increment (pre-increment)

{/* source:cpp-language-operator-incdec:0005 */}
2. prefix decrement (pre-decrement)

### Built-in prefix operators

{/* source:cpp-language-operator-incdec:0006 */}
1. The expression `++x` is equivalent to `x += 1`, with the following exceptions:
   - <Revision until="C++17">If the type of *expression* is (possibly volatile-qualified) `bool`, *expression* is set to `true`. Such a increment is deprecated.</Revision>
   - <Revision since="C++17">If the type of *expression* is (possibly cv-qualified) `bool`, the program is ill-formed.</Revision>
   - <Revision since="C++20">If the type of *expression* is volatile-qualified, the increment is deprecated.</Revision>

{/* source:cpp-language-operator-incdec:0007 */}
2. The expression `--x` is equivalent to `x -= 1`, with the following exceptions:
   - If the type of *expression* is (possibly cv-qualified) `bool`, the program is ill-formed.
   - <Revision since="C++20">If the type of *expression* is volatile-qualified, the decrement is deprecated.</Revision>

### Overloads

{/* source:cpp-language-operator-incdec:0008 */}
In [overload resolution against user-defined operators](/docs/cpp/language/functions/overload_resolution#Call_to_an_overloaded_operator), for every optionally volatile-qualified arithmetic type `A` other than `bool`, and for every optionally volatile-qualified pointer `P` to optionally cv-qualified object type, the following function signatures participate in overload resolution:

{/* source:cpp-language-operator-incdec:0009 */}
<DeclarationDoc>
  <Declaration language="cpp" code={`A& operator++(A&)`} />
  <Declaration language="cpp" until="C++17" code={`bool& operator++(bool&)`} />
  (deprecated)
  <Declaration language="cpp" code={`P& operator++(P&)`} />
  <Declaration language="cpp" code={`A& operator--(A&)`} />
  <Declaration language="cpp" code={`P& operator--(P&)`} />
</DeclarationDoc>

## Postfix operators

{/* source:cpp-language-operator-incdec:0010 */}
The postfix increment and decrement expressions have the form

{/* source:cpp-language-operator-incdec:0011 */}
<DeclarationDoc>
  <Declaration language="cpp" grammar code={`expression ++`} />
  <Declaration language="cpp" grammar code={`expression --`} />
</DeclarationDoc>

{/* source:cpp-language-operator-incdec:0012 */}
1. postfix increment (post-increment)

{/* source:cpp-language-operator-incdec:0013 */}
2. postfix decrement (post-decrement)

### Built-in postfix operators

{/* source:cpp-language-operator-incdec:0014 */}
The result of postfix increment or decrement is the value obtained by applying the [lvalue-to-rvalue conversion](/docs/cpp/language/expressions/implicit_cast#Lvalue-to-rvalue_conversion) to *expression* (before modification). The type of the result is the cv-unqualified version of the type of *expression*.

{/* source:cpp-language-operator-incdec:0015 */}
If *expression* is not a modifiable lvalue of an arithmetic type<InlineRevision since="C++17"> other than (possibly cv-qualified) `bool`</InlineRevision>, or a pointer to a complete object type, the program is ill-formed.

<Revision since="C++20">

{/* source:cpp-language-operator-incdec:0016 */}
If the type of *expression* is volatile-qualified, the increment or decrement is deprecated.

</Revision>

{/* source:cpp-language-operator-incdec:0017 */}
1. The value of *expression* is modified as if it were the operand of the prefix `++` operator.

{/* source:cpp-language-operator-incdec:0018 */}
2. The value of *expression* is modified as if it were the operand of the prefix `--` operator.

{/* source:cpp-language-operator-incdec:0019 */}
The value computation of a postfix increment or decrement is [sequenced before](/docs/cpp/language/expressions/eval_order) the modification of *expression*. With respect to an indeterminately-sequenced function call, the operation of a postfix increment or decrement is a single evaluation.

### Overloads

{/* source:cpp-language-operator-incdec:0020 */}
In [overload resolution against user-defined operators](/docs/cpp/language/functions/overload_resolution#Call_to_an_overloaded_operator), for every optionally volatile-qualified arithmetic type `A` other than `bool`, and for every optionally volatile-qualified pointer `P` to optionally cv-qualified object type, the following function signatures participate in overload resolution:

{/* source:cpp-language-operator-incdec:0021 */}
<DeclarationDoc>
  <Declaration language="cpp" code={`A operator++(A&, int)`} />
  <Declaration language="cpp" until="C++17" code={`bool operator++(bool&, int)`} />
  (deprecated)
  <Declaration language="cpp" code={`P operator++(P&, int)`} />
  <Declaration language="cpp" code={`A operator--(A&, int)`} />
  <Declaration language="cpp" code={`P operator--(P&, int)`} />
</DeclarationDoc>

### Example

{/* source:cpp-language-operator-incdec:0022 */}
```cpp
#include <iostream>

int main()
{
    int n1 = 1;
    int n2 = ++n1;
    int n3 = ++ ++n1;
    int n4 = n1++;
//  int n5 = n1++ ++;   // error
//  int n6 = n1 + ++n1; // undefined behavior
    std::cout << "n1 = " << n1 << '\n'
              << "n2 = " << n2 << '\n'
              << "n3 = " << n3 << '\n'
              << "n4 = " << n4 << '\n';
}
```

Output:

```text
n1 = 5
n2 = 2
n3 = 4
n4 = 4
```

## Notes

{/* source:cpp-language-operator-incdec:0023 */}
Because of the side-effects involved, built-in increment and decrement operators must be used with care to avoid undefined behavior due to violations of [sequencing rules](/docs/cpp/language/expressions/eval_order).

{/* source:cpp-language-operator-incdec:0024 */}
Because a temporary copy of the object is constructed during post-increment and post-decrement, pre-increment or pre-decrement operators are usually more efficient in contexts where the returned value is not used.

## Standard library

{/* source:cpp-language-operator-incdec:0025 */}

## Defect reports

{/* source:cpp-language-operator-incdec:0027 */}
The following behavior-changing defect reports were applied retroactively to previously published C++ standards.

{/* source:cpp-language-operator-incdec:0028 */}
<DefectReportList>
  <DefectReport kind="cwg" id={2855} standard="C++98">
    <PublishedBehavior>usual arithmetic conversions are applied for built-in pre-increment and pre-decrement, but were not applied for their postfix counterparts[^1]</PublishedBehavior>
    <CorrectedBehavior>also applied</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="cwg" id={2901} standard="C++98">
    <PublishedBehavior>lvalue-to-rvalue conversions were not applied for built-in post-increment and post-decrement</PublishedBehavior>
    <CorrectedBehavior>applied</CorrectedBehavior>
  </DefectReport>
</DefectReportList>

{/* source:cpp-language-operator-incdec:0029 */}
[^1]: The prefix `++x` is equivalent to `x += 1`, and the latter is applicable for usual arithmetic conversions (i.e. yield a common type between `decltype(x)` and `int`). However, the effect of the postfix `x++` is simply "adding one to `x`", there is no binary operator present, so no usual arithmetic conversions will take place.
