{/* source:cpp-language-expressions:0000 */}
An expression is a sequence of operators and their operands, that specifies a computation.

{/* source:cpp-language-expressions:0001 */}
Expression evaluation may produce a result (e.g., evaluation of `2 + 2` produces the result `4`) and may generate side-effects (e.g. evaluation of `std::printf("%d", 4)` prints the character `'4'` on the standard output).

{/* source:cpp-language-expressions:0002 */}
Each C++ expression is characterized by two independent properties: A type and a value category.

### General

{/* source:cpp-language-expressions:0003 */}
- [value categories](/docs/cpp/language/expressions/value_category) (lvalue, rvalue<InlineRevision since="C++11">, glvalue, prvalue, xvalue</InlineRevision>) classify expressions by their values
- [order of evaluation](/docs/cpp/language/expressions/eval_order) of arguments and subexpressions specify the order in which intermediate results are obtained

## Primary expressions

{/* source:cpp-language-expressions:0009 */}
The operands of any operator may be other expressions or primary expressions (e.g. in `1 + 2 * 3`, the operands of `operator+` are the [subexpression](/docs/cpp/language/expressions#Full-expressions) `2 * 3` and the primary expression `1`).

{/* source:cpp-language-expressions:0010 */}
Primary expressions are any of the following:

{/* source:cpp-language-expressions:0011 */}
- [`this`](/docs/cpp/language/classes/this)
- literals (e.g. `2` or `"Hello, world"`)
- identifier expressions, including
  - suitably declared [unqualified identifiers](/docs/cpp/language/basic_concepts/name#Unqualified_identifiers) (e.g. `n` or `cout`),
  - suitably declared [qualified identifiers](/docs/cpp/language/basic_concepts/name#Qualified_identifiers) (e.g. [`std::string::npos`](/docs/cpp/library/string/basic_string/npos)), and
  - identifiers to be declared in [declarators](/docs/cpp/language/declarations#Declarators)

{/* source:cpp-language-expressions:0012 */}
<Revision since="C++26">
- [pack indexing expression](/docs/cpp/language/templates/pack_indexing#Pack_indexing_expression)
</Revision>

{/* source:cpp-language-expressions:0013 */}
<Revision since="C++11">
- [lambda expressions](/docs/cpp/language/functions/lambda)
</Revision>

<Revision since="C++17">
- [fold expressions](/docs/cpp/language/templates/fold)
</Revision>

<Revision since="C++20">
- [requires expressions](/docs/cpp/language/templates/requires)
</Revision>

{/* source:cpp-language-expressions:0014 */}
Any expression in parentheses is also classified as a primary expression: this guarantees that the parentheses have higher precedence than any operator. Parentheses preserve value, type, and value category.

### Literals

{/* source:cpp-language-expressions:0015 */}
Literals are the tokens of a C++ program that represent constant values embedded in the source code.

{/* source:cpp-language-expressions:0016 */}
- [integer literals](/docs/cpp/language/expressions/integer_literal) are decimal, octal, hexadecimal or binary numbers of integer type.
- [character literals](/docs/cpp/language/expressions/character_literal) are individual characters of type

{/* source:cpp-language-expressions:0017 */}
  - `char` or `wchar_t`

{/* source:cpp-language-expressions:0018 */}
  - <Revision since="C++11">`char16_t` or `char32_t`</Revision>
  - <Revision since="C++20">`char8_t`</Revision>

{/* source:cpp-language-expressions:0019 */}
- [floating-point literals](/docs/cpp/language/expressions/floating_literal) are values of type `float`, `double`, or `long double`
- [string literals](/docs/cpp/language/expressions/string_literal) are sequences of characters of type

{/* source:cpp-language-expressions:0020 */}
  - `const char[]` or `const wchar_t[]`

{/* source:cpp-language-expressions:0021 */}
  - <Revision since="C++11">`const char16_t[]` or `const char32_t[]`</Revision>
  - <Revision since="C++20">`const char8_t[]`</Revision>

{/* source:cpp-language-expressions:0022 */}
- [boolean literals](/docs/cpp/language/expressions/bool_literal) are values of type `bool`, that is `true` and `false`

{/* source:cpp-language-expressions:0023 */}
<Revision since="C++11">
- [`nullptr`](/docs/cpp/language/expressions/nullptr) is the pointer literal which specifies a null pointer value
- [user-defined literals](/docs/cpp/language/expressions/user_literal) are constant values of user-specified type
</Revision>

## Full-expressions

{/* source:cpp-language-expressions:0024 */}
A constituent expression is defined as follows:

{/* source:cpp-language-expressions:0025 */}
- The constituent expression of an expression is that expression.
- The constituent expressions of a braced-init-list or of a (possibly parenthesized) expression list are the constituent expressions of the elements of the respective list.
- The constituent expressions of a brace-or-equal-initializer of the form `= initializer-clause` are the constituent expressions of the initializer-clause.

{/* source:cpp-language-expressions:0026 */}
```cpp
int num1 = 0;
num1 += 1; // Case 1: the constituent expression of `num += 1` is `num += 1`

int arr2[2] = {2, 22} // Case 2: the constituent expressions
                      //         of `{2, 22}` are `2` and `22`
                      // Case 3: the constituent expressions of ` = {2, 22}`
                      //         are the constituent expressions of `{2, 22}`
                      //         (i.e. also `2` and `22`)
```

{/* source:cpp-language-expressions:0027 */}
The immediate subexpressions of an expression `E` are

{/* source:cpp-language-expressions:0028 */}
- the constituent expressions of `E`'s operands,

{/* source:cpp-language-expressions:0029 */}
- <Revision since="C++14">if `E` creates an [aggregate](/docs/cpp/language/initialization/aggregate_initialization#Definitions) object, the constituent expressions of each [default member initializer](/docs/cpp/language/classes/data_members#Member_initialization) used in the initialization,</Revision>

{/* source:cpp-language-expressions:0030 */}
- <Revision since="C++11">if `E` is a [lambda expression](/docs/cpp/language/functions/lambda), the initialization of the entities captured by copy and the constituent expressions of the initializer of the captures,</Revision>

{/* source:cpp-language-expressions:0031 */}
- any function call that `E` implicitly invokes, or
- if `E` is a function call or implicitly invokes a function, the constituent expressions of each [default argument](/docs/cpp/language/functions/default_arguments) used in the call.

{/* source:cpp-language-expressions:0032 */}
A subexpression of an expression `E` is an immediate subexpression of `E` or a subexpression of an immediate subexpression of `E`. <InlineRevision since="C++11">Note that expressions appearing in the 'function body' of lambda expressions are not subexpressions of the lambda expression.</InlineRevision>

{/* source:cpp-language-expressions:0033 */}
A full-expression is

{/* source:cpp-language-expressions:0034 */}
- an [unevaluated operand](/docs/cpp/language/expressions#Potentially-evaluated_expressions),
- a [constant expression](/docs/cpp/language/expressions/constant_expression),

{/* source:cpp-language-expressions:0035 */}
- <Revision since="C++20">an [immediate invocation](/docs/cpp/language/declarations/consteval),</Revision>

{/* source:cpp-language-expressions:0036 */}
- a declarator of a [simple declaration](/docs/cpp/language/declarations#Simple_declaration) or a [member initializer](/docs/cpp/language/classes/initializer_list), including the constituent expressions of the initializer,
- an invocation of a [destructor](/docs/cpp/language/classes/destructor) generated at the end of the [lifetime](/docs/cpp/language/basic_concepts/lifetime) of an object other than a temporary object whose lifetime has not been extended, or
- an expression that is not a subexpression of another expression and that is not otherwise part of a full-expression.

{/* source:cpp-language-expressions:0037 */}
If a language construct is defined to produce an implicit call of a function, a use of the language construct is considered to be an expression for the purposes of this definition. Conversions applied to the result of an expression in order to satisfy the requirements of the language construct in which the expression appears are also considered to be part of the full-expression.

{/* source:cpp-language-expressions:0038 */}
For an initializer, performing the initialization of the entity <InlineRevision since="C++14">(including evaluating default member initializers of an aggregate)</InlineRevision> is also considered part of the full-expression.

## Potentially-evaluated expressions

{/* source:cpp-language-expressions:0039 */}
<Revision until="C++11">
An expression is *potentially evaluated* unless

- it is the operand of the [`sizeof`](/docs/cpp/language/expressions/sizeof) operator, or
- it is the operand of the [`typeid`](/docs/cpp/language/expressions/typeid) operator and does not designate an lvalue of [polymorphic](/docs/cpp/language/basic_concepts/objects#Polymorphic_objects) class type.
</Revision>

<Revision since="C++11">
The following operands are *unevaluated operands*, they are not evaluated:

- expressions which the [`typeid`](/docs/cpp/language/expressions/typeid) operator applies to, except glvalues of [polymorphic](/docs/cpp/language/basic_concepts/objects#Polymorphic_objects) class types
- expressions which are operands of the [`sizeof`](/docs/cpp/language/expressions/sizeof) operator
- operands of the [`noexcept`](/docs/cpp/language/exceptions/noexcept) operator
- operands of the [`decltype`](/docs/cpp/language/declarations/decltype) specifier

<Revision since="C++20">
- *constraint-expression* of [concept](/docs/cpp/language/templates/constraints#Concepts) definitions
- expressions following the `requires` keyword of [requires-clauses](/docs/cpp/language/templates/constraints#Requires_clauses)
- expressions appearing in *requirement-seq* of [requires-expressions](/docs/cpp/language/templates/requires)
</Revision>

An expression is *potentially evaluated* unless

- it is an unevaluated operand, or
- it is a subexpression of an unevaluated operand.
</Revision>

{/* source:cpp-language-expressions:0040 */}
Potentially-evaluated expressions are [ODR-use](/docs/cpp/language/basic_concepts/definition#ODR-use).

## Discarded-value expressions

{/* source:cpp-language-expressions:0042 */}
A discarded-value expression is an expression that is used for its side-effects only. The value calculated from such expression is discarded. Such expressions include the full-expression of any [expression statement](/docs/cpp/language/statements#Expression_statements), the left-hand operand of the built-in comma operator, or the operand of a cast-expression that casts to the type `void`.

{/* source:cpp-language-expressions:0043 */}
Array-to-pointer and function-to-pointer conversions are never applied to the value calculated by a discarded-value expression. The lvalue-to-rvalue conversion is applied if and only if the expression is a [volatile-qualified](/docs/cpp/language/declarations/cv) glvalue and has one of the following forms (built-in meaning required, possibly parenthesized):

{/* source:cpp-language-expressions:0044 */}
- id-expression,
- array subscript expression,
- class member access expression,
- indirection,
- pointer-to-member operation,
- conditional expression where both the second and the third operands are one of these expressions,
- comma expression where the right operand is one of these expressions.

{/* source:cpp-language-expressions:0045 */}
In addition, if the lvalue is of volatile-qualified class type, a volatile copy constructor is required to initialize the resulting rvalue temporary.

{/* source:cpp-language-expressions:0046 */}
<Revision since="C++17">
If the expression is a non-void prvalue (after any lvalue-to-rvalue conversion that might have taken place), [temporary materialization](/docs/cpp/language/expressions/implicit_cast#Temporary_materialization) occurs.

Compilers may issue warnings when an expression other than cast to `void` discards a value declared [`[[nodiscard]]`](/docs/cpp/language/declarations/attributes/nodiscard).
</Revision>

{/* source:cpp-language-expressions:0047 */}
<Revision since="C++20">
## Expression-equivalence

A number of expressions `e1`, `e2`, ..., `eN` are *expression-equivalent* if all following conditions are satisfied:

1. They have the same effects.
2. Either they are all [constant subexpressions](/docs/cpp/language/expressions/constant_expression#Constant_subexpression) or neither is.
3. Either they are all [noexcept](/docs/cpp/language/exceptions/noexcept_spec) or else neither is.

`e1` is *expression-equivalent to* `e2` if and only if `e1` and `e2` are expression-equivalent (which means `e2` is also expression-equivalent to `e1`).
</Revision>
