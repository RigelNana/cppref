## Explanation

{/* source:cpp-language-string-literal:0001 */}
<ParameterList>
  <Parameter name="s-char-seq">A sequence of one or more *s-char*s</Parameter>
  <Parameter name="s-char">
One of
  - a *basic-s-char*
  - an escape sequence, as defined in [escape sequences](/docs/cpp/language/expressions/escape)
  - a universal character name, as defined in [escape sequences](/docs/cpp/language/expressions/escape)
</Parameter>
  <Parameter name="basic-s-char">A character from the [translation character set](/docs/cpp/language/basic_concepts/charset#Translation_character_set), except the double-quote `"`, backslash `\`, or new-line character</Parameter>
  <Parameter name="d-char-seq">A sequence of one or more *d-char*s, at most 16 characters long</Parameter>
  <Parameter name="d-char">A character from the [basic character set](/docs/cpp/language/basic_concepts/charset#Basic_character_set), except parentheses, backslash and [spaces](/docs/cpp/library/text/byte/isspace)</Parameter>
  <Parameter name="r-char-seq">A sequence of one or more *r-char*s, except that it must not contain the closing sequence `)`*d-char-seq*`"`</Parameter>
  <Parameter name="r-char">A character from the [translation character set](/docs/cpp/language/basic_concepts/charset#Translation_character_set)</Parameter>
</ParameterList>

{/* source:cpp-language-string-literal:0003 */}
In the types listed in the table above, `N` is the number of encoded code units, which is determined [below](/docs/cpp/language/expressions/string_literal#Initialization).

{/* source:cpp-language-string-literal:0004 */}
Ordinary<InlineRevision since="C++11"> and UTF-8</InlineRevision> string literals are collectively referred to as narrow string literals.

{/* source:cpp-language-string-literal:0005 */}
Evaluating a string literal results in a string literal object with static [storage duration](/docs/cpp/language/declarations/storage_duration). Whether all string literals are stored in [nonoverlapping objects](/docs/cpp/language/basic_concepts/objects#Subobjects) and whether successive evaluations of a string literal yield the same or a different object is unspecified.

{/* source:cpp-language-string-literal:0006 */}
The effect of attempting to modify a string literal object is undefined.

{/* source:cpp-language-string-literal:0007 */}
```cpp
bool b = "bar" == 3 + "foobar"; // can be true or false, unspecified

const char* pc = "Hello";
char* p = const_cast<char*>(pc);
p[0] = 'M'; // undefined behavior
```

## Raw string literals

Raw string literals are string literals with a prefix containing `R` (syntaxes (2,4,6,8,10)). They do not escape any character, which means anything between the delimiters *d-char-seq*`(` and `)`*d-char-seq* becomes part of the string. The terminating *d-char-seq* is the same sequence of characters as the initial *d-char-seq*.

```cpp
// OK: contains one backslash,
// equivalent to "\\"
R"(\)";

// OK: contains four \n pairs,
// equivalent to "\\n\\n\\n\\n"
R"(\n\n\n\n)";

// OK: contains one close-parenthesis, two double-quotes and one open-parenthesis,
// equivalent to ")\"\"("
R"-()""()-";

// OK: equivalent to "\n)\\\na\"\"\n"
R"a(
)\
a""
)a";

// OK: equivalent to "x = \"\"\\y\"\""
R"(x = ""\y"")";

// R"<<(-_-)>>"; // Error: begin and end delimiters do not match
// R"-()-"-()-"; // Error: )-" appears in the middle and terminates the literal
```
</Revision>

## Initialization

{/* source:cpp-language-string-literal:0009 */}
String literal objects are initialized with the sequence of code unit values corresponding to the string literal's sequence of *s-char*s<InlineRevision since="C++11"> and *r-char*s</InlineRevision>, plus a terminating null character (U+0000), in order as follows:

{/* source:cpp-language-string-literal:0010 */}
1. For each contiguous sequence of *basic-s-char*s,<InlineRevision since="C++11"> *r-char*s,</InlineRevision> [simple escape sequences](/docs/cpp/language/expressions/escape) and [universal character names](/docs/cpp/language/expressions/escape), the sequence of character it denotes is encoded to a code unit sequence using the string literal's associated character encoding. If a character lacks representation in the associated character encoding, then the program is ill-formed.

{/* source:cpp-language-string-literal:0011 */}
   If the associated character encoding is stateful, the first such sequence is encoded beginning with the initial encoding state and each subsequent sequence is encoded beginning with the final encoding state of the prior sequence.

{/* source:cpp-language-string-literal:0012 */}
2. For each [numeric escape sequence](/docs/cpp/language/expressions/escape), given `v` as the integer value represented by the octal or hexadecimal number comprising the sequence of digits in the escape sequence, and `T` as the string literal's array element type (see the table [above](/docs/cpp/language/expressions/string_literal#Info_table)):

   - If `v` does not exceed the range of representable values of `T`, then the escape sequence contributes a single code unit with value `v`.
   - Otherwise, if<InlineRevision since="C++11"> the string literal is of syntax (1) or (3), and</InlineRevision> `v` does not exceed the range of representable values of the corresponding unsigned type for the underlying type of `T`, then the escape sequence contributes a single code unit with a unique value of type `T`, that is congruent to v mod 2S, where `S` is the width of `T`.
   - Otherwise, the program is ill-formed.

{/* source:cpp-language-string-literal:0013 */}
   If the associated character encoding is stateful, all such sequences have no effect on encoding state.

{/* source:cpp-language-string-literal:0014 */}
3. Each [conditional escape sequence](/docs/cpp/language/expressions/escape) contributes an implementation-defined code unit sequence.

{/* source:cpp-language-string-literal:0015 */}
   If the associated character encoding is stateful, it is implementation-defined what effect these sequences have on encoding state.

## Concatenation

{/* source:cpp-language-string-literal:0016 */}
Adjacent string literals are concatenated at [translation phase 6](/docs/cpp/language/basic_concepts/translation_phases#Phase_6) (after preprocessing):

{/* source:cpp-language-string-literal:0017 */}
- If the two string literals are of the same [kind](/docs/cpp/language/expressions/string_literal#Explanation), the concatenated string literal is also of that kind.

{/* source:cpp-language-string-literal:0018 */}
<Revision until="C++11">
- If an ordinary string literal is adjacent to a wide string literal, the behavior is undefined.
</Revision>

<Revision since="C++11">
- If an ordinary string literal is adjacent to a non-ordinary string literal, the concatenated string literal is of the kind of the latter.
- If a UTF-8 string literal is adjacent to a wide string literal, the program is ill-formed.

<Revision until="C++23">
- Any other combination is conditionally supported with implementation-defined semantics.[^1]
</Revision>

<Revision since="C++23">
- Any other combination is ill-formed.
</Revision>
</Revision>

{/* source:cpp-language-string-literal:0019 */}
```cpp
"Hello, " " world!" // at phase 6, the 2 string literals form "Hello, world!"

L"Δx = %" PRId16    // at phase 4, PRId16 expands to "d"
                    // at phase 6, L"Δx = %" and "d" form L"Δx = %d"
```

{/* source:cpp-language-string-literal:0020 */}
[^1]: No known implementation supports such concatenation.

## Unevaluated strings

{/* source:cpp-language-string-literal:0021 */}
The following contexts expect a string literal, but do not evaluate it:

{/* source:cpp-language-string-literal:0022 */}
- [language linkage](/docs/cpp/language/declarations/language_linkage) specification

{/* source:cpp-language-string-literal:0023 */}
<Revision since="C++11">
- [`static_assert`](/docs/cpp/language/declarations/static_assert)
- [literal operator](/docs/cpp/language/expressions/user_literal#Literal_operators) name
</Revision>

<Revision since="C++14">
- [`[[deprecated]]`](/docs/cpp/language/declarations/attributes/deprecated)
</Revision>

<Revision since="C++20">
- [`[[nodiscard]]`](/docs/cpp/language/declarations/attributes/nodiscard)
</Revision>

<Revision since="C++26">
- [deleted function body](/docs/cpp/language/functions/function#Deleted_functions)
</Revision>

{/* source:cpp-language-string-literal:0024 */}
<Revision until="C++26">
It is unspecified whether non-ordinary string literals are allowed in these contexts<InlineRevision since="C++11">, except that a literal operator name must use an ordinary string literal</InlineRevision>.
</Revision>

<Revision since="C++26">
Only ordinary string literals are allowed in these contexts.

Each [universal character name](/docs/cpp/language/expressions/escape) and each [simple escape sequence](/docs/cpp/language/expressions/escape) in an unevaluated string is replaced by the member of the [translation character set](/docs/cpp/language/basic_concepts/charset) it denotes. An unevaluated string that contains a numeric escape sequence or a conditional escape sequence is ill-formed.
</Revision>

## Notes

{/* source:cpp-language-string-literal:0025 */}
String literals can be used to [initialize character arrays](/docs/cpp/language/initialization/aggregate_initialization). If an array is initialized like `char str[] = "foo";`, `str` will contain a copy of the string `"foo"`.

{/* source:cpp-language-string-literal:0026 */}
<Revision until="C++11">
String literals are convertible and assignable to non-const `char*` or `wchar_t*` in order to be compatible with C, where string literals are of types `char[N]` and `wchar_t[N]`. Such implicit conversion is deprecated.
</Revision>

<Revision since="C++11">
String literals are not convertible or assignable to non-const `CharT*`. An explicit cast (e.g. [`const_cast`](/docs/cpp/language/expressions/const_cast)) must be used if such conversion is wanted.
</Revision>

{/* source:cpp-language-string-literal:0027 */}
A string literal is not necessarily a null-terminated character sequence: if a string literal has embedded null characters, it represents an array which contains more than one string.

{/* source:cpp-language-string-literal:0028 */}
```cpp
const char* p = "abc\0def"; // std::strlen(p) == 3, but the array has size 8
```

{/* source:cpp-language-string-literal:0029 */}
If a valid hexadecimal digit follows a hexadecimal escape sequence in a string literal, it would fail to compile as an invalid escape sequence. String concatenation can be used as a workaround:

{/* source:cpp-language-string-literal:0030 */}
```cpp
//const char* p = "\xfff"; // error: hexadecimal escape sequence out of range
const char* p = "\xff""f"; // OK: the literal is const char[3] holding {'\xff','f','\0'}
```

## Example

{/* source:cpp-language-string-literal:0032 */}
```cpp
#include <iostream>

// array1 and array2 contains the same values:
char array1[] = "Foo" "bar";
char array2[] = {'F', 'o', 'o', 'b', 'a', 'r', '\0'};

const char* s1 = R"foo(
Hello
  World
)foo";
// same as
const char* s2 = "\nHello\n  World\n";
// same as
const char* s3 = "\n"
                 "Hello\n"
                 "  World\n";

const wchar_t* s4 = L"ABC" L"DEF"; // OK, same as
const wchar_t* s5 = L"ABCDEF";
const char32_t* s6 = U"GHI" "JKL"; // OK, same as
const char32_t* s7 = U"GHIJKL";
const char16_t* s9 = "MN" u"OP" "QR"; // OK, same as
const char16_t* sA = u"MNOPQR";

// const auto* sB = u"Mixed" U"Types";
        // before C++23 may or may not be supported by
        // the implementation; ill-formed since C++23

const wchar_t* sC = LR"--(STUV)--"; // OK, raw string literal

int main()
{
    std::cout << array1 << ' ' << array2 << '\n'
              << s1 << s2 << s3 << std::endl;
    std::wcout << s4 << ' ' << s5 << ' ' << sC
               << std::endl;
}
```

Output:

```text
Foobar Foobar

Hello
  World

Hello
  World

Hello
  World

ABCDEF ABCDEF STUV
```
