{/* source:cpp-language-operator-comparison:0000 */}
Compares the arguments.

{/* source:cpp-language-operator-comparison:0001 */}
| Operator name | Syntax | [Overloadable](/docs/cpp/language/expressions/operators) | Prototype examples (for `class T`) | |
| --- | --- | --- | --- | --- |
| | | | Inside class definition | Outside class definition |
| Equal to | `a == b` | Yes | `bool T::operator==(const U& b) const;` | `bool operator==(const T& a, const U& b);` |
| Not equal to | `a != b` | Yes | `bool T::operator!=(const U& b) const;` | `bool operator!=(const T& a, const U& b);` |
| Less than | `a < b` | Yes | `bool T::operator<(const U& b) const;` | `bool operator<(const T& a, const U& b);` |
| Greater than | `a > b` | Yes | `bool T::operator>(const U& b) const;` | `bool operator>(const T& a, const U& b);` |
| Less than or equal to | `a <= b` | Yes | `bool T::operator<=(const U& b) const;` | `bool operator<=(const T& a, const U& b);` |
| Greater than or equal to | `a >= b` | Yes | `bool T::operator>=(const U& b) const;` | `bool operator>=(const T& a, const U& b);` |
| Three-way comparison (C++20) | `a <=> b` | Yes | `R T::operator<=>(const U& b) const;`[^1] | `R operator<=>(const T& a, const U& b);`[^1] |

**Notes**

- Where built-in operators return `bool`, most [user-defined overloads](/docs/cpp/language/expressions/operators) also return `bool` so that the user-defined operators can be used in the same manner as the built-ins. However, in a user-defined operator overload, any type can be used as return type (including `void`).
- `U` can be any type including `T`.

[^1]: *`R`* is the return type of `operator<=>` ([see below](/docs/cpp/language/expressions/operator_comparison#Three-way_comparison))

## Two-way comparison

{/* source:cpp-language-operator-comparison:0002 */}
The two-way comparison operator expressions have the form

#### Relational operators

{/* source:cpp-language-operator-comparison:0003 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="lhs < rhs" />
  <Declaration id="2" language="cpp" grammar code="lhs > rhs" />
  <Declaration id="3" language="cpp" grammar code="lhs <= rhs" />
  <Declaration id="4" language="cpp" grammar code="lhs >= rhs" />
</DeclarationDoc>

#### Equality operators

{/* source:cpp-language-operator-comparison:0004 */}
<DeclarationDoc>
  <Declaration id="5" language="cpp" grammar code="lhs == rhs" />
  <Declaration id="6" language="cpp" grammar code="lhs != rhs" />
</DeclarationDoc>

{/* source:cpp-language-operator-comparison:0005 */}
1. Returns `true` if *lhs* is less than *rhs*, `false` otherwise.

{/* source:cpp-language-operator-comparison:0006 */}
2. Returns `true` if *lhs* is greater than *rhs*, `false` otherwise.

{/* source:cpp-language-operator-comparison:0007 */}
3. Returns `true` if *lhs* is less than or equal to *rhs*, `false` otherwise.

{/* source:cpp-language-operator-comparison:0008 */}
4. Returns `true` if *lhs* is greater than or equal to *rhs*, `false` otherwise.

{/* source:cpp-language-operator-comparison:0009 */}
5. Returns `true` if *lhs* is equal to *rhs*, `false` otherwise.

{/* source:cpp-language-operator-comparison:0010 */}
6. Returns `true` if *lhs* is not equal to *rhs*, `false` otherwise.

### Built-in two-way comparison operators

{/* source:cpp-language-operator-comparison:0011 */}
For built-in two-way comparison operators, [lvalue-to-rvalue conversions](/docs/cpp/language/expressions/implicit_cast#Lvalue-to-rvalue_conversion)<InlineRevision until="C++26">, [array-to-pointer conversions](/docs/cpp/language/expressions/implicit_cast#Array-to-pointer_conversion)</InlineRevision> and [function-to-pointer conversions](/docs/cpp/language/expressions/implicit_cast#Function-to-pointer_conversion) are applied to *lhs* and *rhs*.

{/* source:cpp-language-operator-comparison:0012 */}
<Revision since="C++20" until="C++26">
The comparison is deprecated if both *lhs* and *rhs* have array type prior to the application of these conversions.
</Revision>

<Revision since="C++26">
For built-in relational operators, if one of the operands is a pointer, the [array-to-pointer conversion](/docs/cpp/language/expressions/implicit_cast#Array-to-pointer_conversion) is performed on the other operand.

For built-in equality operators, if one of the operands is a pointer or a [null pointer constant](/docs/cpp/language/declarations/pointer#Null_pointers), the array-to-pointer conversion is performed on the other operand.
</Revision>

{/* source:cpp-language-operator-comparison:0013 */}
For built-in two-way comparison operators, the result is a `bool` prvalue.

### Built-in arithmetic comparison

{/* source:cpp-language-operator-comparison:0014 */}
If the converted operands both have arithmetic or enumeration type (scoped or unscoped), [usual arithmetic conversions](/docs/cpp/language/expressions/usual_arithmetic_conversions) are performed on both operands. The values are compared after conversions:

{/* source:cpp-language-operator-comparison:0015 */}
```cpp
#include <iostream>

int main()
{
    static_assert(sizeof(unsigned char) < sizeof(int),
                  "Cannot compare signed and smaller unsigned properly");
    int a = -1;
    int b = 1;
    unsigned int c = 1;
    unsigned char d = 1;

    std::cout << std::boolalpha
              << "Comparing two signed values:\n"
                 " -1 == 1 ? " << (a == b) << "\n"
                 " -1 <  1 ? " << (a <  b) << "\n"
                 " -1 >  1 ? " << (a >  b) << "\n"
                 "Comparing signed and unsigned:\n"
                 // may issue different-signedness warning:
                 " -1 == 1 ? " << (a == c) << "\n"
                 // may issue different-signedness warning:
                 " -1 <  1 ? " << (a <  c) << "\n"
                 // may issue different-signedness warning:
                 " -1 >  1 ? " << (a >  c) << "\n"
                 "Comparing signed and smaller unsigned:\n"
                 " -1 == 1 ? " << (a == d) << "\n"
                 " -1 <  1 ? " << (a <  d) << "\n"
                 " -1 >  1 ? " << (a >  d) << '\n';
}
```

Output:

```text
Comparing two signed values:
 -1 == 1 ? false
 -1 <  1 ? true
 -1 >  1 ? false
Comparing signed and unsigned:
 -1 == 1 ? false
 -1 <  1 ? false
 -1 >  1 ? true
Comparing signed and smaller unsigned:
 -1 == 1 ? false
 -1 <  1 ? true
 -1 >  1 ? false
```

### Built-in pointer equality comparison

{/* source:cpp-language-operator-comparison:0016 */}
The converted operands of equality operators `==` and `!=` can also have<InlineRevision since="C++11"> the type [`std::nullptr_t`](/docs/cpp/library/utility/types/nullptr_t),</InlineRevision> pointer type or pointer-to-member type.

{/* source:cpp-language-operator-comparison:0017 */}
Built-in pointer equality comparison has three possible results: equal, unequal and unspecified. The values yielded by equality operators for built-in pointer equality comparison is listed below:

{/* source:cpp-language-operator-comparison:0018 */}
| Comparison result of `p` and `q` | Value yielded by `p == q` | `p != q` |
| --- | --- | --- |
| equal | `true` | `false` |
| unequal | `false` | `true` |
| unspecified | unspecified `bool` value | unspecified `bool` value |

{/* source:cpp-language-operator-comparison:0019 */}
If at least one of converted *lhs* and *rhs* is a pointer, [pointer conversions](/docs/cpp/language/expressions/implicit_cast#Pointer_conversions)<InlineRevision since="C++17">, [function pointer conversions](/docs/cpp/language/expressions/implicit_cast#Function_pointer_conversions)</InlineRevision> and [qualification conversions](/docs/cpp/language/expressions/implicit_cast#Qualification_conversions) are performed on both converted operands to bring them to their [composite pointer type](/docs/cpp/language/declarations/pointer#Composite_pointer_type). The two pointers of the composite pointer type are compared as follows:

{/* source:cpp-language-operator-comparison:0020 */}
- If one pointer [represents the address](/docs/cpp/language/declarations/pointer#Pointers) of a complete object, and another pointer

{/* source:cpp-language-operator-comparison:0021 */}
  - represents the address past the end of a different complete non-array object, or
  - represents the address one past the last element of a different complete array object,
  - the result of the comparison is unspecified.

{/* source:cpp-language-operator-comparison:0022 */}
- Otherwise, if the pointers are both null, both point to the same function, or both represent the same address (i.e., they point to or are past the end of the same object), they compare equal.
- Otherwise, the pointers compare unequal.

{/* source:cpp-language-operator-comparison:0023 */}
If at least one of converted *lhs* and *rhs* is a pointer to member, [pointer-to-member conversions](/docs/cpp/language/expressions/implicit_cast#Pointer-to-member_conversions)<InlineRevision since="C++17">, [function pointer conversions](/docs/cpp/language/expressions/implicit_cast#Function_pointer_conversions)</InlineRevision> and [qualification conversions](/docs/cpp/language/expressions/implicit_cast#Qualification_conversions) are performed on both converted operands to bring them to their [composite pointer type](/docs/cpp/language/declarations/pointer#Composite_pointer_type). The two pointers to members of the composite pointer type are compared as follows:

{/* source:cpp-language-operator-comparison:0024 */}
- If two pointers to members are both the null member pointer value, they compare equal.
- If only one of two pointers to members is the null member pointer value, they compare unequal.
- If either is a pointer to a [virtual member function](/docs/cpp/language/classes/virtual), the result is unspecified.
- If one refers to a member of class C1 and the other refers to a member of a different class C2, where neither is a base class of the other, the result is unspecified.
- If both refer to (possibly different) members of the same [union](/docs/cpp/language/classes/union), they compare equal.
- Otherwise, two pointers to members compare equal if they would refer to the same member of the same [most derived object](/docs/cpp/language/basic_concepts/objects#Subobjects) or the same subobject if indirection with a hypothetical object of the associated class type were performed, otherwise they compare unequal.

{/* source:cpp-language-operator-comparison:0025 */}
```cpp
struct P {};
struct Q : P { int x; };
struct R : P { int x; };

int P::*bx = (int(P::*)) &Q::x;
int P::*cx = (int(P::*)) &R::x;

bool b1 = (bx == cx); // unspecified

struct B
{
    int f();
};
struct L : B {};
struct R : B {};
struct D : L, R {};

int (B::*pb)() = &B::f;
int (L::*pl)() = pb;
int (R::*pr)() = pb;
int (D::*pdl)() = pl;
int (D::*pdr)() = pr;

bool x = (pdl == pdr); // false
bool y = (pb == pl);   // true
```

{/* source:cpp-language-operator-comparison:0026 */}
<Revision since="C++11">
Two operands of type [`std::nullptr_t`](/docs/cpp/library/utility/types/nullptr_t) or one operand of type [`std::nullptr_t`](/docs/cpp/library/utility/types/nullptr_t) and the other a null pointer constant compare equal.
</Revision>

### Built-in pointer relational comparison

{/* source:cpp-language-operator-comparison:0027 */}
The converted operands of relational operators `>`, `<`, `>=` and `<=` can also have pointer type.

{/* source:cpp-language-operator-comparison:0028 */}
Built-in pointer relational comparison on unequal pointers `p` and `q` has three possible results: `p` is greater, `q` is greater and unspecified. The values yielded by relational operators for built-in pointer relational comparison is listed below:

{/* source:cpp-language-operator-comparison:0029 */}
| Comparison result of `p` and `q` | Value yielded by `p > q` | `p < q` | `p >= q` | `p <= q` |
| --- | --- | --- | --- | --- |
| equal | `false` | `false` | `true` | `true` |
| `p` is greater | `true` | `false` | `true` | `false` |
| `q` is greater | `false` | `true` | `false` | `true` |
| unspecified | unspecified `bool` value | unspecified `bool` value | unspecified `bool` value | unspecified `bool` value |

{/* source:cpp-language-operator-comparison:0030 */}
If converted *lhs* and *rhs* are both pointers, [pointer conversions](/docs/cpp/language/expressions/implicit_cast#Pointer_conversions)<InlineRevision since="C++17">, [function pointer conversions](/docs/cpp/language/expressions/implicit_cast#Function_pointer_conversions)</InlineRevision> and [qualification conversions](/docs/cpp/language/expressions/implicit_cast#Qualification_conversions) are performed on both converted operands to bring them to their [composite pointer type](/docs/cpp/language/declarations/pointer#Composite_pointer_type). The two pointers of the composite pointer type are compared as follows:

{/* source:cpp-language-operator-comparison:0031 */}
- If the pointers compare equal or the equality comparison result is unspecified, the relational comparison result falls into the same category.
- Otherwise (the pointers compare unequal), if any of the pointers is not a pointer to object, the result is unspecified.
- Otherwise (both pointers point to objects), the result is defined in terms of a partial order consistent with the following rules:

{/* source:cpp-language-operator-comparison:0032 */}
  - Given two different elements `high` and `low` of an array such than `high` has higher subscript than `low`, if one pointer points to `high` (or a subobject of `high`) and the other pointer points to `low` (or a subobject of `low`), the former compares greater than the latter.
  - If one pointer points to an element `elem` (or to a subobject of `elem`) of an array, and the other pointer is past the end of the same array, the past-the-end pointer compares greater than the other pointer.
  - If one pointer points to a complete object, a base class subobject or a member subobject `obj` (or to a subobject of `obj`), and the other pointer is past the end of `obj`, the past-the-end pointer compares greater than the other pointer.

{/* source:cpp-language-operator-comparison:0033 */}
  - If the pointers point to different<InlineRevision since="C++20"> [non-zero-sized](/docs/cpp/language/declarations/attributes/no_unique_address)</InlineRevision> non-static data members<InlineRevision until="C++23"> with the same [member access](/docs/cpp/language/classes/access)</InlineRevision> of the same object of a non-union class type, or to subobjects of such members, recursively, the pointer to the later declared member compares greater than the other pointer.
  - Otherwise, the result is unspecified.

### Pointer total order

{/* source:cpp-language-operator-comparison:0034 */}
There exists an implementation-defined strict total order over pointers in each program. The strict total order is consistent with the partial order described above: unspecified results become implementation-defined, while other results stay the same.

{/* source:cpp-language-operator-comparison:0035 */}
Pointer comparison with the strict total order is applied in the following cases:

{/* source:cpp-language-operator-comparison:0036 */}
- Calling the `operator()` of the pointer type specializations of [`std::less`](/docs/cpp/library/utility/functional/less), [`std::greater`](/docs/cpp/library/utility/functional/greater), [`std::less_equal`](/docs/cpp/library/utility/functional/less_equal), and [`std::greater_equal`](/docs/cpp/library/utility/functional/greater_equal).

{/* source:cpp-language-operator-comparison:0037 */}
<Revision since="C++14">
- Calling built-in operators comparing pointers from the `operator()` of specializations [`std::less<void>`](/docs/cpp/library/utility/functional/less_void), [`std::greater<void>`](/docs/cpp/library/utility/functional/greater_void), [`std::less_equal<void>`](/docs/cpp/library/utility/functional/less_equal_void), and [`std::greater_equal<void>`](/docs/cpp/library/utility/functional/greater_equal_void).
</Revision>

<Revision since="C++20">
- Calling built-in `operator<=>` comparing pointers from the `operator()` of [`std::compare_three_way`](/docs/cpp/library/utility/functional/compare_three_way).
- Calling built-in `operator==` comparing pointers from the `operator()` of [`std::ranges::equal_to`](/docs/cpp/library/utility/functional/ranges/equal_to) and [`std::ranges::not_equal_to`](/docs/cpp/library/utility/functional/ranges/not_equal_to).
- Calling built-in `operator<` comparing pointers from the `operator()` of [`std::ranges::less`](/docs/cpp/library/utility/functional/ranges/less), [`std::ranges::greater`](/docs/cpp/library/utility/functional/ranges/greater), [`std::ranges::less_equal`](/docs/cpp/library/utility/functional/ranges/less_equal), and [`std::ranges::greater_equal`](/docs/cpp/library/utility/functional/ranges/greater_equal).
</Revision>

struct Foo
{
    int n1;
    int n2;
};

union Union
{
    int n;
    double d;
};

int main()
{
    std::cout << std::boolalpha;

    char a[4] = "abc";
    char* p1 = &a[1];
    char* p2 = &a[2];
    std::cout << "Pointers to array elements:\n"
              << "p1 == p2? " << (p1 == p2) << '\n'
              << "p1 <  p2? " << (p1 <  p2) << '\n';

    Foo f;
    int* p3 = &f.n1;
    int* p4 = &f.n2;
    std::cout << "Pointers to members of a class:\n"
              << "p3 == p4? " << (p3 == p4) << '\n'
              << "p3 <  p4? " << (p3 <  p4) << '\n';

    Union u;
    int* p5 = &u.n;
    double* p6 = &u.d;
    std::cout << "Pointers to members of a union:\n"
              << "p5 == (void*)p6? " << (p5 == (void*)p6) << '\n'
              << "p5 <  (void*)p6? " << (p5 <  (void*)p6) << '\n';
}
```

p1 <  p2? true
Pointers to members of a class:
p3 == p4? false
p3 <  p4? true
Pointers to members of a union:
p5 == (void*)p6? true
p5 <  (void*)p6? false
```

### Three-way comparison

The three-way comparison operator expressions have the form

<DeclarationDoc>
  <Declaration language="cpp" grammar code="a <=> b" />
</DeclarationDoc>

The expression returns an object such that

- `(a <=> b) < 0` if `a < b`,
- `(a <=> b) > 0` if `a > b`,
- `(a <=> b) == 0` if `a` and `b` are equal/equivalent.

If one of the operands is of type `bool` and the other is not, the program is ill-formed.

If both operands have arithmetic types, or if one operand has unscoped enumeration type and the other has integral type, the usual arithmetic conversions are applied to the operands, and then

- If a narrowing conversion is required, other than from an integral type to a floating point type, the program is ill-formed.
- Otherwise, if the operands have integral type, the operator yields a prvalue of type [`std::strong_ordering`](/docs/cpp/library/utility/compare/strong_ordering):
  - `std::strong_ordering::equal` if both operands are arithmetically equal,
  - `std::strong_ordering::less` if the first operand is arithmetically less than the second,
  - `std::strong_ordering::greater` otherwise.
- Otherwise, the operands have floating-point type, and the operator yields a prvalue of type [`std::partial_ordering`](/docs/cpp/library/utility/compare/partial_ordering). The expression `a <=> b` yields
  - `std::partial_ordering::less` if `a` is less than `b`,
  - `std::partial_ordering::greater` if `a` is greater than `b`,
  - `std::partial_ordering::equivalent` if `a` is equivalent to `b` (`-0 <=> +0` is equivalent),
  - `std::partial_ordering::unordered` (`NaN <=> anything` is unordered).

If both operands have the same enumeration type `E`, the operator yields the result of converting the operands to the underlying type of E and applying `<=>` to the converted operands.

If at least one of the operands is a pointer to object or pointer to member, [array-to-pointer conversions](/docs/cpp/language/expressions/implicit_cast#Array-to-pointer_conversion), [pointer conversions](/docs/cpp/language/expressions/implicit_cast#Pointer_conversions) and [qualification conversions](/docs/cpp/language/expressions/implicit_cast#Qualification_conversions) are applied to both operands to bring them to their [composite pointer type](/docs/cpp/language/declarations/pointer#Composite_pointer_type). For converted pointer operands `p` and `q`, `p <=> q` returns a prvalue of type [`std::strong_ordering`](/docs/cpp/library/utility/compare/strong_ordering):

- `std::strong_ordering::equal` if they [compare equal](/docs/cpp/language/expressions/operator_comparison#Built-in_pointer_equality_comparison),
- `std::strong_ordering::less` if `q` [compares greater than](/docs/cpp/language/expressions/operator_comparison#Built-in_pointer_relational_comparison) `p`,
- `std::strong_ordering::greater` if `p` compares greater than `q`,
- unspecified result if the two-way comparison result is unspecified.

Otherwise, the program is ill-formed.

### Overloads

In [overload resolution against user-defined operators](/docs/cpp/language/functions/overload_resolution#Call_to_an_overloaded_operator), for pointer or enumeration type `T`, the following function signature participates in overload resolution:

<DeclarationDoc>
  <Declaration language="cpp" code={`R operator<=>(T, T);`} />
</DeclarationDoc>

Where `R` is the ordering category type defined above.

```cpp
#include <compare>
#include <iostream>

int main()
{
    double foo = -0.0;
    double bar = 0.0;

    auto res = foo <=> bar;

    if (res < 0)
        std::cout << "-0 is less than 0";
    else if (res > 0)
        std::cout << "-0 is greater than 0";
    else if (res == 0)
        std::cout << "-0 and 0 are equal";
    else
        std::cout << "-0 and 0 are unordered";
}
```

Output:

```text
-0 and 0 are equal
```
</Revision>

## Notes

{/* source:cpp-language-operator-comparison:0046 */}
Because comparison operators group left-to-right, the expression `a < b < c` is parsed `(a < b) < c`, and not `a < (b < c)` or `(a < b) && (b < c)`.

{/* source:cpp-language-operator-comparison:0047 */}
```cpp
#include <iostream>

int main()
{
    int a = 3, b = 2, c = 1;

    std::cout << std::boolalpha
        << (a < b < c) << '\n' // true; maybe warning
        << ((a < b) < c) << '\n' // true
        << (a < (b < c)) << '\n' // false
        << ((a < b) && (b < c)) << '\n'; // false
}
```

{/* source:cpp-language-operator-comparison:0048 */}
A common requirement for [`user-defined operator<`](/docs/cpp/language/expressions/operators#Comparison_operators) is [strict weak ordering](https://en.wikipedia.org/wiki/Strict_weak_ordering). In particular, this is required by the standard algorithms and containers that work with [Compare](/docs/cpp/library/named_req/Compare) types: [`std::sort`](/docs/cpp/library/algorithm/sort), [`std::max_element`](/docs/cpp/library/algorithm/max_element), [`std::map`](/docs/cpp/library/container/map), etc.

{/* source:cpp-language-operator-comparison:0049 */}
The [comparison result](/docs/cpp/language/expressions/operator_comparison#Member_layout) of pointers to different non-static data members of the same class implies that non-static data members<InlineRevision until="C++23"> in each of the three [member access modes](/docs/cpp/language/classes/access)</InlineRevision> are positioned in memory in order of declaration.

{/* source:cpp-language-operator-comparison:0050 */}
Although the results of comparing pointers of random origin (e.g. not all pointing to members of the same array) is unspecified, many implementations provide [strict total ordering](https://en.wikipedia.org/wiki/Total_order#Strict_total_order) of pointers, e.g. if they are implemented as addresses within continuous virtual address space. Those implementations that do not (e.g. where not all bits of the pointer are part of a memory address and have to be ignored for comparison, or an additional calculation is required or otherwise pointer and integer is not a 1 to 1 relationship), provide a specialization of [`std::less`](/docs/cpp/library/utility/functional/less) for pointers that has that guarantee. This makes it possible to use all pointers of random origin as keys in standard associative containers such as [`std::set`](/docs/cpp/library/container/set) or [`std::map`](/docs/cpp/library/container/map).

{/* source:cpp-language-operator-comparison:0051 */}
For the types that are both [EqualityComparable](/docs/cpp/library/named_req/EqualityComparable) and [LessThanComparable](/docs/cpp/library/named_req/LessThanComparable), the C++ standard library makes a distinction between equality, which is the value of the expression `a == b` and equivalence, which is the value of the expression `!(a < b) && !(b < a)`.

{/* source:cpp-language-operator-comparison:0052 */}
Comparison between pointers and null pointer constants was removed by the resolution of [CWG issue 583](https://cplusplus.github.io/CWG/issues/583.html) included in [N3624](https://wg21.link/N3624):

{/* source:cpp-language-operator-comparison:0053 */}
```cpp
void f(char* p)
{
    if (p > 0) { /*...*/ } // Error with N3624, compiled before N3624
    if (p > nullptr) { /*...*/ } // Error with N3624, compiled before N3624
}

int main() {}
```

{/* source:cpp-language-operator-comparison:0054 */}
Three-way comparison can be automatically generated for class types, see [default comparisons](/docs/cpp/language/expressions/default_comparisons).

{/* source:cpp-language-operator-comparison:0055 */}
If both of the operands are arrays, three-way comparison is ill-formed.

{/* source:cpp-language-operator-comparison:0056 */}
```cpp
unsigned int i = 1;
auto r = -1 < i;    // existing pitfall: returns ‘false’
auto r2 = -1 <=> i; // Error: narrowing conversion required
```

- [other](/docs/cpp/language/expressions/operator_other): function call `a(...)`, comma `a, b`, conditional `a ? b : c`

**Special operators**

- [`static_cast`](/docs/cpp/language/expressions/static_cast) converts one type to another related type
- [`dynamic_cast`](/docs/cpp/language/expressions/dynamic_cast) converts within inheritance hierarchies
- [`const_cast`](/docs/cpp/language/expressions/const_cast) adds or removes [`cv`](/docs/cpp/language/declarations/cv)-qualifiers
- [`reinterpret_cast`](/docs/cpp/language/expressions/reinterpret_cast) converts type to unrelated type
- [C-style cast](/docs/cpp/language/expressions/explicit_cast) converts one type to another by a mix of `static_cast`, `const_cast`, and `reinterpret_cast`
- [`new`](/docs/cpp/language/expressions/new) creates objects with dynamic storage duration
- [`delete`](/docs/cpp/language/expressions/delete) destructs objects previously created by the new expression and releases obtained memory area
- [`sizeof`](/docs/cpp/language/expressions/sizeof) queries the size of a type
- [`sizeof...`](/docs/cpp/language/templates/sizeof...) queries the size of a [`pack`](/docs/cpp/language/templates/parameter_pack) <InlineRevision since="C++11" />
- [`typeid`](/docs/cpp/language/expressions/typeid) queries the type information of a type
- [`noexcept`](/docs/cpp/language/exceptions/noexcept) checks if an expression can throw an exception <InlineRevision since="C++11" />
- [`alignof`](/docs/cpp/language/expressions/alignof) queries alignment requirements of a type <InlineRevision since="C++11" />
