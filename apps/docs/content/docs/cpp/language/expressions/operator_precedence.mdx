{/* source:cpp-language-operator-precedence:0000 */}
The following table lists the precedence and associativity of C++ operators. Operators are listed top to bottom, in descending precedence. `a`, `b` and `c` are operands.

{/* source:cpp-language-operator-precedence:0001 */}
| Precedence | Operator | Description | Associativity |
| --- | --- | --- | --- |
| 1 | `a::b` | [Scope resolution](/docs/cpp/language/basic_concepts/name#Qualified_identifiers) | Left-to-right → |
| 2 | `a++` `a--` | Suffix/postfix [increment and decrement](/docs/cpp/language/expressions/operator_incdec) | Left-to-right → |
| 2 | `type` `(a)` `type` `{a}` | [Functional cast](/docs/cpp/language/expressions/explicit_cast) | Left-to-right → |
| 2 | `a()` | [Function call](/docs/cpp/language/expressions/operator_other#Built-in_function_call_operator) | Left-to-right → |
| 2 | `a[]` | [Subscript](/docs/cpp/language/expressions/operator_member_access#Built-in_subscript_operator) | Left-to-right → |
| 2 | `a.b` `a->b` | [Member access](/docs/cpp/language/expressions/operator_member_access#Built-in_member_access_operators) | Left-to-right → |
| 3 | `++a` `--a` | Prefix [increment and decrement](/docs/cpp/language/expressions/operator_incdec) | Right-to-left ← |
| 3 | `+a` `-a` | Unary [plus and minus](/docs/cpp/language/expressions/operator_arithmetic#Unary_arithmetic_operators) | Right-to-left ← |
| 3 | `!a` `~a` | [Logical NOT](/docs/cpp/language/expressions/operator_logical) and [bitwise NOT](/docs/cpp/language/expressions/operator_arithmetic#Bitwise_logic_operators) | Right-to-left ← |
| 3 | `(type)a` | [C-style cast](/docs/cpp/language/expressions/explicit_cast) | Right-to-left ← |
| 3 | `*a` | [Indirection](/docs/cpp/language/expressions/operator_member_access#Built-in_indirection_operator) (dereference) | Right-to-left ← |
| 3 | `&a` | [Address-of](/docs/cpp/language/expressions/operator_member_access#Built-in_address-of_operator) | Right-to-left ← |
| 3 | [`sizeof`](/docs/cpp/language/expressions/sizeof) | [Size-of](/docs/cpp/language/expressions/sizeof) [note 1] | Right-to-left ← |
| 3 | [`co_await`](/docs/cpp/language/keywords/co_await) | [await-expression](/docs/cpp/language/functions/coroutines) (C++20) | Right-to-left ← |
| 3 | [`new`](/docs/cpp/language/expressions/new) – [`new[]`](/docs/cpp/language/expressions/new) | [Dynamic memory allocation](/docs/cpp/language/expressions/new) | Right-to-left ← |
| 3 | [`delete`](/docs/cpp/language/expressions/delete) – [`delete[]`](/docs/cpp/language/expressions/delete) | [Dynamic memory deallocation](/docs/cpp/language/expressions/delete) | Right-to-left ← |
| 4 | `a.*b` `a->*b` | [Pointer-to-member](/docs/cpp/language/expressions/operator_member_access#Built-in_pointer-to-member_access_operators) | Left-to-right → |
| 5 | `a * b` `a / b` `a % b` | [Multiplication, division, and remainder](/docs/cpp/language/expressions/operator_arithmetic#Multiplicative_operators) | Left-to-right → |
| 6 | `a + b` `a - b` | [Addition and subtraction](/docs/cpp/language/expressions/operator_arithmetic#Additive_operators) | Left-to-right → |
| 7 | `a << b` `a >> b` | Bitwise [left shift and right shift](/docs/cpp/language/expressions/operator_arithmetic#Bitwise_shift_operators) | Left-to-right → |
| 8 | `a <=> b` | [Three-way comparison operator](/docs/cpp/language/expressions/operator_comparison#Three-way_comparison) (since C++20) | Left-to-right → |
| 9 | `a < b` `a <= b` `a > b` `a >= b` | For [relational operators](/docs/cpp/language/expressions/operator_comparison) `<` and `<=` and `>` and `>=` respectively | Left-to-right → |
| 10 | `a == b` `a != b` | For [equality operators](/docs/cpp/language/expressions/operator_comparison) `=` and `!=` respectively | Left-to-right → |
| 11 | `a & b` | [Bitwise AND](/docs/cpp/language/expressions/operator_arithmetic#Bitwise_logic_operators) | Left-to-right → |
| 12 | `a ^ b` | [Bitwise XOR](/docs/cpp/language/expressions/operator_arithmetic#Bitwise_logic_operators) (exclusive or) | Left-to-right → |
| 13 | `a \| b` | [Bitwise OR](/docs/cpp/language/expressions/operator_arithmetic#Bitwise_logic_operators) (inclusive or) | Left-to-right → |
| 14 | `a && b` | [Logical AND](/docs/cpp/language/expressions/operator_logical) | Left-to-right → |
| 15 | `a \|\| b` | [Logical OR](/docs/cpp/language/expressions/operator_logical) | Left-to-right → |
| 16 | `a ? b : c` | [Ternary conditional](/docs/cpp/language/expressions/operator_other#Conditional_operator) [note 2] | Right-to-left ← |
| 16 | [`throw`](/docs/cpp/language/exceptions/throw) | [throw operator](/docs/cpp/language/exceptions/throw) | Right-to-left ← |
| 16 | [`co_yield`](/docs/cpp/language/keywords/co_yield) | [yield-expression](/docs/cpp/language/functions/coroutines) (C++20) | Right-to-left ← |
| 16 | `a = b` | [Direct assignment](/docs/cpp/language/expressions/operator_assignment#Builtin_direct_assignment) (provided by default for C++ classes) | Right-to-left ← |
| 16 | `a += b` `a -= b` | [Compound assignment](/docs/cpp/language/expressions/operator_assignment#Builtin_compound_assignment) by sum and difference | Right-to-left ← |
| 16 | `a *= b` `a /= b` `a %= b` | [Compound assignment](/docs/cpp/language/expressions/operator_assignment#Builtin_compound_assignment) by product, quotient, and remainder | Right-to-left ← |
| 16 | `a <<= b` `a >>= b` | [Compound assignment](/docs/cpp/language/expressions/operator_assignment#Builtin_compound_assignment) by bitwise left shift and right shift | Right-to-left ← |
| 16 | `a &= b` `a ^= b` `a \|= b` | [Compound assignment](/docs/cpp/language/expressions/operator_assignment#Builtin_compound_assignment) by bitwise AND, XOR, and OR | Right-to-left ← |
| 17 | `a, b` | [Comma](/docs/cpp/language/expressions/operator_other#Built-in_comma_operator) | Left-to-right → |

{/* source:cpp-language-operator-precedence:0002 */}
1. ↑ The operand of `sizeof` cannot be a C-style type cast: the expression `sizeof (int) * p` is unambiguously interpreted as `(sizeof(int)) * p`, but not `sizeof((int)*p)`.
2. ↑ The expression in the middle of the conditional operator (between `?` and `:`) is parsed as if parenthesized: its precedence relative to `?:` is ignored.

{/* source:cpp-language-operator-precedence:0003 */}
When parsing an expression, an operator which is listed on some row of the table above with a precedence will be bound tighter (as if by parentheses) to its arguments than any operator that is listed on a row further below it with a lower precedence. For example, the expressions `std::cout << a & b` and `*p++` are parsed as `(std::cout << a) & b` and `*(p++)`, and not as `std::cout << (a & b)` or `(*p)++`.

{/* source:cpp-language-operator-precedence:0004 */}
Operators that have the same precedence are bound to their arguments in the direction of their associativity. For example, the expression `a = b = c` is parsed as `a = (b = c)`, and not as `(a = b) = c` because of right-to-left associativity of assignment, but `a + b - c` is parsed `(a + b) - c` and not `a + (b - c)` because of left-to-right associativity of addition and subtraction.

{/* source:cpp-language-operator-precedence:0005 */}
Associativity specification is redundant for unary operators and is only shown for completeness: unary prefix operators always associate right-to-left (`delete ++*p` is `delete(++(*p))`) and unary postfix operators always associate left-to-right (`a[1][2]++` is `((a[1])[2])++`). Note that the associativity is meaningful for member access operators, even though they are grouped with unary postfix operators: `a.b++` is parsed `(a.b)++` and not `a.(b++)`.

{/* source:cpp-language-operator-precedence:0006 */}
Operator precedence is unaffected by [operator overloading](/docs/cpp/language/expressions/operators). For example, `std::cout << a ? b : c;` parses as `(std::cout << a) ? b : c;` because the precedence of arithmetic left shift is higher than the conditional operator.

## Notes

{/* source:cpp-language-operator-precedence:0007 */}
Precedence and associativity are compile-time concepts and are independent from [order of evaluation](/docs/cpp/language/expressions/eval_order), which is a runtime concept.

{/* source:cpp-language-operator-precedence:0008 */}
The standard itself doesn't specify precedence levels. They are derived from the grammar.

{/* source:cpp-language-operator-precedence:0009 */}
[`const_cast`](/docs/cpp/language/expressions/const_cast), [`static_cast`](/docs/cpp/language/expressions/static_cast), [`dynamic_cast`](/docs/cpp/language/expressions/dynamic_cast), [`reinterpret_cast`](/docs/cpp/language/expressions/reinterpret_cast), [`typeid`](/docs/cpp/language/expressions/typeid), [`sizeof...`](/docs/cpp/language/templates/sizeof...), [`noexcept`](/docs/cpp/language/exceptions/noexcept) and [`alignof`](/docs/cpp/language/expressions/alignof) are not included since they are never ambiguous.

{/* source:cpp-language-operator-precedence:0010 */}
Some of the operators have [alternate spellings](/docs/cpp/language/expressions/operator_alternative) (e.g., `and` for `&&`, `or` for `||`, `not` for `!`, etc.).

{/* source:cpp-language-operator-precedence:0011 */}
In C, the ternary conditional operator has higher precedence than assignment operators. Therefore, the expression `e = a < d ? a++ : a = d`, which is parsed in C++ as `e = ((a < d) ? (a++) : (a = d))`, will fail to compile in C due to grammatical or semantic constraints in C. See the corresponding C page for details.
