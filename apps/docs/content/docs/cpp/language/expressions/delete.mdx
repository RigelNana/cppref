{/* source:cpp-language-delete:0000 */}
Destroys object(s) previously allocated by the [new-expression](/docs/cpp/language/expressions/new) and releases obtained memory area.

## Syntax

{/* source:cpp-language-delete:0001 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code=":: (optional) delete expression" />
  <Declaration id="2" language="cpp" grammar code=":: (optional) delete[] expression" />
</DeclarationDoc>

{/* source:cpp-language-delete:0002 */}
<ParameterList>
  <Parameter name="expression">
    one of the following:
    - an expression of class type [contextually implicitly convertible](/docs/cpp/language/expressions/implicit_cast) to a pointer to object type
    - a prvalue of pointer to object type
  </Parameter>
</ParameterList>

{/* source:cpp-language-delete:0003 */}
1. Destroys one non-array object created by a [new-expression](/docs/cpp/language/expressions/new).

{/* source:cpp-language-delete:0004 */}
2. Destroys an array created by a [new[]-expression](/docs/cpp/language/expressions/new).

## Explanation

{/* source:cpp-language-delete:0005 */}
Given the pointer evaluated from expression (after possible conversions) as `ptr`.

{/* source:cpp-language-delete:0006 */}
1. `ptr` must be one of
   - a null pointer,
   - a pointer to a non-array object created by a [new-expression](/docs/cpp/language/expressions/new), or
   - a pointer to a base subobject of a non-array object created by a [new-expression](/docs/cpp/language/expressions/new).

{/* source:cpp-language-delete:0007 */}
The pointed-to type of `ptr` must be [similar](/docs/cpp/language/expressions/implicit_cast#Similar_types) to the type of the object (or of a base subobject). If `ptr` is anything else, including if it is a pointer obtained by the array form of [new-expression](/docs/cpp/language/expressions/new), the behavior is [undefined](/docs/cpp/language/basic_concepts/ub).

{/* source:cpp-language-delete:0008 */}
2. `ptr` must be a null pointer or a pointer whose value is previously obtained by an array form of [new-expression](/docs/cpp/language/expressions/new) whose [allocation function](/docs/cpp/library/memory/new/operator_new) was not a non-allocating form (i.e. overload (10)).

{/* source:cpp-language-delete:0009 */}
The pointed-to type of `ptr` must be [similar](/docs/cpp/language/expressions/implicit_cast#Similar_types) to the element type of the array object. If `ptr` is anything else, including if it is a pointer obtained by the non-array form of [new-expression](/docs/cpp/language/expressions/new), the behavior is [undefined](/docs/cpp/language/basic_concepts/ub).

{/* source:cpp-language-delete:0010 */}
The result of the delete-expression always has type `void`.

{/* source:cpp-language-delete:0011 */}
If the object being deleted has incomplete class type at the point of deletion, <InlineRevision until="C++26">and the complete class has a non-trivial destructor or a deallocation function, the behavior is undefined</InlineRevision> <InlineRevision since="C++26">the program is ill-formed</InlineRevision>.

{/* source:cpp-language-delete:0012 */}
If `ptr` is not a null pointer<InlineRevision since="C++20"> and the [deallocation function](/docs/cpp/library/memory/new/operator_delete) is not a destroying delete</InlineRevision>, the delete-expression invokes the [destructor](/docs/cpp/language/classes/destructor) (if any) for the object that is being destroyed, or for every element of the array being destroyed (proceeding from the last element to the first element of the array). The destructor must be [accessible](/docs/cpp/language/classes/access) from the point where the delete-expression appears.

{/* source:cpp-language-delete:0013 */}
After that, whether or not an exception was thrown by any destructor, the delete-expression invokes the [deallocation function](/docs/cpp/library/memory/new/operator_delete): either `operator delete` (first version) or `operator delete[]` (second version)<InlineRevision since="C++14">, unless the matching new-expression was combined with another new-expression</InlineRevision>.

{/* source:cpp-language-delete:0014 */}
The deallocation function's name is [looked up](/docs/cpp/language/basic_concepts/lookup) in the scope of the dynamic type of the object pointed to by `ptr`, which means class-specific deallocation functions, if present, are found before the global ones. If `::` is present in the delete-expression, only the global namespace is examined by this lookup. In any case, any declarations other than of usual deallocation functions are discarded.

{/* source:cpp-language-delete:0015 */}
If any deallocation function is found, the function to be called is selected as follows (see [deallocation function](/docs/cpp/library/memory/new/operator_delete) for a more detailed description of these functions and their effects):

{/* source:cpp-language-delete:0016 */}
<Revision since="C++20">
- If at least one of the deallocation functions is a destroying delete, all non-destroying deletes are ignored.
</Revision>

<Revision since="C++17">
- If the type's alignment requirement exceeds `__STDCPP_DEFAULT_NEW_ALIGNMENT__`, alignment-aware deallocation functions (with a parameter of type [std::align_val_t](/docs/cpp/library/memory/new/align_val_t)) are preferred. For other types, the alignment-unaware deallocation functions (without a parameter of type [std::align_val_t](/docs/cpp/library/memory/new/align_val_t)) are preferred.
  - If more than one preferred functions are found, only preferred functions are considered in the next step.
  - If no preferred functions are found, the non-preferred ones are considered in the next step.
- If only one function is left, that function is selected.
</Revision>

{/* source:cpp-language-delete:0017 */}
- If the deallocation functions that were found are class-specific, size-unaware class-specific deallocation function (without a parameter of type [std::size_t](/docs/cpp/library/utility/types/size_t)) is preferred over size-aware class-specific deallocation function (with a parameter of type [std::size_t](/docs/cpp/library/utility/types/size_t)).

{/* source:cpp-language-delete:0018 */}
<Revision since="C++14">
- Otherwise, lookup reached global scope, and:
  - If the type is complete and if, for the array form only, the operand is a pointer to a class type with a non-trivial destructor or a (possibly multi-dimensional) array thereof, the global size-aware global function (with a parameter of type [std::size_t](/docs/cpp/library/utility/types/size_t)) is selected.
  - Otherwise, it is unspecified whether the global size-aware deallocation function (with a parameter of type [std::size_t](/docs/cpp/library/utility/types/size_t)) or the global size-unaware deallocation function (without a parameter of type [std::size_t](/docs/cpp/library/utility/types/size_t)) is selected.
</Revision>

{/* source:cpp-language-delete:0019 */}
The selected deallocation function must be [accessible](/docs/cpp/language/classes/access) from the point where the delete-expression appears, unless the deallocation function is selected at the point of definition of the [dynamic type](/docs/cpp/language/basic_concepts/type-id#Dynamic_type)'s [virtual destructor](/docs/cpp/language/classes/virtual#Virtual_destructor).

{/* source:cpp-language-delete:0020 */}
The pointer to the block of storage to be reclaimed is passed to the [deallocation function](/docs/cpp/library/memory/new/operator_delete) that was selected by the process above as the first argument. The size of the block is passed as the optional [std::size_t](/docs/cpp/library/utility/types/size_t) argument. <InlineRevision since="C++17">The alignment requirement is passed as the optional [std::align_val_t](/docs/cpp/library/memory/new/align_val_t) argument.</InlineRevision>

{/* source:cpp-language-delete:0021 */}
If `ptr` is a null pointer value, no destructors are called, and the deallocation function may or may not be called (it's unspecified), but the default deallocation functions are guaranteed to do nothing when passed a null pointer.

{/* source:cpp-language-delete:0022 */}
If `ptr` is a pointer to a base class subobject of the object that was allocated with [new](/docs/cpp/language/expressions/new), the destructor of the base class must be [virtual](/docs/cpp/language/classes/virtual), otherwise the behavior is undefined.

## Notes

{/* source:cpp-language-delete:0023 */}
A pointer to `void` cannot be deleted because it is not a pointer to an object type.

{/* source:cpp-language-delete:0024 */}
<Revision since="C++11">
Because a pair of brackets following the keyword `delete` is always interpreted as the array form of a delete-expression, a [lambda-expression](/docs/cpp/language/functions/lambda) with an empty capture list immediately after `delete` must be enclosed in parentheses.

```cpp
// delete []{ return new int; }(); // parse error
delete ([]{ return new int; })();  // OK
```
</Revision>
