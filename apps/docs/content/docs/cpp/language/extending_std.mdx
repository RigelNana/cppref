## Adding declarations to std

{/* source:cpp-language-extending-std:0000 */}
It is undefined behavior to add declarations or definitions to namespace `std` or to any namespace nested within `std`, with a few exceptions noted below.

{/* source:cpp-language-extending-std:0001 */}
```cpp
#include <utility>

namespace std
{
    // a function definition added to namespace std: undefined behavior
    pair<int, int> operator+(pair<int, int> a, pair<int, int> b)
    {
        return {a.first + b.first, a.second + b.second};
    }
}
```

## Adding template specializations

### Class templates

{/* source:cpp-language-extending-std:0002 */}
It is allowed to add template specializations for any standard library class template to the namespace `std` only if the declaration depends on at least one [program-defined type](/docs/cpp/language/basic_concepts/type-id#Program-defined_type) and the specialization satisfies all requirements for the original template, except where such specializations are prohibited.

{/* source:cpp-language-extending-std:0003 */}
```cpp
// Get the declaration of the primary std::hash template.
// We are not permitted to declare it ourselves.
// <typeindex> is guaranteed to provide such a declaration, 
// and is much cheaper to include than <functional>.

#include <typeindex> 

// Specialize std::hash so that MyType can be used as a key in 
// std::unordered_set and std::unordered_map.  Opening namespace
// std can accidentally introduce undefined behavior, and is not
// necessary for specializing class templates.
template<>
struct std::hash<MyType>
{
    std::size_t operator()(const MyType& t) const { return t.hash(); }
};
```

{/* source:cpp-language-extending-std:0004 */}
- Specializing the template [`std::complex`](/docs/cpp/library/numeric/complex) for any type other than `float`, `double`, and `long double` is unspecified.

{/* source:cpp-language-extending-std:0005 */}
- Specializations of [`std::numeric_limits`](/docs/cpp/library/utility/types/numeric_limits) must define all members declared <InlineRevision until="C++11">`static const`</InlineRevision><InlineRevision since="C++11">`static constexpr`</InlineRevision> in the primary template, in such a way that they are usable as [integral constant expressions](/docs/cpp/language/expressions/constant_expression).

{/* source:cpp-language-extending-std:0006 */}
<Revision since="C++11">
- None of the templates defined in [`<type_traits>`](/docs/cpp/library/headers/type_traits) may be specialized for a [program-defined type](/docs/cpp/language/basic_concepts/type-id#Program-defined_type), except for [`std::common_type`](/docs/cpp/library/meta/common_type)<InlineRevision since="C++20"> and [`std::basic_common_reference`](/docs/cpp/library/meta/common_reference#Helper_types)</InlineRevision>. This includes the [type traits](/docs/cpp/library/utility/types) and the class template [`std::integral_constant`](/docs/cpp/library/meta/integral_constant).
- Specializations of [`std::hash`](/docs/cpp/library/utility/hash) for program-defined types must satisfy [Hash](/docs/cpp/library/named_req/Hash) requirements.
- Specializations of [`std::atomic`](/docs/cpp/library/atomic/atomic) must have a deleted copy constructor, a deleted copy assignment operator, and a constexpr value constructor.
- Specializations of [`std::shared_ptr`](/docs/cpp/library/memory/shared_ptr) and [`std::weak_ptr`](/docs/cpp/library/memory/weak_ptr) must be [CopyConstructible](/docs/cpp/library/named_req/CopyConstructible) and [CopyAssignable](/docs/cpp/library/named_req/CopyAssignable). In addition, specializations of [`std::shared_ptr`](/docs/cpp/library/memory/shared_ptr) must be [LessThanComparable](/docs/cpp/library/named_req/LessThanComparable), and convertible to `bool`.
- Specializations of [`std::istreambuf_iterator`](/docs/cpp/library/iterator/istreambuf_iterator) must have a trivial copy constructor, a constexpr default constructor, and a trivial destructor.
</Revision>

{/* source:cpp-language-extending-std:0007 */}
<Revision until="C++17">
- [`std::unary_function`](/docs/cpp/library/utility/functional/unary_function) and [`std::binary_function`](/docs/cpp/library/utility/functional/binary_function) may not be specialized.

## Explicit instantiation of templates

{/* source:cpp-language-extending-std:0017 */}
It is allowed to explicitly instantiate a <InlineRevision since="C++20">class</InlineRevision> template defined in the standard library only if the declaration depends on the name of at least one [program-defined type](/docs/cpp/language/basic_concepts/type-id#Program-defined_type) and the instantiation meets the standard library requirements for the original template.

## Other restrictions

{/* source:cpp-language-extending-std:0019 */}
The namespace `std` may not be declared as an [inline namespace](/docs/cpp/language/declarations/namespace#Inline_namespaces).

{/* source:cpp-language-extending-std:0020 */}
<Revision since="C++20">
### Addressing restriction

The behavior of a C++ program is unspecified (possibly ill-formed) if it explicitly or implicitly attempts to form a pointer, reference (for free functions and static member functions) or pointer-to-member (for non-static member functions) to a standard library function or an instantiation of a standard library function template, unless it is designated an *addressable function* (see below).

Following code was well-defined in C++17, but leads to unspecified behaviors and possibly fails to compile since C++20:

```cpp
#include <cmath>
#include <memory>

int main()
{
    // by unary operator&
    auto fptr0 = &static_cast<float(&)(float, float)>(std::betaf);

    // by std::addressof
    auto fptr1 = std::addressof(static_cast<float(&)(float, float)>(std::betaf));

    // by function-to-pointer implicit conversion
    auto fptr2 = static_cast<float(&)(float)>(std::riemann_zetaf);

    // forming a reference
    auto& fref = static_cast<float(&)(float)>(std::riemann_zetaf);
}
```
