{/* source:cpp-language-namespace:0000 */}
Namespaces provide a method for preventing name conflicts in large projects.

{/* source:cpp-language-namespace:0001 */}
Entities declared inside a namespace block are placed in a namespace scope, which prevents them from being mistaken for identically-named entities in other scopes.

{/* source:cpp-language-namespace:0002 */}
Entities declared outside all namespace blocks belong to the *global namespace*. The global namespace belongs to the [global scope](/docs/cpp/language/basic_concepts/scope), and can be referred to explicitly with a leading `::`. While it has no declaration, the global namespace is not an [unnamed namespace](/docs/cpp/language/declarations/namespace#Unnamed_namespaces).

{/* source:cpp-language-namespace:0003 */}
Multiple namespace blocks with the same name are allowed. All declarations within these blocks are declared in the same namespace scope.

## Syntax

{/* source:cpp-language-namespace:0004 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="namespace ns-name { declarations }" />
  <Declaration id="2" language="cpp" since="C++11" grammar code="inline namespace ns-name { declarations }" />
  <Declaration id="3" language="cpp" grammar code="namespace { declarations }" />
  <Declaration id="4" language="cpp" grammar code="ns-name :: member-name" />
  <Declaration id="5" language="cpp" grammar code="using namespace ns-name ;" />
  <Declaration id="6" language="cpp" grammar code="using ns-name :: member-name ;" />
  <Declaration id="7" language="cpp" grammar code="namespace name = qualified-namespace ;" />
  <Declaration id="8" language="cpp" since="C++17" grammar code="namespace ns-name :: member-name { declarations }" />
  <Declaration id="9" language="cpp" since="C++20" grammar code="namespace ns-name :: inline member-name { declarations }" />
</DeclarationDoc>

{/* source:cpp-language-namespace:0005 */}
1. [Named namespace definition](/docs/cpp/language/declarations/namespace#Namespaces) for the namespace ns-name.

{/* source:cpp-language-namespace:0006 */}
2. [Inline namespace definition](/docs/cpp/language/declarations/namespace#Inline_namespaces) for the namespace ns-name. Declarations inside ns-name will be visible in its enclosing namespace.

{/* source:cpp-language-namespace:0007 */}
3. [Unnamed namespace definition](/docs/cpp/language/declarations/namespace#Unnamed_namespaces). Its members have potential scope from their point of declaration to the end of the translation unit, and have [internal linkage](/docs/cpp/language/declarations/storage_duration).

{/* source:cpp-language-namespace:0008 */}
4. Namespace names (along with class names) can appear on the left hand side of the scope resolution operator, as part of [qualified name lookup](/docs/cpp/language/basic_concepts/lookup).

{/* source:cpp-language-namespace:0009 */}
5. [using-directive](/docs/cpp/language/declarations/namespace#Using-directives): From the point of view of unqualified [name lookup](/docs/cpp/language/basic_concepts/lookup) of any name after a using-directive and until the end of the scope in which it appears, every name from ns-name is visible as if it were declared in the nearest enclosing namespace which contains both the using-directive and ns-name.

{/* source:cpp-language-namespace:0010 */}
6. [using-declaration](/docs/cpp/language/declarations/namespace#Using-declarations): makes the symbol member-name from the namespace ns-name accessible for [unqualified lookup](/docs/cpp/language/basic_concepts/lookup) as if declared in the same class scope, block scope, or namespace as where this using-declaration appears.

{/* source:cpp-language-namespace:0011 */}
7. namespace-alias-definition: makes name a synonym for another namespace: see [namespace alias](/docs/cpp/language/declarations/namespace_alias)

{/* source:cpp-language-namespace:0012 */}
8. nested namespace definition: `namespace A::B::C { ... }` is equivalent to `namespace A { namespace B { namespace C { ... } } }`.

{/* source:cpp-language-namespace:0013 */}
9. nested inline namespace definition: `namespace A::B::inline C { ... }` is equivalent to `namespace A::B { inline namespace C { ... } }`. `inline` may appear in front of every namespace name except the first: `namespace A::inline B::C {}` is equivalent to `namespace A { inline namespace B { namespace C {} } }`.

## Explanation

### Namespaces

{/* source:cpp-language-namespace:0014 */}
<DeclarationDoc>
  <Declaration language="cpp" grammar code="inline (optional) namespace attr (optional) identifier { namespace-body }" />
</DeclarationDoc>

{/* source:cpp-language-namespace:0015 */}
<ParameterList>
  <Parameter name="inline"><InlineRevision since="C++11" /> if present, makes this an inline namespace (see below). Cannot appear on the *extension-namespace-definition* if the *original-namespace-definition* did not use `inline`</Parameter>
  <Parameter name="attr"><InlineRevision since="C++17" /> optional sequence of any number of [attributes](/docs/cpp/language/declarations/attributes)</Parameter>
  <Parameter name="identifier">
either
    - a previously unused identifier, in which case this is *original-namespace-definition*;
    - the name of a namespace, in which case this is *extension-namespace-definition*;

    <Revision since="C++17">
    - a sequence of enclosing namespace specifiers separated by `::`, ending with identifier, in which case this is a *nested-namespace-definition*
    </Revision>
  </Parameter>
  <Parameter name="namespace-body">possibly empty sequence of [declarations](/docs/cpp/language/declarations) of any kind (including class and function definitions as well as nested namespaces)</Parameter>
</ParameterList>

{/* source:cpp-language-namespace:0016 */}
Namespace definitions are only allowed at namespace scope, including the global scope.

{/* source:cpp-language-namespace:0017 */}
To reopen an existing namespace (formally, to be an *extension-namespace-definition*), the lookup for the identifier used in the namespace definition must resolve to a namespace name (not a namespace alias), that was declared as a member of the enclosing namespace or of an inline namespace within an enclosing namespace.

{/* source:cpp-language-namespace:0018 */}
The namespace-body defines a [namespace scope](/docs/cpp/language/basic_concepts/scope), which affects [name lookup](/docs/cpp/language/basic_concepts/lookup).

{/* source:cpp-language-namespace:0019 */}
All names introduced by the declarations that appear within namespace-body (including nested namespace definitions) become members of the namespace identifier, whether this namespace definition is the original namespace definition (which introduced identifier), or an extension namespace definition (which "reopened" the already defined namespace)

{/* source:cpp-language-namespace:0020 */}
A namespace member that was declared within a namespace body may be defined or redeclared outside of it using explicit qualification

{/* source:cpp-language-namespace:0021 */}
```cpp
namespace Q
{
    namespace V   // V is a member of Q, and is fully defined within Q
    { // namespace Q::V { // C++17 alternative to the lines above
        class C { void m(); }; // C is a member of V and is fully defined within V
                               // C::m is only declared
        void f(); // f is a member of V, but is only declared here
    }

    void V::f() // definition of V's member f outside of V
                // f's enclosing namespaces are still the global namespace, Q, and Q::V
    {
        extern void h(); // This declares ::Q::V::h
    }

    void V::C::m() // definition of V::C::m outside of the namespace (and the class body)
                   // enclosing namespaces are the global namespace, Q, and Q::V
    {}
}
```

{/* source:cpp-language-namespace:0022 */}
Out-of-namespace definitions and redeclarations are only allowed

{/* source:cpp-language-namespace:0023 */}
- after the point of declaration,
- at namespace scope, and
- in namespaces that enclose the original namespace (including the global namespace).

{/* source:cpp-language-namespace:0024 */}
Also, they must use qualified-id syntax.

{/* source:cpp-language-namespace:0025 */}
```cpp
namespace Q
{
    namespace V    // original-namespace-definition for V
    {
        void f();  // declaration of Q::V::f
    }

    void V::f() {} // OK
    void V::g() {} // Error: g() is not yet a member of V

    namespace V    // extension-namespace-definition for V
    {
        void g();  // declaration of Q::V::g
    }
}

namespace R           // not an enclosing namespace for Q
{
    void Q::V::g() {} // Error: cannot define Q::V::g inside R
}

void Q::V::g() {}     // OK: global namespace encloses Q
```

{/* source:cpp-language-namespace:0026 */}
Names introduced by [friend](/docs/cpp/language/classes/friend) declarations within a non-local class X become members of the innermost enclosing namespace of X, but they do not become visible to ordinary [name lookup](/docs/cpp/language/basic_concepts/lookup) (neither [unqualified](/docs/cpp/language/basic_concepts/unqualified_lookup) nor [qualified](/docs/cpp/language/basic_concepts/qualified_lookup)) unless a matching declaration is provided at namespace scope, either before or after the class definition. Such name may be found through [ADL](/docs/cpp/language/functions/adl) which considers both namespaces and classes.

{/* source:cpp-language-namespace:0027 */}
Only the innermost enclosing namespace is considered by such friend declaration when deciding whether the name would conflict with a previously declared name.

{/* source:cpp-language-namespace:0028 */}
```cpp
void h(int);
namespace A
{
    class X
    {
        friend void f(X);       // A::f is a friend

        class Y
        {
            friend void g();    // A::g is a friend
            friend void h(int); // A::h is a friend, no conflict with ::h
        };
    };
    // A::f, A::g and A::h are not visible at namespace scope
    // even though they are members of the namespace A

    X x;
    void g()  // definition of A::g
    {
        f(x); // A::X::f is found through ADL
    }

    void f(X) {}   // definition of A::f
    void h(int) {} // definition of A::h
    // A::f, A::g and A::h are now visible at namespace scope
    // and they are also friends of A::X and A::X::Y
}
```

{/* source:cpp-language-namespace:0029 */}
<Revision since="C++11">
#### Inline namespaces

An inline namespace is a namespace that uses the optional keyword `inline` in its *original-namespace-definition*.

Members of an inline namespace are treated as if they are members of the enclosing namespace in many situations (listed below). This property is transitive: if a namespace N contains an inline namespace M, which in turn contains an inline namespace O, then the members of O can be used as though they were members of M or N.

- A *using-directive* that names the inline namespace is implicitly inserted in the enclosing namespace (similar to the implicit using-directive for the unnamed namespace)
- In [argument-dependent lookup](/docs/cpp/language/functions/adl), when a namespace is added to the set of associated namespaces, its inline namespaces are added as well, and if an inline namespace is added to the list of associated namespaces, its enclosing namespace is added as well.
- Each member of an inline namespace can be partially specialized, explicitly instantiated, or explicitly specialized as if it were a member of the enclosing namespace.
- Qualified [name lookup](/docs/cpp/language/basic_concepts/lookup) that examines the enclosing namespace will include the names from the inline namespaces even if the same name is present in the enclosing namespace.

```cpp
// in C++14, std::literals and its member namespaces are inline
{
    using namespace std::string_literals; // makes visible operator""s 
                                          // from std::literals::string_literals
    auto str = "abc"s;
}

{
    using namespace std::literals; // makes visible both
                                   // std::literals::string_literals::operator""s
                                   // and std::literals::chrono_literals::operator""s
    auto str = "abc"s;
    auto min = 60s;
}

{
    using std::operator""s; // makes both std::literals::string_literals::operator""s
                            // and std::literals::chrono_literals::operator""s visible
    auto str = "abc"s;
    auto min = 60s;
}
```

Note: the rule about specializations allows library versioning: different implementations of a library template may be defined in different inline namespaces, while still allowing the user to extend the parent namespace with an explicit specialization of the primary template:

```cpp
namespace Lib
{
    inline namespace Lib_1
    {
        template<typename T> class A; 
    }

    template<typename T> void g(T) { /* ... */ }
}
/* ... */
struct MyClass { /* ... */ };
namespace Lib
{
    template<> class A<MyClass> { /* ... */ };
}

int main()
{
    Lib::A<MyClass> a;
    g(a);  // ok, Lib is an associated namespace of A
}
```
</Revision>

### Unnamed namespaces

{/* source:cpp-language-namespace:0030 */}
The *unnamed-namespace-definition* is a namespace definition of the form

{/* source:cpp-language-namespace:0031 */}
<DeclarationDoc>
  <Declaration language="cpp" grammar code="inline (optional) namespace attr (optional) { namespace-body }" />
</DeclarationDoc>

{/* source:cpp-language-namespace:0032 */}
<ParameterList>
  <Parameter name="inline"><InlineRevision since="C++11" /> if present, makes this an inline namespace</Parameter>
  <Parameter name="attr"><InlineRevision since="C++17" /> optional sequence of any number of [attributes](/docs/cpp/language/declarations/attributes)</Parameter>
</ParameterList>

{/* source:cpp-language-namespace:0033 */}
This definition is treated as a definition of a namespace with unique name and a *using-directive* in the current scope that nominates this unnamed namespace (Note: implicitly added using directive makes namespace available for the [qualified name lookup](/docs/cpp/language/basic_concepts/qualified_lookup) and [unqualified name lookup](/docs/cpp/language/basic_concepts/unqualified_lookup), but not for the [argument-dependent lookup](/docs/cpp/language/functions/adl)). The unique name is unique over the entire program, but within a translation unit each unnamed namespace definition maps to the same unique name: multiple unnamed namespace definitions in the same scope denote the same unnamed namespace.

{/* source:cpp-language-namespace:0034 */}
```cpp
namespace
{
    int i; // defines ::(unique)::i
}

void f()
{
    i++;   // increments ::(unique)::i
}

namespace A
{
    namespace
    {
        int i;        // A::(unique)::i
        int j;        // A::(unique)::j
    }

    void g() { i++; } // A::(unique)::i++
}

using namespace A; // introduces all names from A into global namespace

void h()
{
    i++;    // error: ::(unique)::i and ::A::(unique)::i are both in scope
    A::i++; // ok, increments ::A::(unique)::i
    j++;    // ok, increments ::A::(unique)::j
}
```

{/* source:cpp-language-namespace:0035 */}
<Revision until="C++11">
Even though names in an unnamed namespace may be declared with external linkage, they are never accessible from other translation units because their namespace name is unique.
</Revision>

<Revision since="C++11">
Unnamed namespaces as well as all namespaces declared directly or indirectly within an unnamed namespace have [internal linkage](/docs/cpp/language/declarations/storage_duration#Linkage), which means that any name that is declared within an unnamed namespace has internal linkage.
</Revision>

### Using-declarations

{/* source:cpp-language-namespace:0036 */}
Introduces a name that is defined elsewhere into the declarative region where this using-declaration appears.

{/* source:cpp-language-namespace:0037 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" until="C++17" grammar code="using typename (optional) nested-name-specifier unqualified-id ;" />
  <Declaration id="2" language="cpp" since="C++17" grammar code="using declarator-list ;" />
</DeclarationDoc>

{/* source:cpp-language-namespace:0038 */}
<ParameterList>
  <Parameter name="typename">the keyword `typename` may be used as necessary to resolve [dependent names](/docs/cpp/language/templates/dependent_name), when the using-declaration introduces a member type from a base class into a class template</Parameter>
  <Parameter name="nested-name-specifier">a sequence of names and scope resolution operators `::`, ending with a scope resolution operator. A single `::` refers to the global namespace.</Parameter>
  <Parameter name="unqualified-id">an [id-expression](/docs/cpp/language/basic_concepts/name)</Parameter>
  <Parameter name="declarator-list">comma-separated list of one or more declarators of the form `typename` (optional) nested-name-specifier unqualified-id. A declarator may be followed by an ellipsis to indicate [pack expansion](/docs/cpp/language/templates/parameter_pack), although that form is only meaningful in [derived class definitions](/docs/cpp/language/classes/using_declaration)</Parameter>
</ParameterList>

{/* source:cpp-language-namespace:0039 */}
Using-declarations can be used to introduce namespace members into other namespaces and block scopes, or to introduce base class members into derived class definitions<InlineRevision since="C++20">, or to introduce [enumerators](/docs/cpp/language/declarations/enum) into namespaces, block, and class scopes</InlineRevision>.

{/* source:cpp-language-namespace:0040 */}
<Revision since="C++17">
A using-declaration with more than one using-declarator is equivalent to a corresponding sequence of using-declarations with one using-declarator.
</Revision>

{/* source:cpp-language-namespace:0041 */}
For the use in derived class definitions, see [using declaration](/docs/cpp/language/classes/using_declaration).

{/* source:cpp-language-namespace:0042 */}
Names introduced into a namespace scope by a using-declaration can be used just like any other names, including qualified lookup from other scopes:

{/* source:cpp-language-namespace:0043 */}
```cpp
void f();
namespace A
{
    void g();
}

namespace X
{
    using ::f;        // global f is now visible as ::X::f
    using A::g;       // A::g is now visible as ::X::g
    using A::g, A::g; // (C++17) OK: double declaration allowed at namespace scope
}

void h()
{
    X::f(); // calls ::f
    X::g(); // calls A::g
}
```

{/* source:cpp-language-namespace:0044 */}
If, after the using-declaration was used to take a member from a namespace, the namespace is extended and additional declarations for the same name are introduced, those additional declarations do not become visible through the using-declaration (in contrast with using-directive). One exception is when a using-declaration names a class template: partial specializations introduced later are effectively visible, because their [lookup](/docs/cpp/language/basic_concepts/lookup) proceeds through the primary template.

{/* source:cpp-language-namespace:0045 */}
```cpp
namespace A
{
    void f(int);
}
using A::f; // ::f is now a synonym for A::f(int)

namespace A       // namespace extension
{
    void f(char); // does not change what ::f means
}

void foo()
{
    f('a'); // calls f(int), even though f(char) exists.
}

void bar()
{
    using A::f; // this f is a synonym for both A::f(int) and A::f(char)
    f('a');     // calls f(char)
}
```

{/* source:cpp-language-namespace:0046 */}
Using-declarations cannot name [template-id](/docs/cpp/language/templates#template-id), or namespace<InlineRevision until="C++20">, or a scoped enumerator</InlineRevision>. Each declarator in a using-declaration introduces one and only one name, for example using-declaration for an [enumeration](/docs/cpp/language/declarations/enum) does not introduce any of its enumerators.

{/* source:cpp-language-namespace:0047 */}
All restrictions on regular declarations of the same names, hiding, and overloading rules apply to using-declarations:

{/* source:cpp-language-namespace:0048 */}
```cpp
namespace A
{
    int x;
}

namespace B
{
    int i;
    struct g {};
    struct x {};

    void f(int);
    void f(double);
    void g(char); // OK: function name g hides struct g
}

void func()
{
    int i;
    using B::i;   // error: i declared twice

    void f(char);
    using B::f;   // OK: f(char), f(int), f(double) are overloads
    f(3.5);       // calls B::f(double)

    using B::g;
    g('a');       // calls B::g(char)
    struct g g1;  // declares g1 to have type struct B::g

    using B::x;
    using A::x;   // OK: hides struct B::x
    x = 99;       // assigns to A::x
    struct x x1;  // declares x1 to have type struct B::x
}
```

{/* source:cpp-language-namespace:0049 */}
If a function was introduced by a using-declaration, declaring a function with the same name and parameter list is ill-formed (unless the declaration is for the same function). If a function template was introduced by a using-declaration, declaring a function template with the same name, parameter type list, return type, and template parameter list is ill-formed. Two using-declarations can introduce functions with the same name and parameter list, but if a call to that function is attempted, the program is ill-formed.

{/* source:cpp-language-namespace:0050 */}
```cpp
namespace B
{
    void f(int);
    void f(double);
}

namespace C
{
    void f(int);
    void f(double);
    void f(char);
}

void h()
{
    using B::f;  // introduces B::f(int), B::f(double)
    using C::f;  // introduces C::f(int), C::f(double), and C::f(char)
    f('h');      // calls C::f(char)
    f(1);        // error: B::f(int) or C::f(int)?
    void f(int); // error: f(int) conflicts with C::f(int) and B::f(int)
}
```

{/* source:cpp-language-namespace:0051 */}
If an entity is declared, but not defined in some inner namespace, and then declared through using-declaration in the outer namespace, and then a definition appears in the outer namespace with the same unqualified name, that definition is a member of the outer namespace and conflicts with the using-declaration:

{/* source:cpp-language-namespace:0052 */}
```cpp
namespace X
{
    namespace M
    {
        void g(); // declares, but doesn't define X::M::g()
    }
    using M::g;

    void g();     // Error: attempt to declare X::g which conflicts with X::M::g()
}
```

{/* source:cpp-language-namespace:0053 */}
More generally, a declaration that appears in any namespace scope and introduces a name using an unqualified identifier always introduces a member into the namespace it's in and not to any other namespace. The exceptions are explicit instantiations and explicit specializations of a primary template that is defined in an inline namespace: because they do not introduce a new name, they may use unqualified-id in an enclosing namespace.

### Using-directives

{/* source:cpp-language-namespace:0054 */}
A *using-directive* is a [block-declaration](/docs/cpp/language/declarations) with the following syntax:

{/* source:cpp-language-namespace:0055 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="attr (optional) using namespace nested-name-specifier (optional) namespace-name ;" />
</DeclarationDoc>

{/* source:cpp-language-namespace:0056 */}
<ParameterList>
  <Parameter name="attr"><InlineRevision since="C++11" /> any number of [attributes](/docs/cpp/language/declarations/attributes) that apply to this using-directive</Parameter>
  <Parameter name="nested-name-specifier">a sequence of names and scope resolution operators `::`, ending with a scope resolution operator. A single `::` refers to the global namespace. When looking up the names in this sequence, [lookup](/docs/cpp/language/basic_concepts/lookup) considers namespace declarations only</Parameter>
  <Parameter name="namespace-name">a name of a namespace. When looking up this name, [lookup](/docs/cpp/language/basic_concepts/lookup) considers namespace declarations only</Parameter>
</ParameterList>

{/* source:cpp-language-namespace:0057 */}
Using-directives are allowed only in namespace [scope](/docs/cpp/language/basic_concepts/scope) and in block scope. From the point of view of [unqualified name lookup](/docs/cpp/language/basic_concepts/unqualified_lookup) of any name after a using-directive and until the end of the scope in which it appears, every name from namespace-name is visible as if it were declared in the nearest enclosing namespace which contains both the using-directive and namespace-name.

{/* source:cpp-language-namespace:0058 */}
Using-directive does not add any names to the declarative region in which it appears (unlike the using-declaration), and thus does not prevent identical names from being declared.

{/* source:cpp-language-namespace:0059 */}
Using-directives are transitive for the purposes of [unqualified lookup](/docs/cpp/language/basic_concepts/unqualified_lookup): if a scope contains a using-directive that nominates a namespace-name, which itself contains using-directive for some namespace-name-2, the effect is as if the using directives from the second namespace appear within the first. The order in which these transitive namespaces occur does not influence name lookup.

{/* source:cpp-language-namespace:0060 */}
```cpp
namespace A
{
    int i;
}

namespace B
{
    int i;
    int j;

    namespace C
    {
        namespace D
        {
            using namespace A;
            // Names from A are "injected" into D.
            // Unqualified lookup within D considers these names to have the same
            // scope as the global scope (e.g. for the purposes of name hiding).
            // Qualified lookup referring to D (D::name for some name)
            // will find the same name as unqualified lookup within D.

            int j;
            int k;
            int a = i;   // i is B::i, because A::i is hidden by B::i
            int b = ::i; // error: there is still no i in the global namespace
        }

        using namespace D; // names from D and A are injected into C

        int k = 89; // OK to declare name identical to one introduced by a using
        int l = k;  // ambiguous: C::k or D::k
        int m = i;  // ok: B::i hides A::i
        int n = j;  // ok: D::j hides B::j
    }
}

// These are all equivalent definitions:
int t0 = B::i;
int t1 = B::C::a;
int t2 = B::C::D::a;
```

{/* source:cpp-language-namespace:0061 */}
If, after a using-directive was used to nominate some namespace, the namespace is extended and additional members and/or using-directives are added to it, those additional members and the additional namespaces are visible through the using-directive (in contrast with using-declaration)

{/* source:cpp-language-namespace:0062 */}
```cpp
namespace D
{
    int d1;
    void f(char);
}
using namespace D; // introduces D::d1, D::f, D::d2, D::f,
                   // E::e, and E::f into global namespace!

int d1;            // OK: no conflict with D::d1 when declaring

namespace E
{
    int e;
    void f(int);
}

namespace D            // namespace extension
{
    int d2;
    using namespace E; // transitive using-directive
    void f(int);
}

void f()
{
    d1++;    // error: ambiguous ::d1 or D::d1?
    ::d1++;  // OK
    D::d1++; // OK
    d2++;    // OK, d2 is D::d2

    e++;     // OK: e is E::e due to transitive using

    f(1);    // error: ambiguous: D::f(int) or E::f(int)?
    f('a');  // OK: the only f(char) is D::f(char)
}
```

## Notes

{/* source:cpp-language-namespace:0063 */}
The using-directive `using namespace std;` at any namespace scope introduces every name from the namespace `std` into the global namespace (since the global namespace is the nearest namespace that contains both `std` and any user-declared namespace), which may lead to undesirable name collisions. This, and other using directives are generally considered bad practice at file scope of a header file ([SF.7: Don’t write `using namespace` at global scope in a header file](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rs-using-directive)).

## Example

{/* source:cpp-language-namespace:0066 */}
This example shows how to use a namespace to create a class that already has been named in the `std` namespace.

```cpp
#include <vector>

namespace vec
{
    template<typename T>
    class vector
    {
        // ...
    };
} // of vec

int main()
{
    std::vector<int> v1; // Standard vector.
    vec::vector<int> v2; // User defined vector.

    // v1 = v2;          // Error: v1 and v2 are different object's type.

    {
        using namespace std;
        vector<int> v3;  // Same as std::vector
        v1 = v3; // OK
    }

    {
        using vec::vector;
        vector<int> v4;  // Same as vec::vector
        v2 = v4; // OK
    }
}
```
