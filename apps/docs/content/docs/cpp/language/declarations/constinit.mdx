{/* source:cpp-language-constinit:0000 */}
`constinit` - asserts that a variable has static initialization, i.e. [zero initialization](/docs/cpp/language/initialization/zero_initialization) and [constant initialization](/docs/cpp/language/initialization/constant_initialization), otherwise the program is ill-formed.

## Explanation

{/* source:cpp-language-constinit:0001 */}
The `constinit` specifier declares a variable with static or thread [storage duration](/docs/cpp/language/declarations/storage_duration).

{/* source:cpp-language-constinit:0002 */}
<Revision since="C++26">
The `constinit` specifier can also be applied to [structured binding](/docs/cpp/language/declarations/structured_binding) declarations. In this case, `constinit` is also applied to the [uniquely-named variable](/docs/cpp/language/declarations/structured_binding#Binding_process) introduced by the declaration.
</Revision>

{/* source:cpp-language-constinit:0003 */}
If a variable is declared with `constinit`, its [initializing declaration](/docs/cpp/language/initialization) must be applied with `constinit`. If a variable declared with `constinit` has [dynamic initialization](/docs/cpp/language/initialization#Dynamic_initialization) (even if it is [performed as static initialization](/docs/cpp/language/initialization#Early_dynamic_initialization)), the program is ill-formed.

{/* source:cpp-language-constinit:0004 */}
If no `constinit` declaration is reachable at the point of the initializing declaration, the program is ill-formed, no diagnostic required.

{/* source:cpp-language-constinit:0005 */}
`constinit` cannot be used together with `constexpr`. When the declared variable is a reference, `constinit` is equivalent to `constexpr`. When the declared variable is an object, `constexpr` mandates that the object must have static initialization and constant destruction and makes the object const-qualified, however, `constinit` does not mandate constant destruction and const-qualification. As a result, an object of a type which has constexpr constructors and no constexpr destructor (e.g. `std::shared_ptr<T>`) might be declared with `constinit` but not `constexpr`.

{/* source:cpp-language-constinit:0006 */}
```cpp
const char* g() { return "dynamic initialization"; }
constexpr const char* f(bool p) { return p ? "constant initializer" : g(); }

constinit const char* c = f(true);     // OK
// constinit const char* d = f(false); // error
```

{/* source:cpp-language-constinit:0007 */}
`constinit` can also be used in a non-initializing declaration to tell the compiler that a `thread_local` variable is already initialized, [reducing overhead](/docs/cpp/language/declarations/storage_duration#Static_local_variables) that would otherwise be incurred by a hidden guard variable.

{/* source:cpp-language-constinit:0008 */}
```cpp
extern thread_local constinit int x;
int f() { return x; } // no check of a guard variable needed
```

## Example

{/* source:cpp-language-constinit:0011 */}
```cpp
#include <cassert>

constexpr int square(int i)
{
    return i * i;
}

int twice(int i)
{
    return i + i;
}

constinit int sq = square(2);    // OK: initialization is done at compile time
// constinit int x_x = twice(2); // Error: compile time initializer required

int square_4_gen()
{
    static constinit int pow = square(4);

    // constinit int prev = pow; // Error: constinit can only be applied to a
                                 // variable with static or thread storage duration
    int prev = pow;
    pow = pow * pow;
    return prev;
}

int main()
{
    assert(sq == 4);
    sq = twice(1); // Unlike constexpr this value can be changed later at runtime
    assert(sq == 2);

    assert(square_4_gen() == 16);
    assert(square_4_gen() == 256);
    assert(square_4_gen() == 65536);
}
```
