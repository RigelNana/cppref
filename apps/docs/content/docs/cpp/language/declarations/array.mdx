{/* source:cpp-language-array:0000 */}
Declares an object of array type.

## Syntax

{/* source:cpp-language-array:0001 */}
An array declaration is any simple declaration whose [declarator](/docs/cpp/language/declarations) has the form

{/* source:cpp-language-array:0002 */}
<DeclarationDoc>
  <Declaration language="cpp" grammar code="noptr-declarator [ expr (optional) ] attr (optional)" />
</DeclarationDoc>

{/* source:cpp-language-array:0003 */}
<ParameterList>
  <Parameter name="noptr-declarator">any valid *declarator*, but if it begins with `*`, `&`, or `&&`, it has to be surrounded by parentheses (otherwise the whole declarator is treated as a [pointer declarator](/docs/cpp/language/declarations/pointer) or [reference declarator](/docs/cpp/language/declarations/reference)).</Parameter>
  <Parameter name="expr"><InlineRevision until="C++14">an [integral constant expression](/docs/cpp/language/expressions/constant_expression)</InlineRevision><InlineRevision since="C++14">a [converted constant expression](/docs/cpp/language/expressions/constant_expression) of type [`std::size_t`](/docs/cpp/library/utility/types/size_t)</InlineRevision>, which evaluates to a value greater than zero</Parameter>
  <Parameter name="attr"><InlineRevision since="C++11" /> list of [attributes](/docs/cpp/language/declarations/attributes)</Parameter>
</ParameterList>

{/* source:cpp-language-array:0004 */}
A declaration of the form `T a[N];`, declares `a` as an array [object](/docs/cpp/language/basic_concepts/objects) that consists of `N` contiguously allocated objects of type `T`. The elements of an array are numbered `0`, …, `N - 1`, and may be accessed with the [subscript operator \[\]]](/docs/cpp/language/expressions/operator_member_access#Built-in_subscript_operator), as in `a[0]`, …, `a[N - 1]`.

{/* source:cpp-language-array:0005 */}
Arrays can be constructed from any [fundamental type](/docs/cpp/language/basic_concepts/types) (except `void`), [pointers](/docs/cpp/language/declarations/pointer), [pointers to members](/docs/cpp/language/declarations/pointer), [classes](/docs/cpp/language/classes), [enumerations](/docs/cpp/language/declarations/enum), or from other arrays of known bound (in which case the array is said to be multi-dimensional). In other words, only object types except for array types of unknown bound can be element types of array types. Array types of incomplete element type are also incomplete types.

{/* source:cpp-language-array:0006 */}
<Revision since="C++11">
The <InlineRevision since="C++20">possibly [constrained](/docs/cpp/language/templates/constraints)</InlineRevision> [`auto`](/docs/cpp/language/declarations/auto) specifier can be used as array element type in the declaration of a pointer or reference to array, which deduces the element type from the initializer<InlineRevision since="C++14"> or the function argument</InlineRevision>, e.g. `auto (*p)[42] = &a;` is valid if `a` is an lvalue of type `int[42]`.
</Revision>

{/* source:cpp-language-array:0007 */}
There are no arrays of references or arrays of functions.

{/* source:cpp-language-array:0008 */}
Applying [cv-qualifiers](/docs/cpp/language/declarations/cv) to an array type (through typedef or template type manipulation) applies the qualifiers to the element type, but any array type whose elements are of cv-qualified type is considered to have the same cv-qualification.

{/* source:cpp-language-array:0009 */}
```cpp
// a and b have the same const-qualified type "array of 5 const char"
 
typedef const char CC;
CC a[5] = {};
 
typedef char CA[5];
const CA b = {};
```
{/* source:cpp-language-array:0010 */}
When used with [new[]-expression](/docs/cpp/language/expressions/new), the size of an array may be zero; such an array has no elements:

{/* source:cpp-language-array:0011 */}
```cpp
int* p = new int[0]; // accessing p[0] or *p is undefined
delete[] p; // cleanup still required
```
### Assignment

{/* source:cpp-language-array:0012 */}
Objects of array type cannot be modified as a whole: even though they are [lvalues](/docs/cpp/language/expressions/value_category#lvalue) (e.g. an address of array can be taken), they cannot appear on the left hand side of an assignment operator:

{/* source:cpp-language-array:0013 */}
```cpp
int a[3] = {1, 2, 3}, b[3] = {4, 5, 6};
int (*p)[3] = &a; // okay: address of a can be taken
a = b;            // error: a is an array
 
struct { int c[3]; } s1, s2 = {3, 4, 5};
s1 = s2; // okay: implicitly-defined copy assignment operator
         // can assign data members of array type
```
### Array-to-pointer decay

{/* source:cpp-language-array:0014 */}
There is an [implicit conversion](/docs/cpp/language/expressions/implicit_cast) from lvalues and rvalues of array type to rvalues of pointer type: it constructs a pointer to the first element of an array. This conversion is used whenever arrays appear in context where arrays are not expected, but pointers are:

{/* source:cpp-language-array:0015 */}
```cpp
#include <iostream>
#include <iterator>
#include <numeric>
 
void g(int (&a)[3])
{
    std::cout << a[0] << '\n';
}
 
void f(int* p)
{
    std::cout << *p << '\n';
}
 
int main()
{
    int a[3] = {1, 2, 3};
    int* p = a;
 
    std::cout << sizeof a << '\n'  // prints size of array
              << sizeof p << '\n'; // prints size of a pointer
 
    // where arrays are acceptable, but pointers aren't, only arrays may be used
    g(a); // okay: function takes an array by reference
//  g(p); // error
 
    for (int n : a)            // okay: arrays can be used in range-for loops
        std::cout << n << ' '; // prints elements of the array
//  for (int n : p)            // error
//      std::cout << n << ' ';
 
    std::iota(std::begin(a), std::end(a), 7); // okay: begin and end take arrays
//  std::iota(std::begin(p), std::end(p), 7); // error
 
    // where pointers are acceptable, but arrays aren't, both may be used:
    f(a); // okay: function takes a pointer
    f(p); // okay: function takes a pointer
 
    std::cout << *a << '\n' // prints the first element
              << *p << '\n' // same
              << *(a + 1) << ' ' << a[1] << '\n'  // prints the second element
              << *(p + 1) << ' ' << p[1] << '\n'; // same
}
```
### Multidimensional arrays

{/* source:cpp-language-array:0016 */}
When the element type of an array is another array, it is said that the array is multidimensional:

{/* source:cpp-language-array:0017 */}
```cpp
// array of 2 arrays of 3 int each
int a[2][3] = {{1, 2, 3},  // can be viewed as a 2 × 3 matrix
               {4, 5, 6}}; // with row-major layout
```
{/* source:cpp-language-array:0018 */}
Note that when array-to-pointer decay is applied, a multidimensional array is converted to a pointer to its first element (e.g., a pointer to its first row or to its first plane): array-to-pointer decay is applied only once.

{/* source:cpp-language-array:0019 */}
```cpp
int a[2];            // array of 2 int
int* p1 = a;         // a decays to a pointer to the first element of a
 
int b[2][3];         // array of 2 arrays of 3 int
// int** p2 = b;     // error: b does not decay to int**
int (*p2)[3] = b;    // b decays to a pointer to the first 3-element row of b
 
int c[2][3][4];      // array of 2 arrays of 3 arrays of 4 int
// int*** p3 = c;    // error: c does not decay to int***
int (*p3)[3][4] = c; // c decays to a pointer to the first 3 × 4-element plane of c
```
### Arrays of unknown bound

{/* source:cpp-language-array:0020 */}
If *expr* is omitted in the declaration of an array, the type declared is "array of unknown bound of T", which is a kind of [incomplete type](/docs/cpp/language/basic_concepts/incomplete_type), except when used in a declaration with an [aggregate initializer](/docs/cpp/language/initialization/aggregate_initialization):

{/* source:cpp-language-array:0021 */}
```cpp
extern int x[];      // the type of x is "array of unknown bound of int"
int a[] = {1, 2, 3}; // the type of a is "array of 3 int"
```
{/* source:cpp-language-array:0022 */}
Because array elements cannot be arrays of unknown bound, multidimensional arrays cannot have unknown bound in a dimension other than the first:

{/* source:cpp-language-array:0023 */}
```cpp
extern int a[][2]; // okay: array of unknown bound of arrays of 2 int
extern int b[2][]; // error: array has incomplete element type
```
{/* source:cpp-language-array:0024 */}
If there is a preceding declaration of the entity in the same scope in which the bound was specified, an omitted array bound is taken to be the same as in that earlier declaration, and similarly for the definition of a static data member of a class:

{/* source:cpp-language-array:0025 */}
```cpp
extern int x[10];
struct S
{
    static int y[10];
};
 
int x[];               // OK: bound is 10
int S::y[];            // OK: bound is 10
 
void f()
{
    extern int x[];
    int i = sizeof(x); // error: incomplete object type
}
```
{/* source:cpp-language-array:0026 */}
References and pointers to arrays of unknown bound can be formed, <InlineRevision until="C++20">but cannot</InlineRevision><InlineRevision since="C++20">and can</InlineRevision> be initialized or assigned from arrays and pointers to arrays of known bound. Note that in the C programming language, pointers to arrays of unknown bound are compatible with pointers to arrays of known bound and are thus convertible and assignable in both directions.

{/* source:cpp-language-array:0027 */}
```cpp
extern int a1[];
 
int (&r1)[] = a1;  // okay
int (*p1)[] = &a1; // okay
int (*q)[2] = &a1; // error (but okay in C)
 
int a2[] = {1, 2, 3};
int (&r2)[] = a2;  // okay (since C++20)
int (*p2)[] = &a2; // okay (since C++20)
```
{/* source:cpp-language-array:0028 */}
Pointers to arrays of unknown bound cannot participate in [pointer arithmetic](/docs/cpp/language/expressions/operator_arithmetic#Additive_operators) and cannot be used on the left of the [subscript operator](/docs/cpp/language/expressions/operator_member_access#Built-in_subscript_operator), but can be dereferenced.

### Array rvalues

{/* source:cpp-language-array:0029 */}
Although arrays cannot be returned from functions by value and cannot be targets of most cast expressions, array [prvalues](/docs/cpp/language/expressions/value_category) may be formed by using a type alias to construct an array temporary using [brace-initialized functional cast](/docs/cpp/language/expressions/explicit_cast).

{/* source:cpp-language-array:0030 */}
<Revision since="C++17">
Like class prvalues, array prvalues convert to xvalues by [temporary materialization](/docs/cpp/language/expressions/implicit_cast#Temporary_materialization) when evaluated.
</Revision>

{/* source:cpp-language-array:0031 */}
Array [xvalues](/docs/cpp/language/expressions/value_category) may be formed directly by accessing an array member of a class rvalue or by using `std::move` or another cast or function call that returns an rvalue reference.

{/* source:cpp-language-array:0032 */}
```cpp
#include <iostream>
#include <type_traits>
#include <utility>
 
void f(int (&&x)[2][3])
{
    std::cout << sizeof x << '\n';
}
 
struct X
{
    int i[2][3];
} x;
 
template<typename T>
using identity = T;
 
int main()
{
    std::cout << sizeof X().i << '\n';           // size of the array
    f(X().i);                                    // okay: binds to xvalue
//  f(x.i);                                      // error: cannot bind to lvalue
 
    int a[2][3];
    f(std::move(a));                             // okay: binds to xvalue
 
    using arr_t = int[2][3];
    f(arr_t{});                                  // okay: binds to prvalue
    f(identity<int[][3]>{{1, 2, 3}, {4, 5, 6}}); // okay: binds to prvalue
 
}
```
Output:

```text
24
24
24
24
24
```
