{{/* source:cpp-language-language-linkage:0000 */}}
Provides for linkage between program units written in different programming languages.

{{/* source:cpp-language-language-linkage:0001 */}}
<Revision since="C++20">
This can also be used to detach a declaration from its module. See [Module ownership](/docs/cpp/language/basic_concepts/modules#Module_ownership).
</Revision>

{{/* source:cpp-language-language-linkage:0002 */}}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code={`extern string-literal { declaration-seq (optional) }`} />
  <Declaration id="2" language="cpp" grammar code={`extern string-literal declaration`} />
</DeclarationDoc>

{{/* source:cpp-language-language-linkage:0003 */}}
1. Applies the language specification *string-literal* to all function types, function names with external linkage and variables with external linkage declared in *declaration-seq*.

{{/* source:cpp-language-language-linkage:0004 */}}
2. Applies the language specification *string-literal* to a single declaration or definition.

{{/* source:cpp-language-language-linkage:0005 */}}
<ParameterList>
  <Parameter name="string-literal">
    an [unevaluated string literal](/docs/cpp/language/expressions/string_literal#Unevaluated_strings) that names the required language linkage
  </Parameter>
  <Parameter name="declaration-seq">
    a sequence of declarations, which may include nested linkage specifications
  </Parameter>
  <Parameter name="declaration">
    a declaration
  </Parameter>
</ParameterList>

## Explanation

{{/* source:cpp-language-language-linkage:0006 */}}
Every function type, every function name with [external linkage](/docs/cpp/language/declarations/storage_duration), and every variable name with [external linkage](/docs/cpp/language/declarations/storage_duration), has a property called *language linkage*. Language linkage encapsulates the set of requirements necessary to link with a program unit written in another programming language: [calling convention](https://en.wikipedia.org/wiki/calling_convention), [name mangling](https://en.wikipedia.org/wiki/name_mangling) (name decoration) algorithm, etc.

{{/* source:cpp-language-language-linkage:0007 */}}
Only two language linkages are guaranteed to be supported:

{{/* source:cpp-language-language-linkage:0008 */}}
1. `"C++"`, the default language linkage.
2. `"C"`, which makes it possible to link with functions written in the C programming language, and to define, in a C++ program, functions that can be called from the units written in C.

{{/* source:cpp-language-language-linkage:0009 */}}
```cpp
extern "C"
{
    int open(const char *path_name, int flags); // C function declaration
}
 
int main()
{
    int fd = open("test.txt", 0); // calls a C function from a C++ program
}
 
// This C++ function can be called from C code
extern "C" void handler(int)
{
    std::cout << "Callback invoked\n"; // It can use C++
}
```

{{/* source:cpp-language-language-linkage:0010 */}}
Since language linkage is part of every function type, pointers to functions maintain language linkage as well. Language linkage of function types (which represents calling convention) and language linkage of function names (which represents name mangling) are independent of each other:

{{/* source:cpp-language-language-linkage:0011 */}}
```cpp
extern "C" void f1(void(*pf)()); // declares a function f1 with C linkage,
                             // which returns void and takes a pointer to a C function
                             // which returns void and takes no parameters
 
extern "C" typedef void FUNC(); // declares FUNC as a C function type that returns void
                                // and takes no parameters
 
FUNC f2;            // the name f2 has C++ linkage, but its type is C function
extern "C" FUNC f3; // the name f3 has C linkage and its type is C function void()
void (*pf2)(FUNC*); // the name pf2 has C++ linkage, and its type is
                    // "pointer to a C++ function which returns void and takes one
                    // argument of type 'pointer to the C function which returns void
                    // and takes no parameters'"
 
extern "C"
{
    static void f4(); // the name of the function f4 has internal linkage (no language)
                      // but the function's type has C language linkage
}
```

{{/* source:cpp-language-language-linkage:0012 */}}
If [two declarations of an entity](/docs/cpp/language/declarations/conflicting_declarations#Multiple_declarations_of_the_same_entity) give it different language linkages, the program is ill-formed; no diagnostic is required if neither declaration is reachable from the other. A redeclaration of an entity without a linkage specification inherits the language linkage of the entity and its type (if exists).

{{/* source:cpp-language-language-linkage:0013 */}}
```cpp
extern "C" int f();
extern "C++" int f(); // Error: different language linkages
 
extern "C" int g();
int g(); // OK, has C language linkage
 
int h(); // has C++ language linkage by default
extern "C" int h(); // Error: different language linkages
```

### Special rules for "C" linkage

{{/* source:cpp-language-language-linkage:0014 */}}
When class members<InlineRevision since="C++20">, friend functions with a trailing [`requires` clause](/docs/cpp/language/templates/constraints#Requires_clauses),</InlineRevision> or non-static member functions appear in a `"C"` language block, the linkage of their types remains `"C++"` (but parameter types, if any, remain `"C"`):

{{/* source:cpp-language-language-linkage:0015 */}}
```cpp
extern "C"
{
    class X
    {
        void mf();           // the function mf and its type have C++ language linkage
        void mf2(void(*)()); // the function mf2 has C++ language linkage;
                             // the parameter has type “pointer to C function”
    };
}
 
template<typename T>
struct A { struct B; };
 
extern "C"
{
    template<typename T>
    struct A<T>::B
    {
        friend void f(B*) requires true {} // C language linkage ignored
    };
}
 
namespace Q
{
    extern "C" void f(); // not ill-formed
}
```

{{/* source:cpp-language-language-linkage:0016 */}}
Let `C` be a declaration that declares a function or variable with `"C"` language linkage. If another declaration `D` declares an entity with the same name, and it satisfies any of the following conditions, `C` and `D` declare the same entity:

{{/* source:cpp-language-language-linkage:0017 */}}
- `D` declares a variable that belongs to the global scope.
- If `C` declares a variable, `D` also declares a variable.
- If `C` declares a function, `D` also declares a function.

{{/* source:cpp-language-language-linkage:0018 */}}
Unlike [regular redeclarations](/docs/cpp/language/declarations/conflicting_declarations#Multiple_declarations_of_the_same_entity), `C` and `D` can have different [target scopes](/docs/cpp/language/basic_concepts/scope):

{{/* source:cpp-language-language-linkage:0019 */}}
```cpp
extern "C"
{
    int x;
    int f();
    int g() { return 1; }
}
 
namespace A
{
    int x;                // Error: redefines “x”
    int f();              // OK, redeclares “f”
    int g() { return 1; } // Error: redefines “g”
}
```

{{/* source:cpp-language-language-linkage:0020 */}}
However, the [restrictions](/docs/cpp/language/declarations/conflicting_declarations#Restrictions) of such declarations still apply, which means they should either both declare functions or both declare variables, and the declared entities must have the same type:

{{/* source:cpp-language-language-linkage:0021 */}}
```cpp
namespace A
{
    extern "C" int x();
    extern "C" int y();
}
 
int x; // Error: redeclares “x” as a different kind of entity
 
namespace B
{
    void y(); // Error: redeclares “y” with a different type
}
```

## Notes

{{/* source:cpp-language-language-linkage:0022 */}}
Language specifications can only appear in [namespace scope](/docs/cpp/language/basic_concepts/scope#Namespace_scope).

{{/* source:cpp-language-language-linkage:0023 */}}
The braces of the language specification do not establish a scope.

{{/* source:cpp-language-language-linkage:0024 */}}
When language specifications nest, the innermost specification is the one that is in effect.

{{/* source:cpp-language-language-linkage:0025 */}}
A declaration directly contained in a language linkage specification is treated as if it contains the [`extern` specifier](/docs/cpp/language/declarations/storage_duration) for the purpose of determining the [linkage](/docs/cpp/language/declarations/storage_duration#Linkage) of the declared name and whether it is a [definition](/docs/cpp/language/basic_concepts/definition).

{{/* source:cpp-language-language-linkage:0026 */}}
```cpp
extern "C" int x; // a declaration and not a definition
// The above line is equivalent to extern "C" { extern int x; }
 
extern "C" { int x; } // a declaration and definition
 
extern "C" double f();
static double f(); // error: linkage conflict
 
extern "C" static void g(); // error: linkage conflict
```

{{/* source:cpp-language-language-linkage:0027 */}}
`extern "C"` makes it possible to include header files containing declarations of C library functions in a C++ program, but if the same header file is shared with a C program, `extern "C"` (which is not allowed in C) must be hidden with an appropriate [`#ifdef`](/docs/cpp/language/preprocessor/conditional), typically [`__cplusplus`](/docs/cpp/language/preprocessor/replace#Predefined_macros):

{{/* source:cpp-language-language-linkage:0028 */}}
```cpp
#ifdef __cplusplus
extern "C" int foo(int, int); // C++ compiler sees this
#else
int foo(int, int);            // C compiler sees this
#endif
```

{{/* source:cpp-language-language-linkage:0029 */}}
The only modern compiler that differentiates function types with `"C"` and `"C++"` language linkages is Oracle Studio, others do not permit overloads that are only different in language linkage, including the overload sets required by the C++ standard ([`std::qsort`](/docs/cpp/library/algorithm/qsort), [`std::bsearch`](/docs/cpp/library/algorithm/bsearch), [`std::signal`](/docs/cpp/library/utility/program/signal), [`std::atexit`](/docs/cpp/library/utility/program/atexit), and [`std::at_quick_exit`](/docs/cpp/library/utility/program/at_quick_exit)): [GCC bug 2316](https://gcc.gnu.org/bugzilla/show_bug.cgi?id=2316), [Clang bug 6277](https://bugs.llvm.org/show_bug.cgi?id=6277), [CWG issue 1555](https://cplusplus.github.io/CWG/issues/1555.html).

{{/* source:cpp-language-language-linkage:0030 */}}
```cpp
extern "C"   using c_predfun   = int(const void*, const void*);
extern "C++" using cpp_predfun = int(const void*, const void*);
 
// ill-formed, but accepted by most compilers
static_assert(std::is_same<c_predfun, cpp_predfun>::value,
              "C and C++ language linkages shall not differentiate function types.");
 
// following declarations do not declare overloads in most compilers
// because c_predfun and cpp_predfun are considered to be the same type
void qsort(void* base, std::size_t nmemb, std::size_t size, c_predfun*   compar);
void qsort(void* base, std::size_t nmemb, std::size_t size, cpp_predfun* compar);
```

  <DefectReport kind="cwg" id={4} standard="C++98">
    <PublishedBehavior>names with internal linkage can have language linkages</PublishedBehavior>
    <CorrectedBehavior>limited to names with external linkage</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="cwg" id={341} standard="C++98">
    <PublishedBehavior>a function with `"C"` language linkage can have the same name as a global variable</PublishedBehavior>
    <CorrectedBehavior>the program is ill-formed in this case (no diagnostic required if they appear in different translation units)</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="cwg" id={564} standard="C++98">
    <PublishedBehavior>the program was ill-formed if two declarations only differ in language linkage specifications (i.e. different string literals following 'extern')</PublishedBehavior>
    <CorrectedBehavior>the actual language linkages given by the declarations are compared instead</CorrectedBehavior>
  </DefectReport>
  <DefectReport kind="cwg" id={2460} standard="C++20">
