{/* source:cpp-language-cv:0000 */}
Appear in any type specifier, including *decl-specifier-seq* of [declaration grammar](/docs/cpp/language/declarations), to specify constness or volatility of the object being declared or of the type being named.

{/* source:cpp-language-cv:0001 */}
- `const` - defines that the type is constant.
- `volatile` - defines that the type is volatile.

## Explanation

{/* source:cpp-language-cv:0002 */}
Any (possibly [incomplete](/docs/cpp/language/basic_concepts/type-id#Incomplete_type)) type other than [function type](/docs/cpp/language/functions) or [reference type](/docs/cpp/language/declarations/reference) is a type in a group of the following four distinct but related types:

{/* source:cpp-language-cv:0003 */}
- A cv-unqualified version.
- A `const`-qualified version.
- A `volatile`-qualified version.
- A `const volatile`-qualified version.

{/* source:cpp-language-cv:0004 */}
These four types in the same group have the same [representation](/docs/cpp/language/basic_concepts/objects#Object_representation_and_value_representation) and [alignment](/docs/cpp/language/basic_concepts/objects#Alignment) requirements.

{/* source:cpp-language-cv:0005 */}
[Array types](/docs/cpp/language/declarations/array) are considered to have the same cv-qualification as their element types.

### const and volatile objects

{/* source:cpp-language-cv:0006 */}
When an object is first created, the cv-qualifiers used (which could be part of *decl-specifier-seq* or part of a declarator in a [declaration](/docs/cpp/language/declarations), or part of *type-id* in a [new-expression](/docs/cpp/language/expressions/new)) determine the constness or volatility of the object, as follows:

{/* source:cpp-language-cv:0007 */}
- A `const` object is

{/* source:cpp-language-cv:0008 */}
  - an object whose type is const-qualified, or a non-[mutable](/docs/cpp/language/declarations/cv#mutable) subobject of a const object. Such object cannot be modified: attempt to do so directly is a compile-time error, and attempt to do so indirectly (e.g., by modifying the const object through a reference or pointer to non-const type) results in undefined behavior.

{/* source:cpp-language-cv:0009 */}
- A `volatile` object is

{/* source:cpp-language-cv:0010 */}
  - an object whose type is volatile-qualified, a subobject of a volatile object, or a [mutable](/docs/cpp/language/declarations/cv#mutable) subobject of a const-volatile object. Every access (read or write operation, member function call, etc.) made through a glvalue expression of volatile-qualified type is treated as a visible side-effect for the [purposes of optimization](/docs/cpp/language/basic_concepts/as_if) (that is, within a single thread of execution, volatile accesses cannot be optimized out or reordered with another visible side effect that is [sequenced-before](/docs/cpp/language/expressions/eval_order) or sequenced-after the volatile access. This makes volatile objects suitable for communication with a [signal handler](/docs/cpp/library/utility/program/signal), but not with another thread of execution, see [`std::memory_order`](/docs/cpp/library/atomic/memory_order)). Any attempt to access a volatile object through a [glvalue](/docs/cpp/language/expressions/value_category#glvalue) of non-volatile type (e.g. through a reference or pointer to non-volatile type) results in undefined behavior.

{/* source:cpp-language-cv:0011 */}
- A `const volatile` object is

{/* source:cpp-language-cv:0012 */}
  - an object whose type is const-volatile-qualified, a non-[mutable](/docs/cpp/language/declarations/cv#mutable) subobject of a const volatile object, a const subobject of a volatile object, or a non-mutable volatile subobject of a const object. Behaves as both a const object and as a volatile object.

{/* source:cpp-language-cv:0013 */}
Each cv-qualifier (`const` and `volatile`) can appear at most once in any cv-qualifier sequence. For example, `const const` and `volatile const volatile` are not valid cv-qualifier sequences.

## mutable specifier

{/* source:cpp-language-cv:0014 */}
- `mutable` - permits modification of the class member declared mutable even if the containing object is declared const (i.e., the class member is mutable).

{/* source:cpp-language-cv:0015 */}
May appear in the declaration of a non-static [class members](/docs/cpp/language/classes/data_members) of non-reference non-const type:

{/* source:cpp-language-cv:0016 */}
```cpp
class X
{
    mutable const int* p; // OK
    mutable int* const q; // ill-formed
    mutable int&       r; // ill-formed
};
```

{/* source:cpp-language-cv:0017 */}
`mutable` is used to specify that the member does not affect the externally visible state of the class (as often used for mutexes, memo caches, lazy evaluation, and access instrumentation).

{/* source:cpp-language-cv:0018 */}
```cpp
class ThreadsafeCounter
{
    mutable std::mutex m; // The "M&M rule": mutable and mutex go together
    int data = 0;
public:
    int get() const
    {
        std::lock_guard<std::mutex> lk(m);
        return data;
    }

    void inc()
    {
        std::lock_guard<std::mutex> lk(m);
        ++data;
    }
};
```

## Conversions

{/* source:cpp-language-cv:0019 */}
There is partial ordering of cv-qualifiers by the order of increasing restrictions. The type can be said more or less cv-qualified than:

{/* source:cpp-language-cv:0020 */}
- *unqualified* \< `const`
- *unqualified* \< `volatile`
- *unqualified* \< `const volatile`
- `const` \< `const volatile`
- `volatile` \< `const volatile`

{/* source:cpp-language-cv:0021 */}
References and pointers to cv-qualified types can be implicitly converted to references and pointers to more cv-qualified types, see [qualification conversions](/docs/cpp/language/expressions/implicit_cast#Qualification_conversions) for details.

{/* source:cpp-language-cv:0022 */}
To convert a reference or a pointer to a cv-qualified type to a reference or pointer to a less cv-qualified type, [`const_cast`](/docs/cpp/language/expressions/const_cast) must be used.

## Notes

{/* source:cpp-language-cv:0023 */}
The `const` qualifier used on a declaration of a non-local non-volatile <InlineRevision since="C++14">non-[template](/docs/cpp/language/templates/variable_template)</InlineRevision> <InlineRevision since="C++17">non-[inline](/docs/cpp/language/declarations/inline)</InlineRevision> variable that is not declared `extern` gives it [internal linkage](/docs/cpp/language/declarations/storage_duration#Linkage). This is different from C where const file scope variables have external linkage.

{/* source:cpp-language-cv:0024 */}
The C++ language grammar treats `mutable` as a [storage-class-specifier](/docs/cpp/language/declarations/storage_duration), rather than a type qualifier, but it does not affect storage class or linkage.

{/* source:cpp-language-cv:0025 */}
<Revision since="C++20">
Some uses of volatile are deprecated:

- lvalue of volatile type as operand of built-in [increment/decrement](/docs/cpp/language/expressions/operator_incdec) operators;
- lvalue of volatile type as left operand of built-in [direct assignment](/docs/cpp/language/expressions/operator_assignment), unless the direct assignment expression appears in an [unevaluated context](/docs/cpp/language/expressions#Unevaluated_expressions) or is a [discarded-value expression](/docs/cpp/language/expressions#Discarded-value_expressions);
- volatile object type as function parameter type or return type;
- volatile qualifier in [structured binding](/docs/cpp/language/declarations/structured_binding) declaration.
</Revision>

## Keywords

{/* source:cpp-language-cv:0026 */}
[`const`](/docs/cpp/language/keywords/const), [`volatile`](/docs/cpp/language/keywords/volatile), [`mutable`](/docs/cpp/language/keywords/mutable)

## Example

{/* source:cpp-language-cv:0027 */}
```cpp
#include <cstdlib>

int main()
{
    int n1 = 0;          // non-const object
    const int n2 = 0;    // const object
    int const n3 = 0;    // const object (same as n2)
    volatile int n4 = 0; // volatile object

    const struct
    {
        int n1;
        mutable int n2;
    } x = {0, 0};        // const object with mutable member

    n1 = 1;   // OK: modifiable object
//  n2 = 2;   // error: non-modifiable object
    n4 = 3;   // OK: treated as a side-effect
//  x.n1 = 4; // error: member of a const object is const
    x.n2 = 4; // OK: mutable member of a const object isn't const

    const int& r1 = n1; // reference to const bound to non-const object
//  r1 = 2; // error: attempt to modify through reference to const
    const_cast<int&>(r1) = 2; // OK: modifies non-const object n1

    const int& r2 = n2; // reference to const bound to const object
//  r2 = 2; // error: attempt to modify through reference to const
//  const_cast<int&>(r2) = 2; // undefined behavior: attempt to modify const object n2

    [](...){}(n3, n4, x, r2); // see also: [[maybe_unused]]

    std::system("g++ -O3 -Wa,-adhln ./main.cpp"); // may issue asm on POSIX systems
}
```

Possible output:

```text
# typical machine code produced on an x86_64 platform
# (only the code that contributes to observable side-effects is emitted)
main:
    movl    $0, -4(%rsp) # volatile int n4 = 0;
    movl    $3, -4(%rsp) # n4 = 3;
    xorl    %eax, %eax   # return 0 (implicit)
    ret
```
