{/* source:cpp-language-attributes:0000 */}
Introduces implementation-defined attributes for types, objects, code, etc.

## Syntax

{/* source:cpp-language-attributes:0001 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" since="C++11" grammar code="[[ attribute-list ]]" />
  <Declaration id="2" language="cpp" since="C++17" grammar code="[[ using attribute-namespace : attribute-list ]]" />
</DeclarationDoc>

{/* source:cpp-language-attributes:0002 */}
where *attribute-list* is a comma-separated sequence of zero or more *attribute*s (possibly ending with an ellipsis `...` indicating a [pack expansion](/docs/cpp/language/templates/parameter_pack))

{/* source:cpp-language-attributes:0003 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="identifier" />
  <Declaration id="2" language="cpp" grammar code="attribute-namespace :: identifier" />
  <Declaration id="3" language="cpp" grammar code="identifier ( argument-list (optional) )" />
  <Declaration id="4" language="cpp" grammar code="attribute-namespace :: identifier ( argument-list (optional) )" />
</DeclarationDoc>

{/* source:cpp-language-attributes:0004 */}
where *attribute-namespace* is an identifier and *argument-list* is a sequence of tokens where parentheses, brackets and braces are balanced (*balanced-token-seq*).

{/* source:cpp-language-attributes:0005 */}
1. Simple attribute, such as `[[noreturn]]`.
{/* source:cpp-language-attributes:0006 */}
2. Attribute with a namespace, such as `[[gnu::unused]]`.
{/* source:cpp-language-attributes:0007 */}
3. Attribute with arguments, such as `[[deprecated("because")]]`.
{/* source:cpp-language-attributes:0008 */}
4. Attribute with both a namespace and an argument list.

{/* source:cpp-language-attributes:0009 */}
<Revision since="C++17">
If `using namespace:` appears in the beginning of an attribute list, no other attributes in the attribute list can specify a namespace: the namespace specified in a using applies to them all:

```cpp
[[using CC: opt(1), debug]] // same as [[CC::opt(1), CC::debug]]
[[using CC: CC::opt(1)]] // error: cannot combine using and scoped attribute
```
</Revision>

## Explanation

{/* source:cpp-language-attributes:0010 */}
Attributes provide the unified standard syntax for implementation-defined language extensions, such as the GNU and IBM language extensions `__attribute__((...))`, Microsoft extension `__declspec()`, etc.

{/* source:cpp-language-attributes:0011 */}
An attribute can be used almost everywhere in the C++ program, and can be applied to almost everything: to types, to variables, to functions, to names, to code blocks, to entire translation units, although each particular attribute is only valid where it is permitted by the implementation: `[[expect_true]]` could be an attribute that can only be used with an `if`, and not with a class declaration. `[[omp::parallel()]]` could be an attribute that applies to a code block or to a `for` loop, but not to the type `int`, etc (note these two attributes are fictional examples, see below for the standard and some non-standard attributes).

{/* source:cpp-language-attributes:0012 */}
In declarations, attributes may appear both before the whole declaration and directly after the name of the entity that is declared, in which case they are combined. In most other situations, attributes apply to the directly preceding entity.

{/* source:cpp-language-attributes:0013 */}
The [`alignas specifier`](/docs/cpp/language/declarations/alignas) is a part of the attribute specifier sequence, although it has different syntax. It may appear where the `[[...]]` attributes appear and may mix with them (provided it is used where alignas is permitted).

{/* source:cpp-language-attributes:0014 */}
Two consecutive left square bracket tokens (`[[`) may only appear when introducing an attribute-specifier or inside an attribute argument.

{/* source:cpp-language-attributes:0015 */}
```cpp
void f()
{
    int y[3];
    y[[] { return 0; }()] = 1;  // error
    int i [[cats::meow([[]])]]; // OK
}
```

{/* source:cpp-language-attributes:0016 */}
Besides the standard attributes listed below, implementations may support arbitrary non-standard attributes with implementation-defined behavior. <InlineRevision since="C++17">All attributes unknown to an implementation are ignored without causing an error.</InlineRevision>

{/* source:cpp-language-attributes:0017 */}
<Revision since="C++20">
An attribute without *attribute-namespace* and an *attribute-namespace* whose name is either `std` or `std` followed by one or more digits is reserved for future standardization. That is, every non-standard attribute is in the attribute-namespace provided by the implementation, e.g. `[[gnu::may_alias]]`, `[[clang::trivial_abi]]`, and `[[msvc::noop_dtor]]`.
</Revision>

## Standard attributes

{/* source:cpp-language-attributes:0018 */}
The following attributes are defined by the C++ standard.

{/* source:cpp-language-attributes:0019 */}
Standard attributes cannot be syntactically ignored: they cannot contain syntax errors, must be applied to the correct target, and entities in the arguments must be [ODR-use](/docs/cpp/language/basic_concepts/definition#ODR-use).

{/* source:cpp-language-attributes:0020 */}
Standard attributes cannot be semantically ignored either: the behavior with all instances of a particular standard attribute removed would have been a conforming behavior for the original program with the attribute present.

{/* source:cpp-language-attributes:0021 */}
<DescriptionList>
  <DescriptionItem>
    <DescriptionTerm>[`noreturn`](/docs/cpp/language/declarations/attributes/noreturn) <InlineRevision since="C++11" /></DescriptionTerm>
    <DescriptionBody>indicates that the function does not return (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`carries_dependency`](/docs/cpp/language/declarations/attributes/carries_dependency) <InlineRevision since="C++11" /></DescriptionTerm>
    <DescriptionBody>indicates that dependency chain in release-consume [`std::memory_order`](/docs/cpp/library/atomic/memory_order) propagates in and out of the function (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`deprecated`](/docs/cpp/language/declarations/attributes/deprecated), [`deprecated("reason")`](/docs/cpp/language/declarations/attributes/deprecated) <InlineRevision since="C++14" /></DescriptionTerm>
    <DescriptionBody>indicates that the use of the name or entity declared with this attribute is allowed, but discouraged for some *reason* (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`fallthrough`](/docs/cpp/language/declarations/attributes/fallthrough) <InlineRevision since="C++17" /></DescriptionTerm>
    <DescriptionBody>indicates that the fall through from the previous case label is intentional and should not be diagnosed by a compiler that warns on fall-through (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`maybe_unused`](/docs/cpp/language/declarations/attributes/maybe_unused) <InlineRevision since="C++17" /></DescriptionTerm>
    <DescriptionBody>suppresses compiler warnings on unused entities, if any (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`nodiscard`](/docs/cpp/language/declarations/attributes/nodiscard) <InlineRevision since="C++17" />, [`nodiscard("reason")`](/docs/cpp/language/declarations/attributes/nodiscard) <InlineRevision since="C++20" /></DescriptionTerm>
    <DescriptionBody>encourages the compiler to issue a warning if the return value is discarded (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`likely`](/docs/cpp/language/declarations/attributes/likely), [`unlikely`](/docs/cpp/language/declarations/attributes/likely) <InlineRevision since="C++20" /></DescriptionTerm>
    <DescriptionBody>indicates that the compiler should optimize for the case where a path of execution through a statement is more or less likely than any other path of execution (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`no_unique_address`](/docs/cpp/language/declarations/attributes/no_unique_address) <InlineRevision since="C++20" /></DescriptionTerm>
    <DescriptionBody>indicates that a non-static data member need not have an address distinct from all other non-static data members of its class (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`assume`](/docs/cpp/language/declarations/attributes/assume)(*expression*) <InlineRevision since="C++23" /></DescriptionTerm>
    <DescriptionBody>specifies that the *expression* will always evaluate to `true` at a given point (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`indeterminate`](/docs/cpp/language/declarations/attributes/indeterminate) <InlineRevision since="C++26" /></DescriptionTerm>
    <DescriptionBody>specifies that an object has an indeterminate value if it is not initialized (attribute specifier)</DescriptionBody>
  </DescriptionItem>
  <DescriptionItem>
    <DescriptionTerm>[`optimize_for_synchronized`](/docs/cpp/language/declarations/attributes/optimize_for_synchronized) (TM TS)</DescriptionTerm>
    <DescriptionBody>indicates that the function definition should be optimized for invocation from a [synchronized statement](/docs/cpp/language/statements/transactional_memory) (attribute specifier)</DescriptionBody>
  </DescriptionItem>
</DescriptionList>

## Example

{/* source:cpp-language-attributes:0024 */}
```cpp
[[gnu::always_inline]] [[gnu::hot]] [[gnu::const]] [[nodiscard]]
inline int f(); // declare f with four attributes

[[gnu::always_inline, gnu::const, gnu::hot, nodiscard]]
int f(); // same as above, but uses a single attr specifier that contains four attributes

// C++17:
[[using gnu : const, always_inline, hot]] [[nodiscard]]
int f[[gnu::always_inline]](); // an attribute may appear in multiple specifiers

int f() { return 0; }

int main() {}
```
