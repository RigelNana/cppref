{/* source:cpp-language-move-operator:0000 */}
A move assignment operator is a non-template [non-static member function](/docs/cpp/language/classes/member_functions) with the name `operator=` that can be called with an argument of the same class type and copies the content of the argument, possibly mutating the argument.

## Syntax

{/* source:cpp-language-move-operator:0001 */}
For the formal move assignment operator syntax, see [function declaration](/docs/cpp/language/functions/function). The syntax list below only demonstrates a subset of all valid move assignment operator syntaxes.

{/* source:cpp-language-move-operator:0002 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="return-type operator=( parameter-list );" />
  <Declaration id="2" language="cpp" grammar code="return-type operator=( parameter-list ) function-body" />
  <Declaration id="3" language="cpp" grammar code="return-type operator=( parameter-list-no-default ) = default;" />
  <Declaration id="4" language="cpp" grammar code="return-type operator=( parameter-list ) = delete;" />
  <Declaration id="5" language="cpp" grammar code="return-type class-name :: operator=( parameter-list ) function-body" />
  <Declaration id="6" language="cpp" grammar code="return-type class-name :: operator=( parameter-list-no-default ) = default;" />
</DeclarationDoc>

{/* source:cpp-language-move-operator:0003 */}
<ParameterList>
  <Parameter name="class-name">the class whose move assignment operator is being declared, the class type is given as `T` in the descriptions below</Parameter>
  <Parameter name="parameter-list">a [parameter list](/docs/cpp/language/functions/function#Parameter_list) of only one parameter, which is of type `T&&`, `const T&&`, `volatile T&&` or `const volatile T&&`</Parameter>
  <Parameter name="parameter-list-no-default">a [parameter list](/docs/cpp/language/functions/function#Parameter_list) of only one parameter, which is of type `T&&`, `const T&&`, `volatile T&&` or `const volatile T&&` and does not have a default argument</Parameter>
  <Parameter name="function-body">the [function body](/docs/cpp/language/classes/initializer_list) of the move assignment operator</Parameter>
  <Parameter name="return-type">any type, but `T&` is favored in order to be consistent with scala types</Parameter>
</ParameterList>

## Explanation

{/* source:cpp-language-move-operator:0004 */}
1. Declaration of a move assignment operator inside of class definition.
{/* source:cpp-language-move-operator:0005 */}
2. Definition of a move assignment operator inside of class definition.
{/* source:cpp-language-move-operator:0006 */}
   - 3) The move assignment operator is explicitly-defaulted.
{/* source:cpp-language-move-operator:0007 */}
   - 4) The move assignment operator is deleted.
{/* source:cpp-language-move-operator:0008 */}
5. Definition of a move assignment operator outside of class definition (the class must contain a declaration (1)).
{/* source:cpp-language-move-operator:0009 */}
   - 6) The move assignment operator is explicitly-defaulted.

{/* source:cpp-language-move-operator:0010 */}
```cpp
struct X
{
    X& operator=(X&& other);    // move assignment operator
//  X operator=(const X other); // Error: incorrect parameter type
};

union Y
{
    // move assignment operators can have syntaxes not listed above,
    // as long as they follow the general function declaration syntax
    // and do not viloate the restrictions listed above
    auto operator=(Y&& other) -> Y&;       // OK: trailing return type
    Y& operator=(this Y&& self, Y& other); // OK: explicit object parameter
//  Y& operator=(Y&&, int num = 1);        // Error: has other non-object parameters
};
```

{/* source:cpp-language-move-operator:0011 */}
The move assignment operator is called whenever it is selected by [overload resolution](/docs/cpp/language/functions/overload_resolution), e.g. when an object appears on the left-hand side of an assignment expression, where the right-hand side is an rvalue of the same or implicitly convertible type.

{/* source:cpp-language-move-operator:0012 */}
Move assignment operators typically transfer the resources held by the argument (e.g. pointers to dynamically-allocated objects, file descriptors, TCP sockets, thread handles, etc.), rather than make copies of them, and leave the argument in some valid but otherwise indeterminate state. Since move assignment doesn’t change the lifetime of the argument, the destructor will typically be called on the argument at a later point. For example, move-assigning from a [`std::string`](/docs/cpp/library/string/basic_string) or from a [`std::vector`](/docs/cpp/library/container/vector) may result in the argument being left empty. A move assignment is less, not more restrictively defined than ordinary assignment; where ordinary assignment must leave two copies of data at completion, move assignment is required to leave only one.

## Implicitly-declared move assignment operator

{/* source:cpp-language-move-operator:0013 */}
If no user-defined move assignment operators are provided for a class type, and all of the following is true:

{/* source:cpp-language-move-operator:0014 */}
- there are no user-declared [copy constructors](/docs/cpp/language/classes/copy_constructor);
- there are no user-declared [move constructors](/docs/cpp/language/classes/move_constructor);
- there are no user-declared [copy assignment operators](/docs/cpp/language/classes/as_operator);
- there is no user-declared [destructor](/docs/cpp/language/classes/destructor),

{/* source:cpp-language-move-operator:0015 */}
then the compiler will declare a move assignment operator as an inline public member of its class with the signature `T& T::operator=(T&&)`.

{/* source:cpp-language-move-operator:0016 */}
A class can have multiple move assignment operators, e.g. both `T& T::operator=(const T&&)` and `T& T::operator=(T&&)`. If some user-defined move assignment operators are present, the user may still force the generation of the implicitly declared move assignment operator with the keyword `default`.

{/* source:cpp-language-move-operator:0017 */}
The implicitly-declared move assignment operator has an exception specification as described in <InlineRevision until="C++17">[dynamic exception specification](/docs/cpp/language/exceptions/except_spec)</InlineRevision><InlineRevision since="C++17">[noexcept specification](/docs/cpp/language/exceptions/noexcept_spec)</InlineRevision>.

{/* source:cpp-language-move-operator:0018 */}
Because some assignment operator (move or copy) is always declared for any class, the base class assignment operator is always hidden. If a using-declaration is used to bring in the assignment operator from the base class, and its argument type could be the same as the argument type of the implicit assignment operator of the derived class, the using-declaration is also hidden by the implicit declaration.

## Implicitly-defined move assignment operator

{/* source:cpp-language-move-operator:0019 */}
If the implicitly-declared move assignment operator is neither deleted nor trivial, it is defined (that is, a function body is generated and compiled) by the compiler if [odr-used](/docs/cpp/language/basic_concepts/definition#ODR-use)<InlineRevision since="C++14"> or [needed for constant evaluation](/docs/cpp/language/expressions/constant_expression#Functions_and_variables_needed_for_constant_evaluation)</InlineRevision>.

{/* source:cpp-language-move-operator:0020 */}
For union types, the implicitly-defined move assignment operator copies the object representation (as by [`std::memmove`](/docs/cpp/library/text/byte/memmove)).

{/* source:cpp-language-move-operator:0021 */}
For non-union class types, the move assignment operator performs full member-wise move assignment of the object's direct bases and immediate non-static members, in their declaration order, using built-in assignment for the scalars, memberwise move-assignment for arrays, and move assignment operator for class types (called non-virtually).

{/* source:cpp-language-move-operator:0022 */}
<Revision since="C++14" until="C++23">
The implicitly-defined move assignment operator for a class `T` is [`constexpr`](/docs/cpp/language/declarations/constexpr) if `T` is a [literal type](/docs/cpp/library/named_req/LiteralType), and the assignment operator selected to move each direct base class subobject is a `constexpr` function, and for each non-static data member of `T` that is of class type (or array thereof), the assignment operator selected to move that member is a `constexpr` function.
</Revision>

<Revision since="C++23">
The implicitly-defined move assignment operator for a class `T` is [`constexpr`](/docs/cpp/language/declarations/constexpr).
</Revision>

{/* source:cpp-language-move-operator:0023 */}
As with copy assignment, it is unspecified whether virtual base class subobjects that are accessible through more than one path in the inheritance lattice, are assigned more than once by the implicitly-defined move assignment operator:

{/* source:cpp-language-move-operator:0024 */}
```cpp
struct V
{
    V& operator=(V&& other)
    {
        // this may be called once or twice
        // if called twice, 'other' is the just-moved-from V subobject
        return *this;
    }
};

struct A : virtual V {}; // operator= calls V::operator=
struct B : virtual V {}; // operator= calls V::operator=
struct C : B, A {};      // operator= calls B::operator=, then A::operator=
                         // but they may only call V::operator= once

int main()
{
    C c1, c2;
    c2 = std::move(c1);
}
```

## Deleted move assignment operator

{/* source:cpp-language-move-operator:0025 */}
The implicitly-declared or defaulted move assignment operator for class `T` is defined as deleted if any of the following conditions is satisfied:

{/* source:cpp-language-move-operator:0026 */}
- `T` has a non-static data member of a const-qualified non-class type (or possibly multi-dimensional array thereof).
- `T` has a non-static data member of a reference type.
- `T` has a [potentially constructed subobject](/docs/cpp/language/basic_concepts/objects#Potentially_constructed_subobject) of class type `M` (or possibly multi-dimensional array thereof) such that the overload resolution as applied to find `M`'s move assignment operator

{/* source:cpp-language-move-operator:0027 */}
  - does not result in a usable candidate, or
  - in the case of the subobject being a [variant member](/docs/cpp/language/classes/union#Union-like_classes), selects a non-trivial function.

{/* source:cpp-language-move-operator:0028 */}
A deleted implicitly-declared move assignment operator is ignored by [overload resolution](/docs/cpp/language/functions/overload_resolution).

## Trivial move assignment operator

{/* source:cpp-language-move-operator:0029 */}
The move assignment operator for class `T` is trivial if all of the following is true:

{/* source:cpp-language-move-operator:0030 */}
- It is not user-provided (meaning, it is implicitly-defined or defaulted);
- `T` has no virtual member functions;
- `T` has no virtual base classes;
- the move assignment operator selected for every direct base of `T` is trivial;
- the move assignment operator selected for every non-static class type (or array of class type) member of `T` is trivial.

{/* source:cpp-language-move-operator:0031 */}
A trivial move assignment operator performs the same action as the trivial copy assignment operator, that is, makes a copy of the object representation as if by [`std::memmove`](/docs/cpp/library/text/byte/memmove). All data types compatible with the C language are trivially move-assignable.

## Eligible move assignment operator

{/* source:cpp-language-move-operator:0032 */}
<Revision until="C++20">
A move assignment operator is eligible if it is not deleted.
</Revision>

<Revision since="C++20">
A move assignment operator is eligible if all following conditions are satisfied:

- It is not deleted.
- Its [associated constraints](/docs/cpp/language/templates/constraints) (if any) are satisfied.
- No move assignment operator whose associated constraints are satisfied is [more constrained](/docs/cpp/language/templates/constraints#Partial_ordering_of_constraints).
</Revision>

{/* source:cpp-language-move-operator:0033 */}
Triviality of eligible move assignment operators determines whether the class is a [trivially copyable type](/docs/cpp/library/named_req/TriviallyCopyable).

## Notes

{/* source:cpp-language-move-operator:0034 */}
If both copy and move assignment operators are provided, overload resolution selects the move assignment if the argument is an [rvalue](/docs/cpp/language/expressions/value_category) (either a [prvalue](/docs/cpp/language/expressions/value_category) such as a nameless temporary or an [xvalue](/docs/cpp/language/expressions/value_category) such as the result of `std::move`), and selects the copy assignment if the argument is an [lvalue](/docs/cpp/language/expressions/value_category) (named object or a function/operator returning lvalue reference). If only the copy assignment is provided, all argument categories select it (as long as it takes its argument by value or as reference to const, since rvalues can bind to const references), which makes copy assignment the fallback for move assignment, when move is unavailable.

{/* source:cpp-language-move-operator:0035 */}
It is unspecified whether virtual base class subobjects that are accessible through more than one path in the inheritance lattice, are assigned more than once by the implicitly-defined move assignment operator (same applies to [copy assignment](/docs/cpp/language/classes/as_operator)).

{/* source:cpp-language-move-operator:0036 */}
See [assignment operator overloading](/docs/cpp/language/expressions/operators#Assignment_operator) for additional detail on the expected behavior of a user-defined move-assignment operator.

## Example

{/* source:cpp-language-move-operator:0037 */}
```cpp
#include <iostream>
#include <string>
#include <utility>

struct A
{
    std::string s;

    A() : s("test") {}

    A(const A& o) : s(o.s) { std::cout << "move failed!\n"; }

    A(A&& o) : s(std::move(o.s)) {}

    A& operator=(const A& other)
    {
         s = other.s;
         std::cout << "copy assigned\n";
         return *this;
    }

    A& operator=(A&& other)
    {
         s = std::move(other.s);
         std::cout << "move assigned\n";
         return *this;
    }
};

A f(A a) { return a; }

struct B : A
{
    std::string s2; 
    int n;
    // implicit move assignment operator B& B::operator=(B&&)
    // calls A's move assignment operator
    // calls s2's move assignment operator
    // and makes a bitwise copy of n
};

struct C : B
{
    ~C() {} // destructor prevents implicit move assignment
};

struct D : B
{
    D() {}
    ~D() {} // destructor would prevent implicit move assignment
    D& operator=(D&&) = default; // force a move assignment anyway 
};

int main()
{
    A a1, a2;
    std::cout << "Trying to move-assign A from rvalue temporary\n";
    a1 = f(A()); // move-assignment from rvalue temporary
    std::cout << "Trying to move-assign A from xvalue\n";
    a2 = std::move(a1); // move-assignment from xvalue

    std::cout << "\nTrying to move-assign B\n";
    B b1, b2;
    std::cout << "Before move, b1.s = \"" << b1.s << "\"\n";
    b2 = std::move(b1); // calls implicit move assignment
    std::cout << "After move, b1.s = \"" << b1.s << "\"\n";

    std::cout << "\nTrying to move-assign C\n";
    C c1, c2;
    c2 = std::move(c1); // calls the copy assignment operator

    std::cout << "\nTrying to move-assign D\n";
    D d1, d2;
    d2 = std::move(d1);
}
```

Output:

```text
Trying to move-assign A from rvalue temporary
move assigned
Trying to move-assign A from xvalue
move assigned

Trying to move-assign B
Before move, b1.s = "test"
move assigned
After move, b1.s = ""

Trying to move-assign C
copy assigned

Trying to move-assign D
move assigned
```
