{/* source:cpp-language-if:0000 */}
Conditionally executes another statement.

{/* source:cpp-language-if:0001 */}
Used where code needs to be executed based on a condition<InlineRevision since="C++23">, or whether the `if` statement is evaluated in a manifestly constant-evaluated context</InlineRevision>.

## Syntax

{/* source:cpp-language-if:0002 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="attr (optional) if constexpr (optional) ( init-statement (optional) condition ) statement-true" />
  <Declaration id="2" language="cpp" grammar code="attr (optional) if constexpr (optional) ( init-statement (optional) condition ) statement-true else statement-false" />
  <Declaration id="3" language="cpp" grammar since="C++23" code="attr (optional) if ! (optional) consteval compound-statement" />
  <Declaration id="4" language="cpp" grammar since="C++23" code="attr (optional) if ! (optional) consteval compound-statement else statement" />
</DeclarationDoc>

{/* source:cpp-language-if:0003 */}
1. `if` statement without an `else` branch

{/* source:cpp-language-if:0004 */}
2. `if` statement with an `else` branch

{/* source:cpp-language-if:0005 */}
3. consteval if statement without an `else` branch

{/* source:cpp-language-if:0006 */}
4. consteval if statement with an `else` branch

    <Revision since="C++23">
    - an [alias declaration](/docs/cpp/language/declarations/type_alias)

  </Parameter>

  </Parameter>

## Condition

{/* source:cpp-language-if:0008 */}
A condition can either be an [expression](/docs/cpp/language/expressions) or a [simple declaration](/docs/cpp/language/declarations#Simple_declaration).

{/* source:cpp-language-if:0009 */}
<Revision since="C++26">
- If it can be syntactically resolved as a [structured binding](/docs/cpp/language/declarations/structured_binding) declaration, it is interpreted as a structured binding declaration.
</Revision>

{/* source:cpp-language-if:0010 */}
- If it can be syntactically resolved as an expression, it is treated as an expression. Otherwise, it is treated as a declaration<InlineRevision since="C++26"> that is not a structured binding declaration</InlineRevision>.

{/* source:cpp-language-if:0011 */}
When control reaches `condition`, the condition will yield a value, which is used to determine which branch the control will go to.

### Expression

{/* source:cpp-language-if:0012 */}
If `condition` is an expression, the value it yields is the the value of the expression contextually converted to `bool`. If that conversion is ill-formed, the program is ill-formed.

### Declaration

{/* source:cpp-language-if:0013 */}
If `condition` is a simple declaration, the value it yields is the value of the decision variable (see below) contextually converted to `bool`. If that conversion is ill-formed, the program is ill-formed.

#### Non-structured binding declaration

{/* source:cpp-language-if:0014 */}
The declaration has the following restrictions:

{/* source:cpp-language-if:0015 */}
Syntactically conforms to the following form:

{/* source:cpp-language-if:0016 */}
<Revision until="C++11">
- `type-specifier-seq` `declarator` `=` `assignment-expression`
</Revision>

<Revision since="C++11">
- `attribute-specifier-seq` `(optional)` `decl-specifier-seq` `declarator` `brace-or-equal-initializer`
</Revision>

{/* source:cpp-language-if:0017 */}
- The declarator cannot specify a [function](/docs/cpp/language/functions/function) or an [array](/docs/cpp/language/declarations/array).
- The <InlineRevision until="C++11">[type specifier sequence](/docs/cpp/language/declarations#Specifiers)</InlineRevision><InlineRevision since="C++11">[declaration specifier sequence](/docs/cpp/language/declarations#Specifiers) can only contain type specifiers and `constexpr`, and it</InlineRevision> cannot define a [class](/docs/cpp/language/classes/class) or [enumeration](/docs/cpp/language/declarations/enum).

{/* source:cpp-language-if:0018 */}
The decision variable of the declaration is the declared variable.

{/* source:cpp-language-if:0019 */}
<Revision since="C++26">
#### Structured binding declaration

The declaration has the following restrictions:

- The `expression` in its [initializer](/docs/cpp/language/initialization) cannot be of an array type.
- The [declaration specifier sequence](/docs/cpp/language/declarations#Specifiers) can only contain type specifiers and `constexpr`.

The decision variable of the declaration is the invented variable `e` [introduced by the declaration](/docs/cpp/language/declarations/structured_binding).
</Revision>

## Branch selection

{/* source:cpp-language-if:0020 */}
If the condition yields `true`, `statement-true` is executed.

{/* source:cpp-language-if:0021 */}
If the `else` part of the if statement is present and `condition` yields `false`, `statement-false` is executed.

{/* source:cpp-language-if:0022 */}
If the `else` part of the if statement is present and `statement-true` is also an `if` statement, then that inner if statement must contain an `else` part as well (in other words, in nested if statements, the `else` is associated with the closest `if` that does not yet have an associated `else`).

{/* source:cpp-language-if:0023 */}
```cpp
#include <iostream>

int main()
{
    // simple if-statement with an else clause
    int i = 2;
    if (i > 2)
        std::cout << i << " is greater than 2\n";
    else
        std::cout << i << " is not greater than 2\n";

    // nested if-statement
    int j = 1;
    if (i > 1)
        if (j > 2)
            std::cout << i << " > 1 and " << j << " > 2\n";
        else // this else is part of if (j > 2), not of if (i > 1)
            std::cout << i << " > 1 and " << j << " <= 2\n";

    // declarations can be used as conditions with dynamic_cast
    struct Base
    {
        virtual ~Base() {}
    };

    struct Derived : Base
    {
        void df() { std::cout << "df()\n"; }
    };

    Base* bp1 = new Base;
    Base* bp2 = new Derived;

    if (Derived* p = dynamic_cast<Derived*>(bp1)) // cast fails, returns nullptr
        p->df(); // not executed

    if (auto p = dynamic_cast<Derived*>(bp2)) // cast succeeds
        p->df(); // executed
}
```

Output:

```text
2 is not greater than 2
2 > 1 and 1 <= 2
df()
```

## if statements with initializer

If `init-statement` is used, the `if` statement is equivalent to

<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="{ init-statement attr (optional) if constexpr (optional) ( condition ) statement-true }" />
</DeclarationDoc>

or

<DeclarationDoc>
  <Declaration id="2" language="cpp" grammar code="{ init-statement attr (optional) if constexpr (optional) ( condition ) statement-true else statement-false }" />
</DeclarationDoc>

Except that names declared by the `init-statement` (if `init-statement` is a declaration) and names declared by `condition` (if `condition` is a declaration) are in the same scope, which is also the scope of both `statement`s.

```cpp
std::map<int, std::string> m;
std::mutex mx;
extern bool shared_flag; // guarded by mx

int demo()
{
    if (auto it = m.find(10); it != m.end())
        return it->second.size();

    if (char buf[10]; std::fgets(buf, 10, stdin))
        m[0] += buf;

    if (std::lock_guard lock(mx); shared_flag)
    {
        unsafe_ping();
        shared_flag = false;
    }

    if (int s; int count = ReadBytesWithSignal(&s))
    {
        publish(count);
        raise(s);
    }

    if (const auto keywords = {"if", "for", "while"};
        std::ranges::any_of(keywords, [&tok](const char* kw) { return tok == kw; }))
    {
        std::cerr << "Token must not be a keyword\n";
    }
}
```
</Revision>

## Constexpr if

The statement that begins with `if constexpr` is known as the *constexpr if statement*. All substatements of a constexpr if statement are [control-flow-limited statements](/docs/cpp/language/statements#Control-flow-limited_statements).

In a constexpr if statement, `condition` must be <InlineRevision until="C++23">a [contextually converted constant expression of type `bool`](/docs/cpp/language/expressions/constant_expression#Converted_constant_expression)</InlineRevision><InlineRevision since="C++23">an expression [contextually converted to `bool`](/docs/cpp/language/expressions/implicit_cast#Contextual_conversions), where the conversion is a [constant expression](/docs/cpp/language/expressions/constant_expression)</InlineRevision>.

If `condition` yields `true`, then `statement-false` is discarded (if present), otherwise, `statement-true` is discarded.

The `return` statements in a discarded statement do not participate in function return type deduction:

```cpp
template<typename T>
auto get_value(T t)
{
    if constexpr (std::is_pointer_v<T>)
        return *t; // deduces return type to int for T = int*
    else
        return t;  // deduces return type to int for T = int
}
```

The discarded statement can [ODR-use](/docs/cpp/language/basic_concepts/definition#One_Definition_Rule) a variable that is not defined:

```cpp
extern int x; // no definition of x required

int f()
{
    if constexpr (true)
        return 0;
    else if (x)
        return x;
    else
        return -x;
}
```

Outside a template, a discarded statement is fully checked. `if constexpr` is not a substitute for the [`#if`](/docs/cpp/language/preprocessor/conditional) preprocessing directive:

```cpp
void f()
{
    if constexpr(false)
    {
        int i = 0;
        int *p = i; // Error even though in discarded statement
    }
}
```

If a constexpr if statement appears inside a [templated entity](/docs/cpp/language/templates#Templated_entity), and if `condition` is not [value-dependent](/docs/cpp/language/templates/dependent_name#Value-dependent_expressions) after instantiation, the discarded statement is not instantiated when the enclosing template is instantiated.

```cpp
template<typename T, typename ... Rest>
void g(T&& p, Rest&& ...rs)
{
    // ... handle p
    if constexpr (sizeof...(rs) > 0)
        g(rs...); // never instantiated with an empty argument list
}
```

The condition remains value-dependent after instantiation is a nested template:

```cpp
template<class T>
void g()
{
    auto lm = [=](auto p)
    {
        if constexpr (sizeof(T) == 1 && sizeof p == 1)
        {
            // this condition remains value-dependent after instantiation of g<T>,
            // which affects implicit lambda captures
            // this compound statement may be discarded only after
            // instantiation of the lambda body
        }
    };
}
```

The discarded statement cannot be ill-formed for every possible specialization:

```cpp
template<typename T>
void f()
{
    if constexpr (std::is_arithmetic_v<T>)
        // ...
    else {
        using invalid_array = int[-1]; // ill-formed: invalid for every T
        static_assert(false, "Must be arithmetic"); // ill-formed before CWG2518
    }
}
```

The common workaround before the implementation of [CWG issue 2518](https://cplusplus.github.io/CWG/issues/2518.html) for such a catch-all statement is a type-dependent expression that is always `false`:

```cpp
template<typename>
constexpr bool dependent_false_v = false;

template<typename T>
void f()
{
    if constexpr (std::is_arithmetic_v<T>)
        // ...
    else {
        // workaround before CWG2518
        static_assert(dependent_false_v<T>, "Must be arithmetic");
    }
}
```

A [typedef declaration](/docs/cpp/language/declarations/typedef) <InlineRevision since="C++23">or [alias declaration](/docs/cpp/language/declarations/type_alias)</InlineRevision> can be used as the `init-statement` of a constexpr if statement to reduce the scope of the type alias.

</Revision>

## Consteval if

The statement that begins with `if consteval` is known as the *consteval if statement*. All substatements of a consteval if statement are [control-flow-limited statements](/docs/cpp/language/statements#Control-flow-limited_statements).

`statement` must be a compound statement, and it will still be treated as a part of the consteval if statement even if it is not a compound statement (and thus results in a compilation error):

```cpp
constexpr void f(bool b)
{
    if (true)
        if consteval {}
        else ; // error: not a compound-statement
               // else not associated with outer if
}
```

If a consteval if statement is evaluated in a [manifestly constant-evaluated context](/docs/cpp/language/expressions/constant_expression#Manifestly_constant-evaluated_expressions), `compound-statement` is executed. Otherwise, `statement` is executed if it is present.

If the statement begins with `if !consteval`, the `compound-statement` and `statement` (if any) must both be compound statements. Such statements are not considered consteval if statements, but are equivalent to consteval if statements:

- `if !consteval { /* stmt */ }` is equivalent to

    `if consteval {} else { /* stmt */ }`.

- `if !consteval { /* stmt-1 */ } else { /* stmt-2 */ }` is equivalent to

    `if consteval { /* stmt-2 */ } else { /* stmt-1 */ }`.

`compound-statement` in a consteval if statement (or `statement` in the negative form) is in an [immediate function context](/docs/cpp/language/declarations/consteval), in which a call to an immediate function needs not to be a constant expression.

```cpp
#include <cmath>
#include <cstdint>
#include <cstring>
#include <iostream>

constexpr bool is_constant_evaluated() noexcept
{
    if consteval { return true; } else { return false; }
}

constexpr bool is_runtime_evaluated() noexcept
{
    if not consteval { return true; } else { return false; }
}

consteval std::uint64_t ipow_ct(std::uint64_t base, std::uint8_t exp)
{
    if (!base) return base;
    std::uint64_t res{1};
    while (exp)
    {
        if (exp & 1) res *= base;
        exp /= 2;
        base *= base;
    }
    return res;
}

constexpr std::uint64_t ipow(std::uint64_t base, std::uint8_t exp)
{
    if consteval // use a compile-time friendly algorithm
    {
        return ipow_ct(base, exp);
    }
    else // use runtime evaluation
    {
        return std::pow(base, exp);
    }
}

int main(int, const char* argv[])
{
    static_assert(ipow(0, 10) == 0 && ipow(2, 10) == 1024);
    std::cout << ipow(std::strlen(argv[0]), 3) << '\n';
}
```
</Revision>

## Notes

{/* source:cpp-language-if:0027 */}
If `statement-true` or `statement-false` is not a compound statement, it is treated as if it were:

{/* source:cpp-language-if:0028 */}
```cpp
if (x)
    int i;
// i is no longer in scope
```

{/* source:cpp-language-if:0029 */}
is the same as

{/* source:cpp-language-if:0030 */}
```cpp
if (x)
{
    int i;
}
// i is no longer in scope
```

{/* source:cpp-language-if:0031 */}
The scope of the name introduced by `condition`, if it is a declaration, is the combined scope of both statements' bodies:

{/* source:cpp-language-if:0032 */}
```cpp
if (int x = f())
{
    int x; // error: redeclaration of x
}
else
{
    int x; // error: redeclaration of x
}
```

{/* source:cpp-language-if:0033 */}
If `statement-true` is entered by [goto](/docs/cpp/language/statements/goto) or `longjmp`, `condition` is not evaluated and `statement-false` is not executed.

{/* source:cpp-language-if:0034 */}
<Revision since="C++17" until="C++23">
Built-in conversions are not allowed in the `condition` of a constexpr if statement, except for non-[narrowing](/docs/cpp/language/initialization/list_initialization#Narrowing_conversions) [integral conversions](/docs/cpp/language/expressions/implicit_cast#Integral_conversions) to `bool`.
</Revision>
