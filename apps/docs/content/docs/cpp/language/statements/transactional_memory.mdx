{/* source:cpp-language-transactional-memory:0000 */}
Transactional memory is a concurrency synchronization mechanism that combines groups of statements in transactions, that are

{/* source:cpp-language-transactional-memory:0001 */}
- atomic (either all statements occur, or nothing occurs)
- isolated (statements in a transaction may not observe half-written writes made by another transaction, even if they execute in parallel)

{/* source:cpp-language-transactional-memory:0002 */}
Typical implementations use hardware transactional memory where supported and to the limits that it is available (e.g. until the changeset is saturated) and fall back to software transactional memory, usually implemented with optimistic concurrency: if another transaction updated some of the variables used by a transaction, it is silently retried. For that reason, retriable transactions ("atomic blocks") can only call transaction-safe functions.

{/* source:cpp-language-transactional-memory:0003 */}
Note that accessing a variable in a transaction and out of a transaction without other external synchronization is a data race.

{/* source:cpp-language-transactional-memory:0004 */}
If feature testing is supported, the features described here are indicated by the macro constant `__cpp_transactional_memory` with a value equal or greater `201505`.

## Synchronized blocks

{/* source:cpp-language-transactional-memory:0005 */}
<DeclarationDoc>
  <Declaration language="cpp" grammar code={`synchronized compound-statement`} />
</DeclarationDoc>

{/* source:cpp-language-transactional-memory:0006 */}
Executes the [compound statement](/docs/cpp/language/statements#Compound_statements) as if under a global lock: all outermost synchronized blocks in the program execute in a single total order. The end of each synchronized block synchronizes with the beginning of the next synchronized block in that order. Synchronized blocks that are nested within other synchronized blocks have no special semantics.

{/* source:cpp-language-transactional-memory:0007 */}
Synchronized blocks are not transactions (unlike the atomic blocks below) and may call transaction-unsafe functions.

{/* source:cpp-language-transactional-memory:0008 */}
```cpp
#include <iostream>
#include <thread>
#include <vector>

int f()
{
    static int i = 0;
    synchronized { // begin synchronized block
        std::cout << i << " -> ";
        ++i;       // each call to f() obtains a unique value of i
        std::cout << i << '\n';
        return i;  // end synchronized block
    }
}

int main()
{
    std::vector<std::thread> v(10);
    for (auto& t : v)
        t = std::thread([] { for (int n = 0; n < 10; ++n) f(); });
    for (auto& t : v)
        t.join();
}
```

Output:

```text
0 -> 1
1 -> 2
2 -> 3
...
99 -> 100
```

{/* source:cpp-language-transactional-memory:0009 */}
Leaving a synchronized block by any means (reaching the end, executing goto, break, continue, or return, or throwing an exception) exits the block and synchronizes-with the next block in the single total order if the exited block was an outer block. The behavior is undefined if [std::longjmp](/docs/cpp/library/utility/program/longjmp) is used to exit a synchronized block.

{/* source:cpp-language-transactional-memory:0010 */}
Entering a synchronized block by goto or switch is not allowed.

{/* source:cpp-language-transactional-memory:0011 */}
Although synchronized blocks execute as-if under a global lock, the implementations are expected to examine the code within each block and use optimistic concurrency (backed up by hardware transactional memory where available) for transaction-safe code and minimal locking for non-transaction safe code. When a synchronized block makes a call to a non-inlined function, the compiler may have to drop out of speculative execution and hold a lock around the entire call unless the function is declared transaction_safe (see below) or the attribute [[optimize_for_synchronized]] (see below) is used.

## Atomic blocks

{/* source:cpp-language-transactional-memory:0013 */}
<Declaration language="cpp" grammar code={`atomic_noexcept compound-statement`} />

{/* source:cpp-language-transactional-memory:0014 */}
<Declaration language="cpp" grammar code={`atomic_cancel compound-statement`} />

{/* source:cpp-language-transactional-memory:0015 */}
<Declaration language="cpp" grammar code={`atomic_commit compound-statement`} />

{/* source:cpp-language-transactional-memory:0016 */}
1. If an exception is thrown, `std::abort` is called.

{/* source:cpp-language-transactional-memory:0017 */}
2. If an exception is thrown, `std::abort` is called, unless the exception is one of the exceptions used for transaction cancellation (see below) in which case the transaction is cancelled: the values of all memory locations in the program that were modified by side effects of the operations of the atomic block are restored to the values they had at the time the start of the atomic block was executed, and the exception continues stack unwinding as usual.

{/* source:cpp-language-transactional-memory:0018 */}
3. If an exception is thrown, the transaction is committed normally.

{/* source:cpp-language-transactional-memory:0019 */}
The exceptions used for transaction cancellation in atomic_cancel blocks are [std::bad_alloc](/docs/cpp/library/memory/new/bad_alloc), [std::bad_array_new_length](/docs/cpp/library/memory/new/bad_array_new_length), [std::bad_cast](/docs/cpp/library/utility/types/bad_cast), [std::bad_typeid](/docs/cpp/library/utility/types/bad_typeid), [std::bad_exception](/docs/cpp/library/error/bad_exception), [std::exception](/docs/cpp/library/error/exception) and all standard library exceptions derived from it, and the special exception type [`std::tx_exception<T>`](/docs/cpp/library/error/tx_exception).

{/* source:cpp-language-transactional-memory:0020 */}
The compound-statement in an atomic block is not allowed to execute any expression or statement or call any function that isn't transaction_safe (this is a compile time error).

{/* source:cpp-language-transactional-memory:0021 */}
```cpp
// each call to f() retrieves a unique value of i, even when done in parallel
int f()
{
    static int i = 0;
    atomic_noexcept { // begin transaction
//  printf("before%d\n", i); // error: cannot call a non transaction-safe function
        ++i;
        return i; // commit transaction
    }
}
```

{/* source:cpp-language-transactional-memory:0022 */}
Leaving an atomic block by any means other than exception (reaching the end, goto, break, continue, return) commits the transaction. The behavior is undefined if [std::longjmp](/docs/cpp/library/utility/program/longjmp) is used to exit an atomic block.

```cpp
extern volatile int * p = 0;
struct S
{
    virtual ~S();
};
int f() transaction_safe
{
    int x = 0;  // ok: not volatile
    p = &x;     // ok: the pointer is not volatile
    int i = *p; // error: read through volatile glvalue
    S s;        // error: invocation of unsafe destructor
```

{/* source:cpp-language-transactional-memory:0029 */}
```cpp
int f(int x) { // implicitly transaction-safe
    if (x <= 0)
        return 0;
    return x + f(x - 1);
}
```

{/* source:cpp-language-transactional-memory:0030 */}
If a function that is not transaction-safe is called through a reference or pointer to a transaction-safe function, the behavior is undefined.

{/* source:cpp-language-transactional-memory:0031 */}
Pointers to transaction-safe functions and pointers to transaction-safe member functions are implicitly convertible to pointers to functions and pointers to member functions respectively. It is unspecified if the resulting pointer compares equal to the original.

## Attributes

{/* source:cpp-language-transactional-memory:0040 */}
The attribute [[optimize_for_synchronized]](/docs/cpp/language/declarations/attributes/optimize_for_synchronized) may be applied to a declarator in a function declaration and must appear on the first declaration of the function.

{/* source:cpp-language-transactional-memory:0041 */}
If a function is declared [[optimize_for_synchronized]] in one translation unit and the same function is declared without [[optimize_for_synchronized]] in another translation unit, the program is ill-formed; no diagnostic required.

{/* source:cpp-language-transactional-memory:0042 */}
It indicates that a the function definition should be optimized for invocation from a `synchronized` statement. In particular, it avoids serializing synchronized blocks that make a call to a function that is transaction-safe for the majority of calls, but not for all calls (e.g. hash table insertion that may have to rehash, allocator that may have to request a new block, a simple function that may rarely log).

{/* source:cpp-language-transactional-memory:0043 */}
```cpp
std::atomic<bool> rehash{false};

// maintenance thread runs this loop
void maintenance_thread(void*)
{
    while (!shutdown)
    {
        synchronized
        {
            if (rehash)
            {
                hash.rehash();
                rehash = false;
            }
        }
    }
}

// worker threads execute hundreds of thousands of calls to this function 
// every second. Calls to insert_key() from synchronized blocks in other
// translation units will cause those blocks to serialize, unless insert_key()
// is marked [[optimize_for_synchronized]]
[[optimize_for_synchronized]] void insert_key(char* key, char* value)
{
    bool concern = hash.insert(key, value);
    if (concern)
        rehash = true;
}
```

{/* source:cpp-language-transactional-memory:0044 */}
GCC assembly without the attribute: the entire function is serialized

{/* source:cpp-language-transactional-memory:0045 */}
```text
insert_key(char*, char*):
	subq	$8,%rsp
	movq	%rsi,%rdx
	movq	%rdi,%rsi
	movl	$hash,%edi
	call	Hash::insert(char*, char*)
	testb	%al,%al
	je	.L20
	movb	$1, rehash(%rip)
	mfence
.L20:
	addq	$8,%rsp
	ret
```
