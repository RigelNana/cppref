## Template parameters

{/* source:cpp-language-template-parameters:0000 */}
Every [template](/docs/cpp/language/templates) is parameterized by one or more template parameters, indicated in the parameter-list of the template declaration syntax:

{/* source:cpp-language-template-parameters:0001 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="template < parameter-list > declaration" />
  <Declaration id="2" language="cpp" grammar since="C++20" code="template < parameter-list > requires constraint declaration" />
</DeclarationDoc>

{/* source:cpp-language-template-parameters:0002 */}
Each parameter in parameter-list may be:

{/* source:cpp-language-template-parameters:0003 */}
- a non-type template parameter;
- a type template parameter;
- a template template parameter.

### Non-type template parameter

{/* source:cpp-language-template-parameters:0004 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="type name (optional)" />
  <Declaration id="2" language="cpp" grammar code="type name (optional) = default" />
  <Declaration id="3" language="cpp" grammar since="C++11" code="type ... name (optional)" />
</DeclarationDoc>

{/* source:cpp-language-template-parameters:0005 */}
1) A non-type template parameter.

{/* source:cpp-language-template-parameters:0006 */}
2) A non-type template parameter with a default template argument.

{/* source:cpp-language-template-parameters:0007 */}
3) A non-type template parameter pack.

{/* source:cpp-language-template-parameters:0008 */}
<ParameterList>
  <Parameter name="type">
    one of the following types:
    - a structural type (see below)
    - <Revision since="C++17">a type that contains a [placeholder type](/docs/cpp/language/declarations/auto)</Revision>
    - <Revision since="C++20">a [placeholder for a deduced class type](/docs/cpp/language/templates/ctad)</Revision>
  </Parameter>
  <Parameter name="name">
    the name of the non-type template parameter
  </Parameter>
  <Parameter name="default">
    the [default template argument](/docs/cpp/language/templates/template_parameters#Default_template_arguments)
  </Parameter>
</ParameterList>

{/* source:cpp-language-template-parameters:0009 */}
A structural type is one of the following types (optionally cv-qualified, the qualifiers are ignored):

{/* source:cpp-language-template-parameters:0010 */}
- [lvalue reference type](/docs/cpp/language/declarations/reference#lvalue_references) (to object or to function);
- an [integral type](/docs/cpp/language/basic_concepts/type-id);
- a [pointer type](/docs/cpp/language/declarations/pointer) (to object or to function);
- a [pointer to member type](/docs/cpp/language/declarations/pointer#Pointers_to_members) (to member object or to member function);
- an [enumeration type](/docs/cpp/language/declarations/enum);

{/* source:cpp-language-template-parameters:0011 */}
- <Revision since="C++11">[`std::nullptr_t`](/docs/cpp/library/utility/types/nullptr_t);</Revision>

{/* source:cpp-language-template-parameters:0012 */}
<Revision since="C++20">
- a [floating-point type](/docs/cpp/language/basic_concepts/type-id);
- a [lambda closure type](/docs/cpp/language/functions/lambda#Closure_type) whose lambda expression has no capture;
- a non-closure [literal class type](/docs/cpp/library/named_req/LiteralType) with the following properties:
  - all base classes and non-static data members are public and non-mutable and
  - the types of all base classes and non-static data members are structural types or (possibly multi-dimensional) array thereof.
</Revision>

{/* source:cpp-language-template-parameters:0013 */}
Array and function types may be written in a template declaration, but they are automatically replaced by pointer to object and pointer to function as appropriate.

{/* source:cpp-language-template-parameters:0014 */}
When the name of a non-type template parameter is used in an expression within the body of the class template, it is an unmodifiable [prvalue](/docs/cpp/language/expressions/value_category) unless its type was an lvalue reference type<InlineRevision since="C++20">, or unless its type is a class type</InlineRevision>.

{/* source:cpp-language-template-parameters:0015 */}
A template parameter of the form `class Foo` is not an unnamed non-type template parameter of type `Foo`, even if otherwise `class Foo` is an [elaborated type specifier](/docs/cpp/language/declarations/elaborated_type_specifier) and `class Foo x;` declares `x` to be of type `Foo`.

{/* source:cpp-language-template-parameters:0016 */}
<Revision since="C++20">
An [identifier](/docs/cpp/language/basic_concepts/name) that names a non-type template parameter of class type `T` denotes a static storage duration object of type `const T`, called a *template parameter object*, which is [template-argument-equivalent](/docs/cpp/language/templates/template_parameters#Template_argument_equivalence) to the corresponding template argument after it has been converted to the type of the template parameter. No two template parameter objects are template-argument-equivalent.

```cpp
struct A
{
    friend bool operator==(const A&, const A&) = default;
};

template<A a>
void f()
{
    &a;                       // OK
    const A& ra = a, &rb = a; // Both bound to the same template parameter object
    assert(&ra == &rb);       // passes
}
```
</Revision>

### Type template parameter

{/* source:cpp-language-template-parameters:0017 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="type-parameter-key name (optional)" />
  <Declaration id="2" language="cpp" grammar code="type-parameter-key name (optional) = default" />
  <Declaration id="3" language="cpp" grammar since="C++11" code="type-parameter-key ... name (optional)" />
  <Declaration id="4" language="cpp" grammar since="C++20" code="type-constraint name (optional)" />
  <Declaration id="5" language="cpp" grammar since="C++20" code="type-constraint name (optional) = default" />
  <Declaration id="6" language="cpp" grammar since="C++20" code="type-constraint ... name (optional)" />
</DeclarationDoc>

{/* source:cpp-language-template-parameters:0018 */}
<ParameterList>
  <Parameter name="type-parameter-key">
    either `typename` or `class`. There is no difference between these keywords in a type template parameter declaration
  </Parameter>
  <Parameter name="type-constraint">
    either the name of a [concept](/docs/cpp/language/templates/constraints) or the name of a concept followed by a list of template arguments (in angle brackets). Either way, the concept name may be optionally qualified
  </Parameter>
  <Parameter name="name">
    the name of the type template parameter
  </Parameter>
  <Parameter name="default">
    the [default template argument](/docs/cpp/language/templates/template_parameters#Default_template_arguments)
  </Parameter>
</ParameterList>

{/* source:cpp-language-template-parameters:0019 */}
1) A type template parameter without a default.

```cpp
template<class T>
class My_vector { /* ... */ };
```

{/* source:cpp-language-template-parameters:0020 */}
2) A type template parameter with a default.

```cpp
template<class T = void>
struct My_op_functor { /* ... */ };
```

{/* source:cpp-language-template-parameters:0021 */}
3) A type template parameter pack.

```cpp
template<typename... Ts>
class My_tuple { /* ... */ };
```

{/* source:cpp-language-template-parameters:0022 */}
4) A constrained type template parameter without a default.

```cpp
template<My_concept T>
class My_constrained_vector { /* ... */ };
```

{/* source:cpp-language-template-parameters:0023 */}
5) A constrained type template parameter with a default.

```cpp
template<My_concept T = void>
class My_constrained_op_functor { /* ... */ };
```

{/* source:cpp-language-template-parameters:0024 */}
6) A constrained type template parameter pack.

```cpp
template<My_concept... Ts>
class My_constrained_tuple { /* ... */ };
```

{/* source:cpp-language-template-parameters:0025 */}
The name of the parameter is optional:

{/* source:cpp-language-template-parameters:0026 */}
```cpp
// Declarations of the templates shown above:
template<class>
class My_vector;
template<class = void>
struct My_op_functor;
template<typename...>
class My_tuple;
```

{/* source:cpp-language-template-parameters:0027 */}
In the body of the template declaration, the name of a type parameter is a typedef-name which aliases the type supplied when the template is instantiated.

{/* source:cpp-language-template-parameters:0028 */}
<Revision since="C++20">
Each constrained parameter `P` whose *type-constraint* is Q designating the concept `C` introduces a [constraint-expression](/docs/cpp/language/templates/constraints) `E` according to the following rules:

- if `Q` is `C` (without an argument list),
  - if `P` is not a parameter pack, `E` is simply `C<P>`
  - otherwise, `P` is a parameter pack, `E` is a fold-expression `(C<P> && ...)`
- if `Q` is `C<A1,A2...,AN>`, then `E` is `C<P,A1,A2,...AN>` or `(C<P,A1,A2,...AN> && ...)`, respectively.

```cpp
template<typename T>
concept C1 = true;
template<typename... Ts> // variadic concept
concept C2 = true;
template<typename T, typename U>
concept C3 = true;

template<C1 T>         struct s1; // constraint-expression is C1<T>
template<C1... T>      struct s2; // constraint-expression is (C1<T> && ...)
template<C2... T>      struct s3; // constraint-expression is (C2<T> && ...)
template<C3<int> T>    struct s4; // constraint-expression is C3<T, int>
template<C3<int>... T> struct s5; // constraint-expression is (C3<T, int> && ...)
```
</Revision>

### Template template parameter

{/* source:cpp-language-template-parameters:0029 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="template < parameter-list > type-parameter-key name (optional)" />
  <Declaration id="2" language="cpp" grammar code="template < parameter-list > type-parameter-key name (optional) = default" />
  <Declaration id="3" language="cpp" grammar since="C++11" code="template < parameter-list > type-parameter-key ... name (optional)" />
</DeclarationDoc>

{/* source:cpp-language-template-parameters:0030 */}
<ParameterList>
  <Parameter name="type-parameter-key">
    `class` <InlineRevision since="C++17">or `typename`</InlineRevision>
  </Parameter>
</ParameterList>

{/* source:cpp-language-template-parameters:0031 */}
1) A template template parameter with an optional name.

{/* source:cpp-language-template-parameters:0032 */}
2) A template template parameter with an optional name and a default.

{/* source:cpp-language-template-parameters:0033 */}
3) A template template parameter pack with an optional name.

{/* source:cpp-language-template-parameters:0034 */}
In the body of the template declaration, the name of this parameter is a template-name (and needs arguments to be instantiated).

{/* source:cpp-language-template-parameters:0035 */}
```cpp
template<typename T>
class my_array {};

// two type template parameters and one template template parameter:
template<typename K, typename V, template<typename> typename C = my_array>
class Map
{
    C<K> key;
    C<V> value;
};
```

### Name resolution for template parameters

{/* source:cpp-language-template-parameters:0036 */}
The name of a template parameter is not allowed to be redeclared within its scope (including nested scopes). A template parameter is not allowed to have the same name as the template name.

{/* source:cpp-language-template-parameters:0037 */}
```cpp
template<class T, int N>
class Y
{
    int T;      // error: template parameter redeclared
    void f()
    {
        char T; // error: template parameter redeclared
    }
};

template<class X>
class X; // error: template parameter redeclared
```

{/* source:cpp-language-template-parameters:0038 */}
In the definition of a member of a class template that appears outside of the class template definition, the name of a member of the class template hides the name of a template parameter of any enclosing class templates, but not a template parameter of the member if the member is a class or function template.

{/* source:cpp-language-template-parameters:0039 */}
```cpp
template<class T>
struct A
{
    struct B {};
    typedef void C;
    void f();

    template<class U>
    void g(U);
};

template<class B>
void A<B>::f()
{
    B b; // A's B, not the template parameter
}

template<class B>
template<class C>
void A<B>::g(C)
{
    B b; // A's B, not the template parameter
    C c; // the template parameter C, not A's C
}
```

{/* source:cpp-language-template-parameters:0040 */}
In the definition of a member of a class template that appears outside of the namespace containing the class template definition, the name of a template parameter hides the name of a member of this namespace.

{/* source:cpp-language-template-parameters:0041 */}
```cpp
namespace N
{
    class C {};

    template<class T>
    class B
    {
        void f(T);
    };
}

template<class C>
void N::B<C>::f(C)
{
    C b; // C is the template parameter, not N::C
}
```

{/* source:cpp-language-template-parameters:0042 */}
In the definition of a class template or in the definition of a member of such a template that appears outside of the template definition, for each non-[dependent](/docs/cpp/language/templates/dependent_name#Dependent_types) base class, if the name of the base class or the name of a member of the base class is the same as the name of a template parameter, the base class name or member name hides the template parameter name.

{/* source:cpp-language-template-parameters:0043 */}
```cpp
struct A
{
    struct B {};
    int C;
    int Y;
};

template<class B, class C>
struct X : A
{
    B b; // A's B
    C b; // error: A's C isn't a type name
};
```

## Template arguments

{/* source:cpp-language-template-parameters:0044 */}
In order for a template to be instantiated, every template parameter (type, non-type, or template) must be replaced by a corresponding template argument. For [class templates](/docs/cpp/language/templates/class_template), the arguments are either explicitly provided<InlineRevision since="C++17">, [deduced from the initializer](/docs/cpp/language/templates/ctad), </InlineRevision>or defaulted. For [function templates](/docs/cpp/language/templates/function_template), the arguments are explicitly provided, [deduced from the context](/docs/cpp/language/templates/template_argument_deduction), or defaulted.

{/* source:cpp-language-template-parameters:0045 */}
If an argument can be interpreted as both a [type-id](/docs/cpp/language/basic_concepts/type-id) and an expression, it is always interpreted as a type-id, even if the corresponding template parameter is non-type:

{/* source:cpp-language-template-parameters:0046 */}
```cpp
template<class T>
void f(); // #1

template<int I>
void f(); // #2

void g()
{
    f<int()>(); // "int()" is both a type and an expression,
                // calls #1 because it is interpreted as a type
}
```

### Template non-type arguments

{/* source:cpp-language-template-parameters:0047 */}
<Revision until="C++11">
The template argument that can be used with a non-type template parameter can be any [manifestly constant-evaluated expression](/docs/cpp/language/expressions/constant_expression#Manifestly_constant-evaluated_expressions).
</Revision>

<Revision since="C++11">
The template argument that can be used with a non-type template parameter can be any [initializer clause](/docs/cpp/language/initialization#Initializers). If the initializer clause is an expression, it must be [manifestly constant-evaluated](/docs/cpp/language/expressions/constant_expression#Manifestly_constant-evaluated_expressions).
</Revision>

{/* source:cpp-language-template-parameters:0048 */}
Given the *type* of the [non-type template parameter declaration](/docs/cpp/language/templates/template_parameters#Non-type_template_parameter) as `T` and the template argument provided for the parameter as `E`.

{/* source:cpp-language-template-parameters:0049 */}
<Revision since="C++26">
The invented declaration `T x = E;` must satisfy the semantic constraints for the definition of a [`constexpr` variable](/docs/cpp/language/declarations/constexpr#constexpr_variable) with [static storage duration](/docs/cpp/language/declarations/storage_duration#Static_storage_duration).
</Revision>

<Revision since="C++17">
If `T` contains a [placeholder type](/docs/cpp/language/declarations/auto), or is a [placeholder for a deduced class type](/docs/cpp/language/templates/ctad), the type of the template parameter is the type deduced for the variable `x` in the invented declaration `T x = E;`.

If a deduced parameter type is not a [structural type](/docs/cpp/language/templates/template_parameters#Non-type_template_parameter), the program is ill-formed.

For non-type template parameter packs whose type uses a placeholder type, the type is independently deduced for each template argument and need not match.
</Revision>

{/* source:cpp-language-template-parameters:0050 */}
```cpp
template<auto n>
struct B { /* ... */ };

B<5> b1;   // OK: non-type template parameter type is int
B<'a'> b2; // OK: non-type template parameter type is char
B<2.5> b3; // error (until C++20): non-type template parameter type cannot be double

// C++20 deduced class type placeholder, class template arguments are deduced at the
// call site
template<std::array arr>
void f();

f<std::array<double, 8>{}>();

template<auto...>
struct C {};

C<'C', 0, 2L, nullptr> x; // OK
```

{/* source:cpp-language-template-parameters:0051 */}
The value of a non-type template parameter `P` of <InlineRevision since="C++17">(possibly deduced)</InlineRevision> type `T` is determined from its template argument `A` as follows:

{/* source:cpp-language-template-parameters:0052 */}
<Revision until="C++11">
- If `A` is a [converted constant expression](/docs/cpp/language/expressions/constant_expression#Converted_constant_expression) of type `T`, the value of `P` is `A` (as converted).
- Otherwise, the program is ill-formed.
</Revision>

<Revision since="C++11" until="C++20">
- If `A` is an expression:
  - If `A` is a [converted constant expression](/docs/cpp/language/expressions/constant_expression#Converted_constant_expression) of type `T`, the value of `P` is `A` (as converted).
  - Otherwise, the program is ill-formed.
- Otherwise (`A` is a braced-enclosed initializer list), a temporary variable `constexpr T v = A;` is introduced. The value of `P` is that of `v`.
  - The [lifetime](/docs/cpp/language/basic_concepts/lifetime) of `v` ends immediately after initializing it.
</Revision>

<Revision since="C++20">
- If `T` is not a class type and `A` is an expression:
  - If `A` is a [converted constant expression](/docs/cpp/language/expressions/constant_expression#Converted_constant_expression) of type `T`, the value of `P` is `A` (as converted).
  - Otherwise, the program is ill-formed.
- Otherwise (`T` is a class type or `A` is a braced-enclosed initializer list), a temporary variable `constexpr T v = A;` is introduced.
  - If `T` is a class type, a [template parameter object](/docs/cpp/language/templates/template_parameters#Template_parameter_object) exists (which is also denoted by `P`). `P` is copy-initialized from an unspecified candidate initializer that is [template-argument-equivalent](/docs/cpp/language/templates/template_parameters#Template_argument_equivalence) to `v`.
    - The [lifetime](/docs/cpp/language/basic_concepts/lifetime) of `v` ends immediately after initializing it and `P`.
    - If the initialization of `P` satisfies any of the following conditions, the program is ill-formed:
      - The initialization would be ill-formed.
      - The [full-expression](/docs/cpp/language/expressions#Full-expressions) of an invented declarator-initializer sequence for the initialization would not be a constant expression when interpreted as a [manifestly constant-evaluated expression](/docs/cpp/language/expressions/constant_expression#Manifestly_constant-evaluated_expressions).
      - The initialization would cause `P` to not be [template-argument-equivalent](/docs/cpp/language/templates/template_parameters#Template_argument_equivalence) to `v`.
  - Otherwise, the value of `P` is that of `v`.
</Revision>

{/* source:cpp-language-template-parameters:0053 */}
```cpp
template<int i>
struct C { /* ... */ };

C<{42}> c1; // OK

template<auto n>
struct B { /* ... */ };

struct J1
{
    J1* self = this;
};

B<J1{}> j1; // error: initialization of the template parameter object
            //        is not a constant expression

struct J2
{
    J2 *self = this;
    constexpr J2() {}
    constexpr J2(const J2&) {}
};

B<J2{}> j2; // error: the template parameter object is not
            //        template-argument-equivalent to introduced temporary
```

{/* source:cpp-language-template-parameters:0054 */}
<Revision until="C++17">
The following limitations apply when instantiating templates that have non-type template parameters:

- For integral and arithmetic types, the template argument provided during instantiation must be a [converted constant expression](/docs/cpp/language/expressions/constant_expression) of the template parameter's type (so certain implicit conversion applies).
- For pointers to objects, the template arguments have to designate the address of a complete object with static [storage duration](/docs/cpp/language/declarations/storage_duration) and a [linkage](/docs/cpp/language/declarations/storage_duration#Linkage) (either internal or external), or a constant expression that evaluates to the appropriate null pointer<InlineRevision since="C++11"> or [`std::nullptr_t`](/docs/cpp/library/utility/types/nullptr_t)</InlineRevision> value.
- For pointers to functions, the valid arguments are pointers to functions with linkage (or constant expressions that evaluate to null pointer values).
- For lvalue reference parameters, the argument provided at instantiation cannot be a temporary, an unnamed lvalue, or a named lvalue with no linkage (in other words, the argument must have linkage).
- For pointers to members, the argument has to be a pointer to member expressed as `&Class::Member` or a constant expression that evaluates to null pointer<InlineRevision since="C++11"> or [`std::nullptr_t`](/docs/cpp/library/utility/types/nullptr_t)</InlineRevision> value.

In particular, this implies that string literals, addresses of array elements, and addresses of non-static members cannot be used as template arguments to instantiate templates whose corresponding non-type template parameters are pointers to objects.
</Revision>

<Revision since="C++17">
Non-type template parameters of reference or pointer type<InlineRevision since="C++20"> and non-static data members of reference or pointer type in a non-type template parameter of class type and its subobjects</InlineRevision> cannot refer to/be the address of

- a temporary object (including one created during [reference initialization](/docs/cpp/language/initialization/reference_initialization));
- a [string literal](/docs/cpp/language/expressions/string_literal);
- the result of [`typeid`](/docs/cpp/language/expressions/typeid);
- the predefined variable `__func__`;
- or a subobject (including non-static class member, base subobject, or array element)<InlineRevision since="C++20"> of one of the above</InlineRevision>.
</Revision>

{/* source:cpp-language-template-parameters:0055 */}
```cpp
template<const int* pci>
struct X {};

int ai[10];
X<ai> xi; // OK: array to pointer conversion and cv-qualification conversion

struct Y {};

template<const Y& b>
struct Z {};

Y y;
Z<y> z;   // OK: no conversion

template<int (&pa)[5]>
struct W {};

int b[5];
W<b> w;   // OK: no conversion

void f(char);
void f(int);

template<void (*pf)(int)>
struct A {};

A<&f> a;  // OK: overload resolution selects f(int)
```

{/* source:cpp-language-template-parameters:0056 */}
```cpp
template<class T, const char* p>
class X {};

X<int, "Studebaker"> x1; // error: string literal as template-argument

template<int* p>
class X {};

int a[10];

struct S
{
    int m;
    static int s;
} s;

X<&a[2]> x3; // error (until C++20): address of array element
X<&s.m> x4;  // error (until C++20): address of non-static member
X<&s.s> x5;  // OK: address of static member
X<&S::s> x6; // OK: address of static member

template<const int& CRI>
struct B {};

B<1> b2;     // error: temporary would be required for template argument
int c = 1;
B<c> b1;     // OK
```

### Template type arguments

{/* source:cpp-language-template-parameters:0057 */}
A template argument for a type template parameter must be a [type-id](/docs/cpp/language/basic_concepts/type-id#Type_naming), which may name an incomplete type:

{/* source:cpp-language-template-parameters:0058 */}
```cpp
template<typename T>
class X {}; // class template

struct A;            // incomplete type
typedef struct {} B; // type alias to an unnamed type

int main()
{
    X<A> x1;  // OK: 'A' names a type
    X<A*> x2; // OK: 'A*' names a type
    X<B> x3;  // OK: 'B' names a type
}
```

### Template template arguments

{/* source:cpp-language-template-parameters:0059 */}
A template argument for a template template parameter must be an [id-expression](/docs/cpp/language/basic_concepts/name#In_expressions) which names a class template or a template alias.

{/* source:cpp-language-template-parameters:0060 */}
When the argument is a class template, only the primary template is considered when matching the parameter. The partial specializations, if any, are only considered when a specialization based on this template template parameter happens to be instantiated.

{/* source:cpp-language-template-parameters:0061 */}
```cpp
template<typename T> // primary template
class A { int x; };

template<typename T> // partial specialization
class A<T*> { long x; };

// class template with a template template parameter V
template<template<typename> class V>
class C
{
    V<int> y;  // uses the primary template
    V<int*> z; // uses the partial specialization
};

C<A> c; // c.y.x has type int, c.z.x has type long
```

{/* source:cpp-language-template-parameters:0062 */}
To match a template template argument `A` to a template template parameter `P`, `P` must be at least as specialized as `A` (see below).<InlineRevision since="C++11"> If `P`'s parameter list includes a [parameter pack](/docs/cpp/language/templates/parameter_pack), zero or more template parameters (or parameter packs) from `A`'s template parameter list are matched by it.</InlineRevision>

{/* source:cpp-language-template-parameters:0063 */}
Formally, a template template-parameter `P` is at least as specialized as a template template argument `A` if, given the following rewrite to two [function templates](/docs/cpp/language/templates/function_template), the function template corresponding to `P` is at least as specialized as the function template corresponding to `A` according to the partial ordering rules for function templates. Given an invented class template `X` with the template parameter list of `A` (including default arguments):

{/* source:cpp-language-template-parameters:0064 */}
- Each of the two function templates has the same template parameters, respectively, as `P` or `A`.
- Each function template has a single function parameter whose type is a specialization of `X` with template arguments corresponding to the template parameters from the respective function template where, for each template parameter `PP` in the template parameter list of the function template, a corresponding template argument `AA` is formed.<InlineRevision since="C++11"> If `PP` declares a parameter pack, then `AA` is the pack expansion `PP...`; otherwise,</InlineRevision> `AA` is the id-expression `PP`.

{/* source:cpp-language-template-parameters:0065 */}
If the rewrite produces an invalid type, then `P` is not at least as specialized as `A`.

{/* source:cpp-language-template-parameters:0066 */}
```cpp
template<typename T>
struct eval;                     // primary template

template<template<typename, typename...> class TT, typename T1, typename... Rest>
struct eval<TT<T1, Rest...>> {}; // partial specialization of eval

template<typename T1> struct A;
template<typename T1, typename T2> struct B;
template<int N> struct C;
template<typename T1, int N> struct D;
template<typename T1, typename T2, int N = 17> struct E;

eval<A<int>> eA;        // OK: matches partial specialization of eval
eval<B<int, float>> eB; // OK: matches partial specialization of eval
eval<C<17>> eC;         // error: C does not match TT in partial specialization
                        // because TT's first parameter is a
                        // type template parameter, while 17 does not name a type
eval<D<int, 17>> eD;    // error: D does not match TT in partial specialization
                        // because TT's second parameter is a
                        // type parameter pack, while 17 does not name a type
eval<E<int, float>> eE; // error: E does not match TT in partial specialization
                        // because E's third (default) parameter is a non-type
```

{/* source:cpp-language-template-parameters:0067 */}
Before the adoption of [P0522R0](https://wg21.link/p0522r0), each of the template parameters of `A` must match corresponding template parameters of `P` exactly. This hinders many reasonable template argument from being accepted.

{/* source:cpp-language-template-parameters:0068 */}
Although it was pointed out very early ([CWG#150](https://wg21.cmeerw.net/cwg/issue150)), by the time it was resolved, the changes were applied to the C++17 working paper and the resolution became a de facto C++17 feature. Many compilers disable it by default:

{/* source:cpp-language-template-parameters:0069 */}
- [GCC](https://gcc.gnu.org/gcc-7/changes.html#cxx) disables it in all language modes prior to C++17 by default, it can only be enabled by setting a compiler flag in these modes.
- [Clang](https://clang.llvm.org/cxx_status.html#p0522) disables it in all language modes by default, it can only be enabled by setting a compiler flag.
- [Microsoft Visual Studio](https://docs.microsoft.com/en-us/cpp/overview/visual-cpp-language-conformance) treats it as a normal C++17 feature and only enables it in C++17 and later language modes (i.e. no support in C++14 language mode, which is the default mode).

{/* source:cpp-language-template-parameters:0070 */}
```cpp
template<class T> class A { /* ... */ };
template<class T, class U = T> class B { /* ... */ };
template<class... Types> class C { /* ... */ };

template<template<class> class P> class X { /* ... */ };
X<A> xa; // OK
X<B> xb; // OK after P0522R0
         // Error earlier: not an exact match
X<C> xc; // OK after P0522R0
         // Error earlier: not an exact match

template<template<class...> class Q> class Y { /* ... */ };
Y<A> ya; // OK
Y<B> yb; // OK
Y<C> yc; // OK

template<auto n> class D { /* ... */ };   // note: C++17
template<template<int> class R> class Z { /* ... */ };
Z<D> zd; // OK after P0522R0: the template parameter
         // is more specialized than the template argument

template<int> struct SI { /* ... */ };
template<template<auto> class> void FA(); // note: C++17
FA<SI>(); // Error
```

### Default template arguments

{/* source:cpp-language-template-parameters:0071 */}
Default template arguments are specified in the parameter lists after the `=` sign. Defaults can be specified for any kind of template parameter (type, non-type, or template)<InlineRevision since="C++11">, but not to parameter packs</InlineRevision>.

{/* source:cpp-language-template-parameters:0072 */}
If the default is specified for a template parameter of a primary class template<InlineRevision since="C++14">, primary variable template,</InlineRevision> or alias template, each subsequent template parameter must have a default argument<InlineRevision since="C++11">, except the very last one may be a template parameter pack</InlineRevision>. In a function template, there are no restrictions on the parameters that follow a default<InlineRevision since="C++11">, and a parameter pack may be followed by more type parameters only if they have defaults or can be deduced from the function arguments</InlineRevision>.

{/* source:cpp-language-template-parameters:0073 */}
Default parameters are not allowed

{/* source:cpp-language-template-parameters:0074 */}
- in the out-of-class definition of a member of a [class template](/docs/cpp/language/templates/class_template) (they have to be provided in the declaration inside the class body). Note that [member templates](/docs/cpp/language/templates/member_template) of non-template classes can use default parameters in their out-of-class definitions (see [GCC bug 53856](https://gcc.gnu.org/bugzilla/show_bug.cgi?id=53856))
- in [friend class template](/docs/cpp/language/classes/friend#Template_friends) declarations

{/* source:cpp-language-template-parameters:0075 */}
- <Revision until="C++11">in any [function template](/docs/cpp/language/templates/function_template) declaration or definition</Revision>

{/* source:cpp-language-template-parameters:0076 */}
- <Revision since="C++11">On a friend function template declaration, default template arguments are allowed only if the declaration is a definition, and no other declarations of this function appear in this translation unit.</Revision>

{/* source:cpp-language-template-parameters:0077 */}
Default template arguments that appear in the declarations are merged similarly to default function arguments:

{/* source:cpp-language-template-parameters:0078 */}
```cpp
template<typename T1, typename T2 = int> class A;
template<typename T1 = int, typename T2> class A;

// the above is the same as the following:
template<typename T1 = int, typename T2 = int> class A;
```

{/* source:cpp-language-template-parameters:0079 */}
But the same parameter cannot be given default arguments twice in the same scope:

{/* source:cpp-language-template-parameters:0080 */}
```cpp
template<typename T = int> class X;
template<typename T = int> class X {}; // error
```

{/* source:cpp-language-template-parameters:0081 */}
When parsing a default template argument for a non-type template parameter, the first non-nested `>` is taken as the end of the template parameter list rather than a greater-than operator:

{/* source:cpp-language-template-parameters:0082 */}
```cpp
template<int i = 3 > 4>   // syntax error
class X { /* ... */ };

template<int i = (3 > 4)> // OK
class Y { /* ... */ };
```

{/* source:cpp-language-template-parameters:0083 */}
The template parameter lists of template template parameters can have their own default arguments, which are only in effect where the template template parameter itself is in scope:

{/* source:cpp-language-template-parameters:0084 */}
```cpp
// class template, with a type template parameter with a default
template<typename T = float>
struct B {};

// template template parameter T has a parameter list, which
// consists of one type template parameter with a default
template<template<typename = float> typename T>
struct A
{
    void f();
    void g();
};

// out-of-body member function template definitions

template<template<typename TT> class T>
void A<T>::f()
{
    T<> t; // error: TT has no default in scope
}

template<template<typename TT = char> class T>
void A<T>::g()
{
    T<> t; // OK: t is T<char>
}
```

{/* source:cpp-language-template-parameters:0085 */}
[Member access](/docs/cpp/language/classes/access) for the names used in a default template parameter is checked at the declaration, not at the point of use:

{/* source:cpp-language-template-parameters:0086 */}
```cpp
class B {};

template<typename T>
class C
{
protected:
    typedef T TT;
};

template<typename U, typename V = typename U::TT>
class D: public U {};

D<C<B>>* d; // error: C::TT is protected
```

{/* source:cpp-language-template-parameters:0087 */}
<Revision since="C++14">
The default template argument is implicitly instantiated when the value of that default argument is needed, except if the template is used to name a function:

```cpp
template<typename T, typename U = int>
struct S {};

S<bool>* p; // The default argument for U is instantiated at this point
            // the type of p is S<bool, int>*
```
</Revision>

### Template argument equivalence

{/* source:cpp-language-template-parameters:0088 */}
Template argument equivalence is used to determine whether two [template identifiers](/docs/cpp/language/templates#Template_identifiers) are same.

{/* source:cpp-language-template-parameters:0089 */}
Two values are template-argument-equivalent if they are of the same type and any of the following conditions is satisfied:

{/* source:cpp-language-template-parameters:0090 */}
- They are of integral or enumeration type and their values are the same.
- They are of pointer type and they have the same pointer value.
- They are of pointer-to-member type and they refer to the same class member or are both the null member pointer value.
- They are of lvalue reference type and they refer to the same object or function.

{/* source:cpp-language-template-parameters:0091 */}
- <Revision since="C++11">They are of type [`std::nullptr_t`](/docs/cpp/library/utility/types/nullptr_t).</Revision>

{/* source:cpp-language-template-parameters:0092 */}
<Revision since="C++20">
- They are of floating-point type and their values are identical.
- They are of array type (in which case the arrays must be member objects of some class/union) and their corresponding elements are template-argument-equivalent.
- They are of union type and either they both have no active member or they have the same active member and their active members are template-argument-equivalent.
- They are of a lambda closure type.
- They are of non-union class type and their corresponding direct subobjects and reference members are template-argument-equivalent.
</Revision>

## Examples

{/* source:cpp-language-template-parameters:0095 */}
```cpp
#include <array>
#include <iostream>
#include <numeric>

// simple non-type template parameter
template<int N>
struct S { int a[N]; };

template<const char*>
struct S2 {};

// complicated non-type example
template
<
    char c,             // integral type
    int (&ra)[5],       // lvalue reference to object (of array type)
    int (*pf)(int),     // pointer to function
    int (S<10>::*a)[10] // pointer to member object (of type int[10])
>
struct Complicated
{
    // calls the function selected at compile time
    // and stores the result in the array selected at compile time
    void foo(char base)
    {
        ra[4] = pf(c - base);
    }
};

//  S2<"fail"> s2;        // error: string literal cannot be used
    char okay[] = "okay"; // static object with linkage
//  S2<&okay[0]> s3;      // error: array element has no linkage
    S2<okay> s4;          // works

int a[5];
int f(int n) { return n; }

// C++20: NTTP can be a literal class type
template<std::array arr>
constexpr
auto sum() { return std::accumulate(arr.cbegin(), arr.cend(), 0); }

// C++20: class template arguments are deduced at the call site
static_assert(sum<std::array<double, 8>{3, 1, 4, 1, 5, 9, 2, 6}>() == 31.0);
// C++20: NTTP argument deduction and CTAD
static_assert(sum<std::array{2, 7, 1, 8, 2, 8}>() == 28);

int main()
{
    S<10> s; // s.a is an array of 10 int
    s.a[9] = 4;

    Complicated<'2', a, f, &S<10>::a> c;
    c.foo('0');

    std::cout << s.a[9] << a[4] << '\n';
}
```
