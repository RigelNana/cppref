{/* source:cpp-language-parameter-pack:0000 */}
A pack is a C++ entity that defines one of the following:

{/* source:cpp-language-parameter-pack:0001 */}
- a parameter pack

{/* source:cpp-language-parameter-pack:0002 */}
- template parameter pack
- function parameter pack

{/* source:cpp-language-parameter-pack:0003 */}
<Revision since="C++20">
- [lambda init-capture pack](/docs/cpp/language/functions/lambda#Lambda_capture)
</Revision>

{/* source:cpp-language-parameter-pack:0004 */}
<Revision since="C++26">
- [structured binding pack](/docs/cpp/language/declarations/structured_binding)
</Revision>

{/* source:cpp-language-parameter-pack:0005 */}
A template parameter pack is a template parameter that accepts zero or more template arguments (non-types, types, or templates). A function parameter pack is a function parameter that accepts zero or more function arguments.

{/* source:cpp-language-parameter-pack:0006 */}
<Revision since="C++20">
A lambda init-capture pack is a lambda capture that introduces an init-capture for each of the elements in the pack expansion of its initializer.
</Revision>

{/* source:cpp-language-parameter-pack:0007 */}
<Revision since="C++26">
A structured binding pack is an identifier in the structured binding declaration that introduces zero or more structured bindings.
</Revision>

{/* source:cpp-language-parameter-pack:0008 */}
The number of elements of a pack is equal to:

{/* source:cpp-language-parameter-pack:0009 */}
- the number of arguments provided for the parameter pack, if the pack is a template or function parameter pack,

{/* source:cpp-language-parameter-pack:0010 */}
<Revision since="C++20">
- the number of elements in the pack expansion of its initializer, if the pack is a lambda init-capture pack,
</Revision>

{/* source:cpp-language-parameter-pack:0011 */}
<Revision since="C++26">
- structured binding size of the initializer less the number of non-pack elements in the structured binding declaration, if the pack is a structured binding pack.
</Revision>

{/* source:cpp-language-parameter-pack:0012 */}
A template with at least one parameter pack is called a variadic template.

## Explanation

{/* source:cpp-language-parameter-pack:0026 */}
A variadic class template can be instantiated with any number of template arguments:

{/* source:cpp-language-parameter-pack:0027 */}
```cpp
template<class... Types>
struct Tuple {};
 
Tuple<> t0;           // Types contains no arguments
Tuple<int> t1;        // Types contains one argument: int
Tuple<int, float> t2; // Types contains two arguments: int and float
Tuple<0> t3;          // error: 0 is not a type
```

{/* source:cpp-language-parameter-pack:0028 */}
A variadic function template can be called with any number of function arguments (the template arguments are deduced through [template argument deduction](/docs/cpp/language/templates/template_argument_deduction)):

{/* source:cpp-language-parameter-pack:0029 */}
```cpp
template<class... Types>
void f(Types... args);
 
f();       // OK: args contains no arguments
f(1);      // OK: args contains one argument: int
f(2, 1.0); // OK: args contains two arguments: int and double
```

{/* source:cpp-language-parameter-pack:0030 */}
In a primary class template, the template parameter pack must be the final parameter in the template parameter list. In a function template, the template parameter pack may appear earlier in the list provided that all following parameters can be deduced from the function arguments, or have default arguments:

{/* source:cpp-language-parameter-pack:0031 */}
```cpp
template<typename U, typename... Ts>    // OK: can deduce U
struct valid;
// template<typename... Ts, typename U> // Error: Ts... not at the end
// struct Invalid;
 
template<typename... Ts, typename U, typename=void>
void valid(U, Ts...);    // OK: can deduce U
// void valid(Ts..., U); // Can't be used: Ts... is a non-deduced context in this position
 
valid(1.0, 1, 2, 3);     // OK: deduces U as double, Ts as {int, int, int}
```

{/* source:cpp-language-parameter-pack:0032 */}
If every valid specialization of a variadic template requires an empty template parameter pack, the program is ill-formed, no diagnostic required.

## Pack expansion

{/* source:cpp-language-parameter-pack:0033 */}
A pattern followed by an ellipsis, in which the name of at least one pack appears at least once, is *expanded* into zero or more instantiations of the pattern, where the name of the pack is replaced by each of the elements from the pack, in order. Instantiations of [alignment specifiers](/docs/cpp/language/templates/parameter_pack#Alignment_specifier) are space-separated, other instantiations are comma-separated.

{/* source:cpp-language-parameter-pack:0034 */}
```cpp
template<class... Us>
void f(Us... pargs) {}
 
template<class... Ts>
void g(Ts... args)
{
    f(&args...); // “&args...” is a pack expansion
                 // “&args” is its pattern
}
 
g(1, 0.2, "a"); // Ts... args expand to int E1, double E2, const char* E3
                // &args... expands to &E1, &E2, &E3
                // Us... pargs expand to int* E1, double* E2, const char** E3
```

{/* source:cpp-language-parameter-pack:0035 */}
If the names of two packs appear in the same pattern, they are expanded simultaneously, and they must have the same length:

{/* source:cpp-language-parameter-pack:0036 */}
```cpp
template<typename...>
struct Tuple {};
 
template<typename T1, typename T2>
struct Pair {};
 
template<class... Args1>
struct zip
{
    template<class... Args2>
    struct with
    {
        typedef Tuple<Pair<Args1, Args2>...> type;
        // Pair<Args1, Args2>... is the pack expansion
        // Pair<Args1, Args2> is the pattern
    };
};
 
typedef zip<short, int>::with<unsigned short, unsigned>::type T1;
// Pair<Args1, Args2>... expands to
// Pair<short, unsigned short>, Pair<int, unsigned int> 
// T1 is Tuple<Pair<short, unsigned short>, Pair<int, unsigned>>
 
// typedef zip<short>::with<unsigned short, unsigned>::type T2;
// error: pack expansion contains packs of different lengths
```

{/* source:cpp-language-parameter-pack:0037 */}
If a pack expansion is nested within another pack expansion, the packs that appear inside the innermost pack expansion are expanded by it, and there must be another pack mentioned in the enclosing pack expansion, but not in the innermost one:

{/* source:cpp-language-parameter-pack:0038 */}
```cpp
template<class... Args>
void g(Args... args)
{
    f(const_cast<const Args*>(&args)...); 
    // const_cast<const Args*>(&args) is the pattern, it expands two packs
    // (Args and args) simultaneously
 
    f(h(args...) + args...); // Nested pack expansion:
    // inner pack expansion is "args...", it is expanded first
    // outer pack expansion is h(E1, E2, E3) + args..., it is expanded
    // second (as h(E1, E2, E3) + E1, h(E1, E2, E3) + E2, h(E1, E2, E3) + E3)
}
```

{/* source:cpp-language-parameter-pack:0039 */}
When the number of elements in a pack is zero (empty pack), the instantiation of a pack expansion does not alter the syntactic interpretation of the enclosing construct, even in cases where omitting the pack expansion entirely would otherwise be ill-formed or would result in a syntax ambiguity. The instantiation produces an empty list.

{/* source:cpp-language-parameter-pack:0040 */}
```cpp
template<class... Bases> 
struct X : Bases... { };
 
template<class... Args> 
void f(Args... args) 
{
    X<Args...> x(args...);
}
 
template void f<>(); // OK, X<> has no base classes
                     // x is a variable of type X<> that is value-initialized
```

## Expansion loci

{/* source:cpp-language-parameter-pack:0041 */}
Depending on where the expansion takes place, the resulting comma-separated (or space-separated for [alignment specifiers](/docs/cpp/language/templates/parameter_pack#Alignment_specifier)) list is a different kind of list: function parameter list, member initializer list, attribute list, etc. The following is the list of all allowed contexts:

### Function argument lists

{/* source:cpp-language-parameter-pack:0042 */}
A pack expansion may appear inside the parentheses of a function call operator, in which case the largest expression or [brace-enclosed initializer list](/docs/cpp/language/initialization) to the left of the ellipsis is the pattern that is expanded:

{/* source:cpp-language-parameter-pack:0043 */}
```cpp
f(args...);              // expands to f(E1, E2, E3)
f(&args...);             // expands to f(&E1, &E2, &E3)
f(n, ++args...);         // expands to f(n, ++E1, ++E2, ++E3);
f(++args..., n);         // expands to f(++E1, ++E2, ++E3, n);
 
f(const_cast<const Args*>(&args)...);
// f(const_cast<const E1*>(&X1), const_cast<const E2*>(&X2), const_cast<const E3*>(&X3))
 
f(h(args...) + args...); // expands to 
// f(h(E1, E2, E3) + E1, h(E1, E2, E3) + E2, h(E1, E2, E3) + E3)
```

### Parenthesized initializers

{/* source:cpp-language-parameter-pack:0044 */}
A pack expansion may appear inside the parentheses of a [direct initializer](/docs/cpp/language/initialization/direct_initialization), a [function-style cast](/docs/cpp/language/expressions/explicit_cast), and other contexts ([member initializer](/docs/cpp/language/classes/initializer_list), [new-expression](/docs/cpp/language/expressions/new), etc.) in which case the rules are identical to the rules for a function call expression above:

{/* source:cpp-language-parameter-pack:0045 */}
```cpp
Class c1(&args...);             // calls Class::Class(&E1, &E2, &E3)
Class c2 = Class(n, ++args...); // calls Class::Class(n, ++E1, ++E2, ++E3);
 
::new((void *)p) U(std::forward<Args>(args)...) // std::allocator::allocate
```

### Brace-enclosed initializers

{/* source:cpp-language-parameter-pack:0046 */}
In a brace-enclosed initializer list, a pack expansion may appear as well:

{/* source:cpp-language-parameter-pack:0047 */}
```cpp
template<typename... Ts>
void func(Ts... args)
{
    const int size = sizeof...(args) + 2;
    int res[size] = {1, args..., 2};
 
    // since initializer lists guarantee sequencing, this can be used to
    // call a function on each element of a pack, in order:
    int dummy[sizeof...(Ts)] = {(std::cout << args, 0)...};
}
```

### Template argument lists

{/* source:cpp-language-parameter-pack:0048 */}
Pack expansions can be used anywhere in a template argument list, provided the template has the parameters to match the expansion:

{/* source:cpp-language-parameter-pack:0049 */}
```cpp
template<class A, class B, class... C>
void func(A arg1, B arg2, C... arg3)
{
    container<A, B, C...> t1; // expands to container<A, B, E1, E2, E3> 
    container<C..., A, B> t2; // expands to container<E1, E2, E3, A, B> 
    container<A, C..., B> t3; // expands to container<A, E1, E2, E3, B> 
}
```

### Function parameter list

{/* source:cpp-language-parameter-pack:0050 */}
In a function parameter list, if an ellipsis appears in a parameter declaration (whether it names a function parameter pack (as in, *Args* `...` *args*) or not) the parameter declaration is the pattern:

{/* source:cpp-language-parameter-pack:0051 */}
```cpp
template<typename... Ts>
void f(Ts...) {}
 
f('a', 1); // Ts... expands to void f(char, int)
f(0.1);    // Ts... expands to void f(double)
 
template<typename... Ts, int... N>
void g(Ts (&...arr)[N]) {}
 
int n[1];
 
g<const char, int>("a", n); // Ts (&...arr)[N] expands to 
                            // const char (&)[2], int(&)[1]
```

{/* source:cpp-language-parameter-pack:0052 */}
Note: In the pattern `Ts (&...arr)[N]`, the ellipsis is the innermost element, not the last element as in all other pack expansions.

{/* source:cpp-language-parameter-pack:0053 */}
Note: `Ts (&...)[N]` is not allowed because the C++11 grammar requires the parenthesized ellipsis to have a name: [CWG issue 1488](https://cplusplus.github.io/CWG/issues/1488.html).

### Template parameter list

{/* source:cpp-language-parameter-pack:0054 */}
Pack expansion may appear in a template parameter list:

{/* source:cpp-language-parameter-pack:0055 */}
```cpp
template<typename... T>
struct value_holder
{
    template<T... Values> // expands to a non-type template parameter 
    struct apply {};      // list, such as <int, char, int(&)[5]>
};
```

### Base specifiers and member initializer lists

{/* source:cpp-language-parameter-pack:0056 */}
A pack expansion may designate the list of base classes in a [class declaration](/docs/cpp/language/classes/class). Typically, this also means that the constructor needs to use a pack expansion in the [member initializer list](/docs/cpp/language/classes/initializer_list) to call the constructors of these bases:

{/* source:cpp-language-parameter-pack:0057 */}
```cpp
template<class... Mixins>
class X : public Mixins...
{
public:
    X(const Mixins&... mixins) : Mixins(mixins)... {}
};
```

### Lambda captures

{/* source:cpp-language-parameter-pack:0058 */}
Pack expansion may appear in the capture clause of a [lambda](/docs/cpp/language/functions/lambda) expression:

{/* source:cpp-language-parameter-pack:0059 */}
```cpp
template<class... Args>
void f(Args... args)
{
    auto lm = [&, args...] { return g(args...); };
    lm();
}
```

### The sizeof... operator

{/* source:cpp-language-parameter-pack:0060 */}
The [sizeof...](/docs/cpp/language/templates/sizeof...) operator is classified as a pack expansion as well:

{/* source:cpp-language-parameter-pack:0061 */}
```cpp
template<class... Types>
struct count
{
    static const std::size_t value = sizeof...(Types);
};
```

{/* source:cpp-language-parameter-pack:0062 */}
<Revision until="C++17">
#### Dynamic exception specifications

The list of exceptions in a [dynamic exception specification](/docs/cpp/language/exceptions/except_spec) may also be a pack expansion:

```cpp
template<class... X>
void func(int arg) throw(X...)
{
    // ... throw different Xs in different situations
}
```
</Revision>

### Alignment specifier

{/* source:cpp-language-parameter-pack:0063 */}
Pack expansions are allowed in both the lists of types and the lists of expressions used by the keyword [alignas](/docs/cpp/language/declarations/alignas). The instantiations are space-separated:

{/* source:cpp-language-parameter-pack:0064 */}
```cpp
template<class... T>
struct Align
{
    alignas(T...) unsigned char buffer[128];
};
 
Align<int, short> a; // the alignment specifiers after expansion are
                     // alignas(int) alignas(short)
                     // (no comma in between)
```

### Attribute list

{/* source:cpp-language-parameter-pack:0065 */}
Pack expansions are allowed in the lists of [attributes](/docs/cpp/language/declarations/attributes), if permitted by the attribute's specification. For example:

{/* source:cpp-language-parameter-pack:0066 */}
```cpp
template<int... args>
[[vendor::attr(args)...]] void* f();
```

{/* source:cpp-language-parameter-pack:0067 */}
<Revision since="C++17">
#### Fold expressions

In [fold expressions](/docs/cpp/language/templates/fold), the pattern is the entire subexpression that does not contain an unexpanded pack.

#### Using-declarations

In [using declarations](/docs/cpp/language/classes/using_declaration), ellipsis may appear in the list of declarators, this is useful when deriving from a template parameter pack:

```cpp
template<typename... bases>
struct X : bases...
{
    using bases::g...;
};
X<B, D> x; // OK: B::g and D::g introduced
```
</Revision>

{/* source:cpp-language-parameter-pack:0068 */}
<Revision since="C++26">
#### Pack indexing

In [pack indexing](/docs/cpp/language/templates/pack_indexing), the pack expansion contains an unexpanded pack followed by an ellipsis and subscript. The pattern of pack indexing expression is an *identifier*, while the pattern of pack indexing specifier is a *typedef-name*.

```cpp
consteval auto first_plus_last(auto... args)
{
    return args...[0] + args...[sizeof...(args) - 1];
}
 
static_assert(first_plus_last(5) == 10);
static_assert(first_plus_last(5, 4) == 9);
static_assert(first_plus_last(5, 6, 2) == 7);
```

#### Friend declarations

In class [friend declarations](/docs/cpp/language/classes/friend), each type specifier can be followed by an ellipsis:

```cpp
struct C {};
struct E { struct Nested; };
 
template<class... Ts>
class R
{
    friend Ts...;
};
 
template<class... Ts, class... Us>
class R<R<Ts...>, R<Us...>>
{
    friend Ts::Nested..., Us...;
};
 
R<C, E> rce;           // classes C and E are friends of R<C, E>
R<R<E>, R<C, int>> rr; // E::Nested and C are friends of R<R<E>, R<C, int>>
```

#### Fold expanded constraints

In [fold expanded constraints](/docs/cpp/language/templates/constraints#Fold_expanded_constraints), the pattern is the constraint of that fold expanded constraint.

A fold expanded constraint is not instantiated.
</Revision>

## Example

{/* source:cpp-language-parameter-pack:0071 */}
The below example defines a function similar to [std::printf](/docs/cpp/library/io/c/printf), that replace each occurrence of the character % in the format string with a value.

{/* source:cpp-language-parameter-pack:0072 */}
The first overload is called when only the format string is passed and there is no parameter expansion.

{/* source:cpp-language-parameter-pack:0073 */}
The second overload contains a separate template parameter for the head of the arguments and a parameter pack, this allows the recursive call to pass only the tail of the parameters until it becomes empty.

{/* source:cpp-language-parameter-pack:0074 */}
Targs is the template parameter pack and Fargs is the function parameter pack.

{/* source:cpp-language-parameter-pack:0075 */}
```cpp
#include <iostream>
 
void tprintf(const char* format) // base function
{
    std::cout << format;
}
 
template<typename T, typename... Targs>
void tprintf(const char* format, T value, Targs... Fargs) // recursive variadic function
{
    for (; *format != '\0'; format++)
    {
        if (*format == '%')
        {
            std::cout << value;
            tprintf(format + 1, Fargs...); // recursive call
            return;
        }
        std::cout << *format;
    }
}
 
int main()
{
    tprintf("% world% %\n", "Hello", '!', 123);
}
```

Output:

```text
Hello world! 123
```
