{/* source:cpp-language-translation-phases:0000 */}
C++ source files are processed by the compiler to produce C++ programs.

## Translation process

{/* source:cpp-language-translation-phases:0001 */}
The text of a C++ program is kept in units called *source files*.

{/* source:cpp-language-translation-phases:0002 */}
C++ source files undergo *translation* to become a *translation unit*, consisting of the following steps:

{/* source:cpp-language-translation-phases:0003 */}
1. Maps each source file to a character sequence.
2. Converts each character sequence to a preprocessing token sequence, separated by whitespace.
3. Converts each preprocessing token to a token, forming a token sequence.
4. Converts each token sequence to a translation unit.

{/* source:cpp-language-translation-phases:0004 */}
A C++ program can be formed from translated translation units. Translation units can be separately translated and then later linked to produce an executable program.

{/* source:cpp-language-translation-phases:0005 */}
The process above can be organized into 9 [translation phases](/docs/cpp/language/basic_concepts/translation_phases#Translation_phases).

## Preprocessing tokens

{/* source:cpp-language-translation-phases:0006 */}
A *preprocessing token* is the minimal lexical element of the language in translation phases 3 through 6.

{/* source:cpp-language-translation-phases:0007 */}
The categories of preprocessing token are:

{/* source:cpp-language-translation-phases:0008 */}
- [header names](/docs/cpp/language/preprocessor/include) (such as `<iostream>` or `"myfile.h"`)

{/* source:cpp-language-translation-phases:0009 */}
<Revision since="C++20">
- placeholder tokens produced by preprocessing [`import` and `module` directives](/docs/cpp/language/basic_concepts/modules) (i.e. `import XXX;` and `module XXX;`)
</Revision>

{/* source:cpp-language-translation-phases:0010 */}
- [identifiers](/docs/cpp/language/basic_concepts/name)
- preprocessing numbers (see below)
- [character literals](/docs/cpp/language/expressions/character_literal)<InlineRevision since="C++11">, including [user-defined](/docs/cpp/language/expressions/user_literal) character literals</InlineRevision>
- [string literals](/docs/cpp/language/expressions/string_literal)<InlineRevision since="C++11">, including [user-defined](/docs/cpp/language/expressions/user_literal) string literals</InlineRevision>
- [operators and punctuators](/docs/cpp/language/basic_concepts/punctuators), including [alternative tokens](/docs/cpp/language/expressions/operator_alternative)
- individual non-whitespace characters that do not fit in any other category

{/* source:cpp-language-translation-phases:0011 */}
  The program is ill-formed if the character matching this category is

  - apostrophe (`'`, U+0027),
  - quotation mark (`"`, U+0022), or
  - a character not in the [basic character set](/docs/cpp/language/basic_concepts/charset).

### Preprocessing numbers

{/* source:cpp-language-translation-phases:0012 */}
The set of preprocessing tokens of preprocessing number is a superset of the union of the sets of tokens of [integer literals](/docs/cpp/language/expressions/integer_literal) and [floating-point literals](/docs/cpp/language/expressions/floating_literal):

{/* source:cpp-language-translation-phases:0013 */}
<DeclarationDoc>
  <Declaration language="cpp" grammar code=". (optional) digit pp-continue-seq (optional)" />
</DeclarationDoc>

{/* source:cpp-language-translation-phases:0014 */}
<ParameterList>
  <Parameter name="digit">
    one of digits 0-9
  </Parameter>
  <Parameter name="pp-continue-seq">
    a sequence of *pp-continue*s
  </Parameter>
</ParameterList>

{/* source:cpp-language-translation-phases:0015 */}
Each *pp-continue* is one of the following:

{/* source:cpp-language-translation-phases:0016 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="identifier-continue" />
  <Declaration id="2" language="cpp" grammar code="exp-char sign-char" />
  <Declaration id="3" language="cpp" grammar code="." />
  <Declaration id="4" language="cpp" since="C++14" grammar code="’ digit" />
  <Declaration id="5" language="cpp" since="C++14" grammar code="’ nondigit" />
</DeclarationDoc>

{/* source:cpp-language-translation-phases:0017 */}
<ParameterList>
  <Parameter name="identifier-continue">
    any non-first character of a valid [identifier](/docs/cpp/language/basic_concepts/name)
  </Parameter>
  <Parameter name="exp-char">
    one of<InlineRevision since="C++11"> `P`, `p`,</InlineRevision> `E` and `e`
  </Parameter>
  <Parameter name="sign-char">
    one of `+` and `-`
  </Parameter>
  <Parameter name="digit">
    one of digits 0-9
  </Parameter>
  <Parameter name="nondigit">
    one of Latin letters A/a-Z/z and underscore
  </Parameter>
</ParameterList>

{/* source:cpp-language-translation-phases:0018 */}
A preprocessing number does not have a type or a value; it acquires both after a successful conversion an integer/floating-point literal token.

### Whitespace

{/* source:cpp-language-translation-phases:0019 */}
*Whitespace* consists of [comments](/docs/cpp/language/basic_concepts/comments), whitespace characters, or both.

{/* source:cpp-language-translation-phases:0020 */}
The following characters are whitespace characters:

{/* source:cpp-language-translation-phases:0021 */}
- character tabulation (U+0009)
- line feed / new-line character (U+000A)
- line tabulation (U+000B)
- form feed (U+000C)
- space (U+0020)

{/* source:cpp-language-translation-phases:0022 */}
Whitespace is usually used to separate preprocessing tokens, with the following exceptions:

{/* source:cpp-language-translation-phases:0023 */}
- It is not a separator in header name, character literal and string literal.
- Preprocessing tokens separated by whitespace containing new-line characters cannot form [preprocessing directives](/docs/cpp/language/preprocessor).

{/* source:cpp-language-translation-phases:0024 */}
```cpp
#include "my header"        // OK, using a header name containing whitespace

#include/*hello*/<iostream> // OK, using a comment as whitespace

#include
<iostream> // Error: #include cannot span across multiple lines

"str ing"  // OK, a single preprocessing token (string literal)
' '        // OK, a single preprocessing token (character literal)
```

### Maximal munch

{/* source:cpp-language-translation-phases:0025 */}
If the input has been parsed into preprocessing tokens up to a given character, the next preprocessing token is generally taken to be the longest sequence of characters that could constitute a preprocessing token, even if that would cause subsequent analysis to fail. This is commonly known as *maximal munch*.

{/* source:cpp-language-translation-phases:0026 */}
```cpp
int foo = 1;
int bar = 0xE+foo;   // Error: invalid preprocessing number 0xE+foo
int baz = 0xE + foo; // OK
```

{/* source:cpp-language-translation-phases:0027 */}
In other words, the maximal munch rule is in favor of [multi-character operators and punctuators](/docs/cpp/language/basic_concepts/punctuators#Multi-character_operators_and_punctuators):

{/* source:cpp-language-translation-phases:0028 */}
```cpp
int foo = 1;
int bar = 2;

int num1 = foo+++++bar; // Error: treated as “foo++ ++ +baz”, not “foo++ + ++baz”
int num2 = -----foo;    // Error: treated as “-- -- -foo”, not “- -- --foo”
```

{/* source:cpp-language-translation-phases:0029 */}
The maximal munch rule has the following exceptions:

{/* source:cpp-language-translation-phases:0030 */}
- Header name preprocessing tokens are only formed in the following cases:

{/* source:cpp-language-translation-phases:0031 */}
  - after the `include` preprocessing token in an [`#include`](/docs/cpp/language/preprocessor/include) directive

{/* source:cpp-language-translation-phases:0032 */}
<Revision since="C++17">
- in a [`__has_include`](/docs/cpp/language/preprocessor/include) expression
</Revision>

<Revision since="C++20">
- after the `import` preprocessing token in an [`import`](/docs/cpp/language/basic_concepts/modules#Syntax) directive
</Revision>

{/* source:cpp-language-translation-phases:0033 */}
```cpp
std::vector<int> x; // OK, “int” is not a header name
```

{/* source:cpp-language-translation-phases:0034 */}
- If the next three characters are `<::` and the subsequent character is neither `:` nor `>`, the `<` is treated as a preprocessing token by itself instead of the first character of the [alternative token](/docs/cpp/language/expressions/operator_alternative) `<:`.

{/* source:cpp-language-translation-phases:0035 */}
```cpp
struct Foo { static const int v = 1; };
std::vector<::Foo> x;  // OK, <: not taken as the alternative token for [
extern int y<::>;      // OK, same as “extern int y[];”
int z<:::Foo::value:>; // OK, same as “int z[::Foo::value];”
```

{/* source:cpp-language-translation-phases:0036 */}
<Revision since="C++11">
- If the next two characters are `>>` and one of the `>` character can complete a [template identifier](/docs/cpp/language/templates#Template_identifiers), the character is treated as a preprocessing token alone instead of being part of the preprocessing token `>>`.

```cpp
template<int i> class X { /* ... */ };
template<class T> class Y { /* ... */ };

Y<X<1>> x3;      // OK, declares a variable “x3” of type “Y<X<1> >”
Y<X<6>>1>> x4;   // Syntax error
Y<X<(6>>1)>> x5; // OK
```

- If the next character begins a sequence of characters that could be the prefix and initial double quote of a [raw string literal](/docs/cpp/language/expressions/string_literal#Raw_string_literals), the next preprocessing token is a raw string literal. The literal consists of the shortest sequence of characters that matches the raw-string pattern.

```cpp
#define R "x"
const char* s = R"y";         // ill-formed raw string literal, not "x" "y"
const char* s2 = R"(a)" "b)"; // a raw string literal followed by a normal string literal
```
</Revision>

## Tokens

{/* source:cpp-language-translation-phases:0037 */}
A *token* is the minimal lexical element of the language in translation phase 7.

{/* source:cpp-language-translation-phases:0038 */}
The categories of token are:

{/* source:cpp-language-translation-phases:0039 */}
- [identifiers](/docs/cpp/language/basic_concepts/name)
- [keywords](/docs/cpp/language/keywords)
- [literals](/docs/cpp/language/expressions#Literals)
- [operators and punctuators](/docs/cpp/language/basic_concepts/punctuators) (except preprocessing operators)

## Translation phases

{/* source:cpp-language-translation-phases:0040 */}
Translation is performed [as if](/docs/cpp/language/basic_concepts/as_if) in the order from phase 1 to phase 9. Implementations behave as if these separate phases occur, although in practice different phases can be folded together.

### Phase 1: Mapping source characters

{/* source:cpp-language-translation-phases:0041 */}
<Revision until="C++23">
1. The individual bytes of the source code file are mapped (in implementation-defined manner) to the characters of the [basic source character set](/docs/cpp/language/basic_concepts/charset#Basic_source_character_set). In particular, OS-dependent end-of-line indicators are replaced by newline characters.
2. <InlineRevision since="C++11">The set of source file characters accepted is implementation-defined</InlineRevision>. Any source file character that cannot be mapped to a character in the [basic source character set](/docs/cpp/language/basic_concepts/charset#Basic_source_character_set) is replaced by its [universal character name](/docs/cpp/language/expressions/escape) (escaped with `\u` or `\U`) or by some implementation-defined form that is handled equivalently.

<Revision until="C++17">
3. [Trigraph sequences](/docs/cpp/language/expressions/operator_alternative) are replaced by corresponding single-character representations.
</Revision>
</Revision>

<Revision since="C++23">
Input files that are a sequence of UTF-8 code units (UTF-8 files) are guaranteed to be supported. The set of other supported kinds of input files is implementation-defined. If the set is non-empty, the kind of an input file is determined in an implementation-defined manner that includes a means of designating input files as UTF-8 files, independent of their content (recognizing the byte order mark is not sufficient).

- If an input file is determined to be a UTF-8 file, then it shall be a well-formed UTF-8 code unit sequence and it is decoded to produce a sequence of Unicode scalar values. A sequence of [translation character set](/docs/cpp/language/basic_concepts/charset#Translation_character_set) elements is then formed by mapping each Unicode scalar value to the corresponding translation character set element. In the resulting sequence, each pair of characters in the input sequence consisting of carriage return (U+000D) followed by line feed (U+000A), as well as each carriage return (U+000D) not immediately followed by a line feed (U+000A), is replaced by a single new-line character.
- For any other kind of input file supported by the implementation, characters are mapped (in implementation-defined manner) to a sequence of translation character set elements. In particular, OS-dependent end-of-line indicators are replaced by new-line characters.
</Revision>

### Phase 2: Splicing lines

{/* source:cpp-language-translation-phases:0042 */}
1. <InlineRevision since="C++23">If the first translation character is byte order mark (U+FEFF), it is deleted. </InlineRevision>Whenever backslash (`\`) appears at the end of a line (immediately followed by <InlineRevision since="C++23">zero or more whitespace characters other than new-line followed by</InlineRevision> the newline character), these characters are deleted, combining two physical source lines into one logical source line. This is a single-pass operation; a line ending in two backslashes followed by an empty line does not combine three lines into one.

{/* source:cpp-language-translation-phases:0043 */}
2. If a non-empty source file does not end with a newline character after this step (end-of-line backslashes are no longer splices at this point), a terminating newline character is added.

### Phase 3: Lexing

{/* source:cpp-language-translation-phases:0044 */}
1. The source file is decomposed into [preprocessing tokens](/docs/cpp/language/basic_concepts/translation_phases#Preprocessing_tokens) and [whitespace](/docs/cpp/language/basic_concepts/translation_phases#Whitespace):

```cpp
// The following #include directive can de decomposed into 5 preprocessing tokens:

//     punctuators (#, < and >)
//          │
// ┌────────┼────────┐
// │        │        │
   #include <iostream>
//     │        │
//     │        └── header name (iostream)
//     │
//     └─────────── identifier (include)
```

{/* source:cpp-language-translation-phases:0045 */}
If a source file ends in a partial preprocessing token or in a partial comment, the program is ill-formed:

```cpp
// Error: partial string literal
"abc
```

```cpp
// Error: partial comment
/* comment
```

{/* source:cpp-language-translation-phases:0046 */}
<Revision since="C++23">
As characters from the source file are consumed to form the next preprocessing token (i.e., not being consumed as part of a comment or other forms of whitespace), universal character names are recognized and replaced by the designated element of the [translation character set](/docs/cpp/language/basic_concepts/charset#Translation_character_set), except when matching a character sequence in one of the following preprocessing tokens:

- a character literal (*c-char-sequence*)
- a string literal (*s-char-sequence* and *r-char-sequence*), excluding delimiters (*d-char-sequence*)
- a header name (*h-char-sequence* and *q-char-sequence*)
</Revision>

{/* source:cpp-language-translation-phases:0047 */}
<Revision since="C++11">
2. Any transformations performed during<InlineRevision until="C++23"> phase 1 and</InlineRevision> phase 2 between the initial and the final double quote of any [raw string literal](/docs/cpp/language/expressions/string_literal) are reverted.
</Revision>

{/* source:cpp-language-translation-phases:0048 */}
3. Whitespace is transformed:

- Each comment is replaced by one space character.
- New-line characters are retained.
- Whether each nonempty sequence of whitespace characters other than new-line is retained or replaced by one space character is unspecified.

### Phase 4: Preprocessing

{/* source:cpp-language-translation-phases:0049 */}
1. The [preprocessor](/docs/cpp/language/preprocessor) is executed.

{/* source:cpp-language-translation-phases:0050 */}
2. Each file introduced with the [`#include`](/docs/cpp/language/preprocessor/include) directive goes through phases 1 through 4, recursively.

{/* source:cpp-language-translation-phases:0051 */}
3. At the end of this phase, all preprocessor directives are removed from the source.

### Phase 5: Determining common string literal encodings

{/* source:cpp-language-translation-phases:0052 */}
<Revision until="C++23">
1. All characters in [character literals](/docs/cpp/language/expressions/character_literal) and [string literals](/docs/cpp/language/expressions/string_literal) are converted from the source character set to the [encoding](/docs/cpp/language/basic_concepts/charset#Code_unit_and_literal) (which may be a multibyte character encoding such as UTF-8, as long as the 96 characters of the [basic character set](/docs/cpp/language/basic_concepts/charset#Basic_character_set) have single-byte representations).
2. [Escape sequences](/docs/cpp/language/expressions/escape) and universal character names in character literals and non-raw string literals are expanded and converted to the literal encoding.

If the character specified by a universal character name cannot be encoded as a single code point in the corresponding literal encoding, the result is implementation-defined, but is guaranteed not to be a null (wide) character.
</Revision>

<Revision since="C++23">
For a sequence of two or more adjacent [string literal](/docs/cpp/language/expressions/string_literal) tokens, a common encoding prefix is determined as described [here](/docs/cpp/language/expressions/string_literal#Concatenation). Each such string literal token is then considered to have that common encoding prefix.
(Character conversion is moved to phase 3)
</Revision>

### Phase 6: Concatenating string literals

{/* source:cpp-language-translation-phases:0053 */}
Adjacent [string literals](/docs/cpp/language/expressions/string_literal) are concatenated.

### Phase 7: Compiling

{/* source:cpp-language-translation-phases:0054 */}
Compilation takes place: each preprocessing token is converted to a [token](/docs/cpp/language/basic_concepts/translation_phases#Tokens). The tokens are syntactically and semantically analyzed and translated as a [translation unit](/docs/cpp/language/basic_concepts/translation_phases#Translation_process).

### Phase 8: Instantiating templates

{/* source:cpp-language-translation-phases:0055 */}
Each translation unit is examined to produce a list of required template instantiations, including the ones requested by [explicit instantiations](/docs/cpp/language/templates/class_template). The definitions of the templates are located, and the required instantiations are performed to produce *instantiation units*.

### Phase 9: Linking

{/* source:cpp-language-translation-phases:0056 */}
Translation units, instantiation units, and library components needed to satisfy external references are collected into a program image which contains information needed for execution in its execution environment.

## Notes

{/* source:cpp-language-translation-phases:0057 */}
Source files, translation units and translated translation units need not necessarily be stored as files, nor need there be any one-to-one correspondence between these entities and any external representation. The description is conceptual only, and does not specify any particular implementation.

{/* source:cpp-language-translation-phases:0058 */}
<Revision until="C++23">
The conversion performed at phase 5 can be controlled by command line options in some implementations: gcc and clang use `-finput-charset` to specify the encoding of the source character set, `-fexec-charset` and `-fwide-exec-charset` to specify the ordinary and wide literal encodings respectively, while Visual Studio 2015 Update 2 and later uses `/source-charset` and `/execution-charset` to specify the source character set and literal encoding respectively.
</Revision>

{/* source:cpp-language-translation-phases:0059 */}
Some compilers do not implement instantiation units (also known as [template repositories](https://docs.oracle.com/cd/E18659_01/html/821-1383/bkagr.html#scrolltoc) or [template registries](http://www-01.ibm.com/support/knowledgecenter/SSXVZZ_12.1.0/com.ibm.xlcpp121.linux.doc/compiler_ref/fcat_template.html?lang=en)) and simply compile each template instantiation at phase 7, storing the code in the object file where it is implicitly or explicitly requested, and then the linker collapses these compiled instantiations into one at phase 9.
