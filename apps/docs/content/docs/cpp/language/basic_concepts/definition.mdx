---
title: "Definitions and ODR (One Definition Rule)"
description: "Definitions are declarations that fully define the entity introduced by the declaration."
source_url: "https://en.cppreference.com/w/cpp/language/definition"
language: "C++"
---

{/* source:cpp-language-definition:0000 */}
Definitions are [declarations](/docs/cpp/language/declarations) that fully define the entity introduced by the declaration. Every declaration is a definition, except for the following:

{/* source:cpp-language-definition:0001 */}
- A function declaration without a function body:

{/* source:cpp-language-definition:0002 */}
```cpp
int f(int); // declares, but does not define f
```

{/* source:cpp-language-definition:0003 */}
- Any declaration with an `extern` [storage class specifier](/docs/cpp/language/declarations/storage_duration) or with a [language linkage](/docs/cpp/language/declarations/language_linkage) specifier (such as `extern "C"`) without an initializer:

{/* source:cpp-language-definition:0004 */}
```cpp
extern const int a;     // declares, but does not define a
extern const int b = 1; // defines b
```

{/* source:cpp-language-definition:0005 */}
- Declaration of a <InlineRevision since="C++17">non-inline</InlineRevision> [static data member](/docs/cpp/language/classes/static) inside a class definition:

{/* source:cpp-language-definition:0006 */}
```cpp
struct S
{
    int n;               // defines S::n
    static int i;        // declares, but does not define S::i
    inline static int x; // defines S::x
};                       // defines S

int S::i;                // defines S::i
```

{/* source:cpp-language-definition:0007 */}
<Revision since="C++17">
- (deprecated) Namespace scope declaration of a static data member that was defined within the class with the [`constexpr`](/docs/cpp/language/declarations/constexpr) specifier:

```cpp
struct S
{
    static constexpr int x = 42; // implicitly inline, defines S::x
};

constexpr int S::x; // declares S::x, not a redefinition
```
</Revision>

{/* source:cpp-language-definition:0008 */}
- Declaration of a class name (by [forward declaration](/docs/cpp/language/classes/class#Forward_declaration) or by the use of the elaborated type specifier in another declaration):

{/* source:cpp-language-definition:0009 */}
```cpp
struct S;             // declares, but does not define S

class Y f(class T p); // declares, but does not define Y and T (and also f and p)
```

{/* source:cpp-language-definition:0010 */}
<Revision since="C++11">
- An [opaque declaration](/docs/cpp/language/declarations/enum) of an enumeration:

```cpp
enum Color : int; // declares, but does not define Color
```
</Revision>

{/* source:cpp-language-definition:0011 */}
- Declaration of a [template parameter](/docs/cpp/language/templates/template_parameters):

{/* source:cpp-language-definition:0012 */}
```cpp
template<typename T> // declares, but does not define T
```

{/* source:cpp-language-definition:0013 */}
- A parameter declaration in a function declaration that isn't a definition:

{/* source:cpp-language-definition:0014 */}
```cpp
int f(int x); // declares, but does not define f and x

int f(int x)  // defines f and x
{
    return x + a;
}
```

{/* source:cpp-language-definition:0015 */}
- A [typedef](/docs/cpp/language/declarations/typedef) declaration:

{/* source:cpp-language-definition:0016 */}
```cpp
typedef S S2; // declares, but does not define S2 (S may be incomplete)
```

{/* source:cpp-language-definition:0017 */}
<Revision since="C++11">
- An [alias-declaration](/docs/cpp/language/declarations/type_alias):

```cpp
using S2 = S; // declares, but does not define S2 (S may be incomplete)
```
</Revision>

{/* source:cpp-language-definition:0018 */}
- A [using-declaration](/docs/cpp/language/classes/using_declaration):

{/* source:cpp-language-definition:0019 */}
```cpp
using N::d; // declares, but does not define d
```

{/* source:cpp-language-definition:0020 */}
<Revision since="C++17">
- Declaration of a [deduction guide](/docs/cpp/language/templates/ctad#Explicit_deduction_guides) (does not define any entities)
</Revision>

<Revision since="C++11">
- A [static_assert](/docs/cpp/language/declarations/static_assert) declaration (does not define any entities)
- An [attribute declaration](/docs/cpp/language/declarations) (does not define any entities)
</Revision>

{/* source:cpp-language-definition:0021 */}
- An [empty declaration](/docs/cpp/language/declarations) (does not define any entities)
- A [using-directive](/docs/cpp/language/declarations/namespace#Using-directives) (does not define any entities)

{/* source:cpp-language-definition:0022 */}
<Revision since="C++11">
- An [explicit instantiation declaration](/docs/cpp/language/templates/class_template#Class_template_instantiation) (an "extern template"):

```cpp
extern template
f<int, char>; // declares, but does not define f<int, char>
```
</Revision>

{/* source:cpp-language-definition:0023 */}
- An [explicit specialization](/docs/cpp/language/templates/template_specialization) whose declaration is not a definition:

{/* source:cpp-language-definition:0024 */}
```cpp
template<>
struct A<int>; // declares, but does not define A<int>
```

{/* source:cpp-language-definition:0025 */}
An [asm declaration](/docs/cpp/language/declarations/asm) does not define any entities, but it is classified as a definition.

{/* source:cpp-language-definition:0026 */}
Where necessary, the compiler may implicitly define the [default constructor](/docs/cpp/language/classes/default_constructor), [copy constructor](/docs/cpp/language/classes/copy_constructor), [move constructor](/docs/cpp/language/classes/move_constructor), [copy assignment operator](/docs/cpp/language/classes/as_operator), [move assignment operator](/docs/cpp/language/classes/move_operator), and the [destructor](/docs/cpp/language/classes/destructor).

{/* source:cpp-language-definition:0027 */}
If the definition of any object results in an object of [incomplete type](/docs/cpp/language/basic_concepts/incomplete_type) or [abstract class type](/docs/cpp/language/classes/abstract_class), the program is ill-formed.

## One Definition Rule

{/* source:cpp-language-definition:0028 */}
Only one definition of any variable, function, class type, enumeration type<InlineRevision since="C++20">[, concept](/docs/cpp/language/templates/constraints)</InlineRevision> or template is allowed in any one translation unit (some of these may have multiple declarations, but only one definition is allowed).

{/* source:cpp-language-definition:0029 */}
One and only one definition of every non-[inline](/docs/cpp/language/declarations/inline) function or variable that is odr-used (see below) is required to appear in the entire program (including any standard and user-defined libraries). The compiler is not required to diagnose this violation, but the behavior of the program that violates it is undefined.

{/* source:cpp-language-definition:0030 */}
For an inline function<InlineRevision since="C++17"> or inline variable</InlineRevision>, a definition is required in every translation unit where it is *odr-used*.

{/* source:cpp-language-definition:0031 */}
For a class, a definition is required wherever the class is used in a way that requires it to be [complete](/docs/cpp/language/basic_concepts/incomplete_type).

{/* source:cpp-language-definition:0032 */}
There can be more than one definition in a program of each of the following: class type, enumeration type, inline function<InlineRevision since="C++17">, inline variable</InlineRevision>, [templated entity](/docs/cpp/language/templates#Templated_entity) (template or member of template, but not full [template specialization](/docs/cpp/language/templates/template_specialization)), as long as all following conditions are satisfied:

{/* source:cpp-language-definition:0033 */}
- Each definition appears in a different translation unit.

{/* source:cpp-language-definition:0034 */}
<Revision since="C++20">
- The definitions are not [attached to a named module](/docs/cpp/language/basic_concepts/modules).
</Revision>

{/* source:cpp-language-definition:0035 */}
- Each definition consists of the same sequence of [tokens](/docs/cpp/language/basic_concepts/translation_phases#Tokens) (typically, appears in the same header). Name lookup from within each definition finds the same entities (after [overload resolution](/docs/cpp/language/functions/overload_resolution)), except that:

{/* source:cpp-language-definition:0036 */}
- Constants with internal or no linkage may refer to different objects as long as they are not odr-used and have the same values in every definition.

{/* source:cpp-language-definition:0037 */}
<Revision since="C++11">
- [Lambda expressions](/docs/cpp/language/functions/lambda) that are not in a default argument<InlineRevision since="C++20"> or a default template argument</InlineRevision> are uniquely identified by the sequence of tokens used to define them.
</Revision>

{/* source:cpp-language-definition:0038 */}
- Overloaded operators, including conversion, allocation, and deallocation functions refer to the same function from each definition (unless referring to one defined within the definition).
- Corresponding entities have the same language linkage in each definition (e.g. the include file is not inside an `extern "C"` block).
- If a `const` object is [constant-initialized](/docs/cpp/language/initialization/constant_initialization) in any of the definitions, it is constant-initialized in each definition.
- The rules above apply to every default argument used in each definition.
- If the definition is for a class with an implicitly-declared constructor, every translation unit where it is odr-used must call the same constructor for the base and members.

{/* source:cpp-language-definition:0039 */}
<Revision since="C++20">
- If the definition is for a class with a defaulted [three-way comparison](/docs/cpp/language/expressions/default_comparisons), every translation unit where it is odr-used must call the same comparison operator for the base and members.
</Revision>

{/* source:cpp-language-definition:0040 */}
- If the definition is for a template, then all these requirements apply to both names at the point of definition and dependent names at the point of instantiation.

{/* source:cpp-language-definition:0041 */}
If all these requirements are satisfied, the program behaves as if there is only one definition in the entire program. Otherwise, the program is ill-formed, no diagnostic required.

{/* source:cpp-language-definition:0042 */}
Note: in C, there is no program-wide ODR for types, and even extern declarations of the same variable in different translation units may have different types [as long as they are compatible](/docs/c/language/basic_concepts/compatible_type#Compatible_types). In C++, the source-code tokens used in declarations of the same type must be the same as described above: if one .cpp file defines `struct S { int x; };` and the other .cpp file defines `struct S { int y; };`, the behavior of the program that links them together is undefined. This is usually resolved with [unnamed namespaces](/docs/cpp/language/declarations/namespace).

### Naming an entity

{/* source:cpp-language-definition:0043 */}
A variable is named by an expression if the expression is an identifier expression that denotes it.

{/* source:cpp-language-definition:0044 */}
A function is named by an expression or conversion in following cases:

{/* source:cpp-language-definition:0045 */}
- A function whose name appears as an expression or conversion (including named function, overloaded operator, [user-defined conversion](/docs/cpp/language/expressions/cast_operator), user-defined placement forms of [`operator new`](/docs/cpp/library/memory/new/operator_new), non-default initialization) is named by that expression if it is selected by overload resolution, except when it is an unqualified pure virtual member function or a pointer-to-member to a pure virtual function.
- An [allocation](/docs/cpp/library/memory/new/operator_new) or [deallocation](/docs/cpp/library/memory/new/operator_delete) function for a class is named by a [new expression](/docs/cpp/language/expressions/new) appearing in an expression.
- A deallocation function for a class is named by a [delete expression](/docs/cpp/language/expressions/delete) appearing in an expression.
- A constructor selected to copy or move an object is considered to be named by the expression or conversion even if [copy elision](/docs/cpp/language/initialization/copy_elision) takes place. <InlineRevision since="C++17">Using a prvalue in some contexts does not copy or move an object, see [mandatory elision](/docs/cpp/language/initialization/copy_elision#Mandatory_elision_of_copy.2Fmove_operations).</InlineRevision>

{/* source:cpp-language-definition:0046 */}
A potentially evaluated expression or conversion odr-uses a function if it names it.

{/* source:cpp-language-definition:0047 */}
<Revision since="C++11">
A potentially constant evaluated expression or conversion that names a constexpr function makes it [needed for constant evaluation](/docs/cpp/language/expressions/constant_expression#Functions_and_variables_needed_for_constant_evaluation), which triggers definition of a defaulted function or instantiation of a function template specialization, even if the expression is unevaluated.
</Revision>

### Potential results

{/* source:cpp-language-definition:0048 */}
The set of *potential results* of an expression `E` is a (possibly empty) set of identifier expressions that appear within `E`, combined as follows:

{/* source:cpp-language-definition:0049 */}
- If `E` is an [identifier expression](/docs/cpp/language/expressions#Primary_expressions), the expression `E` is its only potential result.
- If `E` is a subscript expression (`E1[E2]`) where one of the operands is an array, the potential results of that operand is included in the set.
- If `E` is a class member access expression of the form `E1.E2` or `E1.template E2` naming a non-static data member, the potential results of `E1` is included in the set.
- If `E` is a class member access expression naming a static data member, the identifier expression designating the data member is included in the set.
- If `E` is a pointer-to-member access expression of the form `E1.*E2` or `E1.*template E2` whose second operand is a constant expression, the potential results of `E1` are included in the set.
- If `E` is an expression in parentheses (`(E1)`), the potential results of `E1` are included in the set.
- If `E` is a glvalue conditional expression (`E1 ? E2 : E3`, where `E2` and `E3` are glvalues), the union of the potential results of `E2` and `E3` are both included in the set.
- If `E` is a comma expression (`E1, E2`), the potential results of `E2` are in the set of potential results.
- Otherwise, the set is empty.

### ODR-use (informal definition)

{/* source:cpp-language-definition:0050 */}
An object is odr-used if its value is read (unless it is a compile time constant) or written, its address is taken, or a reference is bound to it,

{/* source:cpp-language-definition:0051 */}
A reference is odr-used if it is used and its referent is not known at compile time,

{/* source:cpp-language-definition:0052 */}
A function is odr-used if a function call to it is made or its address is taken.

{/* source:cpp-language-definition:0053 */}
If an entity is odr-used, its definition must exist somewhere in the program; a violation of that is usually a link-time error.

{/* source:cpp-language-definition:0054 */}
```cpp
struct S
{
    static const int x = 0; // static data member
    // a definition outside of class is required if it is odr-used
};

const int& f(const int& r);

int n = b ? (1, S::x) // S::x is not odr-used here
          : f(S::x);  // S::x is odr-used here: a definition is required
```

### ODR-use (formal definition)

{/* source:cpp-language-definition:0055 */}
A variable `x` that is named by a [potentially-evaluated expression](/docs/cpp/language/expressions#Potentially-evaluated_expressions) `expr` that appears at a point `P` is odr-used by `expr`, unless any of the following conditions is satisfied:

{/* source:cpp-language-definition:0056 */}
- `x` is a reference that is [usable in constant expressions](/docs/cpp/language/expressions/constant_expression#Usable_in_constant_expressions) at `P`.
- <InlineRevision until="C++26">`x` is not a reference and </InlineRevision>`expr` is an element of the set of potential results of an expression `E`, and any of the following conditions is satisfied:
  - `E` is a [discarded-value expression](/docs/cpp/language/expressions#Discarded-value_expressions), and no lvalue-to-rvalue conversion is applied to it.
  - `x` is a<InlineRevision since="C++26"> non-volatile</InlineRevision> object that is usable in constant expressions at `P` and has no mutable subobjects, and any of the following conditions is satisfied:
    - {/* source:cpp-language-definition:0057 */}<Revision since="C++26">`E` is a [class member access expression](/docs/cpp/language/expressions/operator_member_access) naming a [non-static data member](/docs/cpp/language/classes/data_members) of reference type and whose object expression has non-volatile-qualified type.</Revision>
    - {/* source:cpp-language-definition:0058 */}`E` has non-volatile-qualified non-class type, and the lvalue-to-rvalue conversion is applied to it.

{/* source:cpp-language-definition:0059 */}
```cpp
struct S { static const int x = 1; }; // applying lvalue-to-rvalue conversion
                                      // to S::x yields a constant expression

int f()
{
    S::x;        // discarded-value expression does not odr-use S::x

    return S::x; // expression where lvalue-to-rvalue conversion
                 // applies does not odr-use S::x
}
```

{/* source:cpp-language-definition:0060 */}
`*this` is odr-used if `this` appears as a potentially-evaluated expression (including the implicit `this` in a non-static member function call expression).

{/* source:cpp-language-definition:0061 */}
<Revision since="C++17">
A [structured binding](/docs/cpp/language/declarations/structured_binding) is odr-used if it appears as a potentially-evaluated expression.
</Revision>

{/* source:cpp-language-definition:0062 */}
A function is odr-used in following cases:

{/* source:cpp-language-definition:0063 */}
- A function is odr-used if it is named by (see below) a potentially-evaluated expression or conversion.
- A [virtual member function](/docs/cpp/language/classes/virtual) is odr-used if it is not a pure virtual member function (addresses of virtual member functions are required to construct the vtable).
- A non-placement allocation or deallocation function for a class is odr-used by the definition of a constructor of that class.
- A non-placement deallocation function for a class is odr-used by the definition of the destructor of that class, or by being selected by the lookup at the point of definition of a virtual destructor.
- An assignment operator in a class `T` that is a member or base of another class `U` is odr-used by an implicitly-defined copy-assignment or move-assignment functions of `U`.
- A constructor (including default constructors) for a class is odr-used by the [initialization](/docs/cpp/language/initialization) that selects it.
- A destructor for a class is odr-used if it is [potentially invoked](/docs/cpp/language/classes/destructor#Potentially-invoked_destructor).
