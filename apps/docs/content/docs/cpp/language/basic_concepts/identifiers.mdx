{/* source:cpp-language-identifiers:0000 */}
An identifier is an arbitrarily long sequence of digits, underscores, lowercase and uppercase Latin letters, and most Unicode characters.

{/* source:cpp-language-identifiers:0001 */}
The first character of a valid identifier must be one of the following:

{/* source:cpp-language-identifiers:0002 */}
- uppercase Latin letters A-Z
- lowercase Latin letters a-z
- underscore
- any Unicode character with the Unicode property [XID_Start](https://www.unicode.org/reports/tr31/#Table_Lexical_Classes_for_Identifiers)

{/* source:cpp-language-identifiers:0003 */}
Any other character of a valid identifier must be one of the following:

{/* source:cpp-language-identifiers:0004 */}
- digits 0-9
- uppercase Latin letters A-Z
- lowercase Latin letters a-z
- underscore
- any Unicode character with the Unicode property [XID_Continue](https://www.unicode.org/reports/tr31/#Table_Lexical_Classes_for_Identifiers)

{/* source:cpp-language-identifiers:0005 */}
The lists of characters with properties XID_Start and XID_Continue can be found in [DerivedCoreProperties.txt](https://www.unicode.org/Public/UCD/latest/ucd/DerivedCoreProperties.txt).

{/* source:cpp-language-identifiers:0006 */}
Identifiers are case-sensitive (lowercase and uppercase letters are distinct), and every character is significant. Every identifier must conform to [Normalization Form C](https://www.unicode.org/charts/normalization/).

{/* source:cpp-language-identifiers:0007 */}
Note: Support of Unicode identifiers is limited in most implementations, e.g. [gcc (until 10)](https://gcc.gnu.org/wiki/FAQ#What_is_the_status_of_adding_the_UTF-8_support_for_identifier_names_in_GCC.3F).

## In declarations

{/* source:cpp-language-identifiers:0008 */}
An identifier can be used [to name](/docs/cpp/language/declarations) objects, references, functions, enumerators, types, class members, namespaces, templates, template specializations, <InlineRevision since="C++11">parameter packs</InlineRevision>, goto labels, and other entities, with the following exceptions:

{/* source:cpp-language-identifiers:0009 */}
- The identifiers that are [keywords](/docs/cpp/language/keywords) cannot be used for other purposes.

{/* source:cpp-language-identifiers:0010 */}
  - <Revision since="C++11">The only place they can be used as non-keywords is in an *attribute-token* (e.g. `[[private]]` is a valid [attribute](/docs/cpp/language/declarations/attributes)).</Revision>

{/* source:cpp-language-identifiers:0011 */}
- The identifiers that are [alternative representations](/docs/cpp/language/expressions/operator_alternative) for certain operators and punctuators cannot be used for other purposes.

{/* source:cpp-language-identifiers:0012 */}
<Revision since="C++11">
- The identifiers with special meaning (`final`<InlineRevision since="C++20">, `import`, `module`</InlineRevision> and `override`) are used explicitly in a certain context rather than being regular identifiers.
  - Unless otherwise specified, any ambiguity as to whether a given identifier has a special meaning is resolved to interpret the token as a regular identifier.
</Revision>

{/* source:cpp-language-identifiers:0013 */}
- Identifiers <InlineRevision since="C++11">that appear as a token or preprocessing token (i.e., not in *user-defined-string-literal* like `operator ""id`)</InlineRevision> of one of the following forms are reserved:
  - in the global namespace, identifiers that begin with an underscore
  - identifiers that contain a double underscore or begin with an underscore followed by an uppercase letter, except the following identifiers:

{/* source:cpp-language-identifiers:0014 */}
    - [predefined macros](/docs/cpp/language/preprocessor/replace#Predefined_macros)<InlineRevision since="C++20"> (including [language feature test macros](/docs/cpp/library/feature_test#Language_features))</InlineRevision>

{/* source:cpp-language-identifiers:0015 */}
    - <Revision since="C++11">[`std::_Exit`](/docs/cpp/library/utility/program/_Exit)</Revision>
    - <Revision since="C++11">[`__func__`](/docs/cpp/language/functions/function#func)</Revision>

{/* source:cpp-language-identifiers:0016 */}
    - the following macros defined in the standard library:
      - the C-style I/O library macros `_IOFBF`, `_IOLBF` and `_IONBF`

{/* source:cpp-language-identifiers:0017 */}
    - <Revision since="C++11">the C compatibility macros `__alignas_is_defined` and `__alignof_is_defined` (defined in [`<stdalign.h>`](/docs/cpp/library/headers/cstdalign))</Revision>
    - <Revision since="C++11">the C compatibility macro `__bool_true_false_are_defined` (defined in [`<stdbool.h>`](/docs/cpp/library/headers/cstdbool))</Revision>
    - <Revision since="C++20">[library feature test macros](/docs/cpp/library/feature_test#Library_features)</Revision>

{/* source:cpp-language-identifiers:0018 */}
“Reserved” here means that the standard library headers `#define` or declare such identifiers for their internal needs, the compiler may predefine non-standard identifiers of that kind, and that name mangling algorithm may assume that some of these identifiers are not in use. If the programmer uses such identifiers, the program is ill-formed, no diagnostic required.

{/* source:cpp-language-identifiers:0019 */}
In addition, it is undefined behavior to `#define` or `#undef` certain names in a translation unit, see [reserved macro names](/docs/cpp/language/preprocessor/replace) for more details.

### Zombie identifiers

{/* source:cpp-language-identifiers:0020 */}
As of C++14, some identifiers are removed from the C++ standard library. They are listed in the [list of zombie names](/docs/cpp/symbol-index/zombie-names).

{/* source:cpp-language-identifiers:0021 */}
However, these identifiers are still reserved for previous standardization in a certain context. Removed member function names may not be used as a name for function-like macros, and other removed member names may not be used as a name for object-like macros in portable code.

## In expressions

{/* source:cpp-language-identifiers:0022 */}
An identifier that names a variable, a function, <InlineRevision since="C++20">specialization of a [concept](/docs/cpp/language/templates/constraints),</InlineRevision> or an [enumerator](/docs/cpp/language/declarations/enum) can be used as an [expression](/docs/cpp/language/expressions). The result of an expression consisting of just the identifier is the entity named by the identifier. The [value category](/docs/cpp/language/expressions/value_category) of the expression is *lvalue* if the identifier names a function, a variable<InlineRevision since="C++20">, a [template parameter object](/docs/cpp/language/templates/template_parameters#Non-type_template_parameter)</InlineRevision>, or a data member, and <InlineRevision until="C++11">*rvalue*</InlineRevision><InlineRevision since="C++11">*prvalue*</InlineRevision> otherwise (e.g. an enumerator is <InlineRevision until="C++11">an rvalue</InlineRevision><InlineRevision since="C++11">a prvalue</InlineRevision> expression<InlineRevision since="C++20">, a specialization of a concept is a bool prvalue</InlineRevision>).

### Type

{/* source:cpp-language-identifiers:0023 */}
The type of an identifier expression is the same as the type of the entity it names.

{/* source:cpp-language-identifiers:0024 */}
<Revision since="C++11">
The following exceptions exist:

- If the entity named by the (unqualified) identifier is a local entity, and would result in an intervening [lambda expression](/docs/cpp/language/functions/lambda) capturing it by copy if it were named outside of an unevaluated operand in the declarative region in which the identifier appears, then the type of the expression is the type of a [class member access expression](/docs/cpp/language/expressions/operator_member_access) naming the non-static data member that would be declared for such a capture in the closure object of the innermost such intervening lambda expression.

```cpp
void f()
{
    float x, &r = x;

    [=]
    {
        decltype(x) y1;        // y1 has type float
        decltype((x)) y2 = y1; // y2 has type float const& because this lambda
                               // is not mutable and x is an lvalue
        decltype(r) r1 = y1;   // r1 has type float&
        decltype((r)) r2 = y2; // r2 has type float const&
    };
}
```

<Revision since="C++20">
- If the entity named is a [template parameter object](/docs/cpp/language/templates/template_parameters#Template_parameter_object) for a template parameter of type `T`, the type of the expression is `const T`.
</Revision>
</Revision>

### Unqualified identifiers

{/* source:cpp-language-identifiers:0025 */}
Besides suitably declared identifiers, the following can be used in expressions in the same role:

{/* source:cpp-language-identifiers:0026 */}
- an [overloaded operator](/docs/cpp/language/expressions/operators) name in function notation, such as `operator+` or `operator new`;
- a [user-defined conversion function](/docs/cpp/language/expressions/cast_operator) name, such as `operator bool`;

{/* source:cpp-language-identifiers:0027 */}
- <Revision since="C++11">a [user-defined literal operator](/docs/cpp/language/expressions/user_literal) name, such as `operator "" _km`;</Revision>

{/* source:cpp-language-identifiers:0028 */}
- a [template](/docs/cpp/language/templates) name followed by its argument list, such as `MyTemplate<int>`;
- the character `~` followed by a class name, such as `~MyClass`;

{/* source:cpp-language-identifiers:0029 */}
- <Revision since="C++11">the character `~` followed by a [decltype](/docs/cpp/language/declarations/decltype) specifier, such as `~decltype(str)`.</Revision>

{/* source:cpp-language-identifiers:0030 */}
- <Revision since="C++26">the character `~` followed by a [pack indexing specifier](/docs/cpp/language/templates/pack_indexing#Pack_indexing_specifier), such as `~pack...[0]`.</Revision>

{/* source:cpp-language-identifiers:0031 */}
Together with identifiers they are known as unqualified identifier expressions.

### Qualified identifiers

{/* source:cpp-language-identifiers:0032 */}
A *qualified identifier expression* is an unqualified identifier expression prepended by a scope resolution operator `::`, and optionally, a sequence of any of the following separated by scope resolution operators:

{/* source:cpp-language-identifiers:0033 */}
- a namespace name;
- a class name;

{/* source:cpp-language-identifiers:0034 */}
<Revision since="C++11">
- an enumeration name;
- a [`decltype` specifier](/docs/cpp/language/declarations/decltype) denoting a class or enumeration type.
</Revision>

{/* source:cpp-language-identifiers:0035 */}
- <Revision since="C++26">a [pack indexing specifier](/docs/cpp/language/templates/pack_indexing#Pack_indexing_specifier) denoting a class or enumeration type.</Revision>

{/* source:cpp-language-identifiers:0036 */}
For example, the expression `std::string::npos` is an expression that names the static member `npos` in the class `string` in namespace `std`. The expression `::tolower` names the function `tolower` in the global namespace. The expression `::std::cout` names the global variable `cout` in namespace `std`, which is a top-level namespace. The expression `boost::signals2::connection` names the type `connection` declared in namespace `signals2`, which is declared in namespace `boost`.

{/* source:cpp-language-identifiers:0037 */}
The keyword [`template`](/docs/cpp/language/keywords/template) may appear in qualified identifiers as necessary to disambiguate [dependent template names](/docs/cpp/language/templates/dependent_name).

{/* source:cpp-language-identifiers:0038 */}
See [qualified lookup](/docs/cpp/language/basic_concepts/qualified_lookup) for the details of the name lookup for qualified identifiers.

## Implicit member access transformation

{/* source:cpp-language-identifiers:0039 */}
If an identifier expression `E` denotes a non-static non-type member of some class `C` and all following conditions are satisfied, `E` is transformed into the class member access expression `this->E`:

{/* source:cpp-language-identifiers:0040 */}
- `E` is not the right operand of a [member access operator](/docs/cpp/language/expressions/operator_member_access#Built-in_member_access_operators).
- If `E` is a qualified identifier expression, `E` is not the un-parenthesized operand of an [address-of operator](/docs/cpp/language/expressions/operator_member_access#Built-in_address-of_operator).
- Any of the following conditions is satisfied:

{/* source:cpp-language-identifiers:0041 */}
  - `E` is [potentially evaluated](/docs/cpp/language/expressions#Potentially-evaluated_expressions).
  - `C` is the innermost enclosing class at `E`.
  - `C` is a base class of the innermost enclosing class at `E`.

{/* source:cpp-language-identifiers:0042 */}
This transformation does not apply in the template definition context (see [dependent names](/docs/cpp/language/templates/dependent_name)).

{/* source:cpp-language-identifiers:0043 */}
```cpp
struct X
{
    int x;
};

struct B
{
    int b;
};

struct D : B
{
    X d;

    void func()
    {
        d;   // OK, will be transformed into this->d
        b;   // OK, will be transformed into this->b
        x;   // Error: this->x is ill-formed

        d.x; // OK, will be transformed into this->d.x
             // instead of d.this->x or this->d.this->x
    }
};
```

## Names

{/* source:cpp-language-identifiers:0044 */}
A *name* is the use of one of the following to refer to an entity:

{/* source:cpp-language-identifiers:0045 */}
- an identifier
- an overloaded operator name in function notation (`operator+`, `operator new`)
- a user-defined conversion function name (`operator bool`)

{/* source:cpp-language-identifiers:0046 */}
- <Revision since="C++11">a user-defined literal operator name (`operator ""_km`)</Revision>

{/* source:cpp-language-identifiers:0047 */}
- a template name followed by its argument list (`MyTemplate<int>`)

{/* source:cpp-language-identifiers:0048 */}
Every name is introduced into the program by a [declaration](/docs/cpp/language/declarations). A name used in more than one translation unit may refer to the same or different entities, depending on [linkage](/docs/cpp/language/declarations/storage_duration#Linkage).

{/* source:cpp-language-identifiers:0049 */}
When the compiler encounters an unknown name in a program, it associates it with the declaration that introduced the name by means of [name lookup](/docs/cpp/language/basic_concepts/lookup), except for the [dependent names](/docs/cpp/language/templates/dependent_name) in template declarations and definitions (for those names, the compiler determines whether they name a type, a template, or some other entity, which may require [explicit disambiguation](/docs/cpp/language/templates/dependent_name)).
