{/* source:cpp-language-types:0001 */}
The following types are collectively called *fundamental types*:

{/* source:cpp-language-types:0002 */}
- (possibly cv-qualified) `void`

{/* source:cpp-language-types:0003 */}
<Revision since="C++11">
- (possibly cv-qualified) [std::nullptr_t](/docs/cpp/library/utility/types/nullptr_t)
</Revision>

{/* source:cpp-language-types:0004 */}
- [integral types](/docs/cpp/language/basic_concepts/types#Integral_types)
- [floating-point types](/docs/cpp/language/basic_concepts/types#Floating-point_types)

## void

{/* source:cpp-language-types:0005 */}
`void` — type with an empty set of values. It is an [incomplete type](/docs/cpp/language/basic_concepts/incomplete_type) that cannot be completed (consequently, objects of type `void` are disallowed). There are no [arrays](/docs/cpp/language/declarations/array) of `void`, nor [references](/docs/cpp/language/declarations/reference) to `void`. However, [pointers to void](/docs/cpp/language/declarations/pointer#Pointers_to_void) and [functions](/docs/cpp/language/functions/function) returning type `void` (procedures in other languages) are permitted.

{/* source:cpp-language-types:0006 */}
<Revision since="C++11">
### std::nullptr_t

<DeclarationDoc>
Defined in header [`<cstddef>`](/docs/cpp/library/headers/cstddef)

  <Declaration language="cpp" since="C++11" code={`typedef decltype(nullptr) nullptr_t;`} />
</DeclarationDoc>

[std::nullptr_t](/docs/cpp/library/utility/types/nullptr_t) is the type of the null pointer literal, [`nullptr`](/docs/cpp/language/expressions/nullptr). It is a distinct type that is not itself a pointer type or a pointer to member type. All Its prvalues are [null pointer constants](/docs/cpp/language/declarations/pointer#Null_pointers).

`sizeof(std::nullptr_t)` is equal to `sizeof(void*)`.
</Revision>

## Integral types

### Standard integer types

{/* source:cpp-language-types:0007 */}
`int` — basic integer type. The keyword `int` may be omitted if any of the modifiers listed below are used. If no length modifiers are present, it's guaranteed to have a width of at least 16 bits. However, on 32/64 bit systems it is almost exclusively guaranteed to have width of at least 32 bits (see below).

#### Modifiers

{/* source:cpp-language-types:0008 */}
Modifies the basic integer type. Can be mixed in any order. Only one of each group can be present in type name.

{/* source:cpp-language-types:0009 */}
- Signedness:

{/* source:cpp-language-types:0010 */}
- `signed` — target type will have signed representation (this is the default if omitted)
- `unsigned` — target type will have unsigned representation

{/* source:cpp-language-types:0011 */}
- Size:

{/* source:cpp-language-types:0012 */}
- `short` — target type will be optimized for space and will have width of at least 16 bits.
- `long` — target type will have width of at least 32 bits.

{/* source:cpp-language-types:0013 */}
<Revision since="C++11">
- `long long` — target type will have width of at least 64 bits.
</Revision>

{/* source:cpp-language-types:0014 */}
Note: as with all type specifiers, any order is permitted: `unsigned long long int` and `long int unsigned long` name the same type.

#### Extended integer types

The extended integer types are implementation-defined. Note that [fixed width integer types](/docs/cpp/library/utility/types/integer) are typically aliases of the standard integer types.
</Revision>

### Boolean type

{/* source:cpp-language-types:0020 */}
`bool` — integer type, capable of holding one of the two values: [`true`](/docs/cpp/language/expressions/bool_literal) or [`false`](/docs/cpp/language/expressions/bool_literal). The value of `sizeof(bool)` is implementation defined and might differ from `1`.

### Character types

{/* source:cpp-language-types:0021 */}
Character types are integer types used for a character representation.

{/* source:cpp-language-types:0022 */}
- `signed char` — type for signed character representation.
- `unsigned char` — type for unsigned character representation. Also used to inspect [object representations](/docs/cpp/language/basic_concepts/objects) (raw memory).
- `char` — type for character representation which can be most efficiently processed on the target system (has the same representation and alignment as either `signed char` or `unsigned char`, but is always a distinct type). [Multibyte characters strings](/docs/cpp/library/text/multibyte) use this type to represent code units. <InlineRevision since="C++11">For every value of type `unsigned char` in range [0, 255], converting the value to `char` and then back to `unsigned char` produces the original value.</InlineRevision> The signedness of `char` depends on the compiler and the target platform: the defaults for ARM and PowerPC are typically unsigned, the defaults for x86 and x64 are typically signed.
- `wchar_t` — type for wide character representation (see [wide strings](/docs/cpp/library/text/wide)). It has the same size, signedness, and alignment as one of the integer types, but is a distinct type. In practice, it is 32 bits and holds UTF-32 on Linux and many other non-Windows systems, but 16 bits and holds UTF-16 code units on Windows. The standard used to require `wchar_t` to be large enough to represent any supported character code point. However, such requirement cannot be fulfilled on Windows, and thus it is considered as a [defect](/docs/cpp/language/basic_concepts/types#Defect_reports) and removed.

{/* source:cpp-language-types:0023 */}
<Revision since="C++11">
- `char16_t` — type for UTF-16 character representation, required to be large enough to represent any UTF-16 code unit (16 bits). It has the same size, signedness, and alignment as [std::uint_least16_t](/docs/cpp/library/utility/types/integer), but is a distinct type.
- `char32_t` — type for UTF-32 character representation, required to be large enough to represent any UTF-32 code unit (32 bits). It has the same size, signedness, and alignment as [std::uint_least32_t](/docs/cpp/library/utility/types/integer), but is a distinct type.
</Revision>

{/* source:cpp-language-types:0024 */}
<Revision since="C++20">
- `char8_t` — type for UTF-8 character representation, required to be large enough to represent any UTF-8 code unit (8 bits). It has the same size, signedness, and alignment as `unsigned char` (and therefore, the same size and alignment as `char` and `signed char`), but is a distinct type.
</Revision>

{/* source:cpp-language-types:0025 */}
Besides the minimal bit counts, the C++ Standard guarantees that

{/* source:cpp-language-types:0026 */}
`1` `==` `sizeof(char)` ≤ `sizeof(short)` ≤ `sizeof(int)` ≤ `sizeof(long)` ≤ `sizeof(long long)`.

{/* source:cpp-language-types:0027 */}
Note: this allows the extreme case in which [bytes](https://en.wikipedia.org/wiki/Byte) are sized 64 bits, all types (including `char`) are 64 bits wide, and [`sizeof`](/docs/cpp/language/expressions/sizeof) returns `1` for every type.

## Floating-point types

### Standard floating-point types

{/* source:cpp-language-types:0028 */}
The following three types and their cv-qualified versions are collectively called standard floating-point types.

{/* source:cpp-language-types:0029 */}
- `float` — single precision floating-point type. Usually [IEEE-754 binary32 format](https://en.wikipedia.org/wiki/Single-precision_floating-point_format).
- `double` — double precision floating-point type. Usually [IEEE-754 binary64 format](https://en.wikipedia.org/wiki/Double-precision_floating-point_format).
- `long double` — extended precision floating-point type. Does not necessarily map to types mandated by IEEE-754.
  - [IEEE-754 binary128 format](https://en.wikipedia.org/wiki/Quadruple-precision_floating-point_format) is used by some HP-UX, SPARC, MIPS, ARM64, and z/OS implementations.
  - The most well known [IEEE-754 binary64-extended format](https://en.wikipedia.org/wiki/Extended_precision) is [x87 80-bit extended precision format](https://en.wikipedia.org/wiki/Extended_precision#x86_extended_precision_format). It is used by many x86 and x86-64 implementations (a notable exception is MSVC, which implements `long double` in the same format as `double`, i.e. binary64).
  - On PowerPC [double-double](https://en.wikipedia.org/wiki/Quadruple-precision_floating-point_format#Double-double_arithmetic) can be used.

{/* source:cpp-language-types:0030 */}
<Revision since="C++23">
#### Extended floating-point types

The extended floating-point types are implementation-defined. They may include [fixed width floating-point types](/docs/cpp/library/utility/types/floating-point).
</Revision>

### Properties

{/* source:cpp-language-types:0031 */}
Floating-point types may support [special values](/docs/cpp/library/utility/types/numeric_limits):

{/* source:cpp-language-types:0032 */}
- *infinity* (positive and negative), see [INFINITY](/docs/cpp/library/numeric/math/INFINITY)
- the *negative zero*, `-0.0`. It compares equal to the positive zero, but is meaningful in some arithmetic operations, e.g. `1.0 / 0.0 == INFINITY`, but `1.0 / -0.0 == -INFINITY`), and for some mathematical functions, e.g. [sqrt(std::complex)](/docs/cpp/library/numeric/complex/sqrt)
- *not-a-number* (NaN), which does not compare equal with anything (including itself). Multiple bit patterns represent NaNs, see [std::nan](/docs/cpp/library/numeric/math/nan.2), [NAN](/docs/cpp/library/numeric/math/NAN). Note that C++ takes no special notice of signalling NaNs other than detecting their support by [std::numeric_limits::has_signaling_NaN](/docs/cpp/library/utility/types/numeric_limits/has_signaling_NaN), and treats all NaNs as quiet.

{/* source:cpp-language-types:0033 */}
Floating-point numbers may be used with [arithmetic operators](/docs/cpp/language/expressions/operator_arithmetic) `+`, `-`, `/`, and `*` as well as various mathematical functions from [`<cmath>`](/docs/cpp/library/headers/cmath). Both built-in operators and library functions may raise floating-point exceptions and set [errno](/docs/cpp/library/error/errno) as described in [math errhandling](/docs/cpp/library/numeric/math/math_errhandling).

{/* source:cpp-language-types:0034 */}
Floating-point expressions may have greater range and precision than indicated by their types, see [FLT_EVAL_METHOD](/docs/cpp/library/utility/types/climits/FLT_EVAL_METHOD). Floating-point expressions may also be *contracted*, that is, calculated as if all intermediate values have infinite range and precision, see [`#pragma STDC FP_CONTRACT`](/docs/cpp/language/preprocessor/impl#.23pragma_STDC). Standard C++ does not restrict the accuracy of floating-point operations.

{/* source:cpp-language-types:0035 */}
Some operations on floating-point numbers are affected by and modify the state of [the floating-point environment](/docs/cpp/library/numeric/fenv) (most notably, the rounding direction).

{/* source:cpp-language-types:0036 */}
[Implicit conversions](/docs/cpp/language/expressions/implicit_cast) are defined between floating types and integer types.

{/* source:cpp-language-types:0037 */}
See [limits of floating-point types](/docs/cpp/library/utility/types/climits#Limits_of_floating-point_types) and [std::numeric_limits](/docs/cpp/library/utility/types/numeric_limits) for additional details, limits, and properties of the floating-point types.

## Range of values

{/* source:cpp-language-types:0038 */}
The following table provides a reference for the limits of common numeric representations.

{/* source:cpp-language-types:0039 */}
Prior to C++20, the C++ Standard allowed any signed integer representation, and the minimum guaranteed range of N-bit signed integers was from -(2N-1 -1) to +2N-1 -1 (e.g. −127 to 127 for a signed 8-bit type), which corresponds to the limits of [ones' complement](https://en.wikipedia.org/wiki/Ones%27_complement) or [sign-and-magnitude](https://en.wikipedia.org/wiki/Signed_number_representations#Sign-and-magnitude_method).

{/* source:cpp-language-types:0040 */}
However, all C++ compilers use [two's complement](https://en.wikipedia.org/wiki/Two%27s_complement) representation, and as of C++20, it is the only representation allowed by the standard, with the guaranteed range from -2N-1 to +2N-1 -1 (e.g. −128 to 127 for a signed 8-bit type).

{/* source:cpp-language-types:0041 */}
8-bit ones' complement and sign-and-magnitude representations for `char` have been disallowed since C++11 (via the resolution of [CWG issue 1759](https://cplusplus.github.io/CWG/issues/1759.html)), because a UTF-8 code unit of value 0x80 used in a [UTF-8 string literal](/docs/cpp/language/expressions/string_literal) must be storable in a `char` type object.

{/* source:cpp-language-types:0042 */}
The range for a floating-point type `T` is defined as follows:

{/* source:cpp-language-types:0043 */}
- The minimum guaranteed range is the most negative finite floating-point number representable in `T` through the most positive finite floating-point number representable in `T`.
- If negative infinity is representable in `T`, the range of `T` is extended to all negative real numbers.
- If positive infinity is representable in `T`, the range of `T` is extended to all positive real numbers.

{/* source:cpp-language-types:0044 */}
Since negative and positive infinity are representable in [ISO/IEC/IEEE 60559](https://www.iso.org/standard/80985.html) formats, all real numbers lie within the range of representable values of a floating-point type adhering to ISO/IEC/IEEE 60559.

## Data models

{/* source:cpp-language-types:0048 */}
The choices made by each implementation about the sizes of the fundamental types are collectively known as *data model*. Four data models found wide acceptance:

{/* source:cpp-language-types:0049 */}
32 bit systems:

{/* source:cpp-language-types:0050 */}
- **LP32** or **2/4/4** (`int` is 16-bit, `long` and pointer are 32-bit)
  - Win16 API
- **ILP32** or **4/4/4** (`int`, `long`, and pointer are 32-bit);
  - Win32 API
  - Unix and Unix-like systems (Linux, macOS)

{/* source:cpp-language-types:0051 */}
64 bit systems:

{/* source:cpp-language-types:0052 */}
- **LLP64** or **4/4/8** (`int` and `long` are 32-bit, pointer is 64-bit)
  - [Win32 API](https://learn.microsoft.com/en-us/windows/win32/desktop-programming) (also called the Windows API) with compilation target [64-bit ARM](https://en.wikipedia.org/wiki/AArch64) (AArch64) or [x86-64](https://en.wikipedia.org/wiki/x86-64) (a.k.a. x64)
- **LP64** or **4/8/8** (`int` is 32-bit, `long` and pointer are 64-bit)
  - Unix and Unix-like systems (Linux, macOS)

{/* source:cpp-language-types:0053 */}
Other models are very rare. For example, **ILP64** (**8/8/8**: `int`, `long`, and pointer are 64-bit) only appeared in some early 64-bit Unix systems (e.g. [UNICOS on Cray](https://en.wikipedia.org/wiki/UNICOS)).
