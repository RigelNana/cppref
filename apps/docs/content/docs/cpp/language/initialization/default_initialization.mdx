{/* source:cpp-language-default-initialization:0000 */}
This is the initialization performed when an object is constructed with no initializer.

## Syntax

{/* source:cpp-language-default-initialization:0001 */}
<DeclarationDoc>
  <Declaration id="1" language="cpp" grammar code="T object ;" />
  <Declaration id="2" language="cpp" grammar code="new T" />
</DeclarationDoc>

## Explanation

{/* source:cpp-language-default-initialization:0002 */}
Default-initialization is performed in three situations:

{/* source:cpp-language-default-initialization:0003 */}
1. when a variable with automatic, static, or thread-local [storage duration](/docs/cpp/language/declarations/storage_duration) is declared with no initializer;
{/* source:cpp-language-default-initialization:0004 */}
2. when an object with dynamic storage duration is created by a [new-expression](/docs/cpp/language/expressions/new) with no initializer;
{/* source:cpp-language-default-initialization:0005 */}
3. when a base class or a non-static data member is not mentioned in a [constructor initializer list](/docs/cpp/language/classes/initializer_list) and that constructor is called.

{/* source:cpp-language-default-initialization:0006 */}
The effects of default-initialization are:

{/* source:cpp-language-default-initialization:0007 */}
- if `T` is a (possibly cv-qualified) <InlineRevision until="C++11">non-POD</InlineRevision> class type, the constructors are considered and subjected to [overload resolution](/docs/cpp/language/functions/overload_resolution) against the empty argument list. The constructor selected (which is one of the [default constructors](/docs/cpp/language/classes/default_constructor)) is called to provide the initial value for the new object;
- if `T` is an array type, every element of the array is default-initialized;
- otherwise, no initialization is performed (see [notes](/docs/cpp/language/initialization/default_initialization#Notes)).

## Default-initialization of a const object

{/* source:cpp-language-default-initialization:0008 */}
If a program calls for the default-initialization of an object of a [const](/docs/cpp/language/declarations/cv)-qualified type `T`, `T` shall be a *const-default-constructible* class type or array thereof.

{/* source:cpp-language-default-initialization:0009 */}
A class type `T` is const-default-constructible if default-initialization of `T` would invoke a user-provided constructor of `T` <InlineRevision since="C++11">(not inherited from a base class)</InlineRevision> or if

{/* source:cpp-language-default-initialization:0010 */}
<Revision until="C++11">
Only (possibly cv-qualified) non-POD class types (or arrays thereof) with automatic storage duration were considered to be default-initialized when no initializer is used. Scalars and POD types with dynamic storage duration were considered to be not initialized (since C++11, this situation was reclassified as a form of default-initialization).
</Revision>

{/* source:cpp-language-default-initialization:0011 */}
<Revision until="C++11">
- each direct non-static data member `M` of `T` is of class type `X` (or array thereof), `X` is const-default-constructible, and
- `T` has no direct [variant members](/docs/cpp/language/classes/union#Union-like_classes), and
</Revision>

<Revision since="C++11">
- each direct non-variant non-static data member `M` of `T` has a [default member initializer](/docs/cpp/language/classes/data_members#Member_initialization) or, if `M` is of class type `X` (or array thereof), `X` is const-default-constructible,
- if `T` is a union with at least one non-static data member, exactly one [variant member](/docs/cpp/language/classes/union#Union-like_classes) has a default member initializer,
- if `T` is not a union, for each anonymous union member with at least one non-static data member (if any), exactly one non-static data member has a default member initializer, and
</Revision>

{/* source:cpp-language-default-initialization:0012 */}
each [potentially constructed](/docs/cpp/language/basic_concepts/objects#Potentially_constructed_subobjects) base class of `T` is const-default-constructible.

## Indeterminate and erroneous values

{/* source:cpp-language-default-initialization:0013 */}
<Revision until="C++26">
When storage for an object with automatic or dynamic storage duration is obtained, the object has an *indeterminate value*.

If no initialization is performed for an object, that object retains an indeterminate value until that value is replaced.
</Revision>

<Revision since="C++26">
When storage for an object with automatic or dynamic storage duration is obtained, the bytes comprising the storage for the object have the following initial value:

- If the object has dynamic storage duration, or is the object associated with a variable or [function parameter](/docs/cpp/language/functions/function) whose first declaration is marked with `[[`[`indeterminate`](/docs/cpp/language/declarations/attributes/indeterminate)`]]`, the bytes have *indeterminate values*.
- Otherwise, the bytes have *erroneous values*, where each value is determined by the implementation independently of the state of the program.

If no initialization is performed for an object (including [subobjects](/docs/cpp/language/basic_concepts/objects#Subobjects)), such a byte retains its initial value until that value is replaced.

- If any bit in the [value representation](/docs/cpp/language/basic_concepts/objects#Object_representation_and_value_representation) has an indeterminate value, the object has an *indeterminate value*.
- Otherwise, if any bit in the value representation has an erroneous value, the object has an *erroneous value*.
</Revision>

{/* source:cpp-language-default-initialization:0014 */}
If an evaluation produces an indeterminate value, the behavior is [undefined](/docs/cpp/language/basic_concepts/ub).

{/* source:cpp-language-default-initialization:0015 */}
<Revision since="C++26">
If an evaluation produces an erroneous value, the behavior is [erroneous](/docs/cpp/language/basic_concepts/ub).
</Revision>

### Special cases

{/* source:cpp-language-default-initialization:0016 */}
The following types are *uninitialized-friendly*:

{/* source:cpp-language-default-initialization:0017 */}
<Revision since="C++17">
- [`std::byte`](/docs/cpp/library/utility/types/byte)
</Revision>

{/* source:cpp-language-default-initialization:0018 */}
- `unsigned char`
- `char`, if its underlying type is `unsigned char`

{/* source:cpp-language-default-initialization:0019 */}
Given an indeterminate<InlineRevision since="C++26"> or erroneous</InlineRevision> value `value`, the *uninitialized result value* of `value` is:

{/* source:cpp-language-default-initialization:0020 */}
- An indeterminate value, if `value` is also an indeterminate value.

{/* source:cpp-language-default-initialization:0021 */}
<Revision since="C++26">
- `value`, if `value` is an erroneous value.
</Revision>

{/* source:cpp-language-default-initialization:0022 */}
If an evaluation `eval` produces an indeterminate<InlineRevision since="C++26"> or erroneous</InlineRevision> value `value` of an uninitialized-friendly type, the behavior is well-defined in the following cases:

{/* source:cpp-language-default-initialization:0023 */}
- `eval` is the evaluation of one of the following expressions and operands:

{/* source:cpp-language-default-initialization:0024 */}
  - The second or third operand of a [conditional expression](/docs/cpp/language/expressions/operator_other#Conditional_operator).
  - The right operand of a [comma expression](/docs/cpp/language/expressions/operator_other#Built-in_comma_operator).
  - The operand of an [integral conversion](/docs/cpp/language/expressions/implicit_cast#Integral_conversions), [explicit cast](/docs/cpp/language/expressions/explicit_cast) or [`static_cast`](/docs/cpp/language/expressions/static_cast) to an uninitialized-friendly type.
  - A [discarded-value expression](/docs/cpp/language/expressions#Discarded-value_expressions).

In this case, the result of the operation is the uninitialized result value of `value`.

{/* source:cpp-language-default-initialization:0025 */}
- `eval` is an evaluation of the right operand of a [simple assignment operator](/docs/cpp/language/expressions/operator_assignment#Built-in_simple_assignment_operator) whose left operand is an lvalue of an uninitialized-friendly type.

{/* source:cpp-language-default-initialization:0026 */}
In this case, the value of the object referred to by the left operand is replaced by the uninitialized result value of `value`.

{/* source:cpp-language-default-initialization:0027 */}
- `eval` is the evaluation of the initialization expression when initializing an object of an uninitialized-friendly type.

{/* source:cpp-language-default-initialization:0028 */}
<Revision since="C++17">
- `value` cannot be of type [`std::byte`](/docs/cpp/library/utility/types/byte) if the object being initialized is not of type [`std::byte`](/docs/cpp/library/utility/types/byte).
</Revision>

{/* source:cpp-language-default-initialization:0029 */}
In this case, that object is initialized to the uninitialized result value of `value`.

{/* source:cpp-language-default-initialization:0030 */}
Converting an indeterminate value of an uninitialized-friendly type produces an indeterminate value.

{/* source:cpp-language-default-initialization:0031 */}
<Revision since="C++26">
Converting an erroneous value of an uninitialized-friendly type produces an erroneous value, the result of the conversion is the value of the converted operand.
</Revision>

{/* source:cpp-language-default-initialization:0032 */}
```cpp
// Case 1: Uninitialized objects with dynamic storage duration
// All C++ versions: indeterminate value + undefined behavior
int f(bool b)
{
    unsigned char* c = new unsigned char;
    unsigned char d = *c; // OK, “d” has an indeterminate value
    int e = d;            // undefined behavior
    return b ? d : 0;     // undefined behavior if “b” is true
}

// Case 2: Uninitialized objects with automatic storage duration
// until C++26: indeterminate value + undefined behavior
// since C++26: erroneous value + erroneous behavior
int g(bool b)
{
    unsigned char c;     // “c” has an indeterminate/erroneous value

    unsigned char d = c; // no undefined/erroneous behavior,
                         // but “d” has an indeterminate/erroneous value

    assert(c == d);      // holds, but both integral promotions have
                         // undefined/erroneous behavior

    int e = d;           // undefined/erroneous behavior
    return b ? d : 0;    // undefined/erroneous behavior if “b” is true
}

// Same as case 2
void h()
{
    int d1, d2;  // “d1” and “d2” have indeterminate/erroneous values
    int e1 = d1; // undefined/erroneous behavior
    int e2 = d1; // undefined/erroneous behavior

    assert(e1 == e2); // holds
    assert(e1 == d1); // holds, undefined/erroneous behavior
    assert(e2 == d1); // holds, undefined/erroneous behavior

    // no undefined/erroneous behavior,
    // but “d2” has an indeterminate/erroneous value
    std::memcpy(&d2, &d1, sizeof(int));

    assert(e1 == d2); // holds, undefined/erroneous behavior
    assert(e2 == d2); // holds, undefined/erroneous behavior
}
```

## Notes

{/* source:cpp-language-default-initialization:0033 */}
References and const scalar objects cannot be default-initialized.

## Example

{/* source:cpp-language-default-initialization:0035 */}
```cpp
#include <string>

struct T1 { int mem; };

struct T2
{
    int mem;
    T2() {} // “mem” is not in the initializer list
};

int n; // static non-class, a two-phase initialization is done:
       // 1) zero-initialization initializes n to zero
       // 2) default-initialization does nothing, leaving n being zero

int main()
{
    [[maybe_unused]]
    int n;            // non-class, the value is indeterminate
    std::string s;    // class, calls default constructor, the value is ""
    std::string a[2]; // array, default-initializes the elements, the value is {"", ""}
//  int& r;           // Error: a reference
//  const int n;      // Error: a const non-class
//  const T1 t1;      // Error: const class with implicit default constructor
    [[maybe_unused]]
    T1 t1;            // class, calls implicit default constructor
    const T2 t2;      // const class, calls the user-provided default constructor
                      // t2.mem is default-initialized
}
```
